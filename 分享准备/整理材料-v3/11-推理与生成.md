# 11. 推理与生成：Inference、采样与推理模型

## 0. 本章位置

上一章完成后训练，参数冻结。本章讲"用"：模型如何逐 Token 生成完整回答、采样参数改变什么、KV Cache 为什么快、以及"推理能力"从哪来。

先分掉一个中文歧义：**Inference（运行模型生成输出）≠ Reasoning（多步问题求解）**。本章 1-4 节讲前者，第 5 节讲后者。

---

# 1. 训练 vs Inference

## 解决的问题

"训练"和"使用"是两个完全不同的阶段，混淆它们会导致一堆错误认知（"对话里教模型的事它记住了吗？"）。

## 核心机制

| 维度 | 训练 | Inference |
|---|---|---|
| 输入 | 大量训练样本 | 当前请求上下文 |
| 正确答案 | 来自训练文本或标注 | 通常没有 |
| 计算损失 | 是 | 否 |
| 反向传播 | 是 | 否 |
| 更新参数 | 是 | 否 |
| 主要结果 | 得到参数 | 生成下一个 Token |

这张表直接回答一个高频问题：**为什么我在对话里告诉模型一个新事实，下次新对话它不记得？**——普通 Inference 不更新参数，当前对话的信息只存在于上下文里；关掉上下文，它不会变成模型的知识。

## 核心本质

**训练改参数，Inference 用参数；一次对话不是一次学习。**

# 2. 逐 Token 生成循环

## 解决的问题

模型怎么从"下一个 Token 的概率分布"变成"一整段回答"？

## 定义

**自回归生成是一个循环：前向计算 → 选择 Token → 追加回上下文 → 重复，直到结束。**

## 核心机制

极简伪代码：

```python
while not finished:
    logits = model(context)
    next_token = sample(logits)
    context.append(next_token)
```

一次完整请求的两阶段：

| 阶段 | 做什么 | 特点 |
|---|---|---|
| Prefill | 处理当前已有的全部上下文 Token | Token 已存在，可并行计算 |
| Decode | 逐个生成新 Token | 下一个 Token 依赖上一个，**必须顺序** |

终止条件：结束 Token、停止条件、长度限制或外部控制。

三个常见澄清：

1. **模型不是先在内部写好完整答案再逐字显示**——它在循环中一个 Token 一个 Token 决定后续内容；
2. **Streaming 只是把已生成的 Token 逐步返回给用户**，改善感知延迟，不增加模型能力；
3. 训练时位置可并行（文本已知）、生成时必须顺序（未来未知）——第 6 章因果掩码的两条因果链在这里兑现。

## 核心本质

**整段回答 = 重复"预测一个 Token"几千几万次；生成的顺序性是自回归的结构属性。**

# 3. 采样策略

## 解决的问题

概率分布有了，选哪个 Token？每次都选概率最高的吗？

## 定义

**采样策略决定怎样从下一个 Token 的概率分布中选择 Token。**

## 核心机制

| 策略 | 做法 | 效果 |
|---|---|---|
| 贪心 | 每次选概率最高的 | 稳定，但容易重复、呆板 |
| Temperature | 调节分布的尖锐程度 | 低温集中，高温发散 |
| Top-k | 只在概率最高的 k 个里选 | 截断长尾 |
| Top-p | 只在累计概率达阈值的候选里选 | 自适应截断 |

必须记住的边界——这些参数改变的是**选择方式**，它们不会：

- 为模型注入新知识；
- 修复错误的训练数据；
- 让模型访问实时世界；
- 保证事实正确。

"Temperature 越低答案越准"是误读：如果模型最高概率的答案本身错误，低温只会让它**更稳定地错**。

## 核心本质

**采样参数调节输出的稳定性与多样性，与知识和真实性无关。**

# 4. KV Cache

## 解决的问题

生成第 500 个 Token 时，前 499 个 Token 没变。如果每步都重算全部历史位置的 K、V，浪费巨大。

## 定义

**KV Cache 是缓存此前各层已计算出的 Key 和 Value，生成新 Token 时只计算新位置的 QKV 并与缓存交互的机制。**

## 核心机制

```text
此前 Token 的 K/V → 缓存并复用
新 Token          → 只计算新的表示，新的 Q 与缓存的 K/V 交互
```

代价：KV Cache 占用显存，且随上下文长度和层数增长——这个代价正是后续 GQA 等优化的动机（下一章）。

## 核心本质

**用空间换时间：历史 K/V 算一次、重复用，是自回归生成的关键效率优化。**

# 5. 推理能力与推理模型

## 解决的问题

区分三件事：模型**拥有**知识 ≠ 模型能**调用**知识做多步推理。复杂问题（数学、代码、多步规划）需要后者。

## 定义

**推理能力指模型进行多步问题求解的能力；推理模型指通过训练和推理时计算增强这种能力的模型。**

## 核心机制

### 为什么"生成中间步骤"有用

**模型通过生成中间步骤，获得更大的计算空间。**

一次前向计算直接给答案，计算量固定；先写一步步推导、再得结论，每生成一个 Token 都是一次新的前向计算——**推理的深度变成了生成长度**。这是"模型生成的 Token 数"与"模型思考的步数"挂钩的原理。

### 能力的两个来源

1. **训练侧**：在推理轨迹（长思维链 + 最终答案）上做 SFT / RL（如 RLVR——用可验证奖励做强化学习，答案对错明确的问题尤其适合）；
2. **推理时计算（Test-time Compute）**：允许模型生成更长的思考过程、多次采样再投票/筛选。

### 必要的边界

- 思维链可以由提示引出，也可以由训练增强——**Reasoning ≠ 强化学习**；
- 更长的思考不保证正确，推理模型也会错；
- 推理消耗大量生成 Token，成本高、延迟大。

## 核心本质

**推理能力来自"把思考外化成生成过程"：训练教它怎么想，推理时计算给它时间想。**

---

# 6. 极简总结

**Inference = 参数不变的逐 Token 循环（Prefill 并行、Decode 顺序）；采样 = 调稳定性与多样性，不调知识和真值；KV Cache = 空间换时间；推理模型 = 把思考外化为生成，训练侧 + 推理时计算两侧增强。**

---

# 7. 遗留的问题

模型能用了，但"做大、做长、做快"的工程问题全面浮现：

1. 上下文越长，注意力计算和 KV Cache 显存爆炸（O(n²) / 线性增长）；
2. 模型越大，每次激活全部参数，算力成本高；
3. 部署时显存和延迟的限制，逼着模型压缩。
