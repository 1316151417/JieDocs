M01 · 机器学习一类任务：人做得出来，但规则写不出来

换一种分工：人给约束，机器找参数

传统程序RULES

输出 = f(规则, 输入)

订单计价：金额·优惠·税费·运费，规则写得清。规则写得出来的问题，传统程序就是最优解，无可替代。

垃圾邮件 / 是不是猫 / 会不会流失：几百条规则照样冲突、漏网、过时。

机器学习LEARN

参数 θ = Train(数据, 模型形式, 目标) 预测 ŷ = f(x; θ)

定义：让机器从数据中学习可泛化的规律，使任务表现随经验改善。

不是「机器自动发现一切」——人决定喂什么数据、用什么模型、什么算好；机器只在约束里找那组数字。

本质机器学到的不是人类可读的规则，是一组让误差变小的参数 θ。
M01 · 机器学习「学习」在工程上由哪几个模块构成、怎么转起来？

→

例：ŷ = w·x + b
→

例：L = ½(ŷ−y)²

OPTIMIZER

没有数据 → 无从学；没有模型形式 → 无处放参数

没有损失 → 不知道好坏；没有优化器 → 知道错也不会调

四个角色齐 → 「学习」发生。后面所有模型（含 GPT）都在这个闭环里

M01 · 机器学习训练分数好 = 用起来好吗？

泛化：真正的目标是新数据训练误差低有两种含义

过拟合 = 容量过大，把训练数据连同噪声一起记住
数据集职责
训练集调参数（喂给优化器）
验证集选方案（结构 / 超参）
测试集估计真实使用表现

泛化 = 在没见过、但与真实场景相似的新数据上仍然有效。

所以评估只看新数据上的表现，训练分数本身不说明问题。

本质训练的目标不是压低训练误差，而是新数据上依然有效——否则只是记忆，不是学习。
M02 · 线性模型四个组件在线性回归里各自长什么样？训练过程到底发生了什么？

线性回归：看一次完整的训练▶ 播放 = 梯度下降 140 步

模型  ŷ = w·x + b 损失  L = 1/N Σ(ŷᵢ−yᵢ)² 梯度  ∂L/∂w = 2/N Σ(ŷᵢ−yᵢ)·xᵢ 更新  w ← w − η·∂L/∂w  η=学习率

初始 w, b 随机 → 每步用全体样本的误差方向微调 → 直线贴合数据、损失单调下降。这就是「学习」的全部。

损失曲线 L(w,b)：沿梯度下坡
本质「学习」= 预测 → 算误差 → 沿梯度微调参数 的循环；模型里没有中文规律，只有数字。

M02 · 线性模型三个模型是三种技术吗？叠多层线性能否突破边界？

家族统一于 Wx+b，边界也止于线性

任务输出损失本质
线性回归连续值预测ŷ = wᵀx+b平方误差全部建立在 Wx+b 之上
表达能力全部止步于线性
Softmax 回归多分类softmax(Wx+b)交叉熵
单层感知机二分类step(wᵀx+b)误差驱动更新

叠线性 ≠ 非线性（代数证明）

h₁ = W₁x + b₁ h₂ = W₂h₁ + b₂ = W′x + b′  # W′=W₂W₁, 合并仍是一次线性

所以「多叠几层线性」不能突破边界——必须引入非线性。→ M03

M03 · 多层感知机非线性表达能力从哪来？

MLP = 多层线性 + 非线性激活hᵢ = σ(Wᵢhᵢ₋₁ + bᵢ)

激活函数增加了什么

不是玄学「加非线性」，而是：让不同输入区域走不同的加工路径——网络由此能表示分段、弯曲、任意复杂的边界。

没有非线性的深度是假深度：线性套线性可合并为一次线性（上页已证）。

本质表达能力 = 「多层线性变换 × 非线性折叠」反复复合；Playground 圆/螺旋演示即此（「圆不在直线的世界里，但可被直线组合围出来」）。
M03 · 多层感知机损失只在最末端，中间几十层参数怎么知道该调多少？

反向传播：前向算值，反向算梯度

定义：从损失出发、用链式法则逐层计算每个参数梯度的算法。

关键：每层更新量 = 我的输出对最终损失的影响 × 我能放大的程度。

工程：自动微分由框架完成；没有它，几十层的参数无从训练。

本质把「损失对输出的埋怨」逐层分摊回每一个参数——多层网络因此可训练。
M03 · 多层感知机图片里「猫」的特征是什么？——没人写得全

特征学习：设计特征的工作也交给机器

像素 →▲ 边缘 · 方向 →▲ 纹理 · 局部形状 →▲ 物体部件 →▲ "是猫"
每上一层：离原始像素远一点，离任务目标近一点
传统 ML深度学习
人提供特征 + 模型形式 + 数据网络结构 + 数据
机器学参数特征（中间表示）+ 参数

「深」= 逐层组合：前层拼简单模式，后层把模式组成抽象概念。训练闭环（数据→模型→损失→优化）不变，变的是特征从人手里交出去。

边界中间表示是分布式的（一概念由许多神经元共同表达，未必可命名）；能表达 ≠ 学得出来（初始化/学习率都可能训崩）。
本质深度学习的分界线：表示也自动化——模型逐层形成任务所需的中间表示。

M04 · 结构假设MLP 每次只看固定输入——当前词的含义可能取决于前文

RNN：随序列更新的压缩状态hₜ = tanh(W_x·xₜ + W_h·hₜ₋₁ + b)

状态即记忆：hₜ 是此前信息的压缩摘要，不是完整历史。

历史参与运算：当前词 + 旧摘要 → 新摘要，顺序信息因此进入模型。

历史地位：LSTM / GRU 改良版统治序列建模多年，直到被 Attention 取代 → M05

本质用一个固定维度的压缩状态承载不断增长的历史——这个设计既是它的贡献，也是它的瓶颈。
M05 · 注意力序列一长、模型一大，RNN 的三个结构性限制全部恶化

限制 ①
长距离路径 O(n)

限制 ②
无法并行
h₁₀₀ 要等 h₉₉ —— 序列维串行，而大模型最需要大规模并行训练
限制 ③
固定大小瓶颈
10 个词和 1 万个词都要压进同一个 d 维向量
问题升级LSTM 缓解 ①③，但「按顺序逐步计算」这条路线本身没变——能不能不走接力赛，直接找到需要的那个词？
M05 · 注意力同一个「银行」，为什么在两句话里意思不同？

含义在关系里 → 需要按内容取信息

RNN 的限制Attention 的回应
长距离路径 O(n)任意两位置直接计算关系，路径 = 1

本质Attention = 按内容相关性动态加权汇总：相关的多取、不相关的少取——每个位置由此获得「上下文相关表示」。

M06 · TRANSFORMERAttention 只管通信——一个可训练、可堆叠的单元还缺什么？

部件职责

FFN位置内加工：d → 4d → d（容量主要在这）

M08 · 自回归 LM / GPT互联网规模的文本，谁去标注正确答案？

因果掩码下一次前向同时算出所有位置的预测 → 每个位置一个交叉熵损失，取平均。

# 预训练循环（极简版）
tokens = tokenize(text)
logits = model(tokens[:-1])     # 只看过去
loss   = cross_entropy(logits, tokens[1:])
update(loss).backward() + optimizer
L = −(1/T) Σₜ log P(tₜ₊₁ | t₁…tₜ)

自回归 = 用自己生成的输出作为下一步输入 → 逐 Token 续写。互联网有多大，训练集就有多大，零人工标注。

本质预训练 = 海量文本 × 一个统一目标 × 零标注；把「理解语言」变成逐 Token 的条件概率预测。

M11 · INFERENCE生成第 500 个 Token 时，前 499 个的 K/V 根本没变——却要重算？

KV Cache：算一次，重复用空间换时间

t=1K₁V₁
t=2K₁V₁K₂V₂
t=3K₁V₁K₂V₂K₃V₃
t=4K₁V₁K₂V₂K₃V₃K₄V₄
t=5K₁V₁K₂V₂K₃V₃K₄V₄只算 q₅→查缓存
缓存只增不改；新 Token 只算自己的 QKV，q₅ 与整段缓存做 Attention
KV显存 = 2(K,V) × L(层数) × H_kv(KV头) × d_head × T(长度) × 字节
# 实算：Llama-7B (L=32, H=32, d_head=128, fp16)
每 Token = 2×32×32×128×2B = 0.5 MB
4K 上下文 ≈ 2 GB  32K ≈ 16 GB（比权重还大）

代价：缓存显存随长度线性膨胀 → 这正是 GQA / MQA（M12）要优化的对象。它是性能优化，不改变任何能力。

本质历史 K/V 算一次、重复用——自回归生成的关键效率机制；成本记在显存上。
M11 · INFERENCE概率分布有了——选哪个？每次都选最高分吗？

采样策略：调分布形状，不调对错拖动温度看分布变化

temperature T = 1.00

pᵢ = softmax(zᵢ / T)

  • T → 0：退化为贪心（永远选 top-1，稳定但呆板易重复）
  • T = 1：模型原生分布
  • T > 1：抹平差距，更发散、更有创造性也更易跑偏

截断策略

Top-k：只在最高 k 个里采；Top-p：只在累计概率达阈值的最小集合里采（自适应截断长尾）。

边界采样参数不注入知识、不修复数据、不保证正确——top-1 本身是错的，低温只会让它更稳定地错。
本质温度/截断调节输出的稳定性与多样性，与知识和真实性无关。
M11 · INFERENCE拥有知识 ≠ 能调用知识做多步推理——计算空间从哪来？

推理模型：把思考外化成生成推理深度 = 生成长度

直接回答问题→1 次前向→答案
先思考问题→推导₁→推导₂→…推导ₙ→答案
每个 Token 都是一次完整前向计算——中间步骤 = 额外的计算空间

一次前向直接作答，计算量固定；先写推导再作答，深度与问题匹配。这就是「思考的步数」与「生成的 Token 数」挂钩的原理。

能力的两个来源

  • 训练侧：在长思维链 + 答案的轨迹上做 SFT / RL（RLVR：可验证奖励——答案对错明确的问题尤其适合）
  • 推理时计算：给更长思考预算；多次采样再投票 / 筛选
边界Reasoning ≠ 强化学习（CoT 可由提示引出）；更长 ≠ 更对；推理消耗大量 Token——成本高、延迟大。
本质训练教它怎么想，test-time compute 给它时间想——思考过程本身成了生成内容。

M13 · AGENT不管参数多大：实时数据 / 执行操作 / 长期状态，模型天然做不到

Tool Call：模型出请求，系统出执行

访问实时数据 ✗ —— 训练数据有截止点

执行外部操作 ✗ —— 它只能输出文本

长期状态 / 结果验证 / 多步保证 ✗ —— 推理不更新参数、不验证事实

# 一次工具调用的消息流（模型的输入输出全是 Token）
{"role": "user",     "content": "查一下 order-api 最近 30 分钟的异常指标"}
{"role": "assistant", "tool_calls": [{"tool": "query_metrics", "arguments": {"service": "order-api", "window": "30m"}}]}  ← 模型只生成这段 JSON
{"role": "tool",     "content": "{\"error_rate\": \"3.2%\", \"p99\": \"840ms\"}"}  ← 外部系统执行后，结果拼回上下文
{"role": "assistant", "content": "错误率 3.2%、P99 840ms，疑似连接池耗尽，建议…"}  ← 模型基于新上下文继续

闭环：任务 → 模型判断需要工具 → 生成结构化调用（工具名+参数）→ 系统执行 → 结果喂回 → 模型继续。

关键模型输出工具调用参数 ≠ 模型执行了工具——执行永远发生在外部系统。
本质LLM 是生成器不是执行器——缺的不是智能，是与世界的接口；Tool Call 就是这个接口的协议。
M13 · AGENT一次性生成无法根据执行结果修正——错了就一路错到底

ReAct：环境反馈驱动的循环

观察 Observation→ 思考 Thought→ 行动 Action→ 新观察 …

vs 多轮对话

多轮的驱动力是用户追问；ReAct 的驱动力是环境反馈——单次任务内自我推进。

规划 Planning

复杂目标拆子任务、定顺序、看中间结果、必要时调整。先计划再执行 或 边想边做（ReAct 风格），可组合。

Skill 技能

把「这类任务怎么做」（步骤·约束·工具用法·异常处理）固化成可复用知识，替代每次临场发挥——同类任务不再重复犯错。

本质从「一口气生成」变成「基于反馈不断修正的循环」；Skill 把稳定性从临场发挥变成工程资产。
