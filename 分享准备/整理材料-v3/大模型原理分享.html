一 · 机器学习

有一大类任务：人做得出来，但写不出规则

传统程序

规则 + 输入 → 输出

算订单价格：金额、优惠、税费、运费，规则写得清清楚楚。对规则写得出来的问题，传统程序就是最好的方案，无可替代。

机器学习新的分工

人提供：数据 · 模型形式 · 目标（什么算好）

机器负责：在这些约束里，把那组参数找出来

不是「丢给机器自动发现一切」——人仍然决定喂什么、用什么模型、怎么算好坏。

垃圾邮件判断图片里是不是猫客户会不会流失 共性：说不清楚自己是怎么做的
带走一句机器学到的不是人类可读的规则，是一组让误差变小的数字。

一 · 机器学习 泛化

真正要的不是「背下答案」

过拟合假学会

  • 训练数据上误差很低
  • 拿到新数据就乱猜
  • 本质：容量太大，把数据连同噪声一起背下来

泛化真学会

  • 在没见过的新数据上依然准
  • 这才是训练真正优化的目标
  • 所以：别看训练指标，看新数据上的表现
但是这个例子里「面积」这个特征是人挑的——图片里「猫」的特征是什么？没人写得全。人工挑特征，成了新的瓶颈。

「深」指什么

每往上一层，表示就离原始像素远一点、离任务目标近一点。深度 = 逐层组合。

没有非线性的深度是假深度

线性套线性，合并起来还是一次线性——叠十层等于一层。

所以每层中间加一个激活函数：让不同的输入区域走不同的加工路径，直线才能组合出弯曲的、任意复杂的边界。

二 · 深度学习 顺带定位，然后转向

图像有一句话解法；文本是另一回事

CNN 一句话

同一种局部模式会出现在图片任何位置 → 用一组共享的局部检测器扫全图。这是「把数据结构写进网络」的典型例子。

但前面的输入都是「一堆特征」，没有顺序—— 文本是有顺序的 
「我没有说他偷了钱」——是我没说这话
「我没有说他偷了钱」——偷的是别的东西
「我没有说他偷了钱」——不是我说的，是别人
转折一个代词指谁要看前文，一个词的含义可能取决于几百字前的伏笔——处理序列，模型必须记住前面发生过什么。
三 · 序列与 Transformer RNN

RNN：一份随阅读进度更新的「摘要」

读「我」→摘要 h₁ ＋「喜欢」→摘要 h₂ ＋「学习」→摘要 h₃ ＋……

每读一个词，把「新词 + 旧摘要」压缩成新摘要往下传——同一组参数逐步复用，多长的序列都能处理。LSTM 等改良版统治序列建模多年。

思路的价值

第一次让「历史」以可更新的状态流过整条序列——顺序结构被写进了网络。

但它有三个娘胎里带来的结构问题

不是实现缺陷，是「逐步传递」这条路线本身的限制 →

三 · 序列与 Transformer 接力赛的三个问题

A 影响 E，必须一步一步穿过去

问题 ①
远距离要走远路
A 的信息要影响 E，必须穿过 B、C、D 的更新——路上不断被压缩、损耗
问题 ②
没法并行
算第 100 个词的状态，必须先算完第 99 个——大模型最需要的大规模并行训练上不去
问题 ③
摘要本子固定大小
读十个词还是一万个词，都得压进同一个向量
于是一个词，能不能不走接力赛，直接找到它真正需要的那个词？
三 · 序列与 Transformer Attention 的动机

词的含义不在词本身，在它和上下文的关系里

「河边有一条河。银行」 = 河岸
「我去银行取了钱。」 = 金融机构
查字典查出来一样——你的脑子知道不一样，因为一个旁边站着「河」，一个前面挂着「取钱」。
所以需要一种机制，让「银行」这个位置能根据当前内容，自己决定从哪些词、取多少信息。
三 · 序列与 Transformer Attention 三动词

Attention：寻找 · 亮线索 · 递内容

Q · Query
寻找
当前词发出：「我现在需要什么信息」
→
K · Key
线索
每个词亮出：「我能提供什么匹配特征」
→
V · Value
内容
匹配上的，把内容按相关程度加权递过来

效果：序列里任意两个词直接建立连接，路径长度永远是 1——远距离直达、全体并行、不用压进一个固定摘要。RNN 的三个结构问题同时解决。

Q / K / V 是训练出来的向量，不是人写的问题和关键词 多头 = 多组视角同时匹配（语法 · 指代 · 位置） 位置编码 = 把顺序加回表示（狗咬人 ≠ 人咬狗）
三 · 序列与 Transformer 因果掩码 ★ 全场最关键的一页

训练接龙时，不许偷看答案

每个位置只能看「自己 + 之前」的内容 —— 下三角

训练时一石二鸟 · 之一

整段文本已知，所有位置一次前向同时算——每个位置都在「只看过去」的约束下练习预测下一个词。防偷看，又不牺牲并行。

生成时之二

本来就只有过去——所以模型天然可以顺着往下写：写一个、追加一个、再写下一个。

四 · 预训练 监督信号哪来

洞察：文本自己就是答案

机器 → 学习
机器 学习 → 可以
机器 学习 可以 → 从
……整段文本往左错一位，每个位置自带答案

零人工标注

一段文本，天然自带所有位置的练习题和答案——互联网有多大，训练集就有多大。

这就是预训练

把整个互联网的文本这样喂进去，反复预测下一个 Token、错了就调参数。

四 · 预训练 现场实验 · 全场唯一互动

请把下一个词补完

「如果数据库连接池已经耗尽，
那么新的请求通常会——＿＿＿」
排队超时被拒绝失败都对 ✓

刚才那两秒，你完成了一次「预测下一个 Token」——而且自动调用了连接池的知识才补得出来。不懂连接池的人，猜不准这个词。

规模放到整个互联网：要预测得准，光背词频远远不够——语法、指代、因果关系、代码缩进、解题步骤……这些都能降误差。

带走一句能力不是设计出来的，是优化「预测下一个 Token」这个目标的副产品——这个简单的目标，逼着模型学会了语言、知识和一部分推理。
四 · 预训练 两条边界

两盆冷水，必须浇

① 模型不是数据库

  • 知识不是一条条可查、可溯源的记录
  • 而是分布式地压在几千亿个参数里
  • 所以会出现「参数里有、但说不准」「说得流畅、但不对」

② 数据决定上限

  • 训练数据里没有的、过时的、互相矛盾的——要么不会，要么瞎编
  • 知识有截止时间点

那它现在能当助手吗？

输入：请用三句话解释什么是缓存击穿。
它很可能续写：另一个相似的问题 / 把这句当成网页标题往下编页面

因为在它的训练数据里，「问题后面跟着的还是问题」是极常见的模式——它学的目标是「什么文本可能接着出现」。

带走一句会续写 ≠ 会当助手。能力是预训练给的，行为得有人教。
五 · 后训练 SFT · 示范教学

SFT：把数据换成高质量问答

训练数据长这样

用户问：请用三句话解释缓存击穿
理想回答：（人写的高质量答案）

底层一点都没变

还是「预测下一个 Token」——只是数据从「互联网上什么都有的文本」换成了「高质量的问答回答」。数据分布一换，行为就变了。

学会了什么

类比预训练 = 读了十年书；SFT = 上岗前一周的示范培训。它教的主要不是知识，是怎么把已有的能力按用户要的形式拿出来。

六 · 生成与边界 按下回车之后

生成是一个循环：一次只决定下一个词

while 没结束:
  算出全词表每个 Token 的概率
  按概率挑一个
  追加到上下文末尾，再来
算概率→ 挑一个→ 追加进上下文
↑ 新 Token 变成下一轮的输入
  • 不是先打好整篇草稿再逐字念——真的每次只决定下一个词
  • KV Cache：前面算过的缓存复用——纯性能优化，不改变能力
接下来这个「逐 Token」结构，直接推出三个大家日常都在困惑的结论——今天最想让大家带走的干货。
六 · 生成与边界 三个结论 ★ 核心交付页

逐 Token 生成，直接推出三件事

结论 ①

它不记得你

使用阶段不更新参数——你教的东西只活在当前上下文里，对话一关就没了。

没有进入它的脑子，只是出现在了它的眼前。

产品的「记忆」功能 = 外面拿存储做的，不是模型记住了。

结论 ②

流式输出 ≠ 更聪明

打字机效果只是把已生成的 Token 尽早推给你，改善等待体感。

温度、采样参数管的是选词风格——不注入任何新知识。

本来就要错的话，低温只会让它稳定地错。

结论 ③

幻觉有明确来源

优化目标是「当前上下文下，什么话最可能出现」——

从头到尾，没有任何一个环节在验证事实。

自信的语气不构成可信的证据，关键信息要留验证手段。

七 · Agent 模型 vs 系统

模型只输出文本；执行发生在外部系统

「帮我查线上订单服务的异常指标，定位原因，建个工单，通知负责人。」

模型能

生成查询语句 · 写邮件正文 · 生成调用请求

模型不能

真的去查监控 · 发邮件 · 确认操作成功了没有——它只能输出文本

LLM：理解与决定
生成文本 / 生成「调哪个工具 + 参数」的请求
↓ 请求
外部系统：真正执行
Tool Call：系统执行，结果喂回  ·  ReAct：观察→推理→行动→再观察  ·  Agent：目标+状态+工具+循环
↑ 结果回填，继续决定
判断句模型输出工具调用参数 ≠ 模型执行了工具；Agent 不是新模型，是组织模型的系统。看到产品「能干活」，先问：能力在参数里，还是外面那层系统给的？
