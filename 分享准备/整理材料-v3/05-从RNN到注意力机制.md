# 05. 从 RNN 到注意力机制

## 0. 本章位置

上一章结尾留下 RNN 的三个结构限制：长距离路径长、难并行、压缩瓶颈。本章讲 Attention 如何改变序列中的信息交互方式——这是通往 Transformer 和 LLM 的关键一步。

本章先讲动机与直觉，完整结构（多头、位置编码、Block）留给下一章。

---

# 1. 核心转折：从固定路径到动态连接

## 解决的问题

RNN 中远距离信息必须经过层层传递，模型大了、序列长了之后成为瓶颈。

## 核心对比

```text
RNN：
信息沿固定顺序逐步传递
A → B → C → D → E（A 影响 E 要走 4 步）

Attention：
D 直接计算自己与 A、B、C 的关系
按相关程度汇总它们的信息（一步直达）
```

一句话概括这个转折：

**从"沿固定路径传递信息"，变成"根据当前内容动态建立信息连接"。**

---

# 2. 为什么同一个词需要不同表示

## 问题

先看两句有歧义的话：

```text
银行旁边有一条河。
我去银行取了钱。
```

"银行"的初始 Token 表示可以相同，但它在两句话中的含义不同：第一句的"河"提供河岸语境，第二句的"取钱"提供金融机构语境。

## 需要的能力

**同一个 Token，必须根据上下文得到不同的表示。**

- 静态表示（如查词典、固定 Embedding）做不到这一点；
- 模型需要一种机制，让"银行"这个位置根据当前上下文，决定从哪些位置获取多少信息。

这正是 Attention 要提供的能力。反过来，Attention 也说明：

**Token 的含义不在 Token 本身，而在 Token 与上下文的关系中。**

---

# 3. 注意力机制（Attention）

## 定义

**注意力机制让每个位置根据内容计算与其他位置的相关程度，并按相关程度加权汇总信息。**

## 核心机制：三步

```text
当前词提出问题（我在找什么）
→ 与其他词匹配相关性（谁和我有关）
→ 按相关性汇总信息（把相关的信息取回来）
→ 得到上下文相关的表示
```

## "自"注意力（Self-Attention）中"自"的意思

序列自己和自己做 Attention：**Q、K、V 全部来自同一个序列**。序列中的每个 Token，既是被更新的对象，也是被别人汇总的信息来源。

对比（早期 Attention 的用法）：在 Seq2Seq 翻译中，Decoder 的 Query 去关注 Encoder 的 Key/Value——那不是"自"注意力。Self-Attention 是序列内部自我交互。

## 核心本质

**按内容相关性动态分配信息权重：相关的多取，不相关的少取，每个位置由此获得上下文相关的表示。**

---

# 4. Attention 解决了什么，还没解决什么

## 解决了

| RNN 的限制 | Attention 的回应 |
|---|---|
| 长距离路径长 | 任意两个位置直接计算关系，路径长度变成 1 |
| 难以并行 | 所有位置的计算可以同时进行（训练时） |
| 压缩瓶颈 | 不再把历史压进一个固定状态，按需取用 |

## 还没解决

1. 只有"汇总信息"这一种操作，表达能力够不够？（需要 QKV、多头来细化）
2. 按内容匹配，**顺序信息从哪来**？（"狗咬人"和"人咬狗"的内容相似但顺序不同——需要位置编码）
3. Attention 之外，一个完整的网络还需要什么？（逐位置变换、训练稳定——需要 FFN、残差、Norm）

把这些补齐，就是 Transformer。下一章把它组装完整。

---

# 5. 极简总结

**Attention = 按内容相关性动态加权汇总；Self-Attention = 序列自己与自己做；它把信息交互从"沿固定路径传递"变成"直接建立动态连接"。**
