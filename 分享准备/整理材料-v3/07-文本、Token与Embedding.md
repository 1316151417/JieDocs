# 07. 文本、Token 与 Embedding

## 0. 本章位置

上一章组装完了 Transformer，遗留三个问题：文本怎么进入模型、输出怎么变成 Token、参数怎么训练。本章解决第一个：从字符串到向量。

---

# 1. Token 与分词（Tokenizer）

## 解决的问题

模型不能直接处理人类看到的字符串，需要一个文本与离散符号之间的映射。

## 定义

**Tokenizer 是把文本切分成 Token、并映射为整数 ID 的规则。Token 是 Tokenizer 定义的离散文本单元。**

## 核心机制

```text
字符串
→ Tokenizer
→ Token 序列
→ Token ID 序列
```

Token 不总等于一个汉字或一个英文单词，它可能是完整单词、单词片段、汉字、字节片段或特殊符号（表示文本开始/结束、消息角色、工具调用边界）。示意：

```text
"Transformer 很强"
→ ["Transform", "er", " 很", "强"]
→ [1542, 281, 9201, 763]
```

聊天应用在交给模型前，会把 system、user、assistant 等消息按特定模板编码进同一段 Token 序列。

### Tokenizer 影响什么

- 同一段文本占用多少上下文长度；
- 多语言和代码的切分效率；
- 模型输出和停止的控制方式。

### Tokenizer 不做什么

**它本身不理解语义**，只是文本与 ID 之间的映射规则。

## 核心本质

**在"字符太碎、单词太不统一"之间找平衡的离散化切分规则。**

---

# 2. Embedding

## 解决的问题

Token ID 只是整数编号，编号 1000 比编号 10 大，并不代表语义更强。模型需要的是**向量**——能承载语义、能参与数学运算的表示。

## 定义

**Embedding 是把每个 Token ID 映射成一个高维向量的查找表，是模型参数的一部分。**

## 核心机制

```text
Token ID
→ 查找 Embedding 表中对应的行
→ 得到向量序列
```

两个要点：

1. 这些向量**在训练中不断调整**，不是人工设定的；
2. 必须区分两个概念：

| 概念 | 含义 |
|---|---|
| 初始 Token Embedding | Token 进入网络时的基础向量，所有上下文共享 |
| 上下文表示 | 经过多层 Attention 和 FFN 后，结合上下文形成的向量 |

**同一个"银行"拥有相同的初始 Embedding，但在"河边"和"取钱"的上下文中，最终表示不同**——这正是第 5 章说的"上下文相关表示"。

语义相似性从哪来：训练中功能相近的 Token，向量会被推到相近的位置（因为它们在相似上下文中扮演相似角色）。

## 核心本质

**给每个 Token 一个可学习的初始语义向量；上下文负责把它细化成具体含义。**

---

# 3. 从 Token 到下一个 Token 的候选分数：Logits

## 解决的问题

Decoder Block 的输出是每个位置的向量，怎么变成"下一个 Token 是什么"的预测？

## 核心机制

```text
当前位置的最终表示
→ 输出层（线性变换到词表大小）
→ 为词表中每个候选 Token 产生一个 Logit
→ Softmax
→ 概率分布
→ 按生成策略选择下一个 Token
```

- **Logit**：模型对每个候选 Token 给出的未归一化分数；
- **Softmax**：把分数变成概率分布（回到第 2 章 Softmax 回归的形式——**LLM 的输出层就是一个以全词表为类别的 Softmax 多分类**）；
- **采样**：根据概率和生成参数选择下一个 Token。

示意：在"天空通常是"之后——

| 候选 Token | 概率示意 |
|---|---:|
| 蓝色 | 0.62 |
| 灰色 | 0.15 |
| 晴朗 | 0.08 |
| 其他 | 0.15 |

注意：**概率不是事实置信度**，它表示在当前模型和上下文下，哪些 Token 更符合模型学到的分布。

## 核心本质

**一次前向计算不输出整句话，只输出"下一个 Token"的全词表概率分布。**

# 4. 完整前向过程（Decoder-only LLM）

把 6、7 两章串起来，一条稳定的信息流主干：

```text
文本
→ Tokenizer → Token IDs
→ Embedding → 向量序列
→ 多个 Decoder Blocks
   ├─ Norm
   ├─ Causal Self-Attention（现代模型常配 RoPE、GQA）
   ├─ Residual
   ├─ Norm
   ├─ FFN（现代模型常用 SwiGLU）
   └─ Residual
→ 输出层
→ Logits → Softmax → 下一个 Token
```

RMSNorm、RoPE、SwiGLU、GQA 等属于现代架构的具体选择，只需知道"位于哪里、解决什么问题"（第 12 章统一交代）；**稳定主干是：Token → Embedding → Decoder Blocks → Logits → 下一个 Token。**

---

# 5. 极简总结

**Tokenizer = 文本变离散 ID；Embedding = ID 变可学习向量（初始语义）；多层 Block = 初始语义细化为上下文表示；Logits + Softmax = 上下文表示变下一个 Token 的概率。**
