# 10. SFT 与偏好对齐：从基础模型到助手

## 0. 本章位置

上一章结尾指出：预训练模型"有能力、没行为"。本章讲后训练的两条路线——SFT 塑造"按指令回答"的行为，偏好对齐塑造"哪种回答更好"的倾向。

---

# 1. SFT（监督微调）

## 解决的问题

基础模型不天然服从指令：给它"请用三句话解释缓存击穿"，它可能续写下一个相似问题。

## 定义

**SFT 是用"指令 + 理想回答"格式的样本，继续用下一个 Token 预测目标训练模型，使其学会按指令组织回答的微调方法。**

## 核心机制

数据形式：

```text
用户指令：请用三句话解释什么是缓存击穿。
理想回答：缓存击穿是某个热点 Key 失效后，大量请求同时落到数据库……
```

从底层看，模型仍然在做下一个 Token 预测，**变化的是数据分布**：

```text
预训练：在海量混合文本上学习"什么可能接着出现"
SFT：  在高质量指令回答上学习"怎样响应用户任务"
```

SFT 让模型学会：识别任务形式、遵循输出格式、控制语气篇幅、在多轮对话中扮演助手角色。

### SFT 增加知识还是改变行为

SFT 数据也可能含新知识，但其规模远小于预训练。主要价值是让模型学会**如何调用和表达已有能力**。

一个比喻：预训练像长期阅读大量材料，SFT 像针对"怎样回答用户"的示范教学。

## 核心本质

**SFT 不是注入知识，而是教模型把已有能力按"助手的方式"组织出来——数据分布变了，训练目标没变。**

---

# 2. 偏好数据：为什么 SFT 之后还需要更多

## 解决的问题

一个问题可能有多个"基本正确"的回答，但质量不同：有的准确但冗长，有的简洁但遗漏边界，有的自信但含未经验证的内容，有的安全但过度拒绝。

**许多人类偏好很难写成确定规则**——写几十页规范也无法穷举所有上下文。

## 定义

**偏好数据是同一指令下多个候选回答的人工排序，记录"在这个上下文中，人更偏好哪个回答"。**

## 核心机制

```text
同一个用户指令
→ 模型生成回答 A、B、C、D
→ 标注者按"有帮助、符合意图、清晰、安全"排序
→ 得到偏好数据
```

关键设计：**不要求人写出完美答案，只要求人做相对判断**（A 比 B 好）——这比生成理想回答的门槛低得多，更容易规模化。

必要提醒："人更偏好"≠"客观正确"。偏好受标注规范、标注者背景、任务分布影响。

## 核心本质

**把难以规则化的"好"，转化为可规模化的相对比较。**

---

# 3. 奖励模型（Reward Model）

## 解决的问题

人工排序太贵，不可能给训练中每次更新都找人打分——需要一个自动化的偏好代理。

## 定义

**奖励模型是一个接收"指令 + 回答"、输出标量分数的模型，它学习近似人类偏好：更受偏好的回答得分更高。**

## 核心机制

```text
训练：Prompt + 候选回答 + 人工排序（A > C > B）
     → 让 RM 对更受偏好的回答给出更高分

使用：新回答 → RM → 分数（自动、大量、廉价）
```

注意：**奖励模型不生成回答**，它只打分。它学到的是"当前标注规范下，什么样的回答更符合人类偏好"。

风险伏笔：RM 只是人类偏好的**近似**——模型可能学会利用它的缺陷（Reward Hacking）。

## 核心本质

**把人的相对判断，蒸馏成一个可自动调用的打分函数。**

---

# 4. RLHF 与 PPO（经典 InstructGPT 路线）

## 解决的问题

有了奖励分数，怎么用它更新语言模型？——强化学习的经典场景：用奖励信号优化策略。

## 定义

**RLHF（基于人类反馈的强化学习）指用奖励模型的分数作为奖励，用强化学习算法（经典为 PPO）调整语言模型，使高奖励回答更可能出现。**

## 核心机制

经典三阶段（InstructGPT，2022）：

```text
阶段一：人工示范 → SFT 模型
阶段二：人工排序 → 奖励模型
阶段三：RM 评分 + PPO → 优化策略模型
```

阶段三的循环：

```text
Prompt
→ 当前策略模型（就是正在被优化的语言模型）生成回答
→ 奖励模型评分
→ PPO 根据奖励调整策略模型
→ 产生新的回答分布
→ 重复
```

对应关系：语言模型 = 策略；逐 Token 生成 = 动作；RM 分数 = 奖励。

两个稳定手段（知道即可）：约束新模型不要偏离 SFT 模型太远、混入预训练目标——防止模型为追分牺牲语言能力。

不推导 PPO 公式，只需理解它在这里的职责：**用奖励信号更新策略、同时保持更新幅度受控**。

## 核心本质

**模型不直接读取人类价值观，而是通过"示范 → 排序 → 奖励"的链条，逐步改变回答分布。**

---

# 5. DPO（直接偏好优化）

## 解决的问题

RLHF 流程复杂：要训 RM、要在线采样、PPO 调参难。能不能直接从偏好数据优化语言模型？

## 定义

**DPO 是绕过显式奖励模型和 RL 循环，直接用偏好对（好回答 vs 差回答）优化语言模型的方法。**

## 核心机制

```text
RLHF：偏好数据 → 训 RM → PPO 优化策略（两步间接）
DPO：偏好数据 → 直接更新语言模型（一步到位）
```

直观理解：对每个偏好对，提高"被偏好回答"的 Token 概率、降低"被拒绝回答"的 Token 概率，同时用参考模型（SFT 模型）约束偏移幅度。

DPO 与 RLHF 回答的是**同一个问题**（利用偏好信号塑造行为），只是路线不同；具体方法仍在演进，分享中不必展开对比细节。

## 核心本质

**把"学好回答、学差回答"变成直接的监督式目标，省掉奖励模型和 RL 循环。**

---

# 6. 对齐的能与不能

## InstructGPT 证明了什么

相比只扩大模型，**少量高质量示范和偏好数据，可以显著改变用户感受到的行为质量**。论文人类评估中，较小的 InstructGPT 在偏好度上超过了大得多的原始 GPT-3——"更大"和"更符合意图"是两个维度。

## 对齐不能保证什么

- 奖励模型只是偏好的近似，可能被利用；
- 更受偏好的表达 ≠ 事实正确；
- 不同人、不同场景的偏好可能冲突；
- 过度优化安全或风格，可能造成不必要的拒绝或模板化。

## 核心本质

**对齐改变的是行为的"倾向"，不是知识的"真值"。**

---

# 7. 极简总结

**SFT = 教行为不注知识；偏好数据 = 把"好"变成相对比较；奖励模型 = 偏好的自动打分代理；RLHF = 用奖励改分布；DPO = 省掉 RM 的一步式偏好优化；对齐 = 管倾向，不管真值。**
