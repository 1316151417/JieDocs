# 从机器学习到现代 LLM：一个只会执行规则的程序，如何变成你的 AI 助手

> 一条从"根据误差调整参数"，到"从海量文本学习并逐 Token 生成"的完整认知主线。

我们每天都在使用各种 AI 工具：问问题、写代码、总结文档、分析数据。它表现得像一个能理解意图、掌握知识、组织语言的人。

但只要往下追问一层，问题很快变得模糊：

- 模型的知识是从哪来的？
- 为什么它能看懂上下文？
- 它为什么会听我的指令，而不是自顾自地说话？
- 我按下回车之后，那段回答到底是怎么出来的？

这场分享不教你工具使用技巧，也不盘点模型新闻。我们只做一件事：**在五十分钟里，搭一张足够稳定的认知地图**——以后再看到任何 AI 新概念、新模型、新产品宣传，你能自己判断它到底改变了什么。

整场分享只回答一个问题：

> **一个只会执行人写好的规则的程序，是怎么一步一步变成今天能陪你写代码的助手的？**

答案是七级台阶：

~~~text
机器学习：从数据里找参数
深度学习：连特征也自己学
Transformer：每个词直接看全文
预训练：从海量文本里长出能力
后训练：学会当助手
生成：一个 Token 一个 Token 说出来
Agent：从说话到做事
~~~

先说明一个边界：这不是七代互相淘汰的技术。它们不在同一个层面——机器学习、深度学习是方法；Transformer 是网络结构；预训练、后训练是训练阶段；Agent 是模型外部的系统。把它们排成一条线，只是为了看清**能力是怎么一层一层长出来的**。

还有一个预期管理：今天出现的公式只有一条，就是最简单的一次函数；中间有一个浏览器现场演示；剩下的全部是逻辑，没有数学。

# 第一部分：开场——四个日常困惑

开始之前，把大家日常的困惑摆到桌面上。这四个问题就是整场分享的目录：

~~~text
知识从哪来？        → 预训练
怎么听懂上下文？    → Transformer
为什么听话？        → 后训练
回答怎么出来的？    → 生成循环
~~~

而要回答这四个问题，得先从一个更基础的问题开始：机器怎么从数据里学东西。因为不管模型多大，**今天的大模型仍然是一种机器学习模型：根据数据和误差调整参数，再用这些参数做预测。**

# 第二部分：机器学习——机器怎么从数据里找参数

## 1. 传统程序与机器学习

各位是后端，每天都在写这种代码：

~~~text
规则 + 输入 → 输出
~~~

算一笔订单价格：商品金额、优惠、税费、运费，规则写得清清楚楚。只要规则稳定、边界清晰，这种程序非常可靠。

**对规则写得出来的问题，传统程序就是最好的方案，今天讲的任何东西都替代不了它。**

问题是，有一大类任务，人写不出规则。

判断一封邮件是不是垃圾邮件——你可以凭感觉，但试试把判断条件写全？写出五百条规则，照样有冲突、有漏网，而且垃圾邮件的套路还在变。识别图片里是不是猫、预测客户会不会流失，全是同样的困境：

**人做得出来，但说不清楚自己是怎么做的。**

机器学习换了一种分工：

~~~text
人提供：数据 + 模型形式 + 什么算好（优化目标）
机器负责：找参数
~~~

注意，不是"把数据丢给机器，它自动发现一切"。人仍然决定喂什么数据、用什么模型、怎么算好坏——机器只负责在这些约束里，把那组数值找出来。

> **一句话结论：** 机器学习通过数据、模型和优化目标，寻找一组能在新数据上继续有效的参数。

> **不要误解为：** 机器学习是"机器自己发现一切"。人始终在场，只是从写规则换成了定约束。

## 2. 线性回归：五分钟看懂训练闭环

用最简单的例子把闭环走一遍。根据面积预测房价：

~~~text
预测价格 = w × 面积
~~~

全场唯一的公式，就一个参数 w。

一开始不知道 w 是多少，随便给一个值，比如 1——预测 100 平方的房子 100 万，而真实价格是 300 万。

好，现在有了两件事：知道当前参数不对，而且知道差了多少。把很多样本的误差汇总起来，就是**损失函数**——它回答"当前这组参数有多差"。然后**优化算法**朝让误差变小的方向，微调一下 w。再来一遍。循环往复，直线越来越贴合数据点。

~~~text
给定参数 → 预测 → 算误差 → 调参数 → 再预测 → 重复
~~~

这个循环里请记住一句话：

**机器真正"学到"的，不是一条能用中文念出来的房价规律，而是一组让误差变小的数字。**

这句话适用于今天讲的所有模型，包括最大的那个。模型学到的始终是参数，不是人类可读的规则。

## 3. 泛化：训练的真正目标

最后一个概念，然后上第二级台阶。

如果模型只在训练见过的房子上算得准，拿到新房子就乱猜——它什么都没学会，只是背下了答案。所以我们真正要的不是训练误差低，而是**在没见过的新数据上依然准**，这个能力叫泛化。

训练误差低有两种可能：一种是学到了可迁移的规律；另一种是模型容量太大，把训练数据连同噪声一起背了下来——后者叫过拟合。所以评估模型不能只看训练指标，要看新数据上的表现。

~~~text
训练集：调整参数
测试集：估计真实使用表现
目标：泛化，而不是记忆
~~~

> **一句话结论：** 训练的目标不是把训练误差压到最低，而是在新数据上仍然有效；否则只是记忆，不是学习。

### 留下的瓶颈

闭环有了：数据、模型、损失、优化，四个角色凑齐。

但注意一个细节：这个例子里，"面积"这个特征，是**人挑的**。那图片呢？"猫"的特征是什么？边缘？胡须？比例？——没有人能把"猫"的特征写全。

**人工挑特征，成了新的瓶颈。**

# 第三部分：深度学习——连特征也自己学

## 4. 特征是分层的

深度学习的回答很直接：特征别让人挑了，让模型自己从原始数据里学。

它学出来的特征是分层的：

~~~text
像素 → 边缘和方向 → 纹理和局部形状 → 物体部件 → "是猫"
~~~

前几层把像素拼成简单模式，后面的层把简单模式组合成抽象概念。每往上一层，表示就离原始像素远一点、离任务目标近一点。

**深度学习的"深"，指的就是这个逐层组合的结构。**

一个必要的提醒：这只是帮助理解的示意。真实网络中的中间表示是分布式的——一个概念由许多神经元共同表示，一个神经元也可能参与多个概念，不一定能被人类清晰命名。

## 5. 没有非线性的深度是假深度

这里必须解释一件事，不然"多层"到底多了什么会被误解。

如果层与层之间只是线性变换——加权求和——那叠十层还是一层：线性套线性，合并起来仍是一次线性变换。

所以深度学习在每层中间加了一个非常简单的非线性函数（激活函数），作用一句话：

**让不同的输入区域走不同的加工路径。**

这样一来，简单分割可以被组合成弯曲的、圆形的、任意复杂的决策边界。表达能力从此不一样了。

~~~text
线性变换 → 非线性激活 → 再线性组合 → 再激活 → 逐层形成复杂表示
~~~

> **一句话结论：** 深度网络的力量不只是层数多，而是"非线性 + 多级组合"形成的表达能力；特征学习是深度学习与传统机器学习的分界线。

## 6. 现场演示：亲眼看见边界变弯

空口无凭，现场跑一个。[TensorFlow Playground](https://playground.tensorflow.org/) 能在浏览器里实时训练一个小网络，看它的决策边界怎么变。

### 演示 A：圆形数据

~~~text
数据：蓝色在中间，橙色围在外面
第一步：不加隐藏层 → 无论训练多久，只能画出一条直线
第二步：加一层隐藏层 + 非线性激活
        → 每个神经元学到一条不同角度的直线
        → 后面的层把这些直线的"是与非"组合起来
        → 边界变圆了
~~~

关键不是"模型变聪明了"，而是：**加隐藏层之前，圆不在它的表达范围里；加之后，圆成了可组合的结果。**你不可能用直尺画圆，但可以用很多短直线逼近圆。

### 演示 B：螺旋数据

换一团更难的：两股螺旋缠在一起。浅的网络学不动；加深、加宽，多级组合之后，边界能沿着螺旋盘进去。

但这里必须泼一盆冷水：

**能表达，不等于一定学得出来。**

同一个结构，换个初始化、换个学习率，可能就训崩了。深度提供的是可能性，训练是一门工程。这盆冷水先记着——后面讲大模型时它还会出现：表达能力、数据、训练优化是三个不同的问题。

## 7. 一句话带过 CNN，转向真正的重点

顺带定位，不展开：处理图像的 CNN，核心就一句话——**同一种局部模式会出现在图片任何位置，所以用一组共享的局部检测器扫全图**。它是"把对数据的理解写进网络结构"的典型例子。

今天的主线不在图像。现在到关键转折：

前面不管线性回归还是图像分类，输入都是"一堆特征"，特征之间没有先后顺序。**但文本是有顺序的。**

- "我没有说他偷了钱"——重音放在哪个字上，意思完全不同；
- 一个代词指谁，要看前文；
- 一个词的含义，可能取决于几百个字之前埋的伏笔。

**处理序列，模型需要记住前面发生过什么。**

- CNN 只给一句话就走，不要恋战——它只是"结构假设"的证据，不是主线。

# 第四部分：从 RNN 到 Transformer——上下文怎么流动

这是整场分享最重要的结构转折，讲清它，后面的一切都顺了。

## 8. RNN：一份随阅读更新的摘要

早期的答案是 RNN（循环神经网络）。思路很朴素：维护一个不断更新的隐藏状态，相当于**一份随阅读进度更新的摘要**。

~~~text
读到"我"         → 摘要 h₁
读到"喜欢" + h₁  → 摘要 h₂
读到"学习" + h₂  → 摘要 h₃
~~~

每读一个词，把"新词 + 旧摘要"压缩成新摘要，往下传。同一组参数每一步重复使用，多长的序列都能处理。

这个思路在历史上非常重要，LSTM 等改良版统治了序列建模很多年。

## 9. RNN 的三个结构性限制

但它有三个娘胎里带来的问题。设序列是 A → B → C → D → E：

**第一，远距离要走远路。**A 的信息要影响 E，必须一步一步穿过 B、C、D 的更新。离得越远，路上损耗越大——训练时表现为梯度消失，使用时表现为"前面说的话后面忘了"。

**第二，没法并行。**算第 100 个词的状态，必须先算完第 99 个。序列维度上是串行的，训练效率上不去——而大模型恰恰最需要大规模并行训练。

**第三，摘要本子是固定大小的。**不管读了十个词还是一万个词，都得压进同一个向量里。

LSTM 缓解了第一和第三个，但"按顺序逐步计算"这条路本身没变。

于是那个想法自然冒出来：

**一个词，能不能不走接力赛，直接找到它真正需要的那个词？**

## 10. Attention：按内容直接建立连接

先看一个例子：

~~~text
银行旁边有一条河。
我去银行取了钱。
~~~

两个"银行"，查字典查出来是一样的。但你的脑子知道：第一个是河岸，第二个是金融机构——因为第一个旁边站着"河"，第二个前面挂着"取钱"。

**词的含义不在词本身，在它和上下文的关系里。**

所以模型需要一种机制：让"银行"这个位置，能根据当前内容，自己决定从哪些词取多少信息。这就是 Attention（注意力）：

~~~text
当前词发出"寻找"：我现在需要什么信息
每个词亮出"线索"：我能提供什么匹配特征
匹配上的，把"内容"递过来：按相关程度加权汇总
~~~

落到术语上就是 Q、K、V 三个向量：

- **Q（Query）**：我在找什么；
- **K（Key）**：我提供什么匹配线索；
- **V（Value）**：匹配之后真正递过来的内容。

**注意这三个都不是人写的问题和关键词，是模型训练出来的向量。**直觉对齐就够了，公式放在 QA 附录。

效果：序列里任意两个词直接建立连接，路径长度永远是 1。RNN 的三个结构问题同时解决——远距离直达、全体并行、不用压缩进一个摘要。

> **一句话结论：** Attention 把信息交互从"沿固定路径逐步传递"，变成"根据当前内容动态建立连接"。

> **不要误解为：** Q、K、V 是人工预先定义好的问题、关键词和答案；它们都是训练出来的向量表示。

## 11. 两个一句话概念：多头与位置

**多头注意力**：一组 QKV 只能在一个子空间里做一种匹配。多头 = 并行做几组，各自学不同的关系视角——有人盯语法、有人盯指代、有人盯位置——结果再合并。注意：不是每个头都能用人类概念稳定命名。

**位置编码**：Attention 只按内容匹配，不感知顺序。但"狗咬人"和"人咬狗"词集合相同、顺序不同、意思相反。所以必须把位置信息加进表示（现代模型常用 RoPE，让匹配天然感知相对距离）。

## 12. 因果掩码：从"看上下文"到"会生成"的桥

现在到全场最关键的一步。

假设让模型做"接龙"——给前文，预测下一个词。那训练时，它**不能偷看答案**。所以加一条规则：

~~~text
第 1 个词：只能看第 1 个
第 2 个词：能看 1、2
第 3 个词：能看 1、2、3
……
~~~

每个位置只能看自己和之前的内容——这叫**因果掩码**，画在图上就是一个下三角。

这条规则一石二鸟：

~~~text
训练时：整段文本已知，所有位置一次前向同时算
        每个位置都在"只看过去"的约束下练习预测下一个词
        → 又防偷看，又不牺牲并行

生成时：未来本来就还不存在，只有过去
        → 模型天然可以顺着往下写：写一个、追加一个、再写下一个
~~~

> **一句话结论：** 因果掩码既防止训练时偷看答案，也建立了从左到右生成的结构约束——这是 Transformer 走向语言模型的关键一步。

## 13. Decoder Block：零件装配

最后把零件装起来。一个 Transformer 解码块：

~~~text
Attention      负责词与词之间通信（唯一的跨位置信息交换）
FFN            负责每个位置自己加工（逐位置的非线性变换）
残差连接        保底通道，信息只增不减，训练更稳
Norm           稳压器，深层堆叠不发散
~~~

分工记一句话就够：**Attention 管通信，FFN 管加工。**

这样的块堆几十上百层，就是 GPT、LLaMA 这些模型的骨架。补一句输入输出：文本先被切成 Token（离散单元，不总等于一个字或一个词），每个 Token 查表得到一个初始向量（Embedding），经过几十层块的处理，最后输出层为词表里每个候选 Token 打分，经 Softmax 变成概率分布。

到这里，结构齐了。但请记住：**现在这个网络里的参数还全是随机数，它一个字都不认识。架构不等于能力。**

<details>
<summary>讲者提示（本部分 10 分钟，全场核心）</summary>

- RNN 到 Attention 的转折值得用两张图：左边"A→B→C→D→E 接力"，右边"D 直接连线 A/B/C"。
- "银行"例子先让听众自己反应一秒，再揭示两个"银行"的不同。
- QKV 按三个动词讲：寻找、匹配、取回。先讲动词流程，最后才贴 Q/K/V 三个名字。
- 因果掩码是今天最重要的单独一页，下三角图必须画，慢慢讲。
- 结尾"架构不等于能力"是通往预训练的钩子，语气要留悬念。

</details>

# 第五部分：预训练——能力从海量文本里长出来

## 14. 文本自己就是答案

要训练，得有监督信号——得知道正确答案。互联网那么大，谁去标注？

这里的洞察非常漂亮：**文本自己就是答案。**

拿一句话："机器学习可以从数据中学习参数"。切成词，整体往左错一位：

~~~text
机器              → 学习
机器 学习         → 可以
机器 学习 可以    → 从
机器 学习 可以 从 → 数据
……
~~~

每一段前文，正确答案就是原文的下一个词。

**一段文本，天然自带所有位置的练习题和答案，零人工标注。**

把整个互联网的文本都这样喂进去，让模型反复预测下一个 Token、预测错就调参数——这就是预训练。

## 15. 现场实验：你们刚刚就做了一次"预测下一个 Token"

空讲没用，现场做一次。这句话，请大家心里把下一个词补完：

**"如果数据库连接池已经耗尽，那么新的请求通常会——"**

（停顿两三秒，等大家小声说"失败/被拒绝/超时/排队"）

对，排队、超时、被拒绝，都有道理。大家注意刚才那两秒钟发生了什么：

**你们完成了一次"预测下一个 Token"，而且你们自动调用了连接池的知识才补得出来。**如果不懂连接池，这个词是猜不准的。

模型做的就是这件事，只是规模是整个互联网。而互联网的文本里，要把下一个词预测准，光背词频远远不够——你得懂语法，懂指代，懂"连接池耗尽"和"请求失败"之间的因果关系，懂代码的缩进规律，懂一道数学题的解题步骤往下是什么。

**这些能力都能降低预测误差，所以它们被一起压进了参数。**

这就是那句听起来很玄的话的真相："预测下一个 Token"这个简单的目标，**逼着**模型学会了语言、知识和一部分推理。能力不是设计出来的，是优化这个目标的副产品。

> **一句话结论：** 下一个 Token 预测提供了统一的训练目标；语言、知识和部分能力，是模型为做好这件事而形成的内部表示与行为。

## 16. 两盆冷水：预训练模型的边界

**第一盆：模型不是数据库。**

知识不是一条条存进去、可查可溯源的记录，而是分布在几千亿个参数里的分布式表示。所以它会出现"参数里有、但说不准"，或者"说得流畅但不对"的情况。

**第二盆：数据决定上限。**

训练数据里没有的、过时的、互相矛盾的内容，模型要么不会，要么瞎编。它的知识还有一个截止时间点——问它昨天的事，它只能靠猜。

~~~text
模型的上限由数据决定：
它学到的规律，不可能超出训练信号所呈现的规律
~~~

## 17. 三十秒历史与一句话 Scaling

帮大家把听过的名词归位，三十秒：

~~~text
GPT-1：证明了预训练的能力可以迁移（预训练 + 微调）
GPT-2：证明了多任务可以统一成"续写文本"
GPT-3：证明了新任务可以不训练、直接在上下文里说明
~~~

三步合起来就一件事：**任务接口在逐渐统一**——从"每个任务训一个模型"，变成"一个模型，任务写在提示词里"。

Scaling 一句话：参数、数据、算力三者要平衡，不是无脑堆参数就更强（固定算力下，小模型喂够数据可以胜过吃不饱的大模型）。

### 留下的问题

现在我们手里有一个读过整个互联网、知识渊博的模型了。能直接当助手吗？

看它会怎么表现。你输入：

~~~text
请用三句话解释什么是缓存击穿。
~~~

它很可能续写出**另一个相似的问题**，或者把这句话当成网页标题往下编页面内容。

为什么？因为在它的训练数据里，"问题后面跟着的还是问题"是极常见的模式。它学的目标是"什么文本可能接着出现"，从来没有一条规则告诉它"看到用户请求，要像个助手一样回答"。

**会续写，不等于会当助手。**能力是预训练给的，行为得有人教。

<details>
<summary>讲者提示（本部分 8 分钟）</summary>

- "连接池"实验是全场唯一互动，务必停顿，等听众真的小声说出来再继续。
- 揭示时点破："你们调用了连接池的知识"——这句话是"能力是副产品"论点的现场证据，比任何解释都有力。
- "请用三句话解释缓存击穿 → 它续写一个问题"的例子，最好真找一个 base 模型的输出截图，效果远胜口述。
- GPT 历史超时先删，不影响主线。

</details>

# 第六部分：后训练——教它当助手

## 18. SFT：示范教学

第一步，监督微调。准备一批这样的数据：

~~~text
用户问：请用三句话解释缓存击穿
理想回答：（人写的高质量答案）
~~~

拿这些数据继续训练。注意底层一点都没变——模型还是在做"预测下一个 Token"，只不过训练数据从"互联网上什么都有的文本"换成了"高质量的问答回答"。数据分布一换，行为就变了：它学会了识别任务、遵守格式、控制篇幅、以助手身份组织回答。

**SFT 主要教的不是知识，是"怎么把已有的能力按用户要的形式拿出来"。**

一个类比：预训练是读了十年书，SFT 是上岗前一周的示范培训。

> **不要误解为：** SFT 是模型知识和能力的主要来源——知识主体永远来自预训练，SFT 塑的是行为。

## 19. 偏好对齐：教它"哪种回答更好"

SFT 之后还有一层问题。同一个问题，好几个回答都"对"，但质量不同：有的准但啰嗦，有的简洁但漏了边界条件，有的自信但内容没验证过，有的安全但什么都拒绝。

"哪种回答更好"这件事，**写不成规则**——写五十页规范也穷举不完所有场景。

换个思路：不写规则，让人**做选择题**。

~~~text
同一个问题
→ 模型生成四个候选回答
→ 人只需要排序：A 比 C 好，C 比 B 好
→ 得到偏好数据
~~~

做比较，比写答案容易十倍，而且可以规模化。

有了几十万条排序，训练一个**奖励模型**——它学会模仿人的偏好，给任何回答打分。从此不用每次都找人，机器替人打分。

最后用强化学习（经典方案叫 RLHF；后来的 DPO 把流程简化成直接从偏好对学习，跳过奖励模型——细节在 QA）：

**用打分当奖励，调整模型，让高分的回答更容易出现。**

~~~text
人工示范 → SFT 模型
人工排序 → 奖励模型
奖励模型打分 + 强化学习 → 行为更符合偏好的模型
~~~

## 20. 对齐的能与不能

这一套的效果是实打实的。InstructGPT 论文里有个很说明问题的结果：

**130 亿参数的 InstructGPT，人类偏好评分超过了 1750 亿参数的原始 GPT-3。**

小了十几倍，但人更喜欢。说明"能力大小"和"行为是否符合意图"是两个独立的维度，后者花小钱就能大幅改善。

但也别神化，它不能保证的事同样得说清楚：

- 奖励模型只是人类偏好的近似，可能被模型钻空子；
- **人更偏好，不等于内容更真实**；
- 不同人的偏好还会互相冲突；
- 过度优化安全或风格，可能造成不必要的拒绝。

> **一句话结论：** 对齐改变的是行为的"倾向"，不是知识的"真值"。能力和行为是两回事——能力来自预训练，行为来自后训练。

<details>
<summary>讲者提示（本部分 7 分钟）</summary>

- "四个候选回答排序"最好配一个真实例子，让听众现场投一票再揭示偏好数据的概念。
- 130 亿赢 1750 亿这个数字对比是本部分的记忆点，放慢说。
- RLHF 不讲 PPO，DPO 只给一句话定位——听众只需要知道"偏好信号如何变成参数更新"的思路。

# 第七部分：生成与边界——按下回车之后

## 21. 先分清训练和使用

| | 训练 | 使用（Inference） |
|---|---|---|
| 有正确答案吗 | 有 | 没有 |
| 算损失、调参数吗 | 算、调 | **不算、不调** |
| 产出 | 一组参数 | 下一个 Token |

使用阶段，参数是冻结的。这个区分非常值钱，它直接推出下面的一切。

## 22. 逐 Token 生成循环

生成本身是一个循环，伪代码三行：

~~~text
while 没结束:
    算出全词表每个 Token 的概率
    按概率挑一个
    追加到上下文末尾，再来
~~~

你看到的整段回答，就是这么一次一个 Token 循环出来的。

**模型不是先在肚子里打好了整篇草稿再逐字念给你——它真的是一次只决定下一个词。**

（前面算过的部分会缓存复用，这叫 KV Cache，纯性能优化，不改变任何能力，细节在 QA。）

## 23. 三个结论：今天最想让大家带走的东西

"逐 Token 生成 + 参数冻结"这个结构，直接推出三个大家日常都在困惑的结论。

### 结论一：它不记得你

为什么你在这个对话里教了它一个事实，开个新对话它就忘了？

因为使用阶段不更新参数——你教的东西只活在当前上下文里，对话一关就没了。**它没有进入模型的脑子，只是出现在了它的眼前。**参数里的知识，只有训练才能改变。

产品级的"记忆"功能，是系统在外面拿存储做的，不是模型自己记住了。

### 结论二：流式输出不是它更聪明了

打字机效果只是把已经生成的 Token 尽早推给你，改善等待体感。模型还是那个模型，还是那个顺序。

同理，调温度、调采样参数，改变的是选词的风格——更稳或更发散——**不会注入任何新知识**。温度调低，答案更稳定；但如果它本来就要错，它会稳定地错。

### 结论三：幻觉有明确的来源

模型优化的目标是"当前上下文下，什么话最可能出现"，**从头到尾没有任何一个环节在验证事实**。

训练数据里冲突的、缺失的、过时的内容，加上"让它流畅地接下去"的目标——自然会产生说得特别顺、但完全不对的内容。

所以：**自信的语气不构成可信的证据，关键信息要留验证手段。**

## 24. 模型 vs 系统：Agent 的定位

最后一个区分，也是最近新闻里最容易被混淆的。

你对模型说："帮我查一下线上订单服务的异常指标，定位原因，建个工单，通知负责人。"

模型能生成查询语句，能写出邮件正文——**但它不能真的去查监控、不能发邮件、不能确认操作成功了没有。它只能输出文本。**

所以需要外部系统把它包起来：

~~~text
LLM：负责理解和决定（生成文本 / 生成调用请求）

外部系统：负责真正执行
  ├── Tool Call：模型出"调哪个工具 + 参数"，系统执行，结果喂回来
  ├── ReAct：观察 → 推理 → 行动 → 再观察 的循环
  └── Agent：目标 + 状态 + 工具 + 循环 的完整系统
~~~

关键一句：**模型输出工具调用参数，不等于模型执行了工具。**执行永远发生在外部系统；Agent 不是一种新的模型，而是一套把模型组织起来的系统。

以后看到一个 AI 产品"能干活"，先问一句：这能力是模型参数里的，还是外面那层系统给的？

> **不要误解为：** Agent 或 Harness 是一种新的基础模型架构。它们没有改变 LLM 预测 Token 的底层机制。

- "它没有进入模型的脑子，只是出现在了它的眼前"——这句是设计的记忆点，放慢说。

# 第八部分：总结——把七级台阶再走一遍

## 25. 主线压缩

~~~text
机器学习：预测→误差→调整，从数据里找参数，目标是在新数据上依然有效
深度学习：非线性+多层，特征也自己学
Transformer：每个词按内容直接取用上下文；因果掩码让它只能看过去
预训练：预测下一个 Token，能力是被这个目标逼出来的副产品
后训练：SFT 教形式，偏好教倾向；能力和行为是两回事
生成：参数冻结，一次一个 Token 循环
Agent：模型决定，系统执行
~~~

再压缩，其实就是人把东西一样一样交给机器的过程：

~~~text
规则 → 参数 → 特征 → 表示 → 任务适配 → 行动
~~~

## 26. 留给大家的框架：五个判断问题

以后再看到任何 AI 新概念、新模型、新产品，先别记缩写，问五个问题：

1. 它改的是**模型结构、训练方式、生成过程，还是外部系统**？
2. 它用的**什么数据或反馈信号**？
3. 它实际在**优化什么目标**？
4. 这个能力来自**模型参数，还是工具和工作流**？
5. 它**什么条件下有效，不能保证什么**？

能把这五个问题问出来，这张地图你就带走了。

一句话收场：

> **今天的大模型，底层仍然在预测下一个 Token——真正让人惊讶的不是这个目标多简单，而是当结构、数据和规模足够大之后，为了持续做好这件小事，机器长出了我们称之为"智能"的行为。**

# 附录 B：QA 问题库

> 每条先给一句话答案，再按需展开。

**Q1：Attention 的公式是什么？**
Softmax(QKᵀ/√d)·V。Q 和每个 K 做点积得匹配分，除以维度开根号防止数值过大，Softmax 变成权重，加权求和 V。公式不改变直觉：寻找、匹配、取回。

**Q2：多头到底是什么？**
一组 QKV 只能在一个子空间做一种匹配。多头 = 并行几组，各自学不同关系视角，结果拼接合并。不是每个头都能用人类概念命名。

**Q3：为什么必须要位置编码？**
Attention 只按内容匹配。"狗咬人"和"人咬狗"词集合相同、顺序不同、意思相反。所以要把位置信息加进表示（现代模型用 RoPE，让匹配天然感知相对距离）。

**Q4：温度调低，答案会更准吗？**
不会。低温让选词更集中、输出更稳定；但如果概率最高的答案本身是错的，它只会更稳定地错。采样参数管风格，不管对错。

**Q5：KV Cache 是什么？**
生成第 500 个 Token 时，前 499 个的 K、V 没变，缓存复用，只算新位置的。空间换时间，纯性能优化。它随上下文变长占显存，GQA 等优化就是为省它。

**Q6：和它聊得越多，它会越懂我吗？**
不会——参数不动。当前对话里它"记得"，是因为内容都在上下文里；上下文有长度上限，超了就靠外部系统做摘要和检索。产品的"记忆"功能是模型外面拿数据库实现的。

**Q7：怎么减少幻觉？**
治本没有，治标有路：给上下文（把事实放进提示词）、接检索（RAG）、接工具（让它查而不是猜）、要求引用来源、关键输出加校验。本质都是把"生成最可能的话"换成"基于给定材料说话"。

**Q8：微调、RAG、提示词工程，什么时候用哪个？**
提示词：不改参数，靠上下文临时引导——最便宜，先试它。RAG：不改参数，把外部资料检索进上下文——适合知识和时效。微调：改参数，适合稳定改变行为、格式、领域风格，不适合灌知识。三者可组合。

**Q9：推理模型（o1、R1 那类）是什么原理？**
把思考过程外化成生成内容：先长篇推导再给答案，每生成一个 Token 都是一次前向计算，推理深度变成了生成长度。训练侧在推理轨迹上做 SFT/强化学习，推理侧给更长的思考预算。注意推理 ≠ 强化学习，更长 ≠ 更对。

**Q10：MoE、量化、GQA 这些词都是什么？**
MoE：很多个"专家"FFN，每个 Token 只激活少数几个——容量大、算得少。量化：参数从 16 比特压到 8/4 比特——省显存，略降精度。GQA：多组 Q 共享少量 KV——省缓存。全部是"做大做长做快"的工程，不改变原理。

**Q11：Agent 和 MCP、Skill、Tool Call 是什么关系？**
Tool 是具体能力；Tool Call 是模型请求调用工具的机制；MCP 是把工具标准化的连接协议（解决 M×N 对接问题）；Skill 是封装好的"某类任务怎么做"的可复用知识；Agent 是拿这些拼起来的完整系统。Agent 不是新模型。

**Q12：参数量越大是不是一定越强？**
不是。固定算力下参数和数据要配平（Chinchilla：小模型喂够数据可以胜过大模型）；数据质量、训练方法、后训练水平都影响最终表现；而且"更强"不等于"更符合你的意图"（130 亿 InstructGPT 偏好评赢 1750 亿 GPT-3）。

**Q13：上下文窗口越长，是不是记得越多？**
"放得进"不等于"用得好"。注意力计算量随长度平方涨，且模型对长上下文中间段信息的利用并不可靠（lost in the middle）。长上下文是能力也是成本。

**Q14：SFT/RLHF 会不会把知识教进去？**
会带一点，但量级远小于预训练，不是它的职责。后训练塑的是行为：识别任务、遵守格式、偏好倾向。知识主体永远来自预训练。

**Q15：为什么我在对话里纠正它的错误，它当时改了，下次又犯？**
因为"改了"只发生在当前上下文里——上下文里有了正确信息，它基于上下文回答就对了。新对话没有这个上下文，它回到参数里的原样。参数只有训练能改。

**Q16：模型是一个字一个字生成的，那它怎么"提前规划"整段回答？**
没有严格的提前规划——但每个 Token 的生成条件是完整上下文，包括已生成的半段回答，所以它有一种"边写边想"的动态一致性。推理模型把这个特点推向极致：先写长篇推导，再写结论，思考深度变成生成长度。

| 概念 | 主要职责 | 不等于 |
|---|---|---|
| 参数 | 训练得到的内部数值 | 人类可读规则 |

| 泛化 | 在新数据上依然有效 | 记忆训练数据 |
| Token | Tokenizer 定义的离散单元 | 固定等于单词 |
| Attention | 按内容匹配汇总信息 | 模型的思考过程 |
| 因果掩码 | 禁止看未来 Token | 让模型事实正确 |
| 预训练 | 形成基础能力 | 天然服从用户 |
| SFT | 塑造指令响应行为 | 主要知识来源 |
| RLHF/DPO | 塑造偏好倾向 | 保证永远正确安全 |
| Inference | 运行模型生成输出 | Reasoning / 学习 |
| Streaming | 逐步返回已生成 Token | 提升模型智能 |
| KV Cache | 复用历史 K/V 计算 | 增加知识 |
| Tool Call | 模型生成工具请求 | 工具已被执行 |
| Agent | 组织模型+工具+循环的系统 | 新的模型架构 |
