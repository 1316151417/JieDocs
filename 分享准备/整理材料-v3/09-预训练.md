# 09. 预训练：数据、Scaling 与边界

## 0. 本章位置

上一章讲了预训练的目标与 GPT 演化主线，结尾指出基础模型的三个问题（不听指令、不合偏好、成本高）。在讲"怎么变成助手"之前，先补全预训练自身的全貌：数据、规模、以及它的能力边界。

---

# 1. 预训练数据工程

## 解决的问题

训练目标统一，不代表数据不重要——**模型只能从训练信号中学习统计规律**。数据决定模型"看见过什么"。

## 定义

**预训练数据工程是对海量原始文本进行选择、清洗、配比，使其变成高质量训练语料的过程。**

## 核心机制

现代预训练通常要处理：

| 环节 | 做什么 |
|---|---|
| 来源选择与配比 | 网页、书籍、代码、论文……各占多少 |
| 质量过滤 | 去掉低质量、乱码、模板页 |
| 去重 | 重复内容会放大记忆、浪费算力 |
| 安全与隐私过滤 | 移除敏感、侵权内容 |
| 数据污染检查 | 防止评测集泄漏进训练集 |

数据如何划定能力边界：数据中缺少的知识、过时的信息、互相冲突的说法、大量低质量模式，都会成为模型能力和可靠性的边界。

## 核心本质

**模型的上限由数据决定：它学到的规律，不可能超出训练信号所呈现的规律。**

---

# 2. Scaling Laws（规模定律）

## 解决的问题

"更大 = 更好"是直觉，但它是不是可预测的规律？在固定预算下，模型该多大、数据该多少？

## 定义

**Scaling Laws 是指在一定范围内，训练损失随模型参数量、数据规模和计算量的增加，呈现稳定幂律变化的经验规律。**

## 核心机制

三个变量互相约束：

```text
模型容量（参数量）
+ 数据规模（Token 数）
+ 训练计算量
→ 更低的基础模型损失
```

关键修正（Chinchilla，2022）：**只扩大参数但不给足数据，不是计算最优**。固定算力下，更小但数据更充分的模型可能超过更大却"吃不饱"的模型。模型大小与数据量需要平衡。

同样必须看到的另一面——规模扩大不自动保证：

- 每个任务都更好；
- 输出事实永远正确；
- 偏见和安全问题消失；
- 推理成本可接受；
- 模型符合用户意图。

## 核心本质

**规模是可规划的投资回报曲线，但"参数越多越智能"是误读；容量、数据、算力三者要平衡。**

# 3. 预训练模型的能力边界

## 解决的问题

澄清"预训练模型是什么、不是什么"，为后训练做铺垫。

## 核心机制

### 模型学到的是

- 语言结构（句法、语义）；
- 词语与概念间的关系；
- 训练数据中反复出现的事实关联；
- 文本模式和一部分推理模式。

### 模型没学到的

| 缺失 | 原因 |
|---|---|
| 不天然服从指令 | 预训练目标只要求"生成统计上合理的后续"，没有"看到用户请求要像助手"这一条 |
| 不保证事实正确 | 优化的是概率拟合，不是事实验证 |
| 知识有截止时间 | 参数里的知识冻结在训练数据的时间点 |
| 可能幻觉 | 数据冲突、知识缺失、提示歧义都会产生"流畅但错误"的输出 |

一个典型行为：给只做过预训练的基础模型输入"请用三句话解释什么是缓存击穿"，它可能继续生成一个相似的问题、把这段话当网页标题续写、或生成一堆问答样本——**因为预训练数据里"问题后面还跟着问题"的模式很常见**。

## 核心本质

**预训练给了模型"会说话、有知识"的能力，但没给"当助手"的行为——"可能出现的后续文本"与"用户希望的回答"不是同一个目标。**

---

# 4. 极简总结

**数据工程 = 决定模型看见什么；Scaling = 容量、数据、算力的平衡艺术；预训练模型 = 有能力但没行为的"文本补全器"。**

---

# 5. 遗留的问题

基础模型会续写，不会当助手。怎么把"会续写文本的基础模型"变成"可交互、可控制的语言助手"？

两条后训练路线相继出现：

1. **SFT（监督微调）**：教模型"按指令组织回答"；
2. **偏好对齐（RLHF/DPO）**：教模型"哪种回答更好"。
