建议最终设计为 **6 章**，不要把 CNN、RNN 独立成一章。

```text
1. 机器学习：机器如何从数据中学习参数
2. 深度学习：机器如何自动学习特征
3. Transformer：机器如何建立全局上下文
4. GPT：机器如何从海量文本中获得通用能力
5. 现代 LLM：语言模型如何变得可用、可靠和高效
6. Agent：语言模型如何从生成答案走向完成任务
```

CNN、RNN 放在深度学习章中。它们和 Transformer 不处于同一个抽象层次：

- 深度学习是一种学习范式；
- CNN、RNN、Transformer 是不同网络架构；
- GPT 是基于 Transformer 的语言模型路线；
- 现代 LLM 是 GPT 路线进一步形成的完整训练与工程体系；
- Agent 是建立在 LLM 之上的应用系统。

# **一、整套知识主干**

整条主线可以概括为：

```text
机器学习：学习参数
    ↓
深度学习：学习特征
    ↓
Transformer：学习上下文关系
    ↓
GPT：学习通用语言能力
    ↓
现代 LLM：学习遵循指令、推理并与人交互
    ↓
Agent：基于目标采取行动
```

更本质地说，是人不断把更多工作交给机器：

|**阶段**|**人主要提供**|**机器主要学习或完成**|
|---|---|---|
|传统程序|明确规则|执行规则|
|机器学习|特征、模型形式、数据|参数|
|深度学习|网络结构、数据|特征与参数|
|Transformer|训练目标、数据|上下文表示|
|GPT|海量文本|通用语言能力|
|现代 LLM|指令、偏好、反馈|任务适配与复杂推理|
|Agent|目标、工具、约束|规划和行动|

# **二、第一章：机器学习**

## **章节职责**

回答：

**机器不依赖人写出完整规则，如何从数据中找到一个可用于预测的规律？**

这一章只负责建立机器学习的最小闭环。

## **应该包含**

1. 人学习、传统程序与机器学习的区别；
2. 样本、特征、标签；
3. 模型与参数；
4. 预测；
5. 损失函数；
6. 优化；
7. 回归与分类；
8. 训练集、测试集和泛化。

使用单参数线性回归即可：

```text
房屋面积 x
    ↓
价格预测 y = wx
    ↓
和真实价格比较
    ↓
调整参数 w
```

分类问题只需要说明输出形式变化：

```text
回归：预测一个连续数值
分类：预测样本属于不同类别的可能性
```

## **不负责讲什么**

- 多层神经网络；
- 激活函数；
- CNN、RNN；
- 大规模模型；
- 语言理解。

## **本章核心结论**

机器学习通过数据、模型和优化目标，寻找一组能够在新数据上继续有效的参数。

注意，“在新数据上有效”非常重要。否则只是在记忆训练数据，不是真正有价值的学习。

## **连接下一章**

结尾提出问题：

线性回归中，房屋面积是人提前选好的特征。如果处理图片、声音和文本，什么才是有效特征？难道都要由人手工设计吗？

由此进入深度学习：

**机器学习可以学习参数，但传统方法通常仍依赖人设计特征。深度学习进一步尝试让机器连特征也一起学习。**

---

# **三、第二章：深度学习**

## **章节职责**

回答：

**机器如何从原始数据中，自动学习完成任务所需要的特征表示？**

这一章的核心不是“神经网络更复杂”，而是：

从人工设计特征，转向模型自动学习层次化表示。

## **应该包含**

### **1. 线性模型的边界**

线性模型只能表达有限形式的关系和决策边界。

### **2. 激活函数**

多个纯线性层叠加仍然是一个线性变换。

激活函数引入非线性，使网络能够组合出复杂函数。

### **3. 多层神经网络**

前层学习简单模式，后层将简单模式组合成更抽象的表示。

例如图像：

```text
像素
→ 边缘
→ 纹理和局部形状
→ 物体部件
→ 完整物体
```

### **4. CNN**

CNN 回答：

如何利用图像的局部性和空间结构？

只讲三个核心思想：

- 局部连接；
- 参数共享；
- 层次化视觉特征。

不要展开卷积尺寸计算。

### **5. RNN**

RNN 回答：

如何处理前后顺序有关的序列？

核心机制：

```text
当前输入 + 历史状态
→ 新状态
→ 继续传给下一步
```

它让模型拥有对历史信息的压缩记忆。

## **为什么 CNN、RNN 不单独成章**

CNN 和 RNN 的职责是证明：

深度学习能够针对不同数据结构，引入不同的结构假设。

- CNN 利用空间局部性；
- RNN 利用时间顺序；
- 它们是深度学习的两个典型实例，不是与深度学习并列的阶段。

但 RNN 应该作为本章后半部分的重点，因为它直接引出 Transformer。

## **不负责讲什么**

- QKV；
- Self-Attention；
- GPT；
- 预训练；
- 大模型对齐。

## **本章核心结论**

深度学习让模型不只学习最终预测参数，还能逐层把原始数据转换成适合任务的特征表示。

## **连接下一章**

从 RNN 的局限进入：

RNN 虽然可以处理序列，但它必须按照顺序逐步传递信息。距离越远，信息需要经过的步骤越多；同时，各位置难以并行计算。

然后提出问题：

序列中的一个词，能否不经过层层传递，直接获取其他所有词的信息？

由此进入 Transformer：

**深度学习解决了自动学习特征的问题，Transformer 进一步改变了序列中信息交互的方式。**

---

# **四、第三章：Transformer**

## **章节职责**

回答：

**序列中的每个位置，如何直接根据整个上下文形成自己的表示？**

这章只讲 Transformer 解决的结构问题，不急着讲 GPT。

## **应该包含**

1. RNN 的顺序计算；
2. 长距离信息传递；
3. Attention 的基本思想；
4. Self-Attention；
5. Q、K、V；
6. 多头注意力；
7. 位置编码；
8. Transformer Block 的整体信息流。

## **核心讲解结构**

### **RNN**

```text
信息沿着序列逐步传递
A → B → C → D
```

A 的信息要影响 D，需要经过中间多个步骤。

### **Self-Attention**

```text
D 可以直接计算自己与 A、B、C 的关系
并按相关程度汇总它们的信息
```

关键变化：

从“沿固定路径传递信息”，变成“根据当前内容动态建立信息连接”。

QKV 不需要一开始陷入矩阵公式，可以先解释为：

- Q：当前位置正在寻找什么；
- K：其他位置提供什么匹配线索；
- V：匹配后真正取回什么信息。

## **Transformer 获得的新能力**

1. 每个 token 可以形成上下文相关表示；
2. 长距离信息可以直接交互；
3. 序列各位置可以并行计算；
4. 同一套结构可以扩展到大规模训练。

## **Transformer 的边界**

Transformer 本身只是一种网络架构。

它并不天然等于：

- GPT；
- 聊天机器人；
- 大语言模型；
- Agent。

同样的 Transformer 可以用于编码、生成、图像、语音等不同任务。

## **本章核心结论**

Transformer 让每个 token 根据与整个序列的关系，动态汇总上下文信息，从而形成上下文相关表示。

## **连接下一章**

结尾提出：

Transformer 提供了强大的序列建模架构，但一个架构怎样通过训练获得通用语言能力？

接着进入语言模型：

如果让 Transformer 阅读海量文本，并持续预测下一个 token，它是否会为了做好预测，逐渐学习语言结构、知识和推理模式？

由此进入 GPT：

**Transformer 解决了信息如何交互，GPT 回答了如何利用这种架构从海量文本中获得通用语言能力。**

---

# **五、第四章：GPT**

## **章节职责**

回答：

**Transformer 如何通过自回归预训练，从大量文本中学习可迁移的通用语言能力？**

这一章重点是 GPT 路线的能力演化，不是分别介绍三篇论文。

## **应该包含**

### **1. 语言模型**

根据已有文本预测下一个 token：

```text
输入：今天天气很
预测：好 / 冷 / 热……
```

### **2. 自回归训练**

模型不断预测下一个 token，并通过预测误差调整参数。

### **3. 预训练**

在海量文本上完成同一个训练目标，从中学习：

- 语言结构；
- 词语关系；
- 世界知识；
- 文本模式；
- 一部分推理模式。

### **4. GPT-1 到 GPT-3**

#### **GPT-1：预训练能力可以迁移**

```text
大规模预训练
→ 针对下游任务微调
```

#### **GPT-2：任务可以统一为文本生成**

很多任务不再需要独立输出结构，都可以表达为“根据上下文继续生成文本”。

#### **GPT-3：模型可以通过上下文适配任务**

不修改参数，只给指令或示例，也能完成新任务。

```text
GPT-1：预训练后微调
GPT-2：统一为文本生成
GPT-3：通过上下文适配
```

## **本章真正要讲透的问题**

### **为什么预测下一个 token 能学到这么多能力？**

因为准确预测后续文本，往往要求模型隐式掌握：

- 句法；
- 语义；
- 上下文；
- 事实知识；
- 说话者意图；
- 某些问题的解决过程。

训练目标看起来简单，但完成目标需要大量中间能力。

## **不负责讲什么**

- 指令微调完整流程；
- RLHF、DPO；
- 推理模型；
- MoE、GQA；
- Tool Call；
- Agent。

这些属于现代 LLM 和 Agent。

## **本章核心结论**

GPT 将 Transformer 与自回归预训练结合，使一个统一模型能够从海量文本中学习通用语言能力，并逐渐通过上下文适应不同任务。

## **连接下一章**

GPT-3 虽然展现了通用能力，但仍有明显问题：

- 它主要学习“什么文本可能接着出现”，不天然等于服从用户；
- 输出可能不符合人的偏好；
- 推理过程不够稳定；
- 训练和推理成本很高；
- 上下文长度有限。

由此提出：

如何把一个会续写文本的基础模型，变成真正可交互、可控制、可部署的语言助手？

进入现代 LLM：

**GPT 建立了通用能力，现代 LLM 解决的是如何训练、约束、增强并高效运行这些能力。**

---

# **六、第五章：现代 LLM**

## **章节职责**

回答：

**如何把具备基础语言能力的预训练模型，变成能够遵循指令、进行复杂推理并稳定服务用户的系统？**

现代 LLM 不是突然出现的全新原理，而是围绕 GPT 路线形成的一整套增强体系。

## **建议划分为五部分**

### **1. 基础能力增强**

- 更高质量的数据；
- 数据清洗和配比；
- 更大规模；
- 更长上下文；
- Scaling Law。

### **2. 架构优化**

只讲目的，不讲细节推导：

- RoPE：处理位置信息；
- RMSNorm：稳定训练；
- SwiGLU：增强前馈网络表达；
- GQA：降低推理缓存成本；
- MoE：扩大模型容量而不激活全部参数。

### **3. 指令微调**

让模型从“继续一段文本”转变为：

根据用户提出的任务，生成符合要求的回答。

### **4. 偏好对齐**

通过人类偏好数据，让模型更倾向于：

- 有帮助；
- 符合意图；
- 安全；
- 表达清晰。

### **5. 推理与推理效率**

能力方面：

- 思维链；
- 推理训练；
- 推理时增加计算。

效率方面：

- KV Cache；
- FlashAttention；
- 量化；
- 并行和部署优化。

## **这一章的边界**

现代 LLM 依然主要是一个模型：

```text
输入上下文
→ 计算
→ 输出文本或结构化结果
```

它可以生成计划，可以生成工具调用参数，但它本身不会自动：

- 真正访问数据库；
- 创建日历；
- 长期维护状态；
- 持续执行复杂任务；
- 确认外部操作是否成功。

这些属于 Agent 系统。

## **本章核心结论**

现代 LLM 在 GPT 的预训练基础上，通过数据、规模、架构、指令微调、偏好对齐和推理训练，形成了更通用、可控、可交互的语言能力。

## **连接下一章**

结尾提出一个具体对比：

```text
用户：帮我分析最近的业务异常，并把结论发给负责人。
```

LLM 可以告诉你应该怎么分析，也可以生成查询语句和邮件内容。

但真正完成任务还需要：

1. 查询实时数据；
2. 判断是否异常；
3. 继续补查原因；
4. 找到负责人；
5. 发送邮件；
6. 检查执行结果。

于是问题从：

模型应该生成什么？

变成：

系统下一步应该做什么？

由此进入 Agent：

**现代 LLM 提供理解、推理和生成能力，Agent 将这些能力放进带有目标、状态、工具和反馈的执行循环中。**

# **七、第六章：Agent**

## **章节职责**

回答：

**如何让 LLM 不只生成内容，还能基于目标观察环境、调用工具、处理反馈并完成任务？**

## **应该包含**

### **1. LLM 与 Agent 的区别**

```text
LLM：输入上下文，生成一次结果
Agent：围绕目标，持续决定下一步行动
```

Agent 不是新的基础模型，而是一个以 LLM 为决策核心的系统。

### **2. Streaming**

Streaming 只解决响应体验：

- 边生成边返回；
- 降低用户等待感；
- 不增加模型本身的智能。

它可以作为 LLM 应用工程的起点，但不是 Agent 的核心能力。

### **3. Tool Call**

模型输出结构化调用请求，外部程序真正执行工具：

```text
模型决定调用工具
→ 生成工具名称和参数
→ 系统执行
→ 工具结果返回模型
```

### **4. ReAct**

让模型形成反馈循环：

```text
观察
→ 推理
→ 行动
→ 获得新观察
→ 继续推理
```

它把一次生成扩展为可根据环境反馈修正的过程。

### **5. 规划模式**

将复杂目标拆成多个子任务：

```text
明确目标
→ 制定计划
→ 执行步骤
→ 检查结果
→ 调整计划
```

### **6. Skill**

Skill 是某类任务的可复用执行知识：

- 任务步骤；
- 判断规则；
- 工具使用方式；
- 输入输出规范；
- 异常处理。

它解决的是 Agent 每次都临时推理，容易不稳定的问题。

### **7. MCP**

MCP 解决模型系统连接外部工具和数据源时的标准化问题。

需要区分：

|**概念**|**职责**|
|---|---|
|Tool|提供一个具体外部能力|
|Tool Call|模型请求调用工具的机制|
|MCP|暴露和连接工具的标准协议|
|Skill|使用工具完成某类任务的方法|
|Agent|组织目标、模型、状态、工具和执行循环的系统|

## **本章核心结论**

Agent 没有改变 LLM 预测 token 的底层机制，而是在 LLM 外部加入目标、状态、工具、反馈和控制流程，使模型能够持续行动并完成任务。

# **八、章节之间的连接句**

你可以直接把这些句子作为每章结尾。

## **机器学习 → 深度学习**

机器学习让机器可以从数据中学习参数，但输入什么特征通常仍由人决定。面对图片、声音和文本，人工特征很难覆盖全部规律，因此需要让模型连特征表示也自动学习。

## **深度学习 → Transformer**

深度学习能够自动学习特征，CNN 和 RNN 又分别利用了空间结构和序列结构。但 RNN 必须逐步传递信息，限制了长距离关系建模和并行训练，因此需要一种新的序列信息交互方式。

## **Transformer → GPT**

Transformer 解决了序列中的信息如何高效交互，但架构本身不会自动拥有语言能力。GPT 进一步通过海量文本上的自回归预训练，让 Transformer 学习通用语言规律。

## **GPT → 现代 LLM**

GPT 证明了统一语言模型能够通过预训练和上下文适应多种任务，但基础模型不天然遵循指令，也不一定符合人类偏好，更面临推理稳定性和运行成本问题，因此形成了现代 LLM 的完整训练与工程体系。

## **现代 LLM → Agent**

现代 LLM 已经能够理解指令、生成内容和进行一定推理，但它仍主要输出文本。要完成真实任务，还必须访问外部环境、调用工具、维护状态并根据执行结果调整下一步，这就需要 Agent 系统。

# **九、每章统一的知识主干模板**

搭建主干时，每章都只写下面七项：

```markdown
# 章节名称

## 1. 核心问题
这一章要解决什么问题？

## 2. 上一阶段的能力
之前已经能够做到什么？

## 3. 上一阶段的限制
为什么仍然不够？

## 4. 核心机制
新方法增加了什么关键机制？

## 5. 新获得的能力
它因此能够做到什么？

## 6. 仍然存在的限制
它还不能解决什么？

## 7. 下一阶段为什么出现
这个限制如何引出下一章？
```

这一模板比单纯的“是什么、为什么、怎么做”更适合你的分享，因为它强制每章同时承担承上和启下的职责。
