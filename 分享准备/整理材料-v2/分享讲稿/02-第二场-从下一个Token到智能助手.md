# 第二场：从下一个 Token 到智能助手

副标题：

**LLM 是怎样工作的**

建议时长：

- 正文 40～45 分钟。
- Q&A 10～15 分钟。

本场结束时，听众只需要真正掌握：

1. LLM 是下一个 Token 概率模型。
2. 文本如何变成 Token 和模型内部表示。
3. Transformer 在其中解决什么问题。
4. 预训练为什么能够产生通用能力。
5. Base Model 怎样经过后训练成为助手。
6. 模型怎样逐 Token 生成回答。
7. 为什么模型会幻觉、遗忘上下文或自信地答错。

---

## 第 1 页：把上一次的机器学习骨架带回来

预计时间：5 分钟

### 页面上放什么

第一场：

~~~text
数据 → 模型 → 预测 → 比较目标 → 调整参数
~~~

放到 LLM：

~~~text
大量文本 → Transformer → 预测下一个 Token
                           ↓
                    与真实 Token 比较
                           ↓
                       调整参数
~~~

定义：

> LLM 是在大规模文本上训练、根据已有上下文预测下一个 Token 的概率模型。

### 讲稿

大家好，欢迎来到第二场。

上一场我们建立了一套最小的机器学习骨架。

数据给模型提供经验，模型根据当前参数作出预测，损失衡量预测错了多少，训练再根据错误调整参数。训练会改变模型，推理只是使用模型。最终目标不是记住训练样本，而是能够处理没见过的新输入。

今天我们不再引入一套新的逻辑。我们只做一件事：把上一场的机器学习骨架完整套到语言上。

首先，机器学习需要数据。LLM 的主要预训练数据是大规模文本和代码。

机器学习需要模型。现代 LLM 的核心结构是 Transformer。

机器学习需要预测目标。LLM 的预训练目标非常简单：根据已经看到的 Token，预测真实的下一个 Token。

机器学习需要损失。模型会衡量自己为真实下一个 Token 分配的可能性是否足够高。

机器学习需要训练。预测错误会推动模型参数发生微小调整。这个过程在大量 Token 上重复，模型逐渐形成语言、知识和任务模式。

所以我们先给出今天最重要的定义：

> LLM 是在大规模文本上训练、根据已有上下文预测下一个 Token 的概率模型。

这句话看起来很简单，也容易让人产生疑问：如果它只是在预测下一个 Token，为什么最后会翻译、写作、问答、编程，甚至做数学题？

今天整场分享，就是回答这个问题。

### 互动

可以快速复习：

> 普通聊天时，我们发给模型一个 Prompt，这属于训练还是推理？

预期答案：推理。普通对话通常不会现场修改模型参数。

### 转场

在讨论它为什么产生能力之前，我们先亲自做一次“预测下一个 Token”。

## 第 2 页：语言模型每一步到底在做什么

预计时间：5 分钟

### 页面上放什么

给定上下文：

> 今天下班以后，我们一起去吃

可能的下一个 Token：

|候选|模型可能性|
|---|---|
|饭|较高|
|火锅|较高|
|一个|中等|
|天气|很低|

生成循环：

~~~text
已有上下文 → 下一个 Token 概率 → 选择一个 Token
       ↑                              ↓
       └──────── 追加后继续 ─────────┘
~~~

### 讲稿

大家看这句话：

“今天下班以后，我们一起去吃……”

如果让我们补下一个词，很多人会想到“饭”“火锅”“烧烤”之类的内容，很少有人会突然补一个“天气”。

我们之所以能做出这种判断，是因为我们见过大量语言，知道哪些表达在这样的上下文里更常见、更合理。

语言模型做的事情非常类似，只不过它不是只给出一个答案，而是会为词表中的每个候选 Token 产生一个可能性。

这里一直说 Token，而不是字或者词，是因为模型使用的文本单位不一定等于自然语言中的一个词。

模型得到这组可能性以后，需要按照某种方式选择一个 Token。

如果选择了“饭”，上下文就变成：

“今天下班以后，我们一起去吃饭……”

模型再根据这段更长的上下文预测下一个 Token。

如果下一步选择“吧”，上下文继续增长。模型就这样一步一步生成整个回答。

所以它不是先在内部写好一整段答案，再把答案一次性显示出来。

它的核心生成过程是：

第一步，根据当前上下文预测下一个 Token。

第二步，从预测结果中选择一个 Token。

第三步，把这个 Token 加入上下文。

第四步，继续预测。

这也解释了为什么模型的输出可以具有一定随机性。它产生的是一组可能性，不是所有情况下都只能选择唯一答案。

但请注意，“有概率”不等于“完全随机”。上下文会强烈改变不同 Token 的可能性。正常情况下，模型不会在“我们一起去吃”后面随意选择任意汉字。

### 互动

可以给出三个上下文，让听众说出最可能的后续：

- 一加一等于……
- 北京是中国的……
- 如果明天下雨，记得带……

随后说明：看似简单的预测，背后已经需要语言结构、事实知识和条件关系。

### 转场

人看到的是句子，但神经网络不能直接处理抽象文字。文本进入模型之前，还要经过一次转换。

## 第 3 页：文本怎样变成模型可以处理的输入

预计时间：4 分钟

### 页面上放什么

~~~text
原始文本
   ↓
切分为 Token
   ↓
Token ID
   ↓
可学习的向量表示
   ↓
Transformer
~~~

页面结论：

> Token 是离散身份，向量是模型内部用于计算的表示。

### 讲稿

模型接收到的并不是我们在界面里看到的完整句子。

第一步，分词器会把文本切成 Token。

一个 Token 可能是一个汉字、一个英文单词的一部分、一个标点，或者几个经常一起出现的字符。

为什么不直接按照“词”切？

因为全世界语言、专有名词、新词、代码和拼写变化太多。如果只使用固定的完整单词，词表会极其巨大，而且遇到新词就很难处理。

所以现代模型通常使用更灵活的子词或字节级单元。

每个 Token 都对应一个整数编号，也就是 Token ID。

但整数编号本身只表示身份。编号 1000 的 Token 并不比编号 10 的 Token 大一百倍，它们不是有大小关系的数值。

模型会通过一张可学习的映射表，把每个 Token ID 转换成一组连续数值，也就是一个向量表示。

听众不需要记住“向量”的数学定义。这里可以把它理解为：模型内部用来表示一个 Token 的一组可计算特征。

刚进入模型时，同一个 Token 通常对应同一个初始表示。

但经过 Transformer 结合上下文以后，同一个 Token 在不同句子中会形成不同的上下文表示。

例如“苹果很好吃”和“苹果发布了新产品”里的“苹果”，初始 Token 身份相同，但周围上下文不同，模型后续形成的内部表示也会不同。

### 转场

把 Token 变成表示只是第一步。真正困难的问题是：当前 Token 应该怎样结合前文，理解它在这一句话里的含义？这就是 Transformer 主要解决的问题。

## 第 4 页：Transformer 在其中做什么

预计时间：7 分钟

### 页面上放什么

例子：

> 小李把手机放在桌上，后来它没电了。

问题：

> “它”更应该联系“手机”还是“桌子”？

Attention 的直觉：

~~~text
当前 Token 的需要
        ↓
给上下文中不同 Token 分配不同关注程度
        ↓
汇总相关信息
        ↓
形成当前上下文表示
~~~

页面结论：

> Transformer 让每个 Token 根据当前需要，从上下文中读取相关信息。

### 讲稿

我们看一句话：

“小李把手机放在桌上，后来它没电了。”

处理“它”这个 Token 时，模型需要知道“它”更可能指的是“手机”，而不是“桌子”。

如果只看“它”本身，无法完成判断。模型必须结合前面的“手机”“桌子”和“没电”等信息。

Transformer 的核心价值，就是让序列中每个位置能够根据当前需要，从上下文中的其他位置获取信息。

其中最重要的机制叫 Attention，也就是注意力。

大家可以把 Attention 理解为一个动态的信息选择过程。

当前位置会问：我现在需要什么信息？

上下文中的不同 Token 会根据相关程度获得不同权重。

模型再把这些信息按照权重汇总，形成当前位置新的上下文表示。

在“它没电了”这个例子里，“没电”与“手机”的联系通常比与“桌子”的联系更强。因此处理“它”和“没电”时，模型可以更多地使用“手机”相关的信息。

Attention 和普通关键词搜索不同。

它不是只在文本中寻找完全相同的字，而是使用训练形成的内部表示判断哪些内容在当前上下文里相关。

Transformer 会把这种信息交换和每个位置内部的进一步处理重复很多层。

浅层处理后的结果会成为下一层的输入。随着层数增加，每个 Token 的表示会不断融合更多上下文关系。

需要强调的是，我们今天把 Transformer 当作一个功能模块来理解：

> 它让 Token 根据上下文相互交换和组合信息。

至于它内部怎样把当前需求、可匹配特征和实际内容拆成不同矩阵，怎样使用多个注意力头，怎样加入位置，我们都不需要在主讲中展开。

这些细节很重要，但不会改变今天这条主线。

还有一个限制：生成式 LLM 在预测某个位置时，只能使用这个位置之前已经出现的 Token，不能偷看未来答案。

正因为如此，它才可以学习“根据前文预测后续”，并在推理时按照同样方式逐步生成。

### 互动

可以再给一个例子：

> “虽然外面正在下雨，但他还是没有带伞。”

让听众说出理解“但”需要联系句子中的哪些内容。

重点是让大家感受到：每个 Token 的含义依赖上下文关系。

### 转场

现在模型已经能够把上下文组合起来。接下来的问题是：谁来教 Transformer 应该形成怎样的表示？答案不是人工逐层设计，而是预训练目标。

## 第 5 页：预训练为什么能产生通用能力

预计时间：8 分钟

### 页面上放什么

训练过程：

~~~text
海量文本
   ↓
取出一段 Token
   ↓
预测每个位置的下一个 Token
   ↓
与原文中的真实 Token 比较
   ↓
调整模型参数
   ↓
重复海量次数
~~~

为了持续预测准确，模型需要逐渐学习：

- 语言结构
- 词义与上下文
- 事实和概念关系
- 文本与任务模式
- 代码和部分推理规律

### 讲稿

现在进入今天最关键的一页：为什么一个预测下一个 Token 的任务，会产生这么多看起来远超“补字”的能力？

先看训练数据。

互联网文本、书籍、论文、代码、问答、新闻和其他语料经过清洗和分词后，变成很长的 Token 序列。

模型读取这些序列，并在每个位置预测下一个 Token。

真实答案在哪里？

就在原文里。

例如原文是“水在标准大气压下达到一百摄氏度会沸腾”。

看到前面的 Token，后面的真实 Token 就天然构成训练目标。

这意味着我们不需要人工给数万亿个位置逐个标注答案，数据本身就能产生训练信号。这种方式通常叫自监督学习。

模型作出预测后，与真实 Token 比较。如果预测不好，就调整参数。然后继续下一段文本。

这个过程在海量数据上重复。

现在回到核心问题：为什么不只是学会一些词语搭配？

因为如果模型只记住非常局部的词语搭配，它无法在复杂文本中持续预测准确。

想预测“法国的首都是巴黎”，需要学习实体和事实关系。

想补全一段程序，需要学习编程语言语法、变量关系和常见算法模式。

想继续一段数学推导，需要学习符号结构和解题步骤。

想回答一个问题，需要识别文本中的问答模式，并结合相关知识形成后续。

想让长文章保持一致，需要追踪主题、角色、因果关系和前后约束。

所以为了降低下一个 Token 的预测错误，模型被迫在内部形成对语言、概念、关系、知识和任务模式有用的表示。

这并不意味着模型一定像人一样理解，也不意味着它拥有人的意识。

但也不能把它简单说成“随机拼字”。

从功能上看，它确实形成了能够支持翻译、问答、写作、代码和部分推理的内部表示，只是这些表示来自统计训练目标，而不是人类成长和感知世界的方式。

模型的参数量提供了容纳复杂规律的空间，数据提供了可学习的内容，Transformer 提供了组合上下文的结构，训练过程把这些因素连接在一起。

预训练完成后，我们得到 Base Model。

Base Model 非常擅长根据文本继续写，但它最初学到的是“互联网上的文本通常怎样继续”，不是“当用户提出要求时，我应该怎样作为助手回答”。

比如用户输入“请把下面内容总结成三点”，Base Model 可能继续写一篇类似网页文章，也可能模拟别的文本格式。它不一定稳定服从指令。

因此预训练解决了“获得通用语言与知识能力”，但还没有完整解决“怎样把这些能力以助手形式提供给用户”。

### 互动

可以问：

> 如果训练数据全部都是代码，这个模型最容易获得什么能力，又会缺少什么能力？

预期方向：更擅长代码模式，但语言、领域知识和对话覆盖会受到数据限制。

### 转场

Base Model 已经有能力，但还没有形成稳定的助手行为。下一步不是重新发明模型，而是继续训练它“应该怎样回答”。

## 第 6 页：从 Base Model 到 Assistant Model

预计时间：6 分钟

### 页面上放什么

~~~text
Base Model
擅长续写
    ↓
SFT：学习高质量指令与回答
    ↓
偏好学习：学习哪个回答更好
    ↓
安全与强化训练：提高期望行为概率
    ↓
Assistant Model
~~~

页面结论：

> 预训练获得通用能力，后训练塑造这些能力怎样表现。

### 讲稿

我们现在有了一个 Base Model。

它通过大规模文本学会了语言、知识和很多文本模式，但它首先是一个续写模型。

要把它变成我们熟悉的聊天助手，通常还需要后训练。

后训练的第一层叫 SFT，也就是监督微调。

训练者准备高质量的指令和理想回答。

例如：

用户要求“把这段文字概括成三点”，目标回答就真的按照三点结构完成总结。

用户要求“解释给零基础听众”，目标回答就避免不必要术语，并提供适合的例子。

模型继续使用预测下一个 Token 的方式学习，只不过数据从普通互联网文本，变成了有明确助手行为的指令和回答。

这样，模型逐渐学会：收到不同任务时，理想回答通常长什么样。

但很多问题很难写出唯一标准答案。

两个回答可能都没有明显事实错误，但其中一个更清晰、更有帮助、更安全。

于是可以为同一个问题生成多个候选回答，让人类或其他评审判断哪个更好。

这叫偏好数据。

模型再通过偏好优化或强化学习，提高较好回答的生成概率，降低较差回答的生成概率。

安全行为也可以通过示范、偏好、规则和奖励进入后训练。

因此我们可以把两个阶段压缩为：

> 预训练获得通用能力，后训练塑造这些能力怎样表现。

需要注意，后训练并不能保证模型永远正确，也不能从根本上把它变成确定性程序。

它仍然是同一个自回归语言模型，仍然逐 Token 生成。变化的是在给定指令和上下文时，哪些回答变得更可能。

这就是为什么 Base Model、Instruct Model 和 Chat Model 可以拥有相似的基础结构，却表现出非常不同的交互方式。

### 转场

训练全部完成后，模型正式进入使用阶段。接下来我们走一遍：当用户真的发来一个问题，系统内部发生了什么。

---

## 第 7 页：一次真实请求怎样变成回答

预计时间：5 分钟

### 页面上放什么

~~~text
System 规则 + 用户 Prompt + 对话历史
                  ↓
             序列化为文本
                  ↓
              Token IDs
                  ↓
        Transformer 处理上下文
                  ↓
          下一个 Token 的概率
                  ↓
          选择、追加、继续生成
                  ↓
                回答
~~~

页面结论：

> 上下文会影响当前回答，但普通对话通常不会修改模型参数。

### 讲稿

假设用户输入：“请用三句话解释什么是机器学习。”

系统实际交给模型的内容，通常不只有这句话。

它可能还包括系统规则、用户角色、历史对话，以及告诉模型当前应该从 Assistant 角色开始回答的特殊标记。

这些内容最终都会被组织成一个 Token 序列。

模型先处理当前完整上下文，形成每个位置的内部表示。

然后根据最后一个位置，产生下一个 Token 的可能性。

系统从中选择一个 Token，把它加到上下文里，再继续生成。

这个过程一直持续，直到模型生成结束标记，或者达到系统设置的停止条件。

这里要重新强调第一场的训练与推理区别。

当前 Prompt 的确会改变模型输出，因为模型预测的是“在这个上下文条件下，下一个 Token 应该是什么”。

但普通对话通常不会修改模型参数。

所以 Prompt 可以让模型临时采用某种格式、角色或利用刚刚提供的信息，却不会自动把这些内容永久写入模型。

这也是为什么同一个模型可以根据不同 Prompt 表现出不同风格。

模型参数没有改变，改变的是当前条件。

解码方式也会影响输出。

如果系统总是选择可能性最高的 Token，结果会更稳定，但也可能比较单一。

如果允许在多个高可能性 Token 中采样，结果会更有多样性，但随机性也会增加。

我们不需要记住各种采样参数，只需要知道：

> 模型提供的是一个概率分布，推理系统还需要决定怎样从这个分布中选择 Token。

### 互动

可以现场向同一个模型连续提出两个语义相同但格式要求不同的问题：

- “解释机器学习。”
- “只用一个生活比喻、不要使用专业术语解释机器学习。”

用来说明参数相同，但上下文条件改变了输出分布。

### 转场

现在我们已经知道能力从哪里来，也知道回答怎样产生。最后一个问题是：为什么它明明说得非常流畅，却仍然会自信地犯错？

## 第 8 页：为什么 LLM 会幻觉和犯错

预计时间：6 分钟

### 页面上放什么

|机制|直接带来的边界|
|---|---|
|预测合理的下一个 Token|流畅不等于真实|
|知识来自训练数据|存在缺失、错误和时效限制|
|依赖有限上下文|可能遗漏、混淆长文本信息|
|概率式生成|同一问题可能产生不同答案|
|后训练塑造行为|安全、拒答和帮助性仍可能失效|

页面结论：

> LLM 是强大的概率生成模型，不是事实数据库或确定性程序。

### 讲稿

LLM 最容易让人误判的地方，是语言表达能力非常强。

一段话只要结构完整、语气肯定、细节丰富，我们就很容易把“说得像真的”误认为“它一定知道事实”。

但从今天讲过的机制出发，模型犯错并不神秘。

第一，它直接优化的是下一个 Token 是否符合训练数据中的语言模式，不是每句话是否通过了外部事实验证。

当信息不足时，模型仍然需要继续生成。它可能根据相似文本模式补出一个听起来合理的内容，这就是幻觉的重要来源。

第二，它的参数知识来自训练数据。

训练数据没有覆盖的内容，模型不可能稳定掌握。数据里的错误、偏见和冲突，也可能被模型学到。训练完成后发生的新事件，不会自动写入模型参数。

第三，它依赖有限上下文。

即使一段内容放进了上下文窗口，也不代表模型一定能同样好地利用每个位置。长文本中可能出现遗漏、错误关联和被无关内容干扰。

第四，它是概率式生成。

同一个问题可能产生不同答案。某个 Token 的模型概率很高，也不等于整段回答在事实层面一定正确。

第五，后训练塑造的是行为概率，不是绝对规则。

模型通常会遵循指令、拒绝危险请求或者承认不确定性，但在新的上下文、对抗输入或训练未覆盖的环境中，这些行为仍可能失效。

所以我们应该把 LLM 看成什么？

它是一种非常强大的概率生成模型，能够压缩和组合训练数据中的大量模式，并通过上下文完成多种任务。

但它不是事实数据库，不是搜索引擎，也不是所有输入下都能给出唯一正确结果的确定性程序。

高风险场景中，模型之外仍然需要可靠数据、程序校验、权限控制和人工确认。

### 互动

可以问：

> 如果模型回答得很长、很流畅、还给出了具体日期和人名，我们应该因此更相信它吗？

预期答案：不能。表达质量和事实正确性需要分别验证。

## 第 9 页：从数据到回答的完整主线

预计时间：4 分钟

### 页面上放什么

~~~text
大规模文本
    ↓
Token 化
    ↓
Transformer
    ↓
预测下一个 Token
    ↓
反复训练参数
    ↓
Base Model
    ↓
SFT、偏好与安全后训练
    ↓
Assistant Model
    ↓
用户 Prompt
    ↓
逐 Token 生成回答
    ↓
评估正确性、能力和边界
~~~

四个最终问题：

1. 它是什么？
2. 能力从哪里来？
3. 回答怎样产生？
4. 为什么会犯错？

### 讲稿

现在把两场内容放回一张图。

我们从大量文本开始。

文本被切成 Token，Token 变成模型可以计算的内部表示。

Transformer 负责让每个 Token 结合上下文信息。

模型反复预测下一个 Token，并根据预测错误调整参数。

经过大规模预训练，我们得到 Base Model。它获得了广泛的语言、知识和模式能力，但主要擅长续写。

然后通过 SFT、偏好和安全后训练，让模型更稳定地遵循指令，以助手方式表现能力。

真正使用时，用户 Prompt 和对话历史组成当前上下文。模型预测下一个 Token，选择后追加，再继续预测，最终形成回答。

这套机制同时解释了它的能力和边界。

它为什么能写作、翻译、问答和编程？

因为为了在海量复杂文本中预测准确，它必须形成能够支持这些任务的内部表示。

它为什么能够按照用户要求回答？

因为后训练提高了遵循指令和产生优质回答的概率。

它为什么会幻觉？

因为它优化的是条件文本概率，不是对每句话执行外部事实证明。

它为什么能利用当前提供的新信息，却不会自动永久记住？

因为上下文影响当前推理，只有训练才会长期修改参数。

如果大家最后只能记住四句话，我希望是下面四句：

第一，LLM 本质上是根据上下文预测下一个 Token 的概率模型。

第二，预训练通过海量 Token 预测，让模型获得通用语言、知识和模式能力。

第三，后训练把会续写的 Base Model 塑造成更会遵循指令的助手。

第四，流畅生成不等于事实可靠，模型的训练目标、数据和上下文共同决定了它的能力边界。

到这里，两场分享的主线就完成了。

### 结束语

理解 LLM 不需要先掌握所有公式。

只要记住：

**它仍然是机器学习——用数据训练参数，用上下文产生预测，用评测判断是否真正有用。**
