# 文本、字符、字节、Token 与分词

## 1. 解决的问题

把人类文本转换为模型能够接收的离散整数序列，并在词表大小、序列长度和未知文本处理能力之间取得平衡。

---

## 2. 从文本到模型输入

典型流程是：

**文本 → Unicode 字符 → 字节或子词单元 → Token → Token ID**

### 2.1 字符

字符是文本中的抽象符号，例如汉字、字母、标点和 Emoji。

Unicode 为字符分配码点，但神经网络不能直接对抽象字符执行计算。

### 2.2 字节

文本经过 UTF-8 等编码后变成字节序列。

字节集合很小，可以表示任何文本，但按字节建模通常会产生更长的序列。

### 2.3 Token

**Token 是分词器输出的离散文本单元。**

一个 Token 可能是：

- 一个字。
- 一个词。
- 一个词的一部分。
- 标点或空格组合。
- 一个或多个字节。

Token 不等于自然语言中的“单词”。

### 2.4 Token ID

词表中的每个 Token 都对应一个整数编号：

$$
\text{Token}\rightarrow\text{Token ID}
$$

模型实际接收的是 Token ID 序列：

$$
(t_1,t_2,\ldots,t_T)
$$

---

## 3. 定义

**分词是使用固定词表和确定规则，将文本编码为 Token ID 序列，并将 Token ID 序列解码回文本的过程。**

---

## 4. 为什么不直接按词切分

词级词表存在以下问题：

- 词的数量极大。
- 新词、拼写变化和专有名词难以覆盖。
- 不同语言的分词规则不同。
- 词表过大会增大 Embedding 和输出层参数量。

因此现代 LLM 通常使用子词或字节级子词。

---

## 5. BPE 核心机制

BPE 的基本思想是：

1. 从较小的基本单元开始。
2. 统计训练语料中相邻单元对的频率。
3. 合并最常出现的单元对。
4. 重复合并，直到达到目标词表大小。

高频片段逐渐形成较长 Token，低频词仍可由更小单元组合。

---

## 6. SentencePiece

**SentencePiece 是直接从原始文本训练和应用子词模型的方法框架。**

它把空格等内容也作为文本的一部分处理，不依赖特定语言的预分词器。

常见子词训练方法包括：

- BPE：反复合并高频相邻单元。
- Unigram：从较大的候选词表出发，根据概率模型逐步删减子词单元。

SentencePiece 不是一种神经网络层，而是模型训练前后的文本编码系统。

---

## 7. 词表大小的权衡

### 7.1 词表较大

- 单个 Token 可以表示更长的文本片段。
- 序列通常更短。
- Embedding 和输出层参数更多。
- 低频 Token 学习可能不足。

### 7.2 词表较小

- 参数量较小。
- 对未知文本组合能力强。
- 同一文本会变成更长序列。
- Attention 和推理成本增加。

---

## 8. 特殊 Token

常见特殊 Token 包括：

- 序列开始与结束。
- 填充。
- 未知单元。
- 对话角色与消息边界。
- 工具或结构化内容边界。

特殊 Token 也是词表中的普通离散 ID，但被训练数据赋予了特殊语义。

---

## 9. Tokenizer 与模型的关系

Tokenizer 决定：

- 词表大小 $V$。
- 同一段文本的 Token 数量。
- Embedding 和输出层的第一维。
- 上下文窗口能够容纳多少原始文本。

模型参数必须与指定 Tokenizer 的词表一一对应，不能随意替换 Tokenizer。

---

## 10. 核心本质

**分词器把任意文本压缩成有限词表中的 Token ID 序列，它决定了 LLM 观察和生成文本的最小离散单位。**
