# 二、机器学习（10 分钟 · P06–P13）

> 本块任务：把「学习」拆成四个工程组件并跑通闭环；用线性回归完整走一遍（含全场唯一公式、第一个可视化、第一个证据）；补 Softmax（为 LLM 输出层埋伏笔）与泛化。
> **交接句（块尾）**：特征还是人挑的——图片里「猫」的特征没人写得全 → 人工特征成了新瓶颈。

### P06 · 传统程序 vs 机器学习：换一种分工
- **核心判断**：有一大类任务，人做得出来，但规则写不出来
- **内容要点**：
  - 传统程序：规则 + 输入 → 输出（订单计价，规则写得清，无可替代）
  - 反例：垃圾邮件判断、图片是不是猫、客户流失预测——几百条规则照样冲突、漏网、过时
  - 机器学习的分工：人提供 数据 + 模型形式 + 目标（什么算好）；机器只负责 **找参数**
- **可视化**：左右对比框图
- **备注**：强调「不是机器自动发现一切」，约束仍由人定

### P07 · 训练闭环：四个组件 ★
- **核心判断**：任何监督学习 = 四件套构成的循环
- **内容要点**：
  - **① 数据**：经验来源 (x, y) —— 例：(面积, 价格) × N 条
  - **② 模型** f(x;θ)：规律载体 + 可调参数 —— 例：ŷ = w·x + b
  - **③ 损失函数** L(ŷ,y)：量化当前参数有多差 —— 例：½(ŷ−y)²
  - **④ 优化算法**：往哪调、调多少 —— 例：w ← w − η·∂L/∂w
  - 循环：预测 → 算误差 → 调参数 → 再预测 ↺
- **可视化**：四组件闭环图（带梯度回传虚线）
- **备注**：后面所有模型（含 GPT）都在这个闭环里，只是四件套换内容——这句话埋在这里，第四块回收

### P08 · 线性回归：公式三件套
- **核心判断**：「学习」在数学上就是这三行
- **内容要点**：
  - 模型：ŷ = w·x + b（全场唯一公式，参数只有 w 和 b）
  - 损失：L = (1/N) Σ(ŷᵢ−yᵢ)²
  - 更新：w ← w − η·∂L/∂w（η = 学习率：步子迈多大）
- **可视化**：公式卡 + 散点示意
- **备注**：用房价例子口述一遍：初始 w 随机 → 预测 100 平 = 100 万，实际 300 万 → 误差告诉我们往哪调

### P09 · 看见：梯度下降跑起来 ★（现场演示候选）
- **核心判断**：直线在数据里「下坡」，损失单调下降——这就是学习的全部
- **内容要点**：
  - 散点 + 拟合直线随迭代步数变化；每点的误差线同步缩短
  - 损失曲线同步下降；读数：iter / w / b / L 实时更新
  - 结论句：**模型里没有中文规律，只有一组让误差变小的数字**
- **可视化**：交互式梯度下降（HTML 演示：播放 / 单步 / 重置）【已有 v2 组件可复用】
- **证据·演示**：—（证据在下一页）
- **备注**：口头强调「刚才这 10 秒钟，机器自己找到了那条直线」

### P10 · 证据①：PyTorch 十行实现
- **核心判断**：上面整套闭环，工程上就这几行
- **内容要点**：
  - 代码要点对照四组件：`nn.Linear`（模型）/ `((pred-y)**2).mean()`（损失）/ `SGD`（优化器）/ `loss.backward(); opt.step()`（更新）
  - 运行输出：loss 从 ~20 降到 <0.2
- **可视化**：代码块 + 终端输出
- **证据·演示**：【素材待补】PyTorch 运行截图或 15 秒录屏
- **备注**：对非工程听众一句带过「框架把求导都做了」；对后端听众指一下四组件与代码的对应

```python
import torch
model = torch.nn.Linear(1, 1)                  # 模型: y = w*x + b
opt   = torch.optim.SGD(model.parameters(), lr=0.1)   # 优化器
for x, y in loader:                            # 数据
    loss = ((model(x) - y) ** 2).mean()        # 损失
    opt.zero_grad(); loss.backward(); opt.step()  # 反向传播 + 更新
```

### P11 · Softmax 回归：分数变概率（LLM 伏笔）
- **核心判断**：线性打分 + 指数归一化 = 合法的概率分布
- **内容要点**：
  - z = Wx + b（每类一个 logit）→ pᵢ = e^zᵢ / Σe^zʲ → Σp = 1
  - 损失用交叉熵：L = −log p(真实类)——只罚「真实类别给的概率不够高」
  - 示例：logits [2.1, 0.8, −0.5] → [0.78, 0.21, 0.01]
  - **伏笔（重点标注）**：LLM 的输出层 = 以全词表（5 万+）为类别的 Softmax 回归
- **可视化**：logits→softmax→概率条形图
- **备注**：这句伏笔在 P25（Token/输出层）兑现——「你在第二块已经见过 LLM 的输出形式了」

### P12 · 泛化：真正要的不是背答案
- **核心判断**：训练分数好 ≠ 用起来好；目标是新数据上依然有效
- **内容要点**：
  - 数据三份职责：训练集调参数 / 验证集选方案 / 测试集估真实表现
  - **过拟合**：容量太大，把训练数据连同噪声背下来（训练好、新数据乱猜）
  - **欠拟合**：容量不足或训练不够，训练数据上都没学好
  - 评估纪律：别看训练指标，看新数据表现
- **可视化**：过拟合 / 欠拟合 / 合适拟合 三联对比图
- **备注**：欠拟合一句带过即可，重心放在「训练误差低有两种含义」

### P13 · 交接：人工特征成为瓶颈

# 三、深度学习（8 分钟 · P14–P18）

> 本块任务：用「非线性 + 层次化」双动机引出 MLP；证明特征可以自己学；CNN 作为「结构写进网络」的历史主线快速带过。
> **交接句（块尾）**：图像的结构假设成功了——文本也有自己的结构（顺序与上下文），但 MLP 没有记忆。

### P14 · 双动机：世界是非线性的，也是层次化的 ★
- **核心判断**：线性模型有两条原罪，深度学习逐条解决
- **内容要点**：
  - **动机一（非线性）**：真实规律大量是非线性的——类别互相包围、螺旋缠绕，一条直线无论怎么摆都分不开
  - **动机二（层次化）**：世界是分层表达的（像素→边缘→纹理→部件→物体）；线性回归把所有细节压在「一层加权求和」上，不符合层次结构的高效性
  - 猜想：多叠几层线性行不行？——不行：W₂(W₁x+b₁)+b₂ = W′x+b′，叠十层还是一次线性
- **可视化**：两条动机并排 + 「叠线性仍线性」代数式
- **备注**：这是全场逻辑最「自洽」的一页——深度学习不是拍脑袋，是被两条缺口逼出来的

### P15 · MLP：多层 + 非线性 + 反向传播一句
- **核心判断**：非线性激活让不同输入区域走不同加工路径——弯曲边界变成「可组合的」
- **内容要点**：
  - 结构：hᵢ = σ(Wᵢhᵢ₋₁ + bᵢ)，层层堆叠
  - **没有非线性的深度是假深度**（上页已证）
  - 激活函数的真实作用：让每个神经元管一个区域，后层把「在/不在」组合起来 → 围出任意复杂边界
  - 反向传播一句话：前向算值，反向算梯度——损失对每个参数的「埋怨」逐层分摊回去（工程上框架自动完成）
- **可视化**：多个半平面围出弯曲区域的示意图
- **备注**：反向传播不展开，一句带过；有人追问进 QA

### P16 · 看见：圆与螺旋（Playground 现场演示 ★）
- **核心判断**：加隐藏层之前，圆不在它的世界里；加了之后，圆成了可组合的结果
- **内容要点**：
  - 演示 A（圆形数据）：无隐藏层 → 永远只能画直线；加一层 + 激活 → 直线组合出圆
  - 演示 B（螺旋数据）：更深更宽才能盘进去
  - 冷水：**能表达 ≠ 一定学得出来**——换个初始化/学习率可能训崩；深度提供可能性，训练是工程
- **可视化**：TensorFlow Playground【断网兜底：圆/螺旋静态图（v2 已有 SVG）】
- **证据·演示**：现场演示（全场唯一浏览器演示，约 3 分钟）
- **备注**：两句固定台词照说；这盆冷水在 P28（预训练）还会回来

### P17 · 特征学习：深度学习真正改变了什么
- **核心判断**：把「设计特征」这份工作交给机器——这是深度学习与传统 ML 的分界线
- **内容要点**：
  - 分层表示：像素 → 边缘·方向 → 纹理·局部形状 → 物体部件 →「是猫」
  - 每上一层：离原始像素远一点、离任务目标近一点——「深」= 逐层组合
  - 对比表：传统 ML 人给特征；深度学习 人只给结构与数据，特征自己学
  - 边界提醒：中间表示是分布式的（未必可命名）；训练闭环本身没变，变的是特征从人手里交出去
- **可视化**：分层金字塔 + 对比表
- **备注**：呼应 P07——「四组件闭环没变，换的是四件套的内容」

### P18 · CNN：把图像的结构写进网络（快速带过）
- **核心判断**：CNN 证明了「把对数据的理解写进结构」能大幅提升效率——它是深度学习的历史主线（2012–2017 图像时代）
- **内容要点**：
  - 两个结构假设：局部相关性（边缘由邻近像素构成）+ 平移不变性（左上角的边缘和右下角的边缘是同一个模式）
  - 对应设计：局部连接 + 参数共享（同一组卷积核权重扫全图）
  - 参数量直观对比：全连接第一层 ~1.5 亿 vs 卷积 ~5 千（相差约 3 万倍）
  - 层次化特征天然衔接上一页
- **可视化**：卷积核滑窗 → 特征图（一图）
- **备注**：明确说「LLM 主线不在图像，此页 60 秒」；它存在的意义是给第四块「结构假设」的思路做铺垫

# 四、LLM（18 分钟 · P19–P31）★ 全场重心

> 本块任务：RNN 的困境引出 Attention；组装 Transformer；讲清「文本怎么进出模型」；预训练给能力、SFT/LoRA 给行为——**用户自己的实验是全场高潮**。
> **交接句（块尾）**：模型训完、参数冻结、部署上线——你按下回车，发生了什么？（进入第五块）

### P19 · 转向文本：序列需要记忆
- **核心判断**：文本的核心结构是顺序与上下文——MLP 每次只看固定输入，没有记忆
- **内容要点**：
  - 「我没有说他偷了钱」——重音落在不同字上，意思完全不同
  - 一个代词指谁要看前文；一个词的含义可能取决于几百字前的伏笔
  - RNN 的方案：维护一个随阅读进度更新的「摘要」hₜ = tanh(W_x·xₜ + W_h·hₜ₋₁ + b)，同一组参数逐步复用
- **可视化**：RNN 按时间步展开图（h₁→h₂→h₃ 传递）
- **备注**：RNN/LSTM 曾统治序列建模多年——先给历史地位，再讲限制

### P20 · RNN 的三个限制 → 能否直达？
- **核心判断**：不是实现缺陷，是「逐步传递」这条路线本身的天花板
- **内容要点**：
  - ① 长距离路径 O(n)：A 影响 E 要穿过 B、C、D 的每次更新——损耗（梯度消失 /「前面说的后面忘了」）
  - ② 序列串行：算第 100 个词必须等第 99 个——大模型最需要的并行训练上不去
  - ③ 固定瓶颈：10 个词和 1 万个词都压进同一个 d 维向量
  - 升级问题：**一个词，能不能不走接力赛，直接找到它真正需要的那个词？**
- **可视化**：A→B→C→D→E 接力路径（红）vs Attention 直达弧线（绿）
- **备注**：LSTM 缓解①③，但「按顺序算」没变——这句给足 Transformer 登场理由

### P21 · Attention 的动机：含义在关系里
- **核心判断**：Token 的含义不在 Token 本身，在它与上下文的关系中
- **内容要点**：
  - 「银行旁边有一条河」→ 河岸；「我去银行取了钱」→ 金融机构
  - 查字典（静态表示）区分不了——需要机制让「银行」根据当前内容，自己决定从哪些词取多少信息
  - Attention = 按内容相关性动态加权汇总：相关的多取，不相关的少取
- **可视化**：两句例句卡片 + 高亮
- **备注**：先立直觉，下一页给数据上的「看见」

### P22 · 看见：注意力权重热力图
- **核心判断**：同一个「银行」，两句话里学到的权重分布完全不同——这就是「上下文相关表示」
- **内容要点**：
  - 热力图 A：「银行」行的权重集中在「河」（~0.65）
  - 热力图 B：「银行」行的权重集中在「取了钱」（~0.62）
  - 三个限制同时解决：路径 = 1 / 全并行 / 不压缩历史
- **可视化**：两个注意力矩阵热力图
- **备注**：数值是示意，口头说明「真实模型的权重大致长这样」

### P23 · QKV：一次矩阵运算的信息流
- **核心判断**：寻找（Q）· 线索（K）· 内容（V）三个可学习投影，把三种职责分开
- **内容要点**：
  - 信息流：X [T,d] → Q=XW_Q, K=XW_K, V=XW_V → QKᵀ [T,T] 匹配分（÷√d_k 稳数值）→ softmax 归一化 → 加权汇总 A·V [T,d]
  - 公式（不推导，只认脸）：Attention(Q,K,V) = softmax(QKᵀ/√d_k)·V
  - 为什么三个投影：寻找的维度、被匹配的维度、传的内容不必是同一空间
  - **误解粉碎**：Q 不是自然语言问题、K 不是主键、V 不是现成答案——都是训练出来的向量
- **可视化**：带张量形状标注的数据流图
- **备注**：面向工程听众；文员听众只需要记住「寻找-匹配-取回」三个动词

### P24 · Transformer 组装 + 因果掩码 ★
- **核心判断**：因果掩码一石二鸟——训练时防偷看且不牺牲并行；生成时天然从左向右续写
- **内容要点**：
  - Decoder Block = Attention（通信）+ FFN（位置内加工）+ 残差（保底）+ Norm（稳压），堆几十上百层
  - 因果掩码：第 t 个位置只能看 1…t——上三角填 −∞，softmax 后未来彻底屏蔽
  - 训练侧：整段已知，所有位置一次前向并行练习「预测下一个」
  - 生成侧：本来就只有过去 → 写一个、追加一个、再写下一个
  - 分工记法：**Attention 管通信，FFN 管加工**
- **可视化**：下三角掩码矩阵（−∞ 可见）+ Block 结构图
- **备注**：全场最关键的一页（讲稿标注 ★）；「训练并行 / 生成顺序」在第 32 页兑现

### P25 · 文本怎么进出模型：Token 与输出层
- **核心判断**：一次前向不输出句子——只输出「下一个 Token」的全词表概率分布
- **内容要点**：
  - 输入侧：字符串 → BPE 切分 → Token ID → Embedding 查表（[V,d] 取行）→ 向量序列
  - Token ≠ 词：可能是整词 / 子词 / 字 / 字节；tokenizer 不懂语义，只是映射规则
  - 输出侧：最后位置向量 → 输出层 → logits [V] → softmax → 概率分布
  - **兑现 P11 伏笔**：这就是全词表版本的 Softmax 回归
- **可视化**：输入输出管线图（文本→Token→Emb→N×Block→Logits→Softmax→下一Token）
- **备注**：文员听众最容易卡在「文字怎么变数字」，这页专门服务他们

### P26 · 预训练：文本自己就是答案
- **核心判断**：一段文本左移一位 = 全部位置的练习题和答案，零人工标注
- **内容要点**：
  - 「机器 学习 可以 从…」每个前缀的标签就是下一个词
  - 训练循环（四行伪代码）：tokens → model(tokens[:-1]) → cross_entropy(·, tokens[1:]) → update
  - 互联网规模 × 一个统一目标 × 零标注 = 预训练
  - GPT 三步一句话版：GPT-1 能力可迁移 / GPT-2 任务统一为续写 / GPT-3 指令即接口（In-context learning 不更新参数）
- **可视化**：左移对齐样本表
- **备注**：GPT 三步若超时可砍（在删减顺序表里）

### P27 · 为什么能长出能力 + 两条边界
- **核心判断**：能力是优化「预测下一个 Token」被逼出来的副产品；边界由数据划定
- **内容要点**：
  - 现场实验：请听众补完「如果数据库连接池已经耗尽，那么新的请求通常会——」（排队/超时/被拒绝）——你刚才自动调用了连接池知识才补得出来；预测准需要语法、指代、事实关联、代码结构、推导步骤 → 全被压进参数
  - 边界一：模型不是数据库（知识分布式压在参数里 →「有但说不准」「流畅但不对」）
  - 边界二：数据决定上限（没有的、过时的、矛盾的 → 不会或瞎编；知识有截止时间）
- **可视化**：连接池实验大字页
- **备注**：全场唯一互动，停两秒等大家小声说答案

### P28 · 证据②：llama.c 预训练实录
- **核心判断**：预训练不是 PPT 概念——我亲手跑过，看着 loss 下降、文本逐渐像人话
- **内容要点**：
  - loss 曲线：从随机噪声级别持续下降

  - 呼应 P16 的冷水：训练是一门工程（学习率、稳定性、数据配比都在起作用）
- **可视化**：loss 曲线 + 三个阶段的生成文本对比
- **证据·演示**：【素材待补】llama.c 训练截图 / 60 秒快放录屏
- **备注**：不讲实现细节，只给「眼见为实」；细节留给 QA 或第二场

### P29 · SFT：会续写 ≠ 会当助手
- **核心判断**：SFT 换的是数据分布，不是训练目标——教行为，不注知识
- **内容要点**：
  - 基座模型的行为：「请用三句话解释缓存击穿」→ 续写出另一个相似问题（训练数据里「问题后面还是问题」）
  - SFT 数据：指令 + 人写的理想回答；工程细节：只在回答 Token 上计算损失（prompt 部分置 −100）
  - 底层没变：仍是「预测下一个 Token」，数据从全网文本换成高质量问答

- **可视化**：SFT 样本格式 + loss mask 着色图

### P30 · ★★ 证据③（全场高潮）：我的 SFT + LoRA 实验
- **核心判断**：亲手把一个「只会续写的基座」变成「能听指令、懂我们私有数据的助手」——这条链路每一步都是真的
- **内容要点**：
  - 对比一（完成指令）：同一个问题，基座模型输出（续写/跑题） vs SFT/LoRA 后输出（按指令结构化回答）
  - 对比二（私有数据适配）：问内部知识，基座不知道 / 瞎编 vs 微调后正确回答
  - LoRA 一句话：不重训全部参数，只训一小块低秩增量——消费级显卡也能做
  - 收束：能力来自预训练（P26–28），行为来自后训练（本页）——主线的「任务适配自动化」落地
- **可视化**：左右对话截图对比 ×2 组
- **证据·演示**：【素材待补】基座 vs 微调的对话截图（2 组：指令遵循 / 私有数据问答）+ LoRA 训练 loss 记录
- **备注**：这页多留时间（2–3 分钟）；它是全场唯一「别人讲不了」的内容

### P31 · 偏好对齐（一页收）
- **核心判断**：对齐管「倾向」，不管「真值」——能力和行为、行为和正确都是不同维度
- **内容要点**：
  - 问题：多个回答都「对」但质量不同，「更好」写不成规则 → 换成人做选择题（排序比写答案容易十倍，可规模化）
  - 链条：偏好排序 → 奖励模型（替人打分）→ 强化学习让高分回答更常见（RLHF 经典 / DPO 简化：直接从偏好对学）
  - 实证：130 亿 InstructGPT 偏好评分 > 1750 亿原始 GPT-3
  - 边界：人更偏好 ≠ 更真实；偏好近似可能被钻空子
- **可视化**：四步流程图 + 数字对比
- **备注**：一页带过，细节全进 QA

### P37 · Tool Call：模型出请求，系统出执行 ★
- **核心判断**：模型输出工具调用参数 ≠ 模型执行了工具
- **内容要点**：
  - 消息流（真实 JSON）：user（任务）→ assistant（tool_calls: 工具名 + 参数）→ tool（执行结果）→ assistant（基于结果继续）
  - 关键：模型只生成那段 JSON；执行、鉴权、错误处理全在外部系统
  - 这个能力来自训练（SFT + RL 教会它「何时调用、格式正确」）——但执行权从来不在模型手里
- **可视化**：消息时间线（JSON 着色）
- **备注**：给后端听众指出：这就是一个「由模型驱动的 RPC」

### P38 · 思维链 CoT：把思考外化成生成（一句页）
- **核心判断**：推理深度 = 生成长度
- **内容要点**：
  - 直接回答 = 一次前向；先写推导再回答 = 每个 Token 都是一次前向 → 思考获得了计算空间
  - 能力来源：训练侧（在推理轨迹上做 SFT / 强化学习）+ 推理时给更长思考预算
  - 边界：更长 ≠ 更对；推理 Token 成本高
- **可视化**：直接答 vs 先思考再答 的两条路径对比
- **备注**：与 P37 同源——「会写中间步骤」也是训练带来的行为

### P39 · ReAct：环境反馈驱动的循环
- **核心判断**：从「一口气生成」变成「基于反馈不断修正的循环」
- **内容要点**：
  - 循环：观察 → 思考（Thought）→ 行动（Action）→ 新观察 → …直到得出答案
  - 与多轮对话的区别：多轮的驱动力是用户追问；ReAct 的驱动力是环境反馈——单次任务内自我推进
  - 规划：先计划再执行 / 边想边做，可组合
- **可视化**：循环图（观察→思考→行动 ↺）
- **备注**：用一个排障例子口述一遍循环（查指标→发现异常→查日志→定位→建工单）

### P40 · 现代 Agent 生态（快速带过）
- **核心判断**：都是系统层的扩展——通过工具调用把能力接出去
- **内容要点**：
  - **MCP**：工具连接的标准协议——把 M×N 逐对对接变成 M+N（换模型换工具，协议不变）
  - **Skill**：把「这类任务怎么做」固化成可复用知识（步骤 / 约束 / 模板 / 异常处理）
  - **子 Agent**：用循环编排 LLM 本身——大的 Agent 拆成多个小的协作
  - 共同点：都没有改变模型，改变的是外面的系统
- **可视化**：M×N 蜘蛛网 vs M+N 中心辐射图
- **备注**：超时优先砍本页（在删减顺序表里）；只留 MCP 一句话

### P41 · Agent 是系统，不是模型
- **核心判断**：模型决定，系统执行——看到一个产品「能干活」，先问能力在参数里还是系统里
- **内容要点**：
  - 分层：LLM（理解与决策）/ Harness（循环 · 状态 · 权限 · 校验）/ Skill 与工作流（稳定任务知识）/ MCP（连接）
  - Agent = LLM + 目标 + 状态 + 工具 + 循环；它没有改变「预测下一个 Token」的机制
- **可视化**：分层架构图
- **备注**：本页回答开场四问的最后一问（回车之后 → 生成 → 干活）

  - 收场句（回扣标题）：**今天的大模型，底层仍然在预测下一个 Token——真正让人惊讶的不是这个目标多简单，而是当结构、数据和规模足够大之后，为了持续做好这件小事，机器长出了我们称之为「智能」的行为。**

# 附录 A · QA 速查（被问到再讲）

| 问题 | 一句话答案 |
|---|---|
| Attention 公式？ | Softmax(QKᵀ/√d)·V——寻找、匹配、取回，公式不改变直觉 |
| 多头是什么？ | 多组 QKV 并行，各自学不同的关系视角；头 ≠ 固定人类概念 |
| 为什么需要位置编码？ | Attention 只看内容，「狗咬人 ≠ 人咬狗」；RoPE 让匹配感知相对位置 |
| 温度调低更准吗？ | 只会更稳；top-1 本身是错的话，低温稳定地错 |
| KV Cache 是什么？ | 历史 K/V 算一次重复用，省算力；随长度占显存，GQA 优化它 |
| 怎么减少幻觉？ | 给上下文 / RAG / 接工具 / 要引用 / 加校验——本质是让它「基于材料说话」 |
| 微调 / RAG / 提示词怎么选？ | 改参塑行为 / 检索进上下文 / 临时引导——可组合；灌知识别用微调 |
| LoRA 为什么省？ | 冻结原参数，只训低秩增量矩阵，参数量降低几个数量级 |
| 推理模型原理？ | 思考外化成生成，推理深度 = 生成长度；更长 ≠ 更对 |
| MoE / 量化 / GQA？ | 做大（稀疏激活）/ 做省（低比特）/ 做快（共享 KV）——不改原理 |
| 参数越大越强吗？ | 不是：算力固定下参数和数据要配平（Chinchilla ≈ 1:20）；13B 对齐后偏好可胜 175B |
| 上下文越长记得越多吗？ | 「放得进」≠「用得好」：注意力 O(n²)、中段信息利用不可靠 |

# 附录 C · 迭代纪律（调整时遵守）

1. **先改宪法，再改正文**：主题 / 目标 / 主线问题变了，全文重排；没变，只动页块。
2. **承重测试**：删掉这一页，主线断吗？断了就留。
3. **误导测试**：不讲这个，听众会形成错误心智吗？会就留（哪怕只留一句话）。
4. 新增内容必须绑定一个「看见」或「证据」，否则进 QA 附录。
5. 每页正文 ≤ 5 个信息点；每块保留交接句（新瓶颈 = 下一块的钩子）。
6. 定稿标志：能脱稿讲一遍每页的「核心判断」——然后转 PPT。
