## 〇、我们要回答什么问题

语音识别、图像识别、机器翻译——这些东西十年前还做不好，现在随手可用。再到我们每天都在用的：问问题、写代码、总结文档、分析数据。它们表现出一种像是「理解了意图、掌握了知识」的能力。

但只要往下追问一层，事情就开始模糊：

- 模型的知识是从哪来的？
- 为什么它能看懂上下文？
- 它为什么会听我的指令，而不是自顾自地说话？
- 我按下回车之后，那段回答到底是怎么出来的？

这篇材料就回答这四个问题。回答的方式不是罗列名词，而是沿着一条主线走：**机器是怎么一步步把人做的东西拿走的。**

这条主线可以压缩成六步，每一步都是机器从人手里接过了一项工作：

| 阶段 | 机器拿走了什么 |
|---|---|
| 传统程序 | 执行（人写规则，机器照办） |
| 机器学习 | 找参数（人给数据和目标，机器自己调） |
| 深度学习 | 设计特征（连「看什么」也自己学） |
| Transformer | 上下文建模（词和词的关系自己建） |
| GPT 与后训练 | 任务适配（从每个任务训一个模型，到任务写在提示词里） |
| Agent | 行动选择（决定下一步做什么） |

每一步的驱动力都一样：**上一阶段把某项工作交给机器之后，剩下的瓶颈变成了下一阶段要解决的问题。** 记住这句话，后面每一节都是它的展开。

先划个边界：这篇材料讲原理和判断力，不讲工具使用技巧，不盘点模型新闻，也不做数学推导。它面向所有非算法岗位的同事——后端、前端、产品、运营都一样能读。

## 一、机器学习：机器学的到底是什么

### 1.1 写不出来的规则

先给传统程序应有的尊重。你每天写的代码就是它：规则 + 输入 → 输出。算一笔订单的价格：商品金额、优惠、税费、运费，规则写得清清楚楚。**对规则写得出来的问题，传统程序就是最好的方案**，今天讲的任何东西都替代不了它。

问题在于，有一大类任务，人做得出来，但规则写不出来。

判断一封邮件是不是垃圾邮件——你可以凭感觉，但你试试把判断条件写全？写出五百条规则，照样有冲突、有漏网，而且垃圾邮件的套路还在变。识别图片里是不是猫、预测客户会不会流失，全是同样的困境：**人做得出来，但说不清楚自己是怎么做的。**

机器学习换了一种分工：人提供数据、模型形式和目标（什么算好），机器负责在这些约束里**把参数找出来**。注意，不是「把数据丢给机器，它自动发现一切」——人仍然决定喂什么、用什么模型、怎么算好坏，机器只负责找那组数字。

### 1.2 学习的四个零件

任何监督学习，都由四个零件组成一个循环：

1. **数据**：经验的来源。比如（面积, 价格）配对的样本集。
2. **模型**：承载规律的结构，里面有待调的参数。比如 ŷ = w·x + b。
3. **损失函数**：衡量「当前这组参数有多差」。比如预测价和真实价差的平方。
4. **优化算法**：根据损失指出的方向，微调参数。

循环转起来就是：用当前参数做预测 → 算误差 → 沿让误差变小的方向调参数 → 再预测 → 循环往复。后面讲到的所有模型——包括最大的那个——都没有跳出这个闭环，变的只是四个零件里装的东西。

### 1.3 线性回归：看一次完整的学习

用最简单的例子把闭环走一遍。根据面积预测房价，模型就是全文唯一的公式：

> 预测价格 ŷ = w × 面积 + b

一开始 w 和 b 是随便给的。拿它去预测 100 平的房子，比如算出 100 万，而真实价格是 300 万——现在你知道两件事：当前参数不对，而且知道差多少。把很多样本的误差汇总，就是损失函数；优化算法朝让损失变小的方向微调 w 和 b，再来。几十轮之后，直线贴合数据，损失降到接近零。

**机器真正「学到」的，不是一条能用中文念出来的房价规律，而是一组让误差变小的数字。**这句话适用于本文的所有模型：模型里存的是参数，不是人类可读的规则。

这件事工程上有多小？用 PyTorch 写出来就这几行：

```python
import torch
model = torch.nn.Linear(1, 1)                        # 模型：ŷ = w·x + b
opt   = torch.optim.SGD(model.parameters(), lr=0.1)  # 优化器
for x, y in loader:                                  # 数据
    loss = ((model(x) - y) ** 2).mean()              # 损失
    opt.zero_grad(); loss.backward(); opt.step()     # 反向传播 + 更新
```

我实际跑过它：损失从 20 左右一路降到 0.2 以下，几十步就收敛。四个零件在代码里各占一行——「学习」在工程上就这么大点事。

### 1.4 Softmax 回归：把分数变成概率

线性回归预测连续数值，分类任务怎么办？Softmax 回归：先用线性算出每个类别的分数（logits），再做一个指数归一化，把分数变成合法的概率分布——猫 0.78、狗 0.21、鸟 0.01，加起来正好是 1。训练用的损失叫交叉熵，效果是「真实类别的概率被越推越高」。

记住这个输出形式，它是本文最重要的一处伏笔：**大模型的输出层，就是一个以全词表（五万多个候选）为类别的 Softmax 回归。**你现在见到的「模型回答问题」，底层形式和这里判断猫狗一模一样。

### 1.5 泛化：别把背答案当学会

还有一个必须的概念：泛化。如果模型只会在训练见过的那些房子上算得准，拿到新房子就乱猜，那它什么都没学会，只是背下了答案。所以训练的目标从来不是「训练数据上误差低」，而是**在没见过的新数据上依然准**。

训练误差低其实有两种可能：一种是学到了能迁移的规律；另一种是模型容量太大，把训练数据连同噪声一起背了下来——后者叫过拟合。反过来，模型太弱、训练不够，连训练数据都拟合不好，叫欠拟合。所以工程上的纪律是：把数据分成训练集（调参数）、验证集（选方案）、测试集（估计真实表现），**评估只看新数据上的表现**。

到这里，机器已经能从数据里学参数了。但注意一个细节：这个例子里，「面积」这个特征是人挑的。图片里「猫」的特征是什么？边缘？胡须？比例？——没有人能把「猫」的特征写全。**人工挑特征，成了新的瓶颈。**

## 二、深度学习：特征也交给机器

### 2.1 两条缺口：非线性，和层次

线性模型有两条「原罪」，深度学习逐条解决。

第一条：**世界大量规律是非线性的。**一类数据把另一类包在中间、两股螺旋缠在一起——一条直线无论怎么摆都分不开。那多叠几层线性变换行不行？不行，这是可以证明的：线性套线性，合并起来仍然是一次线性（W₂(W₁x+b₁)+b₂ = W′x+b′），叠十层等于一层。

第二条更深刻：**世界是层次化表达的。**图像由像素组成边缘，边缘组成纹理，纹理组成局部形状，形状组成物体部件。线性回归把所有细节规律压在「一层加权求和」上——这不符合层次结构的高效组织方式。识别一个物体，本该先看简单模式、再把简单模式组合成抽象概念，一层压平了做，既低效也表达不了。

### 2.2 MLP：多层 + 非线性 + 反向传播一句

多层感知机（MLP）的配方：多个线性层，层与层之间夹一个非线性激活函数（比如 ReLU：负数归零、正数保留）。加了这个非线性的折叠，各层再也不能合并成一次线性，网络才能表示弯曲的、分段复杂的边界。

激活函数真正增加的东西，一句话：**让不同的输入区域走不同的加工路径。**每个隐藏神经元相当于一条直线分割，后面的层把「在不在分割内」组合起来，就能围出圆形、任意弯曲的区域。没有非线性，这种组合根本不存在。

隐藏层的参数怎么训练？反向传播，一句话讲完：**前向传播算出每层的值，反向传播用链式法则把「损失对结果的埋怨」逐层分摊回每个参数**，然后照旧用梯度下降更新。工程上框架自动完成，不需要手写。

深度学习里「深」的意思就是：**逐层组合出特征**——前层学简单模式，后层把模式组成抽象概念。从此人只提供网络结构和数据，「设计特征」这份工作交给了机器。这是深度学习与传统机器学习的分界线。

一个必要的冷水：**能表达，不等于一定学得出来。**同样的结构，换个初始化、换个学习率，可能就训崩了。深度提供的是可能性，训练是一门工程。这盆冷水后面讲大模型时还会泼一次。

### 2.3 眼见为实：圆与螺旋

这个结论值得亲眼看到。用浏览器里的神经网络 Playground（tensorflow.org/playground）跑一个经典实验：一団数据，蓝点在中间、橙点围在外面。

不加隐藏层时，无论训练多久，模型只能画出一条直线——不是它笨，是**它的表达形式里根本不存在圆形边界**，你不可能用直尺画圆。加上一层隐藏层和非线性激活之后：每个神经元学到一个不同方向的线性分割，后层把这些分割组合起来——边界变圆了。一句话：**加隐藏层之前，圆不在它的世界里；加了之后，圆成了可组合的结果。**

换更难的两股螺旋，浅的网络学不动，要更深、更宽才能盘进去。我在现场演示这个实验时都会补一句冷水：换个参数它可能就训不出来了——能表达和学得出来是两回事。

### 2.4 CNN：把图像的结构写进网络

深度学习的第一个黄金时代（2012 年起）属于图像，主角是卷积神经网络（CNN）。它在 MLP 基础上做了一次漂亮的结构优化，利用图像的两个先验：

- **局部相关性**：有意义的模式（边缘、角点）由相邻像素构成，所以每个神经元只连接输入的一个局部窗口；
- **平移不变性**：左上角的一条边缘和右下角的一条边缘是同一个模式，所以同一组检测器权重（卷积核）滑过全图共用。

效果直接体现在参数量上：处理 224×224 的图片，全连接第一层要一亿五千万参数，卷积只要几千个，相差约三万倍。CNN 层层堆叠，自然形成「边缘→纹理→部件→物体」的层次特征——正好接上 2.1 的第二条缺口。

这里快速带过，因为它在本文的任务只有一个：证明**把对数据的理解写进网络结构，能大幅提升学习效率**。这个思路马上要用在文本上。

## 三、大模型：训练出能力，推理出回答

### 3.1 文本难在哪：顺序与上下文

MLP 每次只看固定的一团输入，没有顺序、没有记忆。但文本完全不同。看这句话：「我没有说他偷了钱」——重音落在「我」是别人说的，落在「没有」是我可没说，落在「钱」是偷了别的东西。一个代词指谁，要看前文；一个词的含义，可能取决于几百个字之前埋的伏笔。

**处理序列，模型必须记住前面发生过什么。**

早期的答案是循环神经网络（RNN）：维护一个随阅读进度不断更新的「摘要」。读到「我」得到摘要 h₁，读到「喜欢」时把「喜欢 + h₁」压成 h₂，以此类推。同一组参数每步复用，多长的序列都能处理。这个思路统治了序列建模很多年（LSTM 是它的著名改良）。

### 3.2 RNN 的三个天花板

但 RNN 有三个娘胎里带来的结构问题，序列一长、模型一大就全部恶化：

1. **长距离要走远路。**第 1 个词的信息要影响第 100 个词，必须一步一步穿过中间每次的状态更新，越远损耗越大——训练上表现为梯度消失，使用上表现为「前面说的后面忘了」。
2. **没法并行。**算第 100 个词的状态必须先算完第 99 个，序列维是串行的——而大模型最需要的恰恰是大规模并行训练。
3. **摘要本子固定大小。**读十个词和读一万个词，都得压进同一个固定长度的向量里。

LSTM 缓解了一和三，但「按顺序逐步计算」这条路线本身没变。于是问题升级成一句关键的话：**一个词，能不能不走接力赛，直接找到它真正需要的那个词？**

### 3.3 注意力：含义在关系里

看两句话：「银行旁边有一条河」「我去银行取了钱」。两个「银行」查字典查出来完全一样，但你的脑子知道第一个是河岸、第二个是金融机构——因为一个旁边站着「河」，一个前面挂着「取钱」。

**词的含义不在词本身，在它和上下文的关系里。**（在真实的注意力热力图上可以清楚看到：第一句里「银行」的注意力权重大量落在「河」上，第二句里大量落在「取了钱」上。）

所以模型需要一种机制：让「银行」这个位置根据当前内容，自己决定从哪些词、取多少信息。这就是注意力（Attention）：**按内容的相关程度，动态加权汇总**——相关的多取，不相关的少取。序列里任意两个词直接建立连接，路径长度永远是 1；所有位置可以并行算；也不用把历史压进一个固定摘要。RNN 的三个天花板同时解决。

工程实现用了三个可学习的投影，职责分开：

- **Q（Query，寻找）**：我现在需要什么信息；
- **K（Key，线索）**：我能提供什么匹配特征；
- **V（Value，内容）**：匹配上之后真正递过来的东西。

每个位置拿自己的 Q 去和所有位置的 K 算匹配分，分数归一化成权重，按权重把大家的 V 汇总成自己的新表示。公式长这样（不推导，认个脸就行）：Attention(Q,K,V) = softmax(QKᵀ/√d)·V。要防的误解：Q 不是一句自然语言的问题，K 不是数据库主键，V 不是现成的答案——它们都是训练出来的向量。

### 3.4 Transformer：组装，加一把锁

把这些零件组装成可训练、可堆叠的单元，就是 Transformer 的解码块（Decoder Block）：

- **注意力层**：负责词与词之间的通信（唯一的跨位置信息交换）；
- **FFN 前馈层**：负责每个位置自己的加工，模型大部分容量在这里；
- **残差连接**：保底通道，信息只增不减，让深层能训得动；
- **归一化（Norm）**：稳压器，深层堆叠不发散。

分工记一句话：**注意力管通信，FFN 管加工。**这样的块堆几十上百层，就是 GPT、LLaMA 这些模型的骨架。

然后是全场最关键的一步：**因果掩码**。如果我们想让模型做「接龙」——给前文、预测下一个词——那训练时它不能偷看答案。所以加一条规则：第 t 个位置只能看到第 1 到第 t 个词，未来位置一律屏蔽（实现上就是给未来位置的匹配分数加上负无穷，softmax 之后变成零）。

这条锁一石二鸟：**训练时**，整段文本已知，所有位置在一次前向里并行地、各自在「只看过去」的约束下练习预测下一个词——既防偷看又不牺牲并行；**生成时**，本来就更只有过去——模型天然可以从左到右不断续写：写一个、追加一个、再写下一个。

但请注意：此刻这个网络的参数还全是随机数，它一个字都不认识。**架构不等于能力。**能力从哪来？下一节。

### 3.5 文本怎么进出模型

补上输入输出两端，信息流就完整了。

**输入侧**：模型不能读字符串。文本先被分词器（Tokenizer）切成 Token——可能是整词、词片段、汉字或字节片段（Token 不总等于词）——再映射成整数 ID。然后查一张可学习的表（Embedding）：每个 Token ID 对应表里的一行向量。同一个「银行」的初始向量是相同的，它在不同句子里含义的分化，发生在后面几十层注意力的加工里。

**输出侧**：最后一个位置的向量经过输出层，给词表里**每个**候选 Token 打一个分数（logits），经 Softmax 变成概率分布。兑现 1.4 的伏笔：**这就是一次以全词表为类别的 Softmax 回归。**一次前向计算不输出整句话——只输出「下一个 Token」的概率分布。整句话是怎么变成整句话的？3.12 一节揭晓。

### 3.6 预训练：文本自己就是答案

要训练，得有监督信号——得知道正确答案。互联网那么大，谁去标注？

这里的洞察非常漂亮：**文本自己就是答案。**拿一句训练语料「机器学习可以从数据中学习参数」，切成 Token，整体左移一位，就得到所有位置的练习题：「机器 → 学习」「机器 学习 → 可以」「机器 学习 可以 → 从」……每个前缀的正确答案，就是原文的下一个词。**一段文本天然自带全部位置的题目和答案，零人工标注。**

把整个互联网的文本都这样喂进去，让模型反复做一件事——**预测下一个 Token，错了就调参数**——这就是预训练。互联网规模的数据 × 一个统一的目标 × 零标注，GPT 路线由此展开：GPT-1 证明了预训练的能力可以迁移到下游任务；GPT-2 证明了各种任务可以统一成「续写文本」；GPT-3 证明了新任务可以不训练、把任务说明直接写在上下文里。三步合起来一件事：**任务接口在逐渐统一**——从「每个任务训一个模型」变成「一个模型，任务写在提示词里」。

### 3.7 能力从哪来：被目标逼出来的副产品

「预测下一个 Token」听起来太简单了，为什么能长出语言、知识甚至推理能力？做个实验。请心里补完这句话：

> 「如果数据库连接池已经耗尽，那么新的请求通常会——」

排队、超时、被拒绝，对吧。注意刚才那两秒发生了什么：**你完成了一次「预测下一个 Token」，而且你自动调用了连接池的知识才能补出来**——不懂连接池的人猜不准这个词。

模型做的就是这件事，规模是整个互联网。而要在互联网文本上把下一个词预测准，光背词频远远不够：得懂语法、懂指代、懂「连接池耗尽」和「请求失败」的因果关系、懂代码的缩进规律、懂一道数学题的下一步推导。**这些能力都能降低预测误差，所以它们被一起压进了参数。**能力不是设计出来的，是优化这个简单目标的副产品。

但两盆冷水必须浇。第一，**模型不是数据库**：知识不是一条条可查、可溯源的记录，而是分布式地压在几千亿个参数里，所以会出现「参数里有但说不准」「说得流畅但不对」。第二，**数据决定上限**：训练数据里没有的、过时的、互相矛盾的，模型要么不会、要么瞎编，而且它的知识有一个截止时间点。

### 3.8 我跑的一次预训练

预训练不是我转述来的。我用 llama.c 从零跑过一次小规模预训练：初始化时模型输出的是纯乱码——那时它就是一堆随机参数；训练几个小时后，loss（预测误差）从噪声水平持续下降，输出从乱码变成局部通顺的词组，再变成成段合理的句子。看着一段文本「逐渐像人话」，你会非常具体地感受到：所谓能力，就是损失降下来的过程本身。（训练曲线和各阶段生成样本见附图。）

这也呼应第二节的那盆冷水：训练是一门工程——学习率、稳定性、数据配比，任何一环不对都可能训崩。

### 3.9 SFT：会续写，不等于会当助手

预训练完的模型（基座模型）能当助手吗？给它输入「请用三句话解释什么是缓存击穿」，它很可能续写出**另一个相似的问题**，或者把这句话当成网页标题往下编页面内容。因为在它的训练数据里，「问题后面跟着的还是问题」是极常见的模式——它学的目标是「什么文本可能接着出现」，从来没有人告诉它「看到用户请求，要像个助手一样回答」。

**能力是预训练给的，行为得有人教。**教的方法叫 SFT（监督微调）：准备一批「指令 + 人写的理想回答」的数据，继续训练。注意底层一点都没变——它还是在做「预测下一个 Token」，变的只是数据分布：从互联网上什么都有的文本，换成高质量的问答回答。数据分布一换，行为就变了：它学会了识别任务、遵守格式、控制篇幅、以助手身份组织回答。

工程上有个细节值得一提：SFT 时只在「理想回答」的 Token 上计算损失，指令部分被屏蔽（置为无效值）——训练信号只教「怎么回答」，不教「怎么复述问题」。

一个类比：预训练是读了十年书，SFT 是上岗前一周的示范培训。**SFT 教的主要不是知识，是怎么把已有的能力按用户要的形式拿出来。**

### 3.10 我的 SFT + LoRA 实验：亲手教会它当助手

这一节是我自己的实验，也是这篇材料最想让你相信的部分。

**对比一：指令遵循。**同一个问题问基座模型和微调后的模型。基座模型的输出是典型的「续写体」——重复问题、生成一堆相关但没人要的内容；微调后的模型按指令回答：先一句话定义，再讲机制，再给边界，格式稳定。行为的变化肉眼可见，而模型的知识并没有变多。

**对比二：私有数据适配。**问一个只存在于我们内部资料里的问题。基座模型要么不知道、要么一本正经地编一个像模像样的错误答案；微调后的模型能正确回答——因为它在微调数据里见过这些私有知识的相关表述。（两组对比截图见附图。）

微调用的是 LoRA：**不重训全部参数，冻结原模型，只额外训练一小块低秩增量矩阵**，训练量降低几个数量级，消费级显卡就能做。这个小工程恰好把本节的主张落到实处：预训练给能力、后训练给行为——两个独立的旋钮，我拧的是后面那个。

### 3.11 偏好对齐：管倾向，不管真值

SFT 之后还剩一层问题：同一个问题的几个回答都「对」，但质量不同——有的准但啰嗦，有的简洁但漏了边界条件，有的自信但内容没验证过。「哪种更好」写不成规则（写五十页规范也穷举不完），怎么办？换个思路：**不写规则，让人做选择题**。同一问题让模型出四个回答，人只需要排序——做比较比写答案容易十倍，而且可以规模化。

有了几十万条排序，训一个奖励模型（Reward Model）学会替人打分，再用强化学习让高分回答更容易出现——这条经典路线叫 RLHF；后来的 DPO 把流程简化成直接从偏好对学习。效果有实证：论文里 **130 亿参数的 InstructGPT，人类偏好评分超过了 1750 亿参数的原始 GPT-3**——小十几倍的模型靠后训练在「合心意」上反超。说明「能力大小」和「行为是否符合意图」是两个独立的维度。

但也别神化：奖励模型只是人类偏好的近似，可能被钻空子；**人更偏好，不等于内容更真实**。对齐管的是「倾向」，不管「真值」。

### 3.12 按下回车之后：推理就是「只做前向」

训练和使用是两回事，这个区分非常值钱：

| | 训练 | 使用（推理） |
|---|---|---|
| 有正确答案吗 | 有 | 没有 |
| 算损失、调参数吗 | 算、调 | **不算、不调** |
| 产出 | 一组参数 | 下一个 Token |

**使用阶段，参数是冻结的。**

这里有个让整篇材料瞬间收拢的结论：**推理的前向计算，和训练里的前向一模一样**——文本照样被切成 Token、查 Embedding、穿过几十层 Block、最后得到全词表的概率分布。区别只在下一步：训练拿着预测去和正确答案比，算损失、反向传播、更新参数；推理拿着概率分布只做一件事——挑出下一个 Token。同一个架构，训练时「带答案学习」，推理时「不带答案作答」。

工程上把一次请求分成两个阶段：**Prefill（预填充）**把你输入的全部上下文一次性并行处理，你感觉到的「首字慢」主要花在这里；**Decode（解码）**逐个生成新 Token，下一个依赖上一个，只能顺序。这正是 3.4 因果掩码埋的伏笔兑现——训练时全序列并行，生成时必须逐步。

### 3.13 逐 Token 循环与采样

生成的主循环，伪代码只要三行：

```
while 没结束:
    算出全词表每个 Token 的概率
    按概率挑一个，追加到上下文末尾，再来
```

你看到的整段回答，就是这样一次一个 Token 循环出来的。**模型不是先在肚子里打好整篇草稿再逐字念给你——它真的是每次只决定下一个词。**「按概率挑一个」大有讲究——这就是**采样策略**，使用模型时最常碰到的一组参数：

- **贪心（Greedy）**：永远选概率最高的。最稳定，但容易重复、呆板。
- **温度（Temperature）**：把 logits 先除以 T 再做 Softmax。T→0 退化成贪心；T=1 是模型的原生分布；T>1 把概率差距抹平，输出更发散——更有「创造性」，也更容易跑偏。
- **Top-k**：只在概率最高的 k 个候选里采样，概率长尾直接截断。
- **Top-p**：只保留累计概率达到阈值（比如 0.9）的最小候选集合——候选数量随分布形状自动伸缩，比固定 k 更自适应。

两条边界必须说死。其一：**采样参数管的是选词风格，不注入任何新知识**——如果概率最高的答案本身是错的，温度调低只会让它**更稳定地错**。其二：「流式输出」（打字机效果）只是把已生成的 Token 尽早推给你，模型还是那个模型、还是那个顺序——它没有变聪明，也不是「边想边说」。

### 3.14 推理优化：KV Cache 与量化

生成长回答时有一个明显的浪费：生成第 500 个 Token 时，前 499 个 Token 的 K、V 和上一步完全相同，凭什么重算？**KV Cache 的做法是把历史 K/V 缓存起来，每步只计算新位置的 QKV，再让它与整段缓存做注意力**——缓存只增不改，这是自回归生成的关键效率机制。

代价记在显存上：缓存随上下文长度**线性膨胀**。算一笔账：一个 7B 模型（32 层 × 32 头 × 每头 128 维，FP16），每 Token 的 KV 缓存约 0.5 MB——4K 上下文约 2 GB，32K 上下文约 16 GB，比模型权重本身还大。所以推理侧的优化大多围绕它展开：

- **KV Cache 量化**：把缓存从 FP16 压到 INT8 / INT4，缓存显存直接减半或降到四分之一，精度损失很小；
- **GQA（分组查询注意力）**：让多组 Q 共享少量 KV 头，从模型结构上就把缓存变小——现代模型的标配；
- 再往外还有权重量化（7B 模型从 FP16 的 14 GB 压到 INT4 的 3.5 GB）、算子融合、连续批处理等，构成部署侧「做大、做长、做快」的全部工程。

一句话边界：这些优化改变的是**成本与速度**，不改变模型的任何能力。

### 3.15 开头三个困惑，正式作答

走到这里，开头承诺的三个日常困惑可以正式结账了：

1. **为什么新开对话它就忘了？**使用阶段参数冻结——你教的东西只活在当前上下文里，对话一关就没了。**它没有进入模型的脑子，只是出现在了模型的眼前。**产品的「记忆」功能，是系统在外面拿存储做的，不是模型自己记住了。
2. **流式输出是不是它在边想边说？**不是。逐 Token 生成是结构属性（3.13），流式只是尽快推送已生成内容；温度和采样参数也只管风格，救不了知识错误。
3. **为什么会一本正经地胡说？**因为优化目标是「什么话最可能出现」，从头到尾**没有任何环节在验证事实**——来源就是 3.7 的两条边界（知识分布式存储 + 数据决定上限）。治标的路：给上下文、接检索（RAG）、接工具、要求引用、关键输出加校验，本质都是让它「基于给定材料说话」。

最后一个边界，也是通往 Agent 的钥匙。你对模型说：「帮我查一下线上订单服务的异常指标，定位原因，建个工单，通知负责人。」它能生成查询语句、写出邮件正文——**但它不能真的去查监控、不能发邮件、不能确认操作成功了没有。它只能输出文本。**

LLM 是生成器，不是执行器。缺的不是智能，是与世界的接口。

## 四、Agent：从说话到做事

### 4.1 Tool Call：模型出请求，系统出执行

补上接口的第一块叫工具调用（Tool Call）。机制看一次消息流就懂了：

```
用户：        查一下 order-api 最近 30 分钟的异常指标
模型输出：    tool_calls: { "tool": "query_metrics",
             "arguments": { "service": "order-api", "window": "30m" } }
外部系统：    执行查询，把结果 JSON 拼回上下文
模型输出：    错误率 3.2%、P99 840ms，疑似连接池耗尽，建议……
```

关键结论：**模型只生成那段调用请求（工具名 + 参数的 JSON），执行永远发生在外部系统**——包括鉴权、错误处理、结果回填。「会调用工具」这个能力确实是训练（SFT + 强化学习）教出来的，但执行权从来不在模型手里。对后端同事来说，这就是一个由模型驱动的 RPC。

### 4.2 思维链：把思考外化成生成

直接回答问题，模型只有一次前向计算的机会；先写一步步推导、再给答案，每生成一个 Token 都是一次新的前向——**思考的步数和生成的长度挂钩了**。这就是「思维链」（CoT）和推理模型的原理：训练侧教它怎么想（在推理轨迹上做微调和强化学习），使用侧给它更长的思考预算。提醒一句：更长不等于更对，而且推理消耗大量 Token，成本高、延迟大。

### 4.3 ReAct：环境反馈驱动的循环

只调一次工具还不够——一次性生成无法根据执行结果修正，错了就一路错到底。ReAct 模式把它变成循环：**观察 → 思考（我还需要什么信息）→ 行动（调用工具）→ 新观察 → 继续思考**，直到得出最终回答。

它和多轮对话的区别在驱动力：多轮对话是用户在追问，ReAct 是**环境反馈在推动**——模型在单次任务里自我推进。拿排障举个例子：查指标（观察：错误率高）→ 思考：查日志 → 行动 → 观察：连接池告警 → 思考：定位到根因 → 建工单、通知负责人。

### 4.4 现代 Agent 生态：都在系统层

最近常听到的几个名词，其实都是系统层的扩展，快速带过：

- **MCP（Model Context Protocol）**：工具连接的标准协议。以前 M 个应用接 N 个工具要逐对开发（M×N），有了标准协议变成 M+N——换模型、换工具，协议不变。
- **Skill（技能）**：把「某类任务怎么做」（步骤、约束、模板、异常处理）固化成可复用的知识，替代每次临场发挥——同类任务不再重复犯同样的错。
- **子 Agent**：用循环编排 LLM 本身，把大任务拆给多个小 Agent 协作。

它们的共同点：**都没有改变模型，改变的都是外面的系统。**

### 4.5 Agent 是系统，不是模型

分层看一个真正的 Agent：底层是 LLM（理解与决策）；外面是 Harness（执行循环、状态维护、权限控制、结果校验）；再往外是 Skill 和工作流（稳定的任务知识）、MCP（标准连接）。

所以：**Agent = LLM + 目标 + 状态 + 工具 + 循环。它不是一种新的基础模型**——预测下一个 Token 的机制一点没变，变的是组织方式。以后看到一个 AI 产品「能干活」，先问一句：这能力是模型参数里的，还是外面那层系统给的？

## 五、回到主线

把六步再走一遍，每步一句：

1. **机器学习**：预测 → 误差 → 调整的闭环，机器从数据里找参数——学到的是数字，不是规则；目标是在新数据上依然有效。
2. **深度学习**：非线性 + 多层，特征也自己学——世界的非线性规律和层次结构，都交给了网络。
3. **Transformer**：每个词按内容直接取用上下文；因果掩码让它只看过去——上下文建模交给了注意力。
4. **预训练**：预测下一个 Token，能力是被这个目标逼出来的副产品——任务接口统一成了一句提示词。
5. **后训练**：SFT 教形式、偏好教倾向——能力和行为是两回事；我用 LoRA 实验亲手验证过。
6. **生成与 Agent**：参数冻结，一次一个 Token 循环；模型决定、系统执行——行动选择也交给了机器。

再压缩一层：**人把东西一样样交给机器——规则、参数、特征、表示、任务适配、行动。**

最后送你一个框架。以后看到任何 AI 新概念、新模型、新产品，先别记缩写，问五个问题：

1. 它改的是**模型结构、训练方式、生成过程，还是外部系统**？
2. 它用了**什么数据或反馈信号**？
3. 它实际在**优化什么目标**？
4. 这个能力来自**模型参数，还是工具和工作流**？
5. 它**什么条件下有效，不能保证什么**？

能把这五个问题问出来，这篇材料的地图你就带走了。

一句话收场：**今天的大模型，底层仍然在预测下一个 Token——真正让人惊讶的不是这个目标多简单，而是当结构、数据和规模足够大之后，为了持续做好这件小事，机器长出了我们称之为「智能」的行为。**
