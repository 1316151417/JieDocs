## 一、分享目标

### 1. 听众画像

听众是业务后端开发工程师和技术管理者：

- 有软件工程、接口、数据和系统设计经验；
- 使用过很多 AI 工具；
- 没有系统学习过机器学习、深度学习和 LLM 底层知识；
- 不要求掌握高等数学或真实的大模型训练工程。

### 2. 分享目标

这不是机器学习课程，也不是大模型训练实战。

分享要帮助听众建立一张稳定的认知地图：

```text
机器如何从数据中学习参数
→ 神经网络如何学习复杂表示
→ Transformer 如何建立上下文关系
→ Decoder-only 模型如何预测下一个 Token
→ 现代 LLM 如何预训练、后训练和生成
→ Harness 如何把模型组织成可行动的 AI 系统
```

听众不需要记住所有名词，但应该大致理解：

1. LLM 的能力建立在什么基础上；
2. 一个现代 LLM 从文本输入到 Token 输出经历了什么；
3. 预训练、监督微调、偏好对齐分别改变了什么；
4. 模型本身与 Agent/Harness 系统的边界；
5. 面对新的 AI 概念时，能够判断它改变的是模型结构、训练方式、生成过程，还是外部系统。

### 3. 分享不追求什么

- 不追求覆盖完整的机器学习知识体系；
- 不真实训练或微调大模型；
- 不推导 Attention、反向传播或 PPO 的数学公式；
- 不追逐快速迭代的模型优化清单；
- 不深入思维链、推理模型和 Test-time Compute；
- 不把 Agent 工程作为正式主线。

## 二、整场分享的叙事结构

整场分享分成前后两段。

### 第一段：现代 LLM 从哪里来

```text
机器学习
→ 深度学习
→ RNN
→ Transformer
```

这一段回答：为什么需要 Transformer，以及理解 LLM 必须具备哪些最小前置知识。

### 第二段：一个现代 LLM 如何诞生并工作

```text
文本与 Token
→ LLaMA-style Decoder-only Transformer
→ 下一个 Token 预训练
→ SFT 与 InstructGPT
→ 模型生成（Inference）
→ Harness/Agent 简介
```

这一段回答：一个现代 LLM 的数据如何进入、能力如何形成、行为如何被塑造、结果如何生成。

### 必须强调的层级关系

这些概念不处于同一个抽象层次，也不是六代互相替代的技术：

| 概念 | 定位 |
|---|---|
| 机器学习 | 从数据中学习参数的方法体系 |
| 深度学习 | 使用多层神经网络学习表示的学习范式 |
| Transformer | 一种神经网络架构 |
| GPT/LLaMA | Decoder-only Transformer 与自回归预训练路线 |
| 预训练、SFT、RLHF | 塑造模型能力与行为的训练阶段 |
| Inference | 使用固定参数逐 Token 生成的运行过程 |
| Harness/Agent | 模型外部的上下文、工具、状态和控制系统 |

## 四、各模块的复习边界

### 1. 机器学习：建立最小训练闭环

#### 必须讲清

- 样本、特征、标签、模型和参数；
- 使用单参数线性回归 `价格 = w × 面积`；
- 预测、损失、调整参数、再次预测；
- 训练集表现好不等于真实使用效果好；
- 泛化才是机器学习真正的目标。

#### 数学边界

这是整场唯一允许稍微展开数学的部分。

只保留：

- 一元线性模型；
- 一个直观误差；
- 参数沿着误差减小方向调整的概念。

不推导梯度、偏导数和优化算法。

#### 不要误解为

> 机器学习从数据中调整参数，不等于机器发现了唯一正确或具有因果性的规则。

#### 连接下一章

> 房屋面积是人提前选好的特征。面对图片、语音和文本时，什么才是有效特征？能否把特征设计也交给模型？

---

### 2. 深度学习：从线性关系到组合表示

#### 必须讲清

- 多层纯线性变换仍然等价于一次线性变换；
- 激活函数使网络能够表达非线性关系；
- 隐藏层逐级组合简单表示；
- 深度学习减少了对人工特征设计的依赖；
- CNN 只作为“利用空间结构”的一个例子，一笔带过。

#### TensorFlow Playground 演示

总时长控制在 5～6 分钟，连续完成两个画面。

##### 演示一：圆形分布

目的：

```text
线性模型失败
→ 加入激活函数和隐藏层
→ 网络能够组合出非线性决策边界
```

##### 演示二：螺旋分布

目的：

```text
简单边界逐层组合
→ 形成更复杂的决策边界
→ 但表达能力增强不代表一定容易训练
```

##### 演示准备要求

- 提前保存两个固定配置；
- 正式分享前完整操作三遍；
- 只改变预先设计好的少数变量；
- 准备演示前、演示后的截图；
- 准备一段离线录屏，作为网络或页面失效时的备用方案；
- PPT 中明确记录演示结论，不能只依赖现场口述。

#### 不要误解为

> 深层网络能够通过多级组合表达某些复杂关系，但不代表层数越多越好，也不保证训练一定成功。

#### 连接下一章

> 深度网络能够学习表示，但文本还有一个特殊问题：前后位置存在顺序和上下文依赖。

---

### 3. RNN：作为 Transformer 的前置桥梁

#### 必须讲清

- 当前输入与历史状态共同生成新状态；
- 信息沿序列逐步传递；
- 距离越远，信息需要经过的路径越长；
- 各位置需要顺序计算，难以充分并行。

#### 明确弱化

- 不讲 BPTT；
- 不讲梯度消失的数学；
- 不讲 LSTM、GRU 的门结构；
- 不把 RNN 讲成完整独立章节。

#### 不要误解为

> Transformer 的出现不代表 RNN 完全无用；这里比较的是处理长序列时的信息路径和并行方式。

#### 连接下一章

> 一个 Token 能否不经过逐步传递，直接根据内容与其他位置建立联系？

---

### 4. Transformer：整场最重要的结构转折

#### 必须讲清

1. Attention：根据当前内容动态决定关注和汇总哪些信息；
2. Self-Attention：Q、K、V 来自同一序列；
3. Q、K、V：寻找什么、提供什么匹配线索、实际汇总什么内容；
4. 多头注意力：允许模型在不同表示子空间中建立多种关系；
5. 位置信息：Attention 本身不会自动获得顺序；
6. Causal Mask：当前 Token 不能看到未来 Token；
7. Decoder Block：Attention、前馈网络、残差连接和归一化共同组成重复模块。

#### 架构取舍

- Encoder-only：一句话说明侧重输入理解；
- Encoder–Decoder：一句话说明输入与输出分别处理；
- Decoder-only：正式主角，重点讲 Causal Attention 与自回归生成。

#### 数学边界

- 不推导 `softmax(QKᵀ/√d)V`；
- 可以把公式放在附录，但主讲只使用信息流图；
- 不讲矩阵维度和复杂度推导。

#### 不要误解为

> Attention 建立了内容相关的信息连接，但 Attention 权重不等同于模型完整、可靠、可解释的思考过程。

#### 连接下一章

> Decoder-only Transformer 规定了信息怎样流动，但文本怎样进入模型，模型又怎样输出下一个 Token？

---

### 5. LLaMA-style 现代 LLM：从 Token 到 Logits

#### 讲解目标

不绑定某个具体 LLaMA 版本，而是讲稳定的 Decoder-only 共同骨架。

#### 必须讲清的数据流

```text
文本
→ Tokenizer
→ Token ID
→ Embedding
→ 多个 Decoder Block
→ Logits
→ 候选 Token 概率
→ 选择下一个 Token
```

#### 架构图需要包含

```text
Token
→ Embedding
→ N × Decoder Block
   ├─ RMSNorm
   ├─ RoPE + Causal Self-Attention（常见实现可使用 GQA）
   ├─ Residual
   ├─ RMSNorm
   ├─ SwiGLU FFN
   └─ Residual
→ LM Head
→ Logits
```

#### 讲解深度

RMSNorm、RoPE、GQA、SwiGLU 只回答：

1. 它位于哪里；
2. 它大致解决什么问题；
3. 为什么它不改变 Decoder-only 的总体主线。

不比较不同版本，不推导实现，不展开工程优化。

#### 不要误解为

> LLaMA-style 是一组稳定的现代 Decoder-only 设计选择，不代表所有 LLM 的内部结构完全相同。

#### 连接下一章

> 结构只定义模型能够怎样计算。参数怎样从随机状态变成具有语言能力的模型？

---

### 6. 预训练：能力如何形成

#### 必须讲清

- 在大规模文本上预测下一个 Token；
- 训练标签可以直接由文本右移得到；
- 预测错误产生损失，损失用于更新模型参数；
- 为了更准确地预测后续文本，模型需要学习语法、语义、上下文、知识和大量文本模式；
- Scaling 的定位是扩大数据、模型和计算，而不是一个独立的智能机制。

#### 极简伪代码

```python
tokens = tokenize(text)
prediction = model(tokens[:-1])
loss = compare(prediction, tokens[1:])
update_parameters(loss)
```

#### 必须保留的边界

- 预测下一个 Token 是训练目标，不是对模型全部内部能力的完整描述；
- 模型可能压缩并重组训练数据中的规律，但不是精确数据库；
- 参数中包含统计性知识，不保证事实始终正确；
- 更大的模型通常具有更强能力，但规模不是质量、安全和可靠性的充分条件。

#### 不要误解为

> 预测下一个 Token 能促使模型学习广泛规律，但不等于模型在查询一个准确、实时、有来源保证的知识库。

#### 连接下一章

> 预训练模型擅长续写可能出现的文本，但用户需要的是理解指令并给出符合意图的回答。

---

### 7. SFT 与 InstructGPT：从基础模型到助手

#### SFT 必须讲清

- 数据形式是“用户指令 + 理想回答”；
- 模型继续使用语言建模目标学习理想回答；
- 它主要教会模型以任务和对话形式组织已有能力；
- SFT 可以补充知识，但不是大模型知识的主要来源。

#### InstructGPT 的经典三阶段

```text
人工示范
→ 监督微调 SFT

同一提示的多个候选回答 + 人工排序
→ 训练奖励模型 RM

奖励模型给回答打分
→ 使用 PPO 进一步优化模型行为
```

#### 讲解深度

每个阶段只回答：

1. 使用什么数据；
2. 模型输入和输出是什么；
3. 优化目标是什么；
4. 模型行为发生什么变化。

不推导奖励模型损失和 PPO。

#### 历史定位

InstructGPT 是经典 RLHF 教学案例，不应讲成所有现代 LLM 唯一、固定的后训练配方。

稳定的核心问题是：

> 如何使用示范和偏好数据，使基础模型更符合用户意图。

原始参考：[Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)

#### 不要误解为

> 后训练主要塑造模型如何表现和调用已有能力，不代表用少量指令数据重新获得了全部知识和能力。

#### 连接下一章

> 训练完成后，模型参数被固定。用户输入一段文本时，模型怎样一步步生成最终回答？

### 8. 模型如何生成：Inference

#### 术语要求

PPT 中统一写作：

- 模型生成或模型推理（Inference）；
- 推理能力（Reasoning）。

本次只正式讲 Inference。Reasoning、思维链和推理模型只在 QA 附录中做一句定位。

#### 必须讲清

- Inference 不更新模型参数；
- 模型读取当前上下文，并使用最后一个位置的 Logits 预测下一个 Token；
- 系统根据概率和解码策略选择下一个 Token；
- 新 Token 被追加到上下文，再次调用模型；
- 循环直到停止条件满足；
- Temperature、Top-p 等只影响选择方式，不改变模型已经学到的参数。

#### 极简伪代码

```python
while not finished:
    logits = model(context)
    next_token = sample(logits)
    context.append(next_token)
```

#### 不要误解为

> 生成过程可以表现出多步问题求解能力，但逐 Token 生成机制本身不保证推理正确，也不保证事实可靠。

#### 连接下一章

> 模型只能根据上下文生成 Token。要查询实时数据、调用接口和检查执行结果，还需要模型之外的运行系统。

---

### 9. Harness/Agent：三分钟尾声

#### 只使用一张统一图

```text
LLM
└── Harness：组织上下文、状态、权限、工具和执行循环
    ├── ReAct：观察—判断—行动—反馈的循环模式
    ├── Skill：某类任务的可复用执行知识
    └── MCP：连接外部工具与数据源的标准协议
```

#### 必须讲清

- LLM 负责理解上下文并生成 Token 或结构化调用；
- 外部系统负责真正执行工具、保存状态、控制权限和检查结果；
- ReAct、Skill、MCP 不与 LLM 架构处于同一层。

#### 明确弱化

- 不做 Tool Call 工程演示；
- 不展开工作流编排；
- 不深入记忆、规划、多 Agent 和权限设计；
- 不把 Harness 当成新的基础模型。

#### 不要误解为

> Agent/Harness 能把 LLM 组织成可行动的系统，但它没有改变 LLM 预测 Token 的底层机制。

## 五、费曼复习法：每次两小时的固定流程

每次复习都必须先输出、再补知识。禁止一开始就从头阅读资料。

### 0～15 分钟：闭卷复述

不看资料，写下：

```markdown
它解决什么问题？
上一阶段为什么不够？
核心信息流是什么？
训练或运行目标是什么？
它带来了什么能力？
它不能保证什么？
为什么会进入下一阶段？
```

### 15～50 分钟：定向查缺

只查刚才不能准确回答的内容。

每个缺口必须记录为一个明确问题，例如：

- Causal Mask 为什么能防止训练时偷看答案？
- Tokenizer 与模型参数是什么关系？
- SFT 和预训练是否使用完全不同的损失？
- Inference 为什么不更新参数？

禁止使用“再看一遍 Transformer”这类模糊任务。

### 50～80 分钟：制作分享产出

每次至少完成一种可复用产出：

- 一张核心图；
- 一页 PPT；
- 一段 30 秒或 3 分钟讲解；
- 一个示例；
- 一条“不要误解为”；
- 一组 QA 回答。

### 80～105 分钟：口头讲解

不看逐字稿，用自己的话讲一次。

至少完成两个版本：

- 30 秒结论版；
- 3～5 分钟机制版。

### 105～115 分钟：反例与边界

回答：

1. 这段话最容易让听众误解什么？
2. 哪个结论被我说得过于绝对？
3. 如果听众追问“为什么”，我还能再解释一层吗？
4. 哪些内容应该放进 QA，而不是主讲？

### 115～120 分钟：记录复盘

只记录三类问题：

- 不准确；
- 讲不清；
- 超时或冗余。

## 六、三周、十二次复习安排

### 第一周：尽早建立完整骨架

第一周结束时，必须已经能够闭卷讲出 15 分钟主线。不能等所有细节复习完成后才第一次串讲。

#### 第 1 次：基线测试与 60 分钟目录

任务：

- 闭卷写出现有理解；
- 用 15 分钟尝试串讲全部主线；
- 标记讲不出来、跳跃和过度展开的位置；
- 固定 60 分钟时间表；

## 七、Markdown 与 PPT 的协作方式

### 1. Markdown 是内容母版

Markdown 保存完整信息：

- 为什么讲这一部分；
- 准确的知识解释；
- 案例和类比；
- 图示说明；
- 讲者提示；
- 边界和易错点；
- 素材来源；
- QA 备用回答；
- 被删掉但仍值得保留的内容。

推荐每一页 PPT 在 Markdown 中使用以下模板：

```markdown
## 第 N 页：标题

核心结论：

听众此时已经知道：

这一页要解决的问题：

图或案例：

讲者提示词：

不要误解为：

连接下一页：

预计时间：

来源：
```

### 2. PPT 是现场表达层

- 预计 30～35 页；
- 一页只承担一个判断或一次信息流变化；
- 避免复制 Markdown 长段落；
- 关键图尽量统一视觉语言；
- 正文只放现场需要的信息；
- 细节、公式、额外名词和来源说明放讲者备注或附录。

### 3. 推荐的 PPT 页级骨架

```text
1. 标题
2. 为什么要理解 LLM
3. 全局主线
4～6. 机器学习最小闭环
7～9. 深度学习与 Playground
10. CNN 一句话、RNN 登场
11～12. RNN 的信息传递与限制
13～17. Attention、QKV、位置与 Causal Mask
18. 三种 Transformer 架构定位
19～20. Decoder Block 与 LLaMA-style 架构
21～22. Token 到 Logits 的完整数据流
23～25. 下一个 Token 预训练
26. 为什么简单目标形成广泛能力
27～30. SFT 与 InstructGPT
31～32. Inference 生成循环
33. LLM 与 Harness 分层
34. 全场总结
35. QA
```

## 九、核心问题库

### 机器学习与深度学习

- 参数、特征和模型分别是什么？
- 损失函数和优化过程分别负责什么？
- 训练误差低为什么不代表泛化好？
- 多层纯线性网络为什么仍然是线性的？
- 激活函数增加了什么？
- 深度为什么增加组合表达能力，却不保证训练成功？

### Transformer 与现代架构

- RNN 如何传递上下文？它的路径问题是什么？
- Attention 改变了什么？
- Q、K、V 为什么需要承担不同角色？
- Attention 为什么仍然需要位置信息？
- Causal Mask 为什么是 Decoder-only 预训练的关键？
- Decoder-only 与 Encoder-only、Encoder–Decoder 的差别是什么？
- Tokenizer、Embedding、Decoder Block、LM Head 分别做什么？
- Logits 与下一个 Token 的关系是什么？

### 预训练与后训练

- 为什么下一个 Token 标签不需要人工标注？
- 预测下一个 Token 为什么可能形成广泛能力？
- 预训练和 SFT 使用的数据有什么不同？
- SFT 是否主要负责增加知识？
- 奖励模型如何从人工排序中学习偏好？
- InstructGPT 的 PPO 阶段在概念上优化什么？
- 为什么 InstructGPT 只是经典案例，而不是唯一现代配方？

### Inference 与 Harness

- 训练与 Inference 的根本区别是什么？
- 为什么生成下一个 Token 后还要把它重新加入上下文？
- Temperature 改变了什么，没有改变什么？
- Inference 与 Reasoning 为什么不能混用？
- LLM、ReAct、Skill、MCP、Harness 分别处于哪一层？
- 为什么模型生成了工具参数，不等于它已经执行了工具？
