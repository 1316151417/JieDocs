## 二、整场分享只回答一个问题

> 一个只能按照规则运行的程序，如何一步步变成能够从海量文本中学习，并根据上下文持续生成内容的现代大语言模型？

整条主线：

```text
机器学习：从数据中调整参数
    ↓
深度学习：同时学习参数和中间表示
    ↓
RNN：让历史信息沿序列传递
    ↓
Transformer：让 Token 动态建立上下文关系
    ↓
Decoder-only LLM：用因果注意力预测下一个 Token
    ↓
预训练：从海量文本中获得基础能力
    ↓
后训练：学会按照指令和人类偏好表现能力
    ↓
Inference：在参数不变的情况下逐 Token 生成
    ↓
Harness：在模型外组织上下文、工具和执行循环
```

需要在开头说明：

- 这不是六代互相替代的技术；
- 它们处于不同抽象层次；
- 这条线是为了讲清能力形成过程，而不是完整复述 AI 技术史。

## 四、贯穿案例占位符

后半场尽量复用同一个案例，但当前不强行确定具体内容。

### 案例需要满足

- 听众不需要额外学习业务背景；
- 能自然包含上下文关系；
- 能展示“文本续写”和“按指令回答”的区别；
- 能产生两个可供人类比较的候选回答；
- 能在结尾自然延伸到外部工具或 Harness；
- 不暗示模型能够可靠地完成它未实际验证的事情。

### 待填案例模板

```text
原始文本：____________________________

上下文歧义或依赖：____________________

用户指令：____________________________

候选回答 A：__________________________

候选回答 B：__________________________

如果接入工具，需要执行：______________
```

案例将在以下位置复用：

1. Tokenization：文本如何被切成 Token；
2. Attention：当前 Token 需要从前文寻找什么；
3. 预训练：如何构造“预测下一个 Token”的样本；
4. SFT：如何构造“指令＋理想回答”；
5. InstructGPT：如何比较两个候选回答；
6. Inference：模型如何逐 Token 生成最终答案；
7. Harness：模型之外还需要哪些真实操作。

# 五、PPT 页级骨架

## 第一部分：开场与全局地图（0～3 分钟）

### 第 1 页：标题

**标题：** 从机器学习到现代 LLM：大模型如何学习与生成

**副标题：** 一条从参数学习、上下文建模到指令跟随的认知主线

**讲者提示词：**

- 不是使用技巧分享；
- 不是模型新闻盘点；
- 目标是理解今天使用的 AI 工具背后最小原理。

---

### 第 2 页：我们每天使用的 AI，底层到底发生了什么？

**核心问题：**

```text
输入一段文本
→ 模型为什么能够理解上下文？
→ 它从哪里获得知识和能力？
→ 为什么会按照我们的指令回答？
→ 回答又是怎样一个 Token 一个 Token 生成的？
```

**建议画面：** 一个熟悉的 AI 对话界面，向下展开为“模型结构—训练—生成—外部系统”。

**转场：** 先从机器学习最小闭环开始，因为 LLM 仍然是一种通过数据调整参数的机器学习模型。

---

### 第 3 页：全局认知地图

**核心图：**

```text
学习参数
→ 学习中间表示
→ 建立上下文关系
→ 预测下一个 Token
→ 大规模预训练
→ 按人类意图表现能力
→ 逐 Token 生成
```

**必须说明：** 这是理解能力来源的讲述顺序，不是几个互相替代的产品版本。

---

## 第二部分：机器学习的最小闭环（3～8 分钟）

### 第 4 页：传统程序与机器学习

**一句话结论：** 传统程序由人写规则；机器学习由人给出模型、数据和目标，再让机器寻找参数。

**核心对比：**

```text
传统程序：规则 + 输入 → 输出

机器学习：数据 + 正确答案 → 找到模型参数
          输入 + 学到的参数 → 预测
```

**不要误解为：** 机器学习不是“机器自己发现一切”，人仍然决定数据、模型形式和优化目标。

---

### 第 5 页：单参数线性回归

**统一案例：**

```text
输入：房屋面积 x
输出：房屋价格 y
模型：ŷ = wx
```

**只保留一个参数：** `w`

**讲述顺序：**

1. 先给 `w` 一个值；
2. 用它进行预测；
3. 将预测与真实价格比较；
4. 根据误差调整 `w`；
5. 重复，直到损失下降。

**建议画面：** 散点图、当前直线、误差线段、参数调整箭头。

---

### 第 6 页：训练的真正目标是泛化

**一句话结论：** 训练不是为了记住训练数据，而是为了在未见过的数据上仍然有效。

**核心链路：**

```text
样本
→ 预测
→ 损失函数衡量差距
→ 优化算法调整参数
→ 在新数据上检验泛化
```

**不要误解为：** 训练损失越低，不代表真实使用效果一定越好。

**转场问题：** 房屋面积是人提前选择的特征；面对图片和文本，所有有效特征还能由人手工设计吗？

---

## 第三部分：深度学习与 Playground 演示（8～16 分钟）

### 第 7 页：线性模型为什么不够？

**一句话结论：** 单一线性边界只能表达有限形式的关系。

**建议画面：** 圆形分类数据，叠加一条无法正确分类的直线。

**讲述重点：**

- 多个纯线性层叠加仍然等价于一次线性变换；
- 激活函数引入非线性；
- 隐藏层可以组合出更复杂的中间表示。

---

### 第 8 页：TensorFlow Playground 现场演示

**总时长：** 5～6 分钟，不再单独增加其他深度学习演示。

#### 演示 A：圆形分布

```text
没有隐藏层
→ 只能形成线性边界
→ 无法分开圆形数据

加入隐藏层和激活函数
→ 多个简单边界被组合
→ 形成非线性决策区域
```

**本段结论：** 激活函数和隐藏层使网络能够表达非线性关系。

#### 演示 B：螺旋分布

```text
增加适当的网络深度和容量
→ 简单边界经过多级组合
→ 可以表达更加复杂的规则
```

**本段结论：** 深度增加组合表达能力，但表达得出来不代表一定训练得出来。

**现场约束：**

- 使用提前配置好的固定页面；
- 只改变预先确定的一两个设置；
- 不临时展示学习率、正则化等旁支；
- PPT 中准备两个结果截图作为离线备份。

---

### 第 9 页：深度学习学习的是中间表示

**一句话结论：** 深度学习不只寻找最终预测参数，还逐层把原始输入转换成更适合任务的表示。

**核心图：**

```text
原始输入
→ 简单模式
→ 模式组合
→ 抽象表示
→ 任务输出
```

**CNN 一句话定位：** CNN 利用局部连接和参数共享，把图像的空间结构加入网络；它是深度学习的典型架构，但不是本次 LLM 主线。

**不要误解为：** 网络更深，不等于效果必然更好；表达能力、数据和训练优化是不同问题。

**转场问题：** 图像具有空间结构，文本则具有顺序和上下文；模型怎样保存前文信息？

---

## 第四部分：从 RNN 到 Transformer（16～32 分钟）

### 第 10 页：RNN 如何处理序列

**一句话结论：** RNN 用一个随序列不断更新的隐藏状态，压缩此前的信息。

**核心图：**

```text
当前 Token + 上一步状态
          ↓
       新的状态
          ↓
     传给下一位置
```

**讲者提示词：** 顺序、历史状态、共享参数、逐步更新。

---

### 第 11 页：RNN 的结构限制

**核心图：**

```text
A → B → C → D → E
```

**需要讲清：**

- 远距离信息必须经过多个步骤传递；
- 每一步依赖上一步，难以在序列维度充分并行；
- 历史信息被压缩在有限状态中。

**不要误解为：** RNN 完全不能处理长序列；问题是信息路径和训练效率受到结构限制。

**转场问题：** 一个 Token 能否跳过逐步传递，直接寻找当前最相关的上下文？

---

### 第 12 页：Attention 改变了信息交互方式

**一句话结论：** Attention 让当前位置根据内容，动态选择并汇总其他位置的信息。

**核心对比：**

```text
RNN：沿固定顺序传递

Attention：根据当前内容动态建立连接
```

**使用贯穿案例：** 标出当前 Token 需要参考的前文位置。

---

### 第 13 页：为什么同一个词需要不同表示

**临时示例：**

```text
银行旁边有一条河。
我去银行取了钱。
```

**一句话结论：** Token 的初始表示相近，但经过上下文交互后，应形成不同的上下文表示。

**注意：** 该示例可在确定贯穿案例后替换。

---

### 第 14 页：Q、K、V 的直觉

**口语化解释：**

- Q：当前位置想找什么信息；
- K：每个位置提供什么匹配线索；
- V：匹配之后真正被汇总的内容。

**信息流：**

```text
当前 Token 产生 Q
→ 与所有可见 Token 的 K 计算匹配
→ 得到注意力权重
→ 按权重汇总 V
→ 得到上下文相关表示
```

**不讲：** 矩阵维度、缩放点积推导、反向传播。

**不要误解为：** Q、K、V 不是人工写好的问题、关键词和答案，而是训练得到的向量表示。

---

### 第 15 页：为什么需要多头注意力和位置信息

**多头注意力一句话：** 允许模型在不同表示子空间中同时学习多种关系。

**位置信息一句话：** Attention 本身不会仅凭 Token 集合知道顺序，需要向表示中加入位置信息。

**LLaMA-style 定位：** 使用 RoPE 是一种现代位置编码选择；只讲目的，不展开数学实现。

**不要误解为：** 每个注意力头都能稳定对应一个人类可命名的语法或语义功能。

---

### 第 16 页：Causal Mask 是走向 GPT/LLaMA 的关键桥梁

**一句话结论：** 第 `t` 个位置只能看到自己及之前的 Token，不能偷看后面的正确答案。

**建议画面：** 一个下三角可见区域。

```text
Token 1：只能看 1
Token 2：可以看 1、2
Token 3：可以看 1、2、3
……
```

**因果链：**

```text
不能看到未来 Token
→ 可以训练预测下一个 Token
→ 推理时可以从左到右持续生成
```

---

### 第 17 页：一个 Transformer Decoder Block

**稳定骨架：**

```text
输入表示
→ Norm
→ Causal Self-Attention
→ 残差连接
→ Norm
→ Feed-Forward Network
→ 残差连接
```

**只讲职责：**

- Attention：让 Token 交换上下文信息；
- FFN：对每个位置的表示进行进一步变换；
- 残差连接：保留并叠加信息；
- Norm：帮助训练保持稳定。

---

### 第 18 页：三类 Transformer 架构只做定位

| 类型 | 主要用途直觉 | 本次定位 |
|---|---|---|
| Encoder-only | 读取并表示完整输入 | 一句话带过 |
| Encoder–Decoder | 分开处理输入和输出 | 一句话带过 |
| Decoder-only | 根据已有上下文持续生成 | 重点 |

**本段核心结论：** LLaMA-style LLM 采用 Decoder-only Transformer，并使用 Causal Attention 进行自回归生成。

---

## 第五部分：现代 LLM 的稳定结构（32～38 分钟）

### 第 19 页：文本如何进入模型

**完整入口：**

```text
字符串
→ Tokenizer
→ Token ID
→ Embedding
→ 向量序列
```

**需要讲清：**

- 模型直接处理的不是汉字、单词或字符串，而是 Token ID 对应的向量；
- Token 不总等于一个汉字或一个英文单词；
- Tokenizer 决定文本与模型内部离散符号之间的映射。

**不讲：** BPE、SentencePiece 的完整训练算法。

---

### 第 20 页：LLaMA-style Decoder-only Transformer

**核心总图：**

```text
Token IDs
→ Embedding
→ 多个 Decoder Blocks
   ├─ RMSNorm
   ├─ RoPE + Causal Self-Attention / GQA
   ├─ Residual
   ├─ RMSNorm
   ├─ SwiGLU FFN
   └─ Residual
→ 输出层
→ Logits
```

**讲述原则：**

- Decoder-only 是主干；
- RMSNorm、RoPE、GQA、SwiGLU 只说明“位于哪里、解决什么问题”；
- 不比较具体版本，不追逐快速迭代的工程优化。

**不要误解为：** 现代 LLM 与 GPT 使用了完全不同的基础原理；它仍然建立在 Decoder-only Transformer 和自回归语言建模之上。

---

### 第 21 页：Logits 怎样变成下一个 Token

**信息流：**

```text
最后一个位置的表示
→ 输出层
→ 为词表中的每个 Token 产生一个 Logit
→ 转换成概率分布
→ 按生成策略选择下一个 Token
```

**需要定位的概念：**

- Logit：模型对每个候选 Token 给出的未归一化分数；
- Softmax：将分数变成概率分布；
- Sampling：根据概率和生成参数选择下一个 Token。

**不要展开：** Temperature、Top-k、Top-p 的公式；可放到 QA。

**转场问题：** 这些结构一开始只是随机参数，它怎样获得语言、知识和任务能力？

---

## 第六部分：预训练（38～45 分钟）

### 第 22 页：下一个 Token 预训练

**一句话结论：** 给定前文预测下一个 Token，并利用预测误差不断更新模型参数。

**极简伪代码：**

```python
tokens = tokenize(text)
prediction = model(tokens[:-1])
loss = compare(prediction, tokens[1:])
update_parameters(loss)
```

**需要强调：**

- 一段文本可以同时产生许多训练位置；
- 训练阶段会计算损失并更新参数；
- 训练目标始终简单，但要做好它需要学习大量中间规律。

---

### 第 23 页：为什么预测下一个 Token 能学到广泛能力

**因果解释：**

为了更准确地预测后文，模型需要逐渐利用：

- 词语与语法关系；
- 上下文语义；
- 文本结构和写作模式；
- 训练数据中呈现的事实关联；
- 部分任务模式和问题解决轨迹。

**推荐表述：** 预测下一个 Token 是统一训练目标；语言、知识和部分能力，是在优化这一目标的过程中形成的内部表示与行为。

**不要误解为：** 模型在参数中保存了一个能够精确查询和逐条溯源的知识数据库。

---

### 第 24 页：规模为什么重要，但不是全部

**一句话结论：** 更多参数、数据和计算可以扩大模型学习复杂规律的机会，但模型质量还依赖数据、训练方法和评估。

**只做定位：**

```text
模型容量
+ 数据规模与质量
+ 训练计算
→ 更强的基础模型能力
```

**不要误解为：** 参数更多就必然在所有任务上更好，也不代表输出一定真实可靠。

**转场问题：** 一个擅长预测互联网文本后续内容的基础模型，为什么会知道要服从用户的指令？

---

## 第七部分：从基础模型到助手（45～53 分钟）

### 第 25 页：预训练模型不天然等于聊天助手

**核心对比：**

```text
预训练目标：生成在统计上合理的后续文本

用户目标：理解任务、遵守要求、给出清晰且有帮助的回答
```

**一句话结论：** 基础能力主要来自预训练，但行为方式还需要后训练进一步塑造。

---

### 第 26 页：监督微调（SFT）

**数据形式：**

```text
用户指令
+ 理想回答
→ 监督训练样本
```

**需要讲清：**

- 数据是什么：任务描述、输入和理想回答；
- 目标是什么：继续做 Token 预测，但只是在高质量指令回答数据上训练；
- 行为如何变化：模型更容易以助手方式组织和输出已有能力。

**不要误解为：** SFT 是模型知识和全部能力的主要来源。

---

### 第 27 页：经典 InstructGPT 三阶段流程

**核心图：**

```text
阶段 1：人工示范
用户指令 + 人类理想回答
→ 训练 SFT 模型

阶段 2：人工偏好
同一指令 + 多个模型回答 + 人工排序
→ 训练奖励模型

阶段 3：强化学习
奖励模型评价新回答
→ 使用 PPO 调整模型行为
```

**讲解深度：**

- 讲数据输入；
- 讲每一步的训练目标；
- 讲行为变化；
- 不推导 PPO，不讲超参数和分布式工程。

**案例复用：** 使用贯穿案例展示一条指令、两个候选回答和人工排序理由。

---

### 第 28 页：InstructGPT 的定位与边界

**一句话结论：** InstructGPT 是经典的 RLHF 后训练案例，不是所有现代 LLM 的唯一固定配方。

**需要说明：**

- 后续方法可能改变偏好数据、奖励建模和优化方式；
- 稳定问题仍然是：如何让模型行为更符合用户意图和人类偏好；
- 后训练主要引导和释放已有能力，不应被描述成重新完成一次同规模预训练。

**不要误解为：** 人类偏好可以保证模型永远正确、安全或符合每个用户的价值判断。

---

## 第八部分：模型如何生成（Inference）（53～57 分钟）

### 第 29 页：训练与 Inference 是两个阶段

| 维度 | 训练 | Inference |
|---|---|---|
| 输入 | 大量训练样本 | 当前上下文 |
| 是否计算损失 | 是 | 否 |
| 是否更新参数 | 是 | 否 |
| 主要结果 | 得到模型参数 | 生成下一个 Token |

**术语约束：**

- 本章统一使用“模型生成（Inference）”；
- Reasoning 指多步问题求解，不在本次正文展开；
- 强化学习是增强部分推理行为的重要路线之一，但 Reasoning 不等同于强化学习。

---

### 第 30 页：逐 Token 生成循环

**极简伪代码：**

```python
while not finished:
    logits = model(context)
    next_token = sample(logits)
    context.append(next_token)
```

**完整循环：**

```text
当前上下文
→ 模型前向计算
→ 下一个 Token 概率
→ 选择 Token
→ 加回上下文
→ 再次运行模型
```

**需要讲清：**

- 一次前向计算只决定下一个 Token；
- 整段回答由重复循环形成；
- 推理时模型参数通常不更新；
- Streaming 只是将已经生成的 Token 逐步返回给用户，不增加模型能力。

**不要误解为：** 模型先在内部写好完整答案，再把它逐字显示出来。

---

## 第九部分：Harness 尾声与总结（57～60 分钟）

### 第 31 页：从 LLM 到 AI 应用系统

**一句话结论：** LLM 负责理解上下文并生成 Token；Harness 在模型外组织上下文、状态、权限、工具和执行循环。

**总览图：**

```text
LLM
└── 根据上下文生成文本或结构化调用

Harness
├── 组织上下文与状态
├── 控制模型和工具的执行循环
├── 处理权限、失败与结果校验
├── ReAct：观察—思考—行动—反馈的循环模式
├── Skill：可复用的任务执行知识
└── MCP：连接外部工具和数据源的协议
```

**不要误解为：** Agent 或 Harness 是一种新的基础模型架构。

**讲解限制：** 本页只做概念定位，不展开具体框架和工程实现。

---

### 第 32 页：回到整条主线

**最终总结图：**

```text
机器学习
学会根据误差调整参数

深度学习
学会形成中间表示

Transformer
让 Token 动态汇总上下文

Decoder-only LLM
用因果注意力预测下一个 Token

预训练
从海量文本中形成基础能力

SFT / RLHF
让能力更符合任务形式和人类偏好

Inference
参数不变，逐 Token 生成回答

Harness
把模型组织进能够调用外部能力的系统
```

**收尾句：**

> 今天的大语言模型底层仍然在预测下一个 Token；真正的变化，是模型通过规模化训练学会了越来越丰富的内部表示，再通过后训练和外部系统，被组织成我们每天使用的 AI 产品。

# 七、QA 附录页建议

正文不展开，只有听众追问时再使用。

## A1：回归、分类与生成的关系

- 回归：预测连续值；
- 分类：预测有限类别的概率；
- 语言模型：对词表中所有候选 Token 做大规模分类。

## A2：Attention 公式

仅用于回答希望进一步了解数学结构的听众：

```text
Attention(Q, K, V) = softmax(QKᵀ / √d) V
```

正文不推导。

## A3：为什么位置编码不可缺少

- Attention 本身主要依据内容匹配；
- 没有位置信息，模型无法仅凭 Token 集合区分不同排列；
- RoPE 是现代 Decoder-only LLM 中常见的位置处理方式之一。

## A4：KV Cache

- 生成新 Token 时复用此前 Token 的 K、V；
- 避免每一步重新计算全部历史位置的 K、V；
- 属于 Inference 效率优化，不改变训练目标。

## A5：Temperature、Top-k 与 Top-p

- 它们改变从概率分布中选择 Token 的方式；
- 影响输出的稳定性与多样性；
- 不会给模型注入新知识。

## A6：Inference 与 Reasoning

- Inference：运行模型并生成 Token；
- Reasoning：进行多步问题求解；
- 思维链可以通过提示引出；
- 一些推理模型会使用强化学习和增加生成时计算，但 Reasoning 不等同于强化学习。

## A7：GPT-1、GPT-2、GPT-3 的历史定位

```text
GPT-1：预训练能力可以迁移到下游任务
GPT-2：更多任务可以统一为文本生成
GPT-3：通过上下文中的说明和示例适配新任务
```

只作为历史补充，不占正文时间。

## A8：InstructGPT 与其他偏好优化方法

- InstructGPT：SFT → 奖励模型 → PPO；
- 后续方案可能不使用同样的奖励模型或 PPO；
- 共同目标是使用偏好信号塑造模型行为。

## A9：ReAct、Skill、MCP 与 Harness

| 概念 | 职责 |
|---|---|
| ReAct | 交替组织推理、行动和环境反馈的模式 |
| Skill | 针对一类任务的可复用执行知识 |
| MCP | 连接工具和数据源的标准协议 |
| Harness | 组织上下文、模型、工具、权限、状态和执行循环的运行环境 |
