# 从机器学习到现代 LLM：大模型如何学习与生成

> 一条从“根据误差调整参数”，到“从海量文本学习并逐 Token 生成”的认知主线。

我们每天都在使用各种 AI 工具：问问题、写代码、总结文档、分析数据。它们的表现很像一个能够理解意图、掌握知识、组织语言的人。

但如果继续向下追问，问题很快就会变得模糊：

- 模型究竟从哪里获得知识？
- Transformer 改变了什么？
- 为什么“预测下一个 Token”可以产生如此广泛的能力？
- 预训练模型为什么还需要监督微调和人类反馈？
- 模型生成一段回答时，内部到底发生了什么？
- LLM、Agent、Skill、MCP 和 Harness 又分别位于哪一层？

这次分享不尝试罗列所有 AI 技术，也不追逐每一代模型的最新优化。我们只建立一条足够稳定的主线：

~~~text
机器学习：根据数据和误差调整参数
    ↓
深度学习：同时学习参数和中间表示
    ↓
RNN：让历史信息沿序列逐步传递
    ↓
Transformer：让 Token 根据内容动态建立上下文关系
    ↓
Decoder-only LLM：用因果注意力预测下一个 Token
    ↓
预训练：从海量文本中形成基础能力
    ↓
后训练：学会按照指令和人类偏好表现能力
    ↓
Inference：在参数基本不变的情况下逐 Token 生成
    ↓
Harness：在模型外组织上下文、工具、权限和执行循环
~~~

这里有一个必须提前说明的边界：

**这不是几代技术依次淘汰前一代的历史。**

机器学习、深度学习是学习范式；RNN、Transformer 是网络架构；LLaMA-style LLM 是以 Decoder-only Transformer 为基础的一类现代语言模型；预训练和后训练是训练阶段；Harness 和 Agent 则是模型外部的应用系统。

把它们排成一条线，只是为了回答一个问题：

> 一个只能执行人工规则的程序，如何一步步变成能够从海量文本中学习，并根据上下文持续生成内容的现代大语言模型？

# 第一部分：机器学习——机器如何根据数据调整参数

## 1. 从人工规则到从数据中学习

传统程序的基本方式，是由人把规则写清楚：

~~~text
规则 + 输入 → 输出
~~~

例如计算订单价格，我们可以明确写出商品金额、优惠、税费和运费之间的关系。只要规则稳定、边界清晰，这种方式非常可靠。

问题在于，并不是所有任务都能被人完整写成规则。

我们可以凭经验判断一封邮件是不是垃圾邮件、一个客户是否可能流失、一张图片里是不是猫，但很难穷举所有判断条件。即使写出几百条规则，也会遇到规则冲突、场景变化和大量漏网情况。

机器学习换了一种分工方式：

~~~text
人提供：数据、模型形式、优化目标
机器寻找：一组能够降低预测误差的参数
~~~

所以，“机器学习”并不意味着机器自己决定一切。人仍然决定收集什么数据、怎样表示输入、选择什么模型、什么结果算好，以及如何评估模型是否能真实使用。机器主要完成的是：在这些约束下寻找参数。

> **一句话结论：** 机器学习通过数据、模型和优化目标，寻找一组能在新数据上继续有效的参数。

> **不要误解为：** 机器学习不是把数据交给机器后，机器自动发现全部真理。

<details>
<summary>讲者提示（约 1 分钟）</summary>

- 可以先问听众：“如果让你写一套识别垃圾邮件的规则，你准备写多少条？”
- 强调“传统程序”和“机器学习”不是高低之分，而是适合不同问题。
- 后端类比：模型形式像代码骨架，参数像由数据配置出来的大量内部数值，但这个类比不要延伸过度。

## 2. 用线性回归看见最小训练闭环

假设我们只根据房屋面积预测价格。

- 输入：房屋面积 \(x\)
- 正确答案：真实价格 \(y\)
- 模型预测：\(\hat{y}=wx\)
- 需要学习的参数：\(w\)

一开始，我们并不知道 \(w\) 应该是多少，可以先随机给一个值。模型用这个值预测价格，然后把预测值与真实值比较。

假设一套 100 平方米的房子真实价格是 300 万元，而模型只预测了 200 万元。这个差距告诉我们，当前参数还不够好。把许多样本的误差汇总起来，就得到损失函数。

为了保持直观，可以使用均方误差：

\[
L(w)=\frac{1}{n}\sum_{i=1}^{n}(\hat{y_i}-y_i)^2
\]

损失函数负责回答：

> 当前这组参数有多差？

优化算法负责回答：

> 参数向哪个方向调整，损失更可能下降？

于是训练形成一个循环：

~~~text
给参数一个当前值
→ 根据输入进行预测
→ 计算预测与正确答案的差距
→ 根据误差调整参数
→ 用新参数再次预测
→ 重复许多次
~~~

模型真正“学到”的，不是一条可以用自然语言读出来的房价规则，而是一组使损失较低的参数。

<details>
<summary>PPT 与讲述建议</summary>

- PPT 只画一张散点图、一条预测直线和几条误差线。
- 现场可以移动直线斜率，让听众直观看到损失变化。
- 不需要推导梯度，只需要说：“优化算法利用损失变化，寻找更可能下降的方向。”
- 这是全场唯一保留公式的部分。

</details>

## 3. 为什么训练得好，还不等于模型有用

如果模型只是记住了训练样本，却无法处理新样本，那么它并没有学到可复用的规律。

因此，机器学习真正关心的是**泛化**：

> 模型在没有见过、但与真实使用场景相似的数据上，是否仍然有效？

这也是为什么需要区分训练集、验证集和测试集。训练集用于调整参数，验证集用于选择方案，测试集则用于估计模型面对新数据时的表现。

训练损失很低，可能有两种完全不同的含义：

1. 模型学到了能够迁移到新样本的规律；
2. 模型容量足够大，记住了训练数据中的细节甚至噪声。

第二种情况就是过拟合的典型风险。

> **一句话结论：** 训练的目标不是把训练误差压到最低，而是获得对真实新数据仍然有效的参数。

> **不要误解为：** 训练损失越低，真实使用效果就一定越好。

### 从机器学习走向深度学习

在线性回归例子中，“房屋面积”是人提前选好的特征。但面对图片、声音和文本，我们很难提前写出所有有效特征。

于是问题从：

> 怎样根据特征学习参数？

继续向前走了一步：

> 能不能让模型连有用的中间表示也一起学习？

# 第二部分：深度学习——机器如何学习中间表示

## 4. 线性模型的表达边界

线性模型擅长表达一条直线、一个平面或更高维空间中的线性边界。

如果数据恰好可以被一条直线分开，线性模型已经足够好。但如果一类数据包围着另一类数据，或者形成互相缠绕的螺旋，一条直线无论怎样移动都无法正确分开它们。

有人可能会想到：多叠几层线性变换是否就够了？

答案是否定的。两个线性变换复合后，仍然可以合并成一个线性变换。十层没有激活函数的线性网络，在表达形式上仍然相当于一层线性网络。

激活函数在层与层之间加入非线性，使模型能够把多个简单变换组合成弯曲、分段和更复杂的决策边界。

~~~text
线性变换
→ 非线性激活
→ 再次线性组合
→ 再次非线性激活
→ 逐层形成复杂表示
~~~

> **一句话结论：** 深度网络的力量不只是“层数多”，而是通过非线性和多级组合形成复杂表示。

## 5. TensorFlow Playground：现场建立直觉

这一段不靠公式解释，而是通过 [TensorFlow Playground](https://playground.tensorflow.org/) 观察模型如何改变决策边界。

### 演示一：圆形分布

先选择圆形数据，只保留线性模型。

此时无论怎样训练，模型都只能形成接近直线的边界，无法把中心和外围数据分开。这里不要把重点放在“模型表现差”，而要让听众看到：

> 当前模型的表达形式里，根本不存在我们想要的那条圆形边界。

然后加入隐藏层和非线性激活。不同神经元形成不同方向的简单分割，后面的层再组合这些分割，最终形成近似圆形的区域。

这一段要得到的结论是：

> 激活函数和隐藏层改变了模型能够表达的函数范围。

### 演示二：螺旋分布

接着切换到螺旋数据。螺旋比圆形具有更复杂的局部结构，较浅、容量较小的网络通常难以形成合适边界。增加适当深度和容量后，模型可以通过多级组合逐渐形成更复杂的划分。

但这一段不能讲成“网络越深越聪明”。螺旋数据也可能训练不成功，结果会受到初始化、优化、学习率、网络宽度和训练时间等因素影响。

真正应该留下的判断是：

> 深度增加了组合表达能力，但“能够表达”与“能够顺利训练出来”是两个问题。

<summary>现场操作脚本（总计 5～6 分钟）</summary>

1. 提前打开并配置好两个固定页面；
2. 圆形分布先展示无隐藏层的结果；

- 圆形：“非线性使网络可以组合出直线之外的边界。”

</details>

## 6. 深度学习到底学习了什么

传统机器学习常常依赖人工特征：人先决定输入中哪些信息重要，再让模型学习这些特征与目标之间的关系。

深度学习把部分特征工程也交给模型。前层把原始输入转换成较简单的模式，后层继续组合这些模式，形成更适合任务的内部表示。

以图像为例，可以形成这样的直觉：

~~~text
像素
→ 边缘和方向
→ 纹理与局部形状
→ 物体部件
→ 与任务相关的抽象表示
~~~

这只是一种帮助理解的示意，不能把每一层都机械地解释成人类可命名的概念。真实网络中的中间表示往往是分布式的：一个概念由许多神经元共同表示，一个神经元也可能参与多个概念。

CNN 在这里可以一句话定位：

> CNN 利用局部连接和参数共享，把“图像中的相同局部模式可能出现在不同位置”这一结构假设加入网络。

CNN 证明了一个重要思想：面对不同类型的数据，可以通过网络结构加入不同的归纳偏置。但它不是这次 LLM 分享的主线。

> **一句话结论：** 深度学习让模型不只学习最终预测参数，还能把原始输入逐层转换成适合任务的中间表示。

> **不要误解为：** 每一层都会自动学习到清晰、可命名且符合人类直觉的概念。

### 从深度学习走向序列建模

图片的关键结构之一是空间局部性。文本的关键结构则包括顺序和上下文：

- “我没有说他偷了钱”中，强调不同词会改变含义；
- 一个代词指向谁，通常依赖前文；
- 一个词的含义可能需要结合几百个 Token 之前的信息。

模型怎样保存和使用历史信息？RNN 给出了早期的重要答案。

# 第三部分：从 RNN 到 Transformer——上下文如何流动

## 7. RNN：让历史信息沿序列传递

RNN，也就是循环神经网络，处理序列时会维护一个不断更新的隐藏状态。

可以把它理解成一份随阅读进度更新的摘要：

~~~text
当前 Token + 上一步隐藏状态
          ↓
       新隐藏状态
          ↓
    传给下一个位置
~~~

例如模型依次读到“我”“喜欢”“学习”：

~~~text
“我”       → 状态 h₁
“喜欢”+ h₁ → 状态 h₂
“学习”+ h₂ → 状态 h₃
~~~

当前位置不仅接收当前输入，也接收此前状态，因此能够利用历史信息。相同的一组参数会在每个时间步重复使用，使网络可以处理不同长度的序列。

RNN 的关键贡献不是“记住所有原文”，而是让模型具备了一个随序列变化的内部状态。

> **一句话结论：** RNN 把此前信息压缩进隐藏状态，并沿序列逐步传递。

## 8. RNN 为什么会遇到瓶颈

假设序列是：

~~~text
A → B → C → D → E
~~~

如果 A 的信息要影响 E，它必须依次经过 B、C、D 的状态更新。距离越远，信息路径越长；大量历史还需要持续被压缩进固定大小的状态。

这会带来三个结构性问题。

### 8.1 长距离信息路径较长

距离很远的两个位置不能直接交互。前面的信息需要经过多次变换才能抵达后面，在训练中也更容易出现梯度消失、梯度爆炸或信息逐渐弱化。

LSTM、GRU 等结构改善了记忆和梯度传播，但没有改变“按顺序逐步计算”这个基本路径。

### 8.2 序列维度难以充分并行

计算第 100 个状态之前，需要先得到第 99 个状态。这种依赖使训练难以同时处理同一序列的所有位置。

### 8.3 历史被压缩进有限状态

模型需要把不断增长的历史压缩进一个固定维度的向量。它可以学习选择性保留信息，但这个状态仍然承担了很重的压缩任务。

> **不要误解为：** RNN 完全不能处理长序列。更准确的说法是，它的信息路径与顺序依赖限制了长距离建模和大规模并行训练。

于是，一个新的问题出现了：

> 当前 Token 能不能不经过层层传递，直接与上下文中真正相关的位置建立联系？

## 9. Attention：从固定路径到动态连接

Attention 改变的首先不是训练目标，而是序列中信息交互的方式。

~~~text
RNN：
信息沿固定顺序逐步传递

Attention：
当前位置根据内容，直接计算与其他可见位置的相关程度
~~~

考虑两句话：

~~~text
银行旁边有一条河。
我去银行取了钱。
~~~

“银行”的初始 Token 表示可以相同，但它在两句话中的含义不同。第一句中的“河”提供了河岸的语境，第二句中的“取钱”提供了金融机构的语境。

Attention 允许“银行”这个位置根据当前上下文，给“河”或“取钱”等位置不同的权重，再汇总它们提供的信息。经过这一过程，同一个 Token 可以得到不同的上下文表示。

这里要注意，Attention 不是从人类词典里查询词义，也不是显式执行一条人工语法规则。它通过训练得到一套连续向量空间中的匹配和汇总机制。

> **一句话结论：** Attention 让 Token 根据当前内容，动态选择并汇总可见上下文的信息。

## 10. Q、K、V 到底在做什么

Self-Attention 中，每个位置的当前表示都会经过三组学习到的线性变换，产生 Query、Key 和 Value。

可以先使用下面的口语化直觉：

- **Q（Query）**：当前位置正在寻找什么信息；
- **K（Key）**：每个位置提供什么匹配线索；
- **V（Value）**：匹配之后，真正被取回并汇总的内容。

完整信息流是：

~~~text
当前位置生成 Q
→ Q 与所有可见位置的 K 计算匹配分数
→ 匹配分数变成注意力权重
→ 按权重汇总所有位置的 V
→ 得到新的上下文相关表示
~~~

为什么不直接使用原始表示，而要分成 Q、K、V？

因为“用什么维度寻找信息”“用什么维度参与匹配”和“匹配之后传递什么内容”并不一定是同一件事。分开的投影让模型可以为这三个职责学习不同的表示空间。

同时必须避免把这个比喻理解得过于字面：

- Q 不是一句自然语言问题；
- K 不是数据库主键；
- V 也不是已经写好的答案；
- 它们都是训练得到的向量。

> **不要误解为：** Q、K、V 是人工预先定义好的问题、关键词和答案。

<details>
<summary>讲者提示：怎样在不讲公式的情况下讲清 QKV</summary>

先只画 4 个 Token。高亮其中一个 Token，画出它的 Q；再从所有 Token 画出 K 与 V。用线条粗细表示 Q 和 K 的匹配程度，最后把 V 汇聚回当前 Token。

口述时按“寻找—匹配—取回”三个动词讲，不要一开始就抛出三个英文缩写。等听众理解流程后，再把 Q、K、V 名称贴到图上。

</details>

## 11. 多头注意力和位置信息

### 11.1 为什么需要多个头

单个注意力头在一个表示子空间中完成匹配和汇总。多头注意力并行进行多组投影，使模型可以同时学习多种不同的关系，再把结果合并。

可以把它理解为：

> 对同一段上下文，同时使用多组不同的匹配视角。

但不要把每个头都强行解释成一个固定的人类概念。某些头可能呈现局部语法、指代或位置模式，但这种对应通常不是稳定且完备的。

### 11.2 为什么还需要位置信息

Attention 主要依据内容计算关系。如果只给出一组 Token 表示，不额外加入顺序信息，模型无法仅凭集合本身区分：

~~~text
狗咬人
人咬狗
~~~

因此，模型需要把位置信息加入 Token 表示或注意力计算。

原始 Transformer 使用绝对位置编码；LLaMA-style 模型常使用 RoPE，让位置信息进入 Query 和 Key 的关系计算。这里不需要展开旋转矩阵，只需要知道它解决的是：

> 让内容匹配同时感知相对位置和顺序。

## 12. Causal Mask：从 Transformer 走向 GPT/LLaMA

如果训练目标是预测下一个 Token，那么模型在预测当前位置时不能看到未来的正确答案。

Causal Mask，也叫因果掩码，会限制每个位置的可见范围：

~~~text
位置 1：只能看 1
位置 2：可以看 1、2
位置 3：可以看 1、2、3
位置 4：可以看 1、2、3、4
~~~

在图上，它通常表现为一个下三角可见区域。

这座桥非常关键：

~~~text
不能看到未来 Token
→ 每个位置只能根据前文形成表示
→ 可以训练它预测下一个 Token
→ 生成时可以从左到右不断续写
~~~

训练时，我们已经拥有完整文本。借助因果掩码，多个位置仍然可以在一次前向计算中并行得到预测，只是每个位置的可见范围不同。

生成时则不同：下一个 Token 尚不存在，必须先生成第一个新 Token，把它加入上下文，再生成第二个。因此，自回归 Inference 在 Token 维度仍然是顺序过程。

> **一句话结论：** Causal Mask 既防止训练时偷看答案，也建立了从左到右生成的结构约束。

> **不要误解为：** Transformer 在所有情况下都能并行生成整段回答；训练时位置可并行，逐 Token 生成仍然具有顺序依赖。

## 13. 一个 Decoder Block 的稳定骨架

一个简化的现代 Decoder Block 可以画成：

~~~text
输入表示
→ Norm
→ Causal Self-Attention
→ 残差连接
→ Norm
→ Feed-Forward Network
→ 残差连接
~~~

四个部件分别承担不同职责：

### Causal Self-Attention

让每个位置在不查看未来的前提下，动态汇总此前上下文。

### Feed-Forward Network

Attention 完成位置之间的信息交换后，FFN 对每个位置的表示进行进一步非线性变换。它不直接在位置之间传递信息，但承担了大量表示转换和模型容量。

### Residual Connection

让子层学习“在已有表示上增加什么”，并为信息和梯度提供更直接的路径。

### Normalization

控制表示尺度，改善深层网络的训练稳定性。许多 LLaMA-style 模型使用 RMSNorm，并采用子层之前先归一化的 Pre-Norm 结构。

几十甚至上百个 Decoder Block 依次堆叠，使每个 Token 的表示反复经历：

~~~text
汇总上下文
→ 变换表示
→ 保留并叠加已有信息
→ 进入下一层
~~~

## 14. 三类 Transformer 架构的定位

Transformer 可以有不同组织方式：

| 结构 | 直观定位 | 典型用途 |
|---|---|---|
| Encoder-only | 每个位置读取完整输入，形成上下文表示 | 文本理解、分类、表示学习 |
| Encoder–Decoder | Encoder 读取输入，Decoder 根据输入生成输出 | 翻译、摘要等输入输出任务 |
| Decoder-only | 根据已有上下文持续生成后续 Token | GPT、LLaMA-style 大语言模型 |

这次分享只需要记住：

> 现代通用 LLM 的重要主线，是 Decoder-only Transformer 加上 Causal Attention 和大规模自回归训练。

Encoder-only 和 Encoder–Decoder 并没有失效，也不是被 Decoder-only 完全淘汰。它们只是面向不同任务组织信息流。

### 从 Transformer 走向现代 LLM

Transformer 解决了上下文信息怎样高效交互，但一个随机初始化的 Transformer 并不懂语言。

接下来的问题是：

> 字符串怎样进入模型？Decoder Block 最终输出什么？这些随机参数又怎样通过训练获得能力？

# 第四部分：现代 LLM 的稳定结构——从文本到下一个 Token

## 15. 文本怎样进入模型：Tokenizer

模型不能直接处理人类看到的字符串。第一步是由 Tokenizer 把文本转换成 Token，再映射为整数 ID。

~~~text
字符串
→ Tokenizer
→ Token 序列
→ Token ID 序列
~~~

Token 不一定等于一个汉字、一个英文单词或一个标点。它可能是一个完整单词、单词片段、汉字、字节片段或特殊符号，具体切分取决于 Tokenizer。

例如下面只是一个示意，而不是所有模型的固定切分：

~~~text
“Transformer 很强”
→ [“Transform”, “er”, “ 很”, “强”]
→ [1542, 281, 9201, 763]
~~~

Tokenizer 还有一些特殊 Token，用来表示文本开始、文本结束、不同消息角色或工具调用边界。聊天应用在交给模型之前，通常会把 system、user、assistant 等消息按照特定模板编码进同一段 Token 序列。

Tokenizer 会直接影响：

- 同一段文本占用多少上下文长度；
- 多语言和代码的切分效率；
- 模型最终输出和停止的控制方式。

但 Tokenizer 本身并不理解语义。它只是文本与离散 ID 之间的映射规则。

> **不要误解为：** 一个 Token 就等于一个自然语言单词。

## 16. 从 Token ID 到向量：Embedding

Token ID 只是整数编号。编号 1000 比编号 10 大，并不代表它的语义更强。

Embedding 层把每个 Token ID 映射成一个高维向量：

~~~text
Token ID
→ 查找 Embedding 向量
→ 得到向量序列
~~~

这些向量是模型参数的一部分，会在训练中不断调整。它们为每个 Token 提供初始表示；随后经过多个 Decoder Block，表示会结合上下文不断变化。

因此需要区分：

- **初始 Token Embedding**：Token 在进入网络时的基础向量；
- **上下文表示**：经过多层 Attention 和 FFN 后，结合当前上下文形成的向量。

同一个“银行”拥有相同的初始 Token 表示，但在“河边”和“取钱”的上下文中，最终表示会不同。

## 17. LLaMA-style Decoder-only 模型

一类稳定、简化的现代 LLM 骨架可以表示为：

~~~text
文本
→ Tokenizer
→ Token IDs
→ Embedding
→ 多个 Decoder Blocks
   ├─ RMSNorm
   ├─ RoPE + Causal Self-Attention
   ├─ Residual
   ├─ RMSNorm
   ├─ SwiGLU FFN
   └─ Residual
→ 输出层
→ Logits
~~~

这里真正稳定的主干是：

1. Tokenizer 把文本变成离散 Token；
2. Embedding 把 Token 变成向量；
3. 多个 Decoder Block 反复处理上下文表示；
4. 输出层为词表中的候选 Token 产生分数；
5. 模型根据这些分数选择下一个 Token。

RMSNorm、RoPE、SwiGLU 和 GQA 等属于现代架构中常见的具体选择：

- **RMSNorm**：帮助深层训练保持数值稳定；
- **RoPE**：把位置信息加入 Attention 关系；
- **SwiGLU**：现代 FFN 常见的门控激活结构；
- **GQA**：让多组 Query 共享较少的 Key/Value 头，降低 KV Cache 与 Inference 成本。

它们值得知道“位于哪里、解决什么问题”，但不适合成为这次分享的主线。不同模型会更换或组合这些部件，而 Decoder-only、因果注意力和下一个 Token 预测仍然是更稳定的理解骨架。

[LLaMA 原论文](https://arxiv.org/abs/2302.13971)展示了 RMSNorm、RoPE 和 SwiGLU 等结构选择；[Llama 3 技术报告](https://arxiv.org/abs/2407.21783)则呈现了更大规模模型、GQA、预训练与后训练的完整系统。具体模型版本会继续变化，因此这里抽取共同结构，不绑定单一版本。

> **不要误解为：** LLaMA-style 模型与 GPT 使用了完全不同的基础原理；它们都建立在 Decoder-only Transformer 和自回归语言建模主线上。

## 18. 从最后一层表示到 Logits

经过最后一个 Decoder Block 后，每个位置都有一个上下文表示。输出层把某个位置的表示映射到词表大小的向量。

假设词表里有 100,000 个 Token，模型就会为每个候选 Token 给出一个分数。这个未经归一化的分数叫 Logit。

~~~text
当前位置的最终表示
→ 输出层
→ 100,000 个候选 Token 的 Logits
→ Softmax
→ 概率分布
→ 选择下一个 Token
~~~

例如，在“天空通常是”之后，模型可能给出这样的示意分布：

| 候选 Token | 概率示意 |
|---|---:|
| 蓝色 | 0.62 |
| 灰色 | 0.15 |
| 晴朗 | 0.08 |
| 绿色 | 0.01 |
| 其他 Token | 0.14 |

概率不是事实置信度。它表示在当前模型和上下文下，哪些 Token 更符合模型学到的分布。

选择概率最高的 Token 会使输出更确定；根据概率采样则会带来多样性。Temperature、Top-k、Top-p 等生成参数会改变选择方式，但不会为模型增加新知识。

> **一句话结论：** 模型不会直接输出一个完整句子；一次前向计算首先得到的是下一个 Token 的候选分数。

### 从模型结构走向预训练

现在我们已经有了一条完整的信息流：

~~~text
文本
→ Token
→ 向量
→ 多层 Decoder Block
→ Logits
→ 下一个 Token
~~~

但在训练开始前，这些层里的参数基本是随机的，输出也没有意义。

它们如何从随机数逐渐变成能够处理语言、代码和知识的模型？答案是大规模预训练。

# 第五部分：预训练——基础能力从哪里来

## 19. 下一个 Token 预测如何构造训练信号

假设训练文本是：

~~~text
机器学习可以从数据中学习参数
~~~

把它切成 Token 后，可以同时构造多组“前文—下一个 Token”关系：

~~~text
机器                    → 学习
机器 学习               → 可以
机器 学习 可以          → 从
机器 学习 可以 从       → 数据
……
~~~

模型在每个位置根据此前 Token 预测下一个 Token。真实文本天然提供了正确答案，因此不需要人工为海量文本逐句标注类别。

一个极简训练循环是：

~~~python
tokens = tokenize(text)
prediction = model(tokens[:-1])
loss = compare(prediction, tokens[1:])
update_parameters(loss)
~~~

真实预训练会把大量文本清洗、去重、混合并切成固定长度的训练序列，再分批送入模型。一次前向计算可以同时得到序列中多个位置的预测；损失函数衡量这些预测与真实下一个 Token 之间的差距；反向传播计算参数调整方向；优化器更新参数。

~~~text
准备文本数据
→ Tokenize 并组成训练序列
→ 模型预测各位置的下一个 Token
→ 计算交叉熵损失
→ 反向传播
→ 更新参数
→ 对海量批次重复
~~~

训练阶段会更新参数。之后的普通 Inference 则主要使用这些已经学到的参数，不再根据每次用户输入重新训练。

## 20. 一个简单目标为什么会形成广泛能力

“预测下一个 Token”听起来非常简单，但要在大量复杂文本上持续做好这件事，模型必须利用许多中间规律。

预测下面这句话的后续：

~~~text
如果数据库连接池已经耗尽，那么新的请求通常会……
~~~

只知道局部词频可能不够。模型还需要利用：

- 语言的词法和句法；
- 前后文的语义关系；
- 文档和代码的组织模式；
- 训练数据中反复出现的事实关联；
- 问题、推导步骤与答案之间的模式；
- 不同任务如何被表达成文本。

因为这些能力都可以帮助降低下一个 Token 的预测误差，模型有动力把它们压缩进参数和内部表示。

但必须把表述控制在合理范围：

1. 我们可以观察到模型形成了广泛能力；
2. 这些能力与数据、规模、架构和训练过程共同相关；
3. 不能简单断言每个参数保存了哪条知识，或者模型内部以人类同样的方式理解世界。

> **推荐表述：** 下一个 Token 预测提供了统一训练目标；语言、知识和部分任务能力，是模型为了优化这个目标而形成的内部表示与行为。

> **不要误解为：** 模型参数是一套可以精确查询、逐条溯源并保证正确的知识数据库。

## 21. 预训练数据决定了模型看见什么

训练目标统一，不代表训练数据不重要。

数据会影响模型接触到的语言、知识领域、代码风格、质量分布、偏见和错误。现代预训练通常需要处理：

- 来源选择与配比；
- 文本质量过滤；
- 重复内容去除；
- 隐私与安全过滤；
- 多语言和代码比例；
- 数据污染与评测泄漏；
- Tokenizer 与上下文打包。

模型只能从训练信号中学习统计规律。数据中缺少的知识、长期过时的信息、互相冲突的说法以及大量低质量模式，都会成为模型能力和可靠性的边界。

因此，看到“模型参数更多”时，还需要继续问：

> 它使用了什么数据？训练了多少有效 Token？数据质量和配比怎样？评测是否真的覆盖目标场景？

## 22. Scaling：规模重要，但不是越大越好

语言模型研究中观察到一个重要经验规律：在一定范围内，训练损失会随着模型参数、数据规模和计算量增加而呈现较稳定的幂律变化。这类结果通常被称为 Scaling Laws。[Scaling Laws for Neural Language Models](https://arxiv.org/abs/2001.08361)

但 Scaling 不是一句“参数越多越智能”。

在固定计算预算下，模型大小和训练数据量需要平衡。Chinchilla 研究说明，只扩大参数但不给足数据，可能不是计算最优的选择；较小但训练数据更充分的模型，也可能超过参数更大的模型。[Training Compute-Optimal Large Language Models](https://arxiv.org/abs/2203.15556)

可以把基础模型能力简化成四个互相约束的因素：

~~~text
模型容量
+ 数据规模与质量
+ 训练计算
+ 训练与评估方法
→ 基础模型能力
~~~

规模扩大可以提供更大的表达容量和更多学习机会，但不会自动保证：

- 每个任务都更好；
- 输出事实永远正确；
- 偏见和安全问题消失；
- Inference 成本可以接受；
- 模型符合用户意图。

> **不要误解为：** 参数数量是衡量模型能力和产品价值的唯一尺度。

## 23. GPT 路线的三步历史定位

这次不按论文逐篇展开，只保留三步历史定位：

~~~text
GPT-1：
生成式预训练得到的能力可以迁移到多个下游任务

GPT-2：
更多任务可以统一表示为“根据上下文继续生成文本”

GPT-3：
模型规模扩大后，可以通过上下文中的指令和示例适配新任务
~~~

这里最重要的不是记住三个模型的参数量，而是看到任务接口逐渐统一：

~~~text
每个任务单独训练
→ 许多任务统一成文本生成
→ 通过上下文临时说明任务
~~~

这为现代通用语言模型奠定了基础。

### 从预训练走向后训练

预训练模型主要学习：

> 给定这段文本，什么内容最可能继续出现？

但用户真正期待的是：

> 理解我的任务，遵守我的要求，给出清晰、有帮助并符合偏好的回答。

“可能出现的后续文本”与“用户希望得到的回答”并不是同一个目标。

所以，一个基础模型要成为我们熟悉的聊天助手，还需要后训练。

# 第六部分：从基础模型到助手——SFT 与 InstructGPT

## 24. 基础模型为什么不天然服从指令

假设给一个只做过预训练的基础模型输入：

~~~text
请用三句话解释什么是缓存击穿。
~~~

它可能给出一个不错的解释，也可能：

- 继续生成一个相似的问题；
- 把这段话当成网页中的标题；
- 写成问答数据集的多个样本；
- 生成冗长、格式不符或不够有帮助的内容。

这并不奇怪。预训练数据中包含网页、书籍、代码、论坛、对话和许多不同体裁。预训练目标只要求模型生成统计上合理的后续文本，并没有单独规定“看到用户请求时必须像助手一样回答”。

因此需要区分两个概念：

| 阶段 | 主要问题 |
|---|---|
| 预训练 | 如何获得语言、知识和广泛任务模式 |
| 后训练 | 如何更稳定地按照指令和偏好表现这些能力 |

基础能力主要来自大规模预训练；后训练则重新塑造模型面对指令时的行为分布。

> **一句话结论：** 会续写文本，不等于会稳定地充当助手。

## 25. 监督微调（SFT）怎样教模型按指令回答

SFT，也就是监督微调，会准备高质量的“指令—理想回答”数据：

~~~text
用户指令：
请用三句话解释什么是缓存击穿。

理想回答：
缓存击穿是某个热点 Key 失效后，大量请求同时落到数据库……
~~~

然后继续使用语言模型熟悉的 Token 预测目标，让模型提高理想回答中各个 Token 的概率。

从模型底层看，它仍然在做下一个 Token 预测；变化的是数据分布：

~~~text
预训练：
在海量混合文本上学习可能的后续内容

SFT：
在高质量指令与回答上学习“怎样响应用户任务”
~~~

SFT 让模型更容易学会：

- 识别任务形式；
- 遵循输出格式；
- 控制语气和篇幅；
- 使用已有知识完成任务；
- 在多轮对话中扮演助手角色。

### SFT 到底增加知识还是改变行为

SFT 数据当然也可能包含新知识，但它的规模通常远小于预训练，主要价值是让模型学习如何调用和表达已有能力。

可以使用这个比喻：

> 预训练像长期阅读大量材料，SFT 像针对“怎样回答用户”进行示范教学。

这个比喻并不完美，但能帮助区分两类训练的主要职责。

> **不要误解为：** SFT 是模型全部知识和通用能力的主要来源。

~~~text
用户指令：

理想回答：
____________________________

SFT 之后希望改变的行为：
____________________________
~~~

重点不是让听众看数据量，而是让他们看到“数据形式发生了变化”。

## 26. 为什么 SFT 之后还需要偏好数据

一个问题可能有多个基本正确的回答，但它们的质量不同：

- 有的准确但冗长；
- 有的简洁但遗漏关键边界；
- 有的格式正确但没有回答真正意图；
- 有的看似自信却包含未经验证的事实；
- 有的更安全，但过度拒绝正常请求。

许多人类偏好很难完整写成一套确定规则。即使写成几十页规范，也无法穷举所有上下文。

一种做法是让人直接比较多个候选回答：

~~~text
同一个用户指令
→ 模型生成回答 A、B、C、D
→ 标注者按照标准进行排序
→ 得到“在这个上下文中，人更偏好哪个回答”的数据
~~~

偏好数据不要求人写出完美答案，而是让人完成相对判断。这为进一步塑造模型行为提供了训练信号。

需要提醒听众：

> “人更偏好”不等于“客观事实一定正确”。

偏好会受到标注规范、标注者背景、任务分布和文化差异影响。

## 27. InstructGPT：经典 RLHF 三阶段流程

[InstructGPT 原论文](https://arxiv.org/abs/2203.02155)提供了一条非常适合教学的经典后训练流程：

~~~text
阶段一：人工示范 → SFT
阶段二：人工排序 → 奖励模型
阶段三：奖励模型评分 → PPO 优化策略模型
~~~

它不是今天所有 LLM 的固定配方，但非常适合看清“数据—目标—行为变化”之间的关系。

### 27.1 阶段一：收集示范并训练 SFT 模型

标注者根据用户提示编写理想回答，形成监督数据。

~~~text
输入：
用户 Prompt

训练目标：
提高人类示范回答 Token 的概率

结果：
得到更会按照指令回答的 SFT 模型
~~~

SFT 模型同时是下一阶段生成候选回答的起点。

### 27.2 阶段二：收集排序并训练奖励模型

针对同一个 Prompt，让模型生成多个候选回答。标注者按照“有帮助、符合意图、清晰、安全”等标准进行排序。

~~~text
输入：
Prompt + 候选回答

人工信号：
A 优于 C，C 优于 B……

训练目标：
让奖励模型对更受偏好的回答给出更高分

结果：
得到一个近似人类偏好的奖励模型
~~~

奖励模型不负责生成回答。它接收 Prompt 和回答，并输出一个标量分数。

这一步本质上是在学习：

> 什么样的回答更符合当前标注规范下的人类偏好？

### 27.3 阶段三：使用 PPO 继续优化语言模型

语言模型针对新 Prompt 生成回答，奖励模型给出分数。PPO 使用这个分数作为反馈，调整语言模型，使高奖励回答更可能出现。

~~~text
Prompt
→ 当前策略模型生成回答
→ 奖励模型评分
→ PPO 根据奖励调整策略模型
→ 产生新的回答分布
~~~

“策略模型”在这里就是正在被优化的语言模型。它选择的“动作”可以理解为依次生成 Token。

经典 InstructGPT 训练还会约束新模型不要偏离 SFT 模型过远，并混入预训练目标，以降低只追逐奖励分数而损害原有语言能力的风险。正文不需要展开 PPO 公式，只需要说明：

> 模型不是直接读取人类的抽象价值观，而是通过示范、排序和一个学习出来的奖励信号，逐步改变回答分布。

<details>
<summary>贯穿案例模板：偏好比较</summary>

~~~text
用户指令：
____________________________

候选回答 A：
____________________________

候选回答 B：
____________________________

为什么偏好 A/B：
- 是否真正回答问题
- 是否准确
- 是否遵守格式
- 是否清晰且不过度冗长
- 是否包含不必要风险
~~~

讲述时最好让现场听众先投票，再揭示“偏好数据”这一概念。

</details>

## 28. InstructGPT 带来了什么，又不能保证什么

InstructGPT 的意义不是把全部知识重新训练一遍，而是证明了：

> 相比只扩大预训练模型，使用少量高质量示范和人类偏好，也可以显著改变模型在用户眼中的行为质量。

论文的人类评估中，较小的 InstructGPT 模型甚至可以在偏好度上超过大得多的原始 GPT-3。这说明“模型更大”和“回答更符合用户意图”是两个不同维度。

但 RLHF 也不能神奇地解决所有问题：

- 奖励模型只是人类偏好的近似；
- 模型可能学会利用奖励模型的缺陷；
- 标注分布之外的行为仍然不稳定；
- 更受偏好的表达不代表事实一定正确；
- 不同人和不同场景的偏好可能冲突；
- 过度优化某种安全或风格目标，也可能造成不必要的拒绝或模板化。

后来的偏好优化方法可能替换奖励模型、PPO 或数据生成方式，例如使用直接偏好优化等路线。但稳定的问题没有改变：

> 怎样利用有限反馈，让模型行为更符合用户意图，同时尽量保留基础能力并控制副作用？

> **不要误解为：** 经过人类反馈训练后，模型就能保证永远正确、安全并符合每个人的价值判断。

### 从训练走向使用

至此，模型经历了两个主要阶段：

~~~text
预训练：
形成基础语言与任务能力

后训练：
塑造指令跟随与偏好行为
~~~

训练完成后，参数被保存下来。用户真正发起一次请求时，不会重新执行整套训练。

接下来进入模型生成，也就是 Inference。

# 第七部分：模型如何生成——Inference

## 29. 先把两个“推理”分开

中文里“推理”常指两件不同的事：

- **Inference**：运行模型，根据输入生成输出；
- **Reasoning**：进行多步问题求解。

本节只讲 Inference。为了避免混淆，后文统一使用“模型生成”或“Inference”。

Reasoning 可能受到预训练、提示方式、监督数据、强化学习和生成时计算等多种因素影响。它不是强化学习的同义词，也不是这次分享的正文主题。

## 30. 一次请求进入模型后发生了什么

以聊天应用为例，一次请求大致经历：

~~~text
系统指令 + 历史消息 + 当前用户消息
→ 按聊天模板拼成上下文
→ Tokenizer 转成 Token IDs
→ 模型处理整个已有上下文
→ 得到下一个 Token 的 Logits
→ 选择一个 Token
→ 把它加入上下文
→ 重复，直到结束
~~~

这里可以进一步分成两个阶段。

### 30.1 Prefill：处理已有上下文

模型读取当前已有的全部 Token，并通过多层 Decoder Block 为它们建立上下文表示。

由于这些 Token 已经存在，Prefill 可以利用矩阵计算并行处理多个位置，但 Causal Mask 仍然保证每个位置看不到未来。

### 30.2 Decode：逐个生成新 Token

模型从最后一个位置的 Logits 中选择一个 Token，将它追加到上下文，再运行下一步。

一个极简循环是：

~~~python
while not finished:
    logits = model(context)
    next_token = sample(logits)
    context.append(next_token)
~~~

实际系统会在遇到结束 Token、停止条件、长度限制或外部控制时终止。

最后，Tokenizer 把 Token 序列解码回字符串；Streaming 则把已生成内容逐步传给用户，使用户不必等待整段回答完成。

> **不要误解为：** 模型先在内部写好完整答案，然后再逐字显示。自回归模型通常是在循环中一个 Token 一个 Token 决定后续内容。

## 31. 训练和 Inference 的关键区别

| 维度 | 训练 | Inference |
|---|---|---|
| 输入 | 大量训练样本 | 当前请求上下文 |
| 正确答案 | 来自训练文本或标注 | 通常没有 |
| 是否计算训练损失 | 是 | 通常否 |
| 是否反向传播 | 是 | 否 |
| 是否更新模型参数 | 是 | 通常否 |
| 主要结果 | 得到或调整参数 | 生成下一个 Token |

这张表可以解释一个常见问题：

> 为什么我在对话里告诉模型一个新事实，它下一次新对话不一定记得？

因为普通 Inference 并没有更新基础模型参数。当前对话中的信息通常只存在于上下文或模型外部的记忆系统中。关闭上下文后，它不会自动变成预训练知识。

## 32. KV Cache：为什么不用每次重算全部历史

生成第 500 个 Token 时，前 499 个 Token 并没有改变。如果每一步都重新计算全部历史位置的 Key 和 Value，会浪费大量计算。

KV Cache 会保存此前各层已经计算出的 Key 和 Value。生成新 Token 时，只需要计算新位置的 Q、K、V，并让新的 Q 与缓存的 K、V 交互。

~~~text
此前 Token 的 K/V → 缓存并复用
新 Token          → 只计算新的表示
~~~

KV Cache 不改变模型学到的知识，也不改变训练目标。它是自回归 Inference 的关键效率优化，同时会占用显存，且占用通常随上下文长度增长。

正文只需要讲到这个直觉，不展开张量形状、分页缓存和具体推理框架。

## 33. 生成参数改变的是选择方式

模型输出 Logits 后，需要决定怎样选择下一个 Token。

- 贪心选择：每次选择概率最高的 Token；
- Temperature：改变概率分布的尖锐程度；
- Top-k：只在概率最高的 k 个 Token 中选择；
- Top-p：只在累计概率达到阈值的候选集合中选择。

这些方法可以改变回答的稳定性、多样性和重复程度，但不会：

- 为模型注入新知识；
- 修复错误的训练数据；
- 让模型访问实时世界；
- 保证事实正确。

> **一句话结论：** Inference 使用已经训练好的参数，在当前上下文中反复计算并选择下一个 Token。

### 从模型走向 AI 产品

一个 LLM 到这里仍然只完成：

~~~text
接收上下文
→ 输出文本或结构化 Token
~~~

如果用户说“查询线上指标、定位异常、创建工单并通知负责人”，模型本身并不会凭空完成这些外部操作。

这就需要模型外部的 Harness。

# 第八部分：Harness——模型如何被组织成 AI 应用

## 34. LLM 与 Harness 的边界

“Harness”并不是所有生态都完全统一使用的严格标准术语。这里采用一个工作定义：

> Harness 是包围 LLM 的运行与控制层，负责组织上下文、状态、权限、工具、执行循环、错误处理和结果校验。

可以把两层职责画成：

~~~text
LLM
└── 根据当前上下文生成文本或结构化调用

Harness
├── 组织系统指令、历史和外部上下文
├── 决定何时再次调用模型
├── 真正执行工具
├── 维护任务状态
├── 控制权限与用户确认
├── 处理失败、重试和超时
└── 检查任务是否完成
~~~

如果模型生成：

~~~json
{
  "tool": "query_metrics",
  "arguments": {
    "service": "order-api",
    "window": "30m"
  }
}
~~~

这只是一个调用请求。真正访问监控系统的是 Harness 或外部程序；工具结果再被放回上下文，供模型决定下一步。

> **不要误解为：** LLM 输出了工具调用参数，就等于模型亲自执行了工具。

## 35. ReAct、Skill、MCP 分别解决什么

### ReAct：怎样形成观察和行动循环

ReAct 是一种把推理轨迹与外部行动交替组织的模式：

~~~text
观察当前信息
→ 判断下一步需要什么
→ 执行动作
→ 获得新的观察
→ 继续判断和行动
~~~

它把一次性回答扩展成可以利用环境反馈修正下一步的循环。原始 [ReAct 论文](https://arxiv.org/abs/2210.03629)重点展示了语言推理与任务行动交替带来的效果。

### Skill：怎样复用任务执行知识

这里把 Skill 定义为一类任务的可复用执行知识，例如：

- 任务步骤；
- 判断规则；
- 需要调用的工具；
- 输入输出规范；
- 异常处理和验收标准。

不同产品对 Skill 的实现和命名可能不同，因此分享中只讲职责，不把某个产品的格式当成通用标准。

### MCP：怎样标准化连接

MCP 解决的是 AI 应用连接外部上下文与能力时的协议问题。根据 [MCP 规范](https://modelcontextprotocol.io/specification/2025-11-25)，Server 可以向 Client 暴露 Resources、Prompts 和 Tools 等能力；Host/Client 负责连接、权限和上下文组织。

可以用一句话定位：

> Tool 是具体能力，MCP 是暴露和连接这些能力的一种标准协议。

MCP 不负责自动制定完整计划，也不等于 Agent。协议可以让工具更容易被发现和调用，但可靠执行仍然需要权限控制、参数校验、错误处理和用户确认。

## 36. Agent 不是新的基础模型

Agent 通常指围绕目标组织模型、状态、工具和执行循环的系统。

~~~text
目标
→ 规划或选择下一步
→ 调用模型或工具
→ 观察结果
→ 更新状态
→ 检查是否完成
~~~

它的能力来自多个部分：

- LLM 提供语言理解、生成和一定的决策能力；
- 工具提供数据库、文件、浏览器、代码执行等外部能力；
- Harness 提供控制循环、状态、权限和验证；
- Skill 或工作流提供更稳定的任务知识。

所以，当一个 AI 产品表现出“可以完成任务”的能力时，要继续判断：

> 这是基础模型本身的新能力，还是模型、工具、数据和控制系统共同产生的系统能力？

这就是模型原理最终与产品判断连接起来的地方。

# 第九部分：总结——把整条主线重新压缩

## 37. 从参数学习到 AI 应用

现在回到开场的问题。

### 机器学习

人给出数据、模型形式和目标，机器根据误差调整参数。真正目标不是记住训练数据，而是在新数据上泛化。

### 深度学习

多层非线性网络不仅学习最终预测参数，还能逐层形成适合任务的中间表示。更深意味着更强的组合表达可能性，不意味着必然训练成功。

### RNN

隐藏状态让历史信息沿序列传递，但长距离路径和顺序依赖限制了信息交互与并行训练。

### Transformer

Attention 让 Token 根据内容动态汇总上下文；Causal Mask 保证它只能使用过去信息，从而连接到下一个 Token 预测。

### LLaMA-style Decoder-only LLM

文本经过 Tokenizer、Embedding 和多个 Decoder Block，最后变成词表中所有候选 Token 的 Logits。

### 预训练

模型在海量文本上反复预测下一个 Token，通过统一目标形成语言、知识和广泛任务模式。能力来自架构、数据、规模和训练过程的共同作用。

### SFT 与人类反馈

SFT 使用指令和理想回答教模型以助手方式表现能力；InstructGPT 展示了示范、偏好排序、奖励模型和 PPO 共同塑造模型行为的经典路线。

### Inference

模型参数通常不再更新。系统把当前上下文送入模型，得到下一个 Token 的概率分布，选择 Token、追加到上下文并不断重复。

### Harness

Harness 在模型外组织上下文、工具、权限、状态和执行循环，把“生成 Token 的模型”变成能够参与真实工作流的 AI 应用。

## 38. 最终认知地图

~~~text
学习参数
→ 学习中间表示
→ 建立上下文关系
→ 用因果结构预测下一个 Token
→ 通过大规模预训练形成基础能力
→ 通过后训练塑造指令跟随与偏好
→ 在 Inference 中逐 Token 生成
→ 在 Harness 中连接外部世界
~~~

今天的大语言模型，底层仍然在预测下一个 Token。

真正令人惊讶的地方，不是这个目标听起来多么复杂，而是当模型结构、数据、参数和计算扩展到足够规模后，为了持续做好这个目标，模型形成了丰富的内部表示和可迁移能力。

理解这一点之后，我们面对新的 AI 概念和产品宣传时，可以少问一句：

> “它是不是更智能了？”

多问五句：

1. 它改变的是模型结构、训练方式、Inference，还是模型外部系统？
2. 它使用了什么数据或反馈信号？
3. 它实际优化的目标是什么？
4. 能力来自模型参数，还是工具、上下文和工作流？
5. 它在哪些条件下有效，又不能保证什么？

这五个问题，就是这次分享希望留下的最小判断框架。

<details>
<summary>60 分钟分享的收尾口述</summary>

“如果今天只记住一句话，我希望大家记住：LLM 的底层仍然是根据上下文预测下一个 Token。

机器学习告诉我们参数怎样根据误差被调整；深度学习让模型可以形成中间表示；Transformer 让 Token 动态建立上下文关系；因果注意力把这种结构变成从左到右的语言模型；预训练用海量文本形成基础能力；SFT 和人类反馈让它更像一个愿意配合用户的助手；Inference 把这些参数运行起来，一个 Token 一个 Token 形成回答；Harness 再把模型与工具、状态和真实系统连接起来。

以后再听到一个新模型或新产品时，我们不必先记住所有缩写。先判断变化发生在哪一层、优化了什么目标、又不能保证什么。做到这一点，我们就已经拥有了一张不会轻易过时的认知地图。”

</details>

## 附录 B：15 分钟闭卷骨架

这份版本不是正式分享，而是检验自己是否真正掌握主线。

### 0～1 分钟：开场

现代 LLM 并不是突然出现的新物种。它仍然是一种机器学习模型：根据数据和损失调整参数，再用这些参数根据上下文预测下一个 Token。

### 1～3 分钟：机器学习

传统程序由人写规则；机器学习由人给出数据、模型形式和目标，机器寻找参数。线性回归展示“预测—损失—优化”闭环。真正目标是对新数据泛化。

### 3～5 分钟：深度学习

线性模型表达有限；激活函数和多层组合使网络可以形成非线性边界。深度学习不仅学习最终预测参数，也学习中间表示。更深增加表达能力，不保证训练成功。

### 5～8 分钟：RNN 与 Transformer

RNN 用隐藏状态逐步传递历史，但长距离路径、状态压缩和顺序依赖限制了建模与并行。Attention 让 Token 根据内容直接匹配并汇总上下文。Q、K、V 分别承担寻找、匹配和取回的向量职责。

### 8～10 分钟：Decoder-only

Causal Mask 让每个位置不能看未来，从而可以预测下一个 Token。现代 LLM 把 Token 变成 Embedding，经过多层 Decoder Block，再输出全词表 Logits。

### 10～12 分钟：预训练

海量文本天然提供下一个 Token 的正确答案。模型为降低预测误差，逐渐利用语言结构、上下文、知识关联和任务模式。能力来自数据、模型容量、计算和训练方法的共同作用。

### 12～14 分钟：后训练与生成

预训练模型擅长续写，但不天然服从用户。SFT 使用指令和理想回答塑造助手行为；InstructGPT 再使用人类排序、奖励模型和 PPO 调整偏好。Inference 不更新参数，而是反复生成并追加下一个 Token。

### 14～15 分钟：Harness 与总结

LLM 输出文本或工具请求；Harness 真正组织上下文、工具、权限、状态和循环。理解 AI 产品时，要判断能力来自模型、训练、Inference，还是模型外系统。

## 附录 F：QA 问题库与建议回答

### Q1：语言模型是不是只会背诵训练数据？

模型确实可能记忆部分训练内容，尤其是重复、罕见或高度可识别的文本；但它也会从大量样本中形成可组合的统计表示，因此能处理训练集中没有原样出现的新输入。不能把它简单描述成纯检索，也不能忽略记忆、隐私和版权风险。

### Q2：知识具体存在哪个参数里？

通常不能把一条知识精确对应到一个参数。模型知识更接近分布式表示：许多参数共同影响一个行为，同一个参数也参与许多模式。参数编辑和可解释性研究可以定位部分机制，但还不存在一张完整、可靠的“参数—知识”索引。

### Q3：Attention 权重是不是模型的思考过程？

不是。Attention 权重反映某层、某头在一次前向计算中的信息汇总比例，但最终输出还经过多层 Attention、FFN、残差和非线性变换。它可以提供线索，却不能直接等同于完整解释或真实推理过程。

### Q4：Transformer 为什么比 RNN 更适合大规模训练？

主要因为训练时序列多个位置可以在因果掩码下并行计算，任意两个可见位置之间的信息路径也更短。代价是标准全注意力对序列长度的时间和显存开销增长较快。

### Q5：既然 Transformer 能并行，为什么生成还是慢？

训练时正确的整段文本已经存在，可以同时预测多个位置。生成时未来 Token 尚不存在，必须先生成一个，再把它加入上下文生成下一个，所以 Decode 仍然是顺序过程。

### Q6：模型为什么会幻觉？

模型优化的是在当前上下文下生成高概率 Token，而不是直接验证每句话是否符合外部事实。训练数据冲突、知识缺失、提示歧义、分布外问题和生成策略都可能造成看似流畅但错误的回答。检索、工具、校验和更好的训练可以降低风险，但不能保证完全消除。

### Q7：上下文窗口越长，模型就能记住越多吗？

它能接收更多 Token，但“放得进去”不等于“每处信息都能被可靠使用”。长上下文还带来计算、KV Cache、位置泛化和信息检索难度。模型对不同位置和不同信息类型的利用能力也可能不同。

### Q8：预训练、SFT 和 RLHF 会不会都在更新参数？

通常都会更新某些模型参数，但使用的数据和优化信号不同。预训练依赖海量文本中的下一个 Token；SFT 依赖高质量指令回答；经典 RLHF 使用人类偏好训练奖励模型，再用奖励信号调整策略模型。

### Q9：SFT 和 Prompt Engineering 有什么区别？

SFT 会改变模型参数，使某类行为更稳定地成为模型分布的一部分。Prompt Engineering 不更新模型参数，只通过当前上下文临时引导模型。前者成本更高但效果可固化，后者灵活、便宜但受上下文和模型能力限制。

### Q10：RAG 与微调有什么区别？

RAG 在 Inference 时检索外部资料并放入上下文，适合更新知识、提供依据和访问私有数据。微调修改参数，更适合稳定改变行为、格式或领域模式。两者可以组合，不能简单互相替代。

### Q11：为什么需要奖励模型，不能直接让人给每次训练打分吗？

直接让人参与每次策略更新成本极高。奖励模型先从有限的人类排序中学习偏好近似，再为大量新回答提供自动评分。但近似会产生偏差，因此奖励模型本身也是系统风险来源。

### Q12：PPO 在 InstructGPT 中做了什么？

它使用奖励模型分数调整语言模型的生成策略，使高奖励回答更可能出现，同时通过约束避免模型偏离 SFT 模型过远。正文不需要掌握 PPO 的裁剪目标和优势估计公式。

### Q13：DPO 与 InstructGPT 的 RLHF 有什么关系？

它们都利用偏好数据塑造模型行为。经典 InstructGPT 先训练奖励模型，再使用 PPO；DPO 类方法可以直接从偏好对优化语言模型，减少显式奖励模型与在线 RL 流程。具体方法仍在快速演进，正文只需知道它们回答同一个偏好优化问题。

### Q14：Temperature 越低，答案越准确吗？

不一定。低 Temperature 会让选择更集中、更稳定，但如果模型最高概率的答案本身错误，它只会更稳定地输出错误。生成参数改变采样，不等于事实校验。

### Q15：KV Cache 会让模型变聪明吗？

不会。它复用此前 Token 的 Key 和 Value，降低重复计算。它改善速度，但不改变参数、训练目标或知识。

### Q16：Inference 和 Reasoning 是一回事吗？

不是。Inference 是运行模型产生输出；Reasoning 是多步问题求解能力。任何模型回答都需要 Inference，但不代表它一定进行了可靠的复杂推理。

### Q17：思维链一定来自强化学习吗？

不一定。思维链可以通过提示示例被引出；也可以通过 SFT、过程监督、强化学习、蒸馏或增加生成时计算得到增强。强化学习是重要路线之一，不是“推理”的上位概念。

### Q18：模型真的会调用工具吗？

模型通常只生成结构化调用请求，包括工具名和参数。Harness 或外部程序负责校验权限、执行工具、处理错误，再把结果返回模型。

### Q19：MCP 等于 Tool Call 吗？

不等于。Tool Call 是模型请求使用某个工具的交互机制；MCP 是应用连接和暴露 Resources、Prompts、Tools 等能力的一种标准协议。

### Q20：Agent 是一种新模型吗？

通常不是。Agent 是围绕目标组织 LLM、工具、状态、控制循环和验证逻辑的系统。它可能使用更适合规划或工具调用的模型，但“Agent”描述的是系统组织方式。

| 概念 | 主要职责 | 不等于 |
|---|---|---|
| 参数 | 训练得到的内部数值 | 人类可读规则 |
| 特征/表示 | 模型用于完成任务的内部表达 | 必然可命名概念 |
| Token | Tokenizer 定义的离散文本单元 | 固定等于单词 |
| Embedding | Token ID 对应的初始向量 | 完整上下文语义 |
| Attention | 根据内容匹配并汇总信息 | 完整思考解释 |
| Causal Mask | 禁止位置看到未来 Token | 让模型事实正确 |
| Logit | 候选 Token 的未归一化分数 | 事实置信度 |
| 预训练 | 从大规模文本形成基础能力 | 天然学会服从用户 |
| SFT | 用示范塑造指令响应行为 | 主要知识来源 |
| RLHF | 用人类偏好进一步塑造行为 | 永久保证安全正确 |
| Inference | 运行模型生成输出 | Reasoning |
| Streaming | 逐步返回已生成 Token | 提升模型智能 |
| KV Cache | 复用历史 K/V 计算 | 增加模型知识 |
| Tool Call | 模型生成工具请求 | 工具已经执行 |
| MCP | 连接上下文和能力的协议 | Agent 或工作流 |
| Skill | 某类任务的可复用执行知识 | 基础模型或具体工具 |
| Harness | 组织模型、上下文、工具和控制的外层运行环境 | 单一通用标准 |
| Agent | 围绕目标持续观察和行动的系统 | 新的神经网络架构 |
