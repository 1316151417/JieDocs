# 第13章 迁移学习与微调

> **核心问题**：如何利用预训练模型？如何高效微调？

---

## 13.1 迁移学习概述

### 13.1.1 什么是迁移学习

**定义**：将在一个任务上学到的知识应用到另一个相关任务上

**核心假设**：源域和目标域有共享的知识

### 13.1.2 迁移学习的类型

**归纳迁移学习**：
- 源域和目标域相同
- 任务不同
- 例：ImageNet预训练 → 医学图像分类

**直推迁移学习**：
- 任务相同
- 域不同
- 例：英文情感分析 → 中文情感分析

**无监督迁移学习**：
- 源域和目标域都无标签
- 例：自监督预训练

### 13.1.3 为什么迁移学习有效

**特征复用**：
- 低层特征（边缘、纹理）是通用的
- 高层特征（语义概念）需要任务特定

**数据效率**：
- 预训练利用大量无标注数据
- 微调只需少量标注数据

---

## 13.2 预训练-微调范式

### 13.2.1 计算机视觉

**典型流程**：
```
ImageNet预训练 → 替换分类头 → 在目标数据集上微调
```

**常见预训练模型**：
- ResNet、EfficientNet（有监督）
- CLIP、DINO（自监督）

### 13.2.2 自然语言处理

**典型流程**：
```
大规模语料预训练 → 在下游任务上微调
```

**常见预训练模型**：
- BERT、RoBERTa（理解任务）
- GPT、LLaMA（生成任务）

### 13.2.3 微调策略

**全量微调**：更新所有参数
- 效果最好
- 计算成本高
- 可能过拟合

**特征提取**：冻结预训练模型，只训练新层
- 计算成本低
- 效果有限

**部分微调**：微调部分层
- 平衡效果和成本
- 通常微调高层

## 13.3 参数高效微调（PEFT）

### 13.3.1 为什么需要PEFT

**问题**：
- 大模型参数量巨大（7B、70B、405B）
- 全量微调需要大量GPU内存
- 每个任务需要存储完整模型

**解决方案**：只微调少量参数

### 13.3.2 LoRA（Low-Rank Adaptation）

**核心思想**：用低秩矩阵近似权重更新

**公式**：
```
W' = W + ΔW = W + BA
```
其中：
- W ∈ R^{d×k}：原始权重
- B ∈ R^{d×r}：低秩矩阵
- A ∈ R^{r×k}：低秩矩阵
- r << min(d, k)

**参数量**：从 d×k 减少到 (d+k)×r

**实现**：
```python
class LoRALinear(nn.Module):
    def __init__(self, in_features, out_features, r=8):
        super().__init__()
        self.linear = nn.Linear(in_features, out_features, bias=False)
        self.linear.weight.requires_grad = False  # 冻结原始权重
        
        self.lora_A = nn.Linear(in_features, r, bias=False)
        self.lora_B = nn.Linear(r, out_features, bias=False)
        self.scaling = 1 / r
    
    def forward(self, x):
        return self.linear(x) + self.lora_B(self.lora_A(x)) * self.scaling
```

**优势**：
- 参数量大幅减少（通常<1%）
- 效果接近全量微调
- 可以合并到原始权重，推理无额外开销

### 13.3.3 QLoRA

**核心思想**：在量化模型上进行LoRA

**步骤**：
1. 将预训练模型量化为4-bit
2. 在量化模型上添加LoRA
3. 只训练LoRA参数

**优势**：
- 进一步减少内存需求
- 可以在单GPU上微调大模型

### 13.3.4 Adapter

**核心思想**：在Transformer层中插入小型适配器模块

**结构**：
```
输入 → [下投影] → [激活函数] → [上投影] → 残差连接 → 输出
```

**特点**：
- 参数量小
- 可以按任务组合
- 推理有轻微开销

### 13.3.5 Prefix Tuning

**核心思想**：在输入前添加可学习的前缀

**公式**：
```
h_i = [P_i; x_i]  # 拼接前缀和输入
```

**特点**：
- 不修改模型结构
- 参数量极小
- 适合生成任务

### 13.3.6 Prompt Tuning

**核心思想**：只优化prompt embedding

**公式**：
```
input = [P_1, P_2, ..., P_n, x_1, x_2, ..., x_m]
```

**特点**：
- 参数量最小
- 效果随模型规模提升

## 13.4 微调实践

### 13.4.1 数据准备

**数据格式**：
```json
{
  "instruction": "将以下英文翻译成中文",
  "input": "Hello, how are you?",
  "output": "你好，你好吗？"
}
```

**数据质量**：
- 高质量标注
- 多样性
- 覆盖边界情况

### 13.4.2 超参数选择

| 参数 | 推荐值 |
|------|--------|
| 学习率 | 1e-5 到 5e-5 |
| 批量大小 | 4-32 |
| 训练轮数 | 1-5 |
| 权重衰减 | 0.01 |
| warmup比例 | 0.1 |

### 13.4.3 避免灾难性遗忘

**问题**：微调后，模型忘记预训练知识

**解决方案**：
- 使用小学习率
- 混合预训练数据
- 使用正则化（如L2、EWC）

### 13.4.4 评估

**评估方法**：
- 验证集性能
- 人工评估
- 与原始模型对比

## 13.5 领域适配

### 13.5.1 什么是领域适配

**问题**：源域和目标域分布不同

**例子**：
- 通用文本 → 医学文本
- 自然图像 → 遥感图像

### 13.5.2 适配方法

**继续预训练**：
- 在目标领域数据上继续预训练
- 然后在下游任务上微调

**领域特定微调**：
- 使用领域数据进行指令微调
- 构建领域特定的训练数据

### 13.5.3 医学领域示例

**PubMedBERT**：
- 在PubMed摘要上预训练
- 医学NLP任务表现更好

**Med-PaLM**：
- Google的医学大模型
- 在医学问答上达到专家水平

---

## 13.6 多任务学习

### 13.6.1 什么是多任务学习

**定义**：同时学习多个相关任务

**优势**：
- 共享表示，提高泛化
- 任务间相互促进
- 减少过拟合

### 13.6.2 硬参数共享

```
共享层 → 任务1头
       → 任务2头
       → 任务3头
```

### 13.6.3 软参数共享

```
任务1网络 ←正则化→ 任务2网络 ←正则化→ 任务3网络
```

### 13.6.4 T5：统一文本到文本

**框架**：
```
输入："translate English to French: Hello"
输出："Bonjour"
```

**所有任务统一为文本到文本**：
- 翻译
- 摘要
- 问答
- 分类

## 13.7 实践建议

### 13.7.1 微调方法选择

| 场景 | 推荐方法 |
|------|----------|
| 资源充足，追求最佳效果 | 全量微调 |
| 资源有限，多个任务 | LoRA |
| 单GPU，大模型 | QLoRA |
| 极少参数 | Prompt Tuning |

### 13.7.2 学习率选择

**全量微调**：1e-5 到 5e-5
**LoRA**：1e-4 到 3e-4
**Prompt Tuning**：0.1 到 0.3

### 13.7.3 数据量建议

**最少数据**：100-1000条高质量样本
**理想数据**：1000-10000条
**过多数据**：可能过拟合，需要早停
