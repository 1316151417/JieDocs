# 第12章 大语言模型与基础模型

> **核心问题**：大语言模型为什么如此强大？Scaling Laws意味着什么？

## 12.1 从预训练到基础模型

### 12.1.1 基础模型的定义

**定义**：在大规模数据上预训练，可以适应广泛下游任务的模型

**特征**：
- 大规模（参数量大、数据量大、计算量大）
- 通用性（适用于多种任务）
- 涌现能力（小模型不具备的能力）

### 12.1.2 发展历程

**2018年**：BERT（340M参数）、GPT（117M参数）
**2019年**：GPT-2（1.5B参数）
**2020年**：GPT-3（175B参数）
**2022年**：ChatGPT、PaLM（540B参数）
**2023年**：GPT-4、LLaMA、Mistral
**2024年**：LLaMA 3、Claude 3、Gemini

## 12.2 大语言模型架构

### 12.2.1 仅解码器架构

**为什么选择解码器架构**：
- 适合生成任务
- 训练目标简单（预测下一个token）
- 可以自然地进行few-shot学习

**架构细节**：
```
输入token → [Embedding] → [Transformer层×N] → [LM Head] → 输出概率
```

### 12.2.2 现代架构改进

**RMSNorm**：替代LayerNorm，更稳定
**SwiGLU**：替代ReLU/GELU，效果更好
**RoPE**：旋转位置编码，支持更长序列
**GQA**：分组查询注意力，减少KV缓存

### 12.2.3 LLaMA架构详解

```
输入 → RMSNorm → Attention → 残差连接 → RMSNorm → SwiGLU FFN → 残差连接 → 输出
```

**关键参数**：
| 模型 | 层数 | 隐藏维度 | 头数 | 参数量 |
|------|------|----------|------|--------|
| LLaMA-7B | 32 | 4096 | 32 | 7B |
| LLaMA-13B | 40 | 5120 | 40 | 13B |
| LLaMA-65B | 80 | 8192 | 64 | 65B |

## 12.3 Scaling Laws

### 12.3.1 核心发现

**Kaplan et al. (2020)**：
```
L(N) ∝ N^(-0.076)
L(D) ∝ D^(-0.095)
L(C) ∝ C^(-0.050)
```

其中：
- N：模型参数量
- D：数据量
- C：计算量

### 12.3.2 Chinchilla Scaling Laws

**Hoffmann et al. (2022)**：
- 模型大小和数据量应该同步增长
- 最优比例：20 tokens/parameter
- Chinchilla（70B）用更多数据训练，效果优于Gopher（280B）

### 12.3.3 实践意义

**计算预算分配**：
```
给定计算预算C，最优模型大小N ∝ C^0.5，最优数据量D ∝ C^0.5
```

**训练策略**：
- 先确定计算预算
- 根据Scaling Laws选择模型大小和数据量
- 不要盲目追求大模型

## 12.4 涌现能力

### 12.4.1 什么是涌现能力

**定义**：小模型不具备，但大模型突然出现的能力

**例子**：
- 思维链（Chain-of-Thought）
- 少样本学习（Few-shot Learning）
- 代码生成
- 复杂推理

### 12.4.2 涌现能力的例子

**思维链推理**：
```
Q: Roger has 5 tennis balls. He buys 2 more cans of tennis balls. 
   Each can has 3 tennis balls. How many tennis balls does he have now?
A: Roger started with 5 balls. 2 cans of 3 balls each is 6 balls. 
   5 + 6 = 11. The answer is 11.
```

小模型无法做到，但大模型可以。

### 12.4.3 涌现能力的解释

**假说1**：度量选择问题
- 某些指标（如精确匹配）是离散的
- 实际能力是连续提升的

**假说2**：任务组合
- 复杂任务是简单任务的组合
- 大模型可以组合更多技能

## 12.6 训练技术

### 12.6.1 分布式训练

**数据并行**：
```
每个GPU持有完整模型，处理不同数据
梯度同步：AllReduce
```

**模型并行**：
```
张量并行：将矩阵切分到多个GPU
流水线并行：将不同层放在不同GPU
```

**3D并行**：
```
数据并行 + 张量并行 + 流水线并行
```

### 12.6.2 内存优化

**梯度检查点**：
- 只保存部分层的激活
- 需要时重新计算
- 以时间换空间

**ZeRO优化**：
- ZeRO-1：优化器状态分片
- ZeRO-2：梯度分片
- ZeRO-3：参数分片

### 12.6.3 混合精度训练

**BF16 vs FP16**：
- BF16：范围大，精度低
- FP16：范围小，精度高
- BF16更适合大模型训练

## 12.7 指令微调与对齐

### 12.7.1 指令微调（Instruction Tuning）

**目标**：让模型遵循指令

**数据格式**：
```
{
  "instruction": "解释量子计算",
  "input": "",
  "output": "量子计算是利用量子力学原理进行计算的技术..."
}
```

**效果**：
- 提高指令遵循能力
- 提高零样本性能
- 减少有害输出

### 12.7.2 RLHF（基于人类反馈的强化学习）

**步骤**：
1. **监督微调**：用高质量数据微调
2. **奖励模型训练**：学习人类偏好
3. **PPO优化**：使用强化学习优化

**奖励模型**：
```
R(x, y) → 标量分数
```

**PPO目标**：
```
max E[R(x, y)] - β * KL(π || π_ref)
```

### 12.7.3 DPO（直接偏好优化）

**核心思想**：跳过奖励模型，直接优化偏好

**损失函数**：
```
L = -log σ(β * [log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)])
```

**优势**：
- 更简单
- 更稳定
- 不需要奖励模型

## 12.8 推理技术

### 12.8.1 采样策略

**贪心搜索**：
```
选择概率最高的token
```

**束搜索（Beam Search）**：
```
保留top-k个候选序列
```

**采样方法**：
```
Top-k：从概率最高的k个token中采样
Top-p（Nucleus）：从累积概率达到p的token中采样
Temperature：调整概率分布的尖锐程度
```

### 12.8.2 KV缓存

**问题**：自回归生成时，重复计算已生成token的Key和Value

**解决方案**：缓存已计算的KV

```python
# 推理时
if past_key_values is not None:
    # 只计算新token的Q，拼接缓存的KV
    k = torch.cat([past_key_values[0], k], dim=1)
    v = torch.cat([past_key_values[1], v], dim=1)
```

### 12.8.3 投机解码

**核心思想**：用小模型预测，大模型验证

**步骤**：
1. 小模型快速生成多个token
2. 大模型并行验证
3. 接受正确的token，拒绝错误的

**效果**：2-3倍加速
