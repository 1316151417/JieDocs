**一、问题定义**

“把现实问题变成机器可以学习的数据”，本质是在解决：

> 如何把一个真实世界中的模糊任务，转化为机器能接收、计算、比较、优化的形式。

例如：

- “判断一张图片是不是猫”
- “预测一套房子的价格”
- “识别用户是否会流失”
- “根据病历判断风险等级”

这些问题在人看来是“理解问题”，但机器不能直接理解“猫”“贵不贵”“风险高不高”。机器只能处理数字、结构、关系和目标函数。

所以第一步不是建模型，而是完成一次转换：

```text
现实问题
↓
可观测对象
↓
可记录数据
↓
可表示特征
↓
可学习目标
↓
训练样本
```

如果这一步做错，后面的模型再复杂也只是在认真学习错误的东西。

---

**二、问题产生原因**

这个问题之所以出现，是因为现实世界和机器学习系统之间存在四个断层。

**1. 现实问题是语义的，机器输入是数值的**

人说“这张图像像猫”，背后包含视觉经验、形状理解、语境判断。  
但机器看到的只是像素矩阵：

```text
猫
→ 图片
→ 像素
→ 数字张量
```

机器不能直接学习“猫”这个概念，它只能从大量数字模式中归纳出和“猫”相关的统计规律。

**2. 现实任务是开放的，机器学习任务必须是封闭的**

现实里“房价高不高”可能受地段、学区、政策、装修、市场情绪影响。  
但模型训练时必须明确：

- 输入是什么？
- 输出是什么？
- 什么算预测对？
- 用什么数据训练？
- 用什么指标评估？

如果任务边界不清楚，机器就不知道该优化什么。

**3. 现实数据是脏的，机器学习要求结构化**

真实数据常常有：

- 缺失值
- 异常值
- 重复样本
- 单位不统一
- 类别含义混乱
- 文本、图片、表格混在一起
- 标签错误或不一致

人可以凭常识补全，但机器会把这些问题当成真实规律来学。

**4. 现实目标和可学习目标不总是一回事**

比如公司真正想要的是“提升收入”，但模型可能只能学习“预测点击率”。  
医生真正关心的是“降低误诊风险”，但数据里可能只有“是否确诊”的标签。

这就产生一个核心矛盾：

```text
我们真正关心的目标
≠
数据中可以直接学习的目标
```

所以需要把现实目标转译成可训练目标。

---

**三、解决思路**

核心思想是：

> 不要直接让机器理解现实，而是把现实问题重构成一个“输入到输出的映射问题”。

也就是：

```text
给定输入 X
学习一个函数 f
让 f(X) 尽可能接近目标 y
```

例如：

```text
房屋信息 X → 模型 f → 房价 y
图片像素 X → 模型 f → 类别 y
用户行为 X → 模型 f → 流失概率 y
文本内容 X → 模型 f → 情感标签 y
```

这里最重要的不是“用什么模型”，而是先完成四个定义：

```text
定义对象：要研究什么东西？
定义输入：机器能看到哪些信息？
定义输出：希望机器预测什么？
定义样本：一条训练数据长什么样？
```

一旦完成这四个定义，现实问题才进入机器学习系统。

---

**四、方案框架**

```text
问题：
现实问题无法被机器直接理解和优化
↓
核心思想：
把现实任务转化为输入 X 到目标 y 的可学习映射
↓
关键机制：
1. 明确任务类型
2. 收集可观测数据
3. 把对象表示成特征
4. 把目标表示成标签
5. 清洗和预处理数据
6. 构造训练集、验证集、测试集
7. 用指标判断模型是否学到了有用规律
↓
最终效果：
现实问题被转化为机器可以计算、训练、评估、改进的数据问题
```

更细一点，可以拆成六步。

**1. 明确任务：到底要预测什么？**

先判断问题类型：

```text
预测连续数值 → 回归问题
预测类别 → 分类问题
预测概率 → 风险评估问题
发现结构 → 聚类或表示学习问题
生成内容 → 生成问题
排序结果 → 排序问题
```

例如“预测房价”是回归；“识别衣服类别”是分类。

这一步决定了后面标签、损失函数和评估指标怎么设计。

**2. 明确样本：一个训练对象是什么？**

机器学习不是直接学习“市场”“图像世界”“用户群体”，而是学习一条条样本。

```text
一个房子 = 一个样本
一张图片 = 一个样本
一次用户访问 = 一个样本
一段文本 = 一个样本
```

样本定义错，问题就会变形。

例如预测用户是否流失时，样本可以是：

```text
一个用户
一次登录
一个月的用户行为
一次购买记录
```

不同定义会导致完全不同的模型问题。

**3. 明确输入：机器能看到什么？**

输入就是特征。

表格数据中，特征可能是：

```text
面积、卧室数、地段、年份、楼层
```

图像数据中，特征最初是：

```text
像素值
```

文本数据中，特征可以是：

```text
词、token、向量表示
```

这里的关键问题是：

> 哪些信息是模型预测目标时允许使用的？

不能把未来信息、泄露标签的信息放进输入，否则模型会在训练时表现很好，上线后崩掉。

**4. 明确输出：机器应该学什么目标？**

输出就是标签或目标值。

```text
房价预测：真实成交价
图片分类：图片类别
流失预测：未来是否流失
风险预测：是否发生风险事件
```

标签决定模型学到什么。

如果标签本身有偏差，模型会学习这种偏差。  
如果标签太粗糙，模型学不到细致规律。  
如果标签和真实业务目标不一致，模型会优化错方向。

**5. 数据预处理：把脏数据变成可训练数据**

这一步解决的是：

```text
现实数据不能直接喂给模型
```

常见处理包括：

```text
缺失值 → 填充、删除、单独标记
类别变量 → 编码
数值变量 → 标准化或归一化
异常值 → 修正、截断、剔除
文本 → 分词、token 化、向量化
图像 → 缩放、裁剪、归一化
```

预处理不是杂活，它是在决定机器最终能“看见”什么。

**6. 划分数据：如何判断模型真的学会了？**

如果只在训练数据上评估，模型可能只是记住答案。

所以要划分：

```text
训练集：用于学习参数
验证集：用于选择模型和调参
测试集：用于最终评估泛化能力
```

这一步把“会背题”和“会解题”区分开。

---

**五、与其它方案比较**

**为什么不能直接把现实问题交给模型？**

因为模型不能直接处理语义世界。  
模型需要明确的输入、输出和优化目标。

```text
现实问题：这个客户重要吗？
机器问题：给定客户行为特征，预测未来 30 天购买概率
```

后者才是可训练问题。

**为什么不能只靠人工规则？**

人工规则适合边界清楚的问题，比如：

```text
年龄 < 18 → 未成年人
库存 = 0 → 不可购买
```

但面对复杂模式时，规则会迅速失效：

```text
什么样的图片是猫？
什么样的用户会流失？
什么样的房子会涨价？
```

这些规律太复杂，人工难以完整写出，所以需要模型从数据中学习。

**为什么不能只收集更多数据，不做问题定义？**

更多数据不等于更好学习。  
如果任务定义不清、标签错误、特征泄露、样本口径混乱，更多数据只会放大问题。

机器学习真正需要的是：

```text
和目标相关的数据
结构一致的数据
标签可靠的数据
分布合理的数据
可用于泛化的数据
```

**这个方案解决了什么？**

它解决的是“现实到模型”的入口问题：

```text
现实任务不可计算
→ 转化为输入、输出、样本、标签
→ 模型可以训练
→ 结果可以评估
→ 系统可以改进
```

**它又带来了什么新问题？**

一旦现实问题被转化为数据问题，就会出现新的挑战：

```text
数据是否代表真实世界？
标签是否可靠？
特征是否泄露未来信息？
训练集和真实环境是否分布一致？
模型学到的是因果关系还是相关性？
评估指标是否真的符合业务目标？
```

这也是为什么深度学习里，“数据构造”不是前置小步骤，而是整个学习系统成败的根基。

**总结一句**

把现实问题变成机器可以学习的数据，本质是一次“问题翻译”：

```text
人的问题：
我想解决一个现实目标

机器学习的问题：
给定一批样本 X 和目标 y，
学习一个函数 f，
让 f 在新样本上也能做出接近 y 的预测
```

这一步完成后，后面的线性回归、Softmax、MLP、CNN、优化算法、正则化，才真正有了用武之地。
