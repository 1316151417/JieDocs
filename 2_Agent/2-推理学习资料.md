我全网筛了一轮。如果你的目标明确是：

**不是学“怎么部署 vLLM”，而是从 0 写一个 LLM 推理引擎 + 推理服务器，并最终能读懂 vLLM。**

我建议不要找一门“大而全课程”。目前最好的资料实际上是**几篇核心文章 + 一个教学项目 + 官方源码**组合起来学。

### **第一梯队：最值得投入时间的 5 个**

**1. 首推：Inside vLLM: Anatomy of a High-Throughput LLM Inference System**

⁠Inside vLLM 官方长文

这是我最推荐你先看的。

它不是教你 `vllm serve xxx`，而是从系统设计角度拆整个推理系统，覆盖：

```text
LLM Engine
↓
Scheduler
↓
Continuous Batching
↓
KV Cache
↓
PagedAttention
↓
Prefix Caching
↓
Chunked Prefill
↓
Speculative Decoding
↓
Multi-GPU
↓
Disaggregated Prefill / Decode
```

而且它采用“先建立整体模型，再深入子系统”的方式。文章本身约 41 分钟阅读量。 

**适合你：★★★★★**

我建议把它当成整个学习路线的“教材目录”。

---

**2. 最适合动手：mini-vLLM**

⁠mini-vLLM：约 1000 行实现推理引擎

这个项目和你的目标高度一致：

“A lightweight LLM inference engine built from scratch.”

而且作者刻意控制在大约 **1000 行代码**，支持 Qwen3，已经包含：

```text
Model Loading
↓
KV Cache
↓
Continuous Batching
↓
Prefix Caching
↓
CUDA Graph
```

甚至自己实现了简化版 FlashAttention。 

它最大的价值不是拿来用，而是：

**完整到足以理解推理引擎，又小到你真的可以读完。**

你现在完全可以拿 Qwen3-0.6B 跑它。

**适合你：★★★★★**

不过我不建议“读完然后照抄”。

应该：

```text
自己写
 ↓
卡住
 ↓
看 mini-vLLM
 ↓
理解作者为什么这么设计
 ↓
关掉源码
 ↓
自己实现
```

**3. 非常适合建立底层直觉：KV Cache From Scratch**

这个视频反而很符合你之前学习 GPT 源码的方式。

接近 2 小时，从：

```text
Transformer
↓
为什么自回归推理慢
↓
KV Cache 数学原理
↓
PyTorch 手写 KV Cache
↓
接入 Transformer
↓
Inference Engine
↓
Request
↓
Scheduler
↓
Prefill
↓
Decode
↓
性能 Benchmark
↓
为什么 Decode 是 Memory Bound
```

一路实现下来。 

尤其后半部分很重要：

为什么 Prefill 是 compute-bound，而 Decode 通常是 memory-bound？

如果这个东西真正理解了，很多推理优化技术你都能自己推导出来。

**适合你：★★★★★**

甚至建议你**先看这个，再看 vLLM**。

---

**4. 专门手写 Continuous Batching**

⁠Build a Continuous Batching LLM Scheduler From Scratch

这是 2026 年 9 月刚出的教程，针对性很强：

```text
Request Queue
↓
Paged KV Cache
↓
Scheduler
↓
动态加入/退出 Request
↓
Continuous Batching
```

重点不是讲概念，而是让你自己做一个 Scheduler。 

它特别适合作为你自己的第二个里程碑：

```text
V0 单请求推理
↓
V1 KV Cache
↓
V2 Continuous Batching
```

**适合你：★★★★☆**

---

**5. 最后才看：vLLM 官方源码/文档**

⁠vLLM 官方文档

现在的 vLLM 已经非常复杂，包含 PagedAttention、Continuous Batching、Chunked Prefill、Prefix Cache、CUDA Graph、各种量化、FlashAttention/FlashInfer/Triton、Speculative Decoding、PD 分离，以及 Tensor/Pipeline/Data/Expert/Context Parallelism 等。 

所以我**强烈不建议第一天直接读 vLLM**。

否则很容易变成：

```text
Scheduler
EngineCore
Worker
ModelRunner
KVCacheManager
AttentionBackend
...
```

每个类都知道“干什么”，但不知道：

**为什么推理系统必须设计出这个东西？**

等你自己的 mini-engine 做出来以后再读，感觉会完全不同。

**现在：★★☆☆☆**

**完成 mini-vLLM 后：★★★★★**
