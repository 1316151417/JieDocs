# 01–05 睡前巩固

睡前重点巩固这条主线：**TS 描述数据形状 → 模块组织代码 → Node 执行代码 → 异步协调任务 → fs/path/process 操作本地环境。**

下面这份大约 5 分钟能过一遍。

1. **01｜TypeScript：分清“类型”和“运行时的值”**

   TS 在 JS 上加了编译期类型检查。`interface`、类型标注、泛型会被擦除；**`as User` 只是告诉编译器相信你，不会转换或校验数据**。外部 JSON、LLM 响应仍要做运行时检查。

   TS 主要按**形状**匹配类型：有要求的字段和方法即可，不必先继承或 `implements`。读源码时，先看参数要求什么形状。

   Agent 里最关键的建模方式是 **判别联合**：用 `type: "success" | "error"` 等真实字段区分变体，`switch` 收窄类型，`never` 检查是否漏了分支。

   高频语法只记三个区别：`?.` 遇到空值短路；`??` 只对 `null/undefined` 兜底；`...` 展开对象时是浅拷贝，后面的字段覆盖前面的。

2. **02｜模块：看 import，就能开始追依赖**

   模块内部的名字通过 `export` 对外开放，再由其他文件 `import`。`import type` 只引入类型，编译后消失；普通 import 可以引入运行时的值。

   先认清三类路径：

   - `./tool.js`：项目内文件；常见 TS 编译流程里写的是**产物路径**，源码可能是 `tool.ts`。
   - `@scope/pi-ai`：包名，结合 `node_modules` 和包的 `exports/main` 找入口。
   - `node:fs`：Node 内置模块。

   `import/export` 属于 ESM；`require/module.exports` 属于 CJS。看到 `index.ts` 中的 re-export，要继续追到真正实现。

3. **03｜Node：JS 单线程，I/O 可以并发**

   **Node = V8 执行 JS + libuv 协调 I/O + 核心模块。**

   默认主线程上的 JS 一段一段执行；等待网络、文件操作时，底层 OS 或线程池可以继续工作，完成后再让 JS 处理结果。

   性能判断最重要的一句：**长时间同步工作会占住 JS 线程，让其他回调也等着。**`readFileSync`、大 `JSON.parse`、重 CPU 循环都可能造成这种阻塞。给函数加 `async`，不会把计算搬到另一个线程。

4. **04｜异步：启动、等待、组合、取消是四件事**

   调用普通 `async` 函数就开始执行，直到第一个 `await`；**不 await，也已经启动了**。`await` 暂停当前函数，让其他任务有机会执行；恢复时，共享状态可能已经变了。

   四个组合子记成：

   | 写法 | 核心语义 |
   |---|---|
   | `all` | 全成功才成功；一个失败就整体失败 |
   | `allSettled` | 等全部结束，分别收集成败 |
   | `race` | 采用最先结束的结果，无论成败 |
   | `any` | 采用最先成功的结果 |

   **这些组合子不会自动取消剩余任务。**取消靠 `AbortController` 发信号、`AbortSignal` 沿调用链传递，操作需要配合响应。

   Agent 中看到 `for await...of`，想到逐段消费 token 或其他异步数据；看到裸调异步函数或 `void foo()`，想到：**错误由谁接住？**

5. **05｜本地环境：路径到底相对于哪里？**

   `fs` 操作文件，`path` 处理路径，`process` 提供进程信息。

   **`cwd` 是当前工作目录，模块目录是代码文件所在目录。**用户给的相对文件路径通常以会话工作目录为锚点；随代码分发的模板、资源以模块目录为锚点。

   `path.join` 拼接并规范化路径；`path.resolve` 得到绝对路径。**得到绝对路径不等于完成权限或沙箱校验。**

   小细节记住：`readFile(p, "utf8")` 返回文本，不传编码返回 `Buffer`；命令行参数通常取 `argv.slice(2)`；环境变量是字符串或 `undefined`；`process.exit()` 立即退出，可能截断待完成的输出。

**最后闭眼自测，能答出这 5 个问题就够了：**

- `JSON.parse(raw) as User` 校验数据了吗？——**没有。**
- 不 await 一个 async 函数，它会开始执行吗？——**会。**
- `await` 会阻塞 JS 线程吗？——**不会；但右侧的同步计算仍会。**
- `Promise.all` 中一个失败，其他任务会停吗？——**不会。**
- 相对文件路径默认相对于源码目录吗？——**相对于当前工作目录。**

把它们放回 Agent 中，就是：**组织消息 → 调 LLM → 消费流 → 执行工具 → 把结果放回消息 → 再调 LLM。**你今天学的 01–05，已经覆盖了理解这条链路的基本语言和运行机制。
