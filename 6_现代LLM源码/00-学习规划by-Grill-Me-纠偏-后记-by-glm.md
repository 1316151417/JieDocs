# 后续行动规划（极简版）

## 主原则
**业务是主线，AI 是每周固定一小块的维护线。盒子不能变大。**

## 时间结构
- 默认所有时间 → 业务 + 休息
- 每周一个周末上午（3~5h）→ AI，保连续、不保量

## 收尾动作：接下来 3 个周末，做完宣布战役结束
1. **KV Cache 实验**：在 llama2.c 的 `run.c` 上对比有无缓存的生成耗时 + 显存增长，配一页 GQA 笔记
2. **费曼缺口自测**：RoPE（性质级）、BPE（行为级）口头过一遍，卡壳回翻；然后把实验 repo 挂上 GitHub（README 写清三个对比实验）
3. **可选**：vLLM 本地起小模型拨参数看吞吐；或直接休整

## 停止清单（显式冻结，不留心理欠债）
- 从零写 train.py → 兴趣项目，无 deadline
- 组件消融实验 → 不做
- DeepSeek V3 / Qwen 专题 → 继续后移
- 分享材料 → v6 冻结，不出 v7
- 发表文章 → 等有精力，repo 已是证据主体
- 第二场分享 → 可做可不做；要做就把 KV Cache 实验放进去

## 方向（以年计，不着急）
- **主线**：Agent / 应用工程。重点学 tool call、RAG、**评测（evals，最稀缺的核心技能）**
- **深度线**：推理系统。路径：KV Cache → vLLM/PagedAttention → 量化
- **远期可选**：后训练/数据工程——经应用侧站稳后够到，门没锁；评测做深本身就是标签

## 业务里的唯一动作（一石二鸟）
在新业务中主动找 **1~2 个 AI 落地点**（日志分类、测试生成、文档问答，再小也行）——既是业务绩效，也是转方向的履历证据。

## 每季度 10 分钟自检
1. 我对数据/评测的兴趣是否持续高于做应用？→ 是，则重新加权
2. 业务里是否出现了 AI 落地机会？
3. 每周一小块的节奏还在吗？

---

一句话版：**三个周末收完尾，然后精力还给业务；AI 每周一小块，主线应用、深度推理，评测主动认领，业务里找落地。**
