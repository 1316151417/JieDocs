# 现代 LLM 深度学习路线图

## 目标

以长期认知与学习能力为核心，而非短期转岗焦虑。

通过理解机器如何学习，训练自己分析复杂系统、提出假设、用证据修正判断的能力。职业选择、Agent 项目和作品集是这条学习线的自然副产物。

首个阶段目标：在 6–9 个月完成一个公开、可复现的“小型 Llama 全链路实验”。

## 时间与资源

- 每周投入：约 15 小时
- 本地设备：3080 8GB
- 云算力总预算：¥1,000 以内
- 原则：本地完成调试和小模型实验；云端只用于验证明确假设，不追求训练出商用能力的大模型。

## 学习结构

- 70%：LLM 原理、源码、实现和实验
- 20%：由当前问题触发的数学基础
- 10%：日常反思与跨领域迁移

跨领域迁移不是生搬硬套模型概念，而是识别其假设、证据和失效条件。例如，机器学习强调高质量、多样化数据与对困难样本的持续训练，这可以启发个人的信息输入与刻意练习设计。

## 核心方法：三角验证

每个核心主题都经过三层验证：

1. 阅读原始论文或高质量讲解，理解问题与设计动机。
2. 阅读源码，确认真实实现、张量维度和工程细节。
3. 亲手修改一个变量，用最小实验观察结果。

每个模块必须回答：

1. 它解决了什么问题？
2. 数学上发生了什么？
3. 代码和张量维度上如何实现？
4. 删除、替换或改变它后，会如何影响训练稳定性、速度、显存与生成质量？

## 阶段路线

| 阶段 | 时间 | 学习重点 | 验收产出 |
|---|---:|---|---|
| 1. 现代架构 | 4–6 周 | RMSNorm、RoPE、SwiGLU、GQA、KV Cache、预归一化与残差路径 | 模块解释笔记、最小实现、替换/消融实验 |
| 2. 小模型预训练 | 6–8 周 | Tokenizer、数据清洗与打包、Llama 风格 Decoder、训练循环、采样生成 | 30M–60M 小模型完成预训练；稳定的 train/valid loss 曲线 |
| 3. 微调 | 4–6 周 | SFT、LoRA、数据格式、训练目标与过拟合诊断 | 一个窄任务微调模型；全参微调与 LoRA 对比 |
| 4. 推理与量化 | 4–6 周 | KV Cache、批处理生成、INT8/INT4 量化、部署 | 显存、速度、延迟、质量退化对比报告 |
| 5. 收口沉淀 | 2–3 周 | 可复现性、文档、实验结论、复盘 | 公开仓库、实验报告、技术文章 |

## 数学最低骨架

数学不需要脱离问题预先学完，但以下主题需要逐步补齐：

- 线性代数：矩阵乘法、向量空间、特征分解、旋转矩阵
- 微积分：导数、偏导、链式法则、梯度
- 概率统计：条件概率、期望、方差、常见分布
- 统计学习：最大似然、交叉熵、KL 散度
- 优化：梯度下降、Adam、初始化、数值稳定性

遇到 RoPE 就补复数和旋转矩阵，遇到训练不稳定就补优化与数值分析；保持“问题驱动的向下挖掘”。

## 最小评测原则

不以研究 Benchmark 为目标，但每个实验必须有判断依据：

- 训练与验证损失
- 固定提示词集
- 小型目标任务集
- 微调后的任务指标
- 量化前后的质量、显存、吞吐和延迟

评测是实验的仪表盘，不是独立赛道。

## 每周节奏

- 10.5 小时：论文、源码、实现和实验
- 3 小时：当前问题对应的数学补课
- 1.5 小时：实验日志、技术笔记与日常反思

建议每 8–12 周复盘一次：

- 哪些概念能独立推导、实现和解释？
- 哪些实验结论有数据支撑？
- 哪些数学短板反复阻塞理解？
- 下一阶段应继续深入，还是调整主线？

## 算力使用原则

- 前两阶段优先使用本地显卡。
- 先验证极小模型、极小数据和极短训练流程正确。
- 云端训练只服务于规模、上下文长度或训练策略的对比。
- 预算可暂定为：¥300 预训练扩展实验、¥300 微调对比、¥200 推理实验、¥200 缓冲。
- 不把“训练出强模型”作为成功标准；以“能解释、复现、修改和验证机制”为标准。

## 当前聚焦

停止无边界地新增 Agent 框架知识。除非直接服务于主项目，否则先记录在“以后再学”列表。

当前最高杠杆是：把已经掌握的 Transformer、GPT 和现代 LLM 组件连成一条完整链路——能读懂、能实现、能训练、能微调、能部署、能用实验解释结果。
