## LLM 生态系统概述

大家好，在这个视频中我想继续我们面向普通观众的大语言模型系列。在上一期关于 LLM 深度解析的视频中（你可以在我的 YouTube 频道找到），我们深入探讨了这些模型训练的底层原理，以及你该如何理解它们的认知或"心理"。现在在这个视频中，我想谈谈这些工具的更实际的应用。我会向你展示大量案例，带你了解所有可用的设置，并展示我是如何使用这些工具的，以及你如何在自己的生活和工作中使用它们。让我们开始吧。

## ChatGPT 交互的底层原理

与语言模型最基本的交互方式是：我们给它文本，然后它返回一些文本作为回应。例如，我们可以让它写一首关于"成为大语言模型是什么感觉"的俳句。这是一个很好的提问范例，因为这些模型非常擅长写作——无论是写俳句、诗歌、求职信、简历还是邮件回复，它们都很在行。

当我们提出这样的请求时，实际发生的事情如下：模型会回应，"词语如流无尽回响，无念之思不可见"——好吧，相当有戏剧性。但我们在 ChatGPT 中看到的是看起来有点像你与朋友的对话——像聊天气泡一样。

我们在上一期视频中了解到，在底层发生的事情是：我们有一段文本（用户查询），这段文本以及模型的回答都被切分成小块的文本块，我们称之为 token。所以这段文本序列在底层是一个一维的 token 序列。

我们可以看到这些 token 的方法之一是使用像 Tiktokenizer 这样的应用。确保选中了 GPT-4o，我可以把我的文本粘贴进去，这就是模型在底层实际看到的东西。我的这段文本对模型来说是一个恰好 15 个 token 的序列，这些就是模型看到的小文本块。这里的词汇表大约有 200,000 个可能的 token，而这些是与我查询中所有小文本块对应的 token ID。你可以尝试编辑，会看到它是大小写敏感的——你会得到不同的 token。你可以实时编辑并观察 token 序列的变化。

所以我们的查询是 15 个 token，模型的回答是恰好 19 个 token 的序列。所以那首俳句就是这个 19 个 token 的序列。

现在因为这是一个对话，我们想要维护构成对话对象的许多元数据，所以底层的实际情况会更复杂一些。我们在上一期视频中了解了一些关于对话格式的内容。事情变得更复杂了，因为我们必须采用我们的用户查询，并使用所谓的聊天格式。

让我删除系统消息——我认为它对理解底层机制不太重要。让我把我的消息作为用户粘贴进去，然后把模型的回答作为助手粘贴进去。这个工具在这个操作上不太准确，让我适当地裁剪一下。这就是底层的实际情况：有各种特殊 token，基本上标记了来自用户的消息开始，然后用户说的话是具体内容，然后用户结束，然后助手开始并说了这些话，等等。

对话格式的精确细节并不重要。我想传达的是：在你看来的来回聊天气泡，在底层是我们在与模型协作，共同写入一个 token 流。这两个来回的气泡在底层是恰好 42 个 token 的序列——我贡献了前面的一些 token，然后模型继续了这个 token 序列并给出了回答。我们可以交替地继续向这里添加 token。我们在一起构建一个 token 窗口——一个一维的 token 序列。

让我们回到 ChatGPT。我们看到的是我们和模型之间的聊天气泡来来回回。在底层，我们正在构建一个一维的 token 序列。当我点击"新聊天"时，这会清空 token 窗口，将 token 重置为零，从头开始对话。

当我和模型对话时，我脑海中的示意图是这样的：当我们点击"新聊天"时，我们开始一个 token 序列——一个一维的 token 序列。用户——我们可以将 token 写入这个流，然后当我们按下回车键时，我们将控制权移交给语言模型，语言模型用自己的 token 流进行回应。然后语言模型有一个特殊的 token，基本上说类似"我完成了"的意思，当它发出那个 token 时，ChatGPT 应用将控制权交还给我们，我们就可以轮流交替。我们一起构建了 token 流，我们也称之为上下文窗口。

所以上下文窗口就像是这个对话的工作记忆，由 token 组成。在这个上下文窗口内的任何东西都处于这个对话的工作记忆中，可以被模型非常直接地访问。

那么我们在对话的这个实体是什么，我们应该如何理解它呢？这个语言模型——我们在上一期视频中看到了它的训练方式，有两个主要阶段：预训练阶段和后训练阶段。

预训练阶段就像把整个互联网的内容切分成 token，然后将其压缩成一个类似 zip 文件的单一文件。但这个 zip 文件不是精确的——它是有损的、概率性的 zip 文件。因为我们不可能用仅仅一个比如说 1TB 的 zip 文件来表示整个互联网——信息太多了。所以我们只是获得了互联网的"要旨"或"感觉"。

这个 zip 文件内部实际上是神经网络的参数。例如，一个 1TB 的 zip 文件大致对应约一万亿个参数。这个神经网络在尝试做的事情是：接收 token 并尝试预测序列中的下一个 token。但它是基于互联网文档来做这件事的，所以它有点像是一个互联网文档生成器。

在预测互联网序列中下一个 token 的过程中，神经网络获得了关于世界的巨量知识，这些知识全部被表示、填充和压缩在语言模型的大约一万亿个参数中。

预训练阶段也是相当昂贵的，可能是数千万美元、大约三个月的训练时间等等。因为这是一个昂贵且漫长的阶段，所以不会经常进行。例如 GPT-4o，这个模型的预训练可能是在很多个月前，甚至可能是一年前完成的。这就是为什么这些模型有些过时——它们有一个所谓的"知识截止日期"，这个知识截止日期对应模型的预训练时间，它的知识只到那个时间点为止。

一些知识可以通过后训练阶段进入模型（我们稍后会谈到），但大致上你应该认为这些模型有些过时，因为预训练太昂贵且不频繁。所以任何最近的信息——比如你想和模型讨论上周发生的事情——我们需要通过其他方式将这些信息提供给模型，因为它不在模型的知识存储中。所以我们会有各种工具使用方式来将这些信息给到模型。

在预训练之后，还有第二个阶段——后训练。后训练阶段实际上就是给这个 zip 文件加上一个"笑脸"。因为我们不想要生成互联网文档，我们想要这个东西扮演一个回答用户查询的助手角色。这是通过后训练过程完成的，我们将数据集替换为由人类构建的对话数据集。这就是模型获得这种"人格"的地方——这样我们就可以提问，它会以答案回应。所以它通过后训练获得了助手的风格，但它拥有整个互联网的知识——这是通过预训练获得的。这两者结合在这个产物中。

对于这一节，我认为重要的是理解：默认情况下，你对话的对象是一个完全自包含的实体。把这个语言模型想象成磁盘上的一个 1TB 文件，它秘密地代表了一万亿个参数以及它们在神经网络中的精确设置，这个网络试图给你序列中的下一个 token。但这是一个完全自包含的实体——没有计算器，没有电脑和 Python 解释器，没有万维网浏览，到目前为止我们所说的都没有任何工具使用。你在与一个 zip 文件对话。如果你向它流入 token，它会用 token 回应你。

这个 zip 文件拥有来自预训练的知识，拥有来自后训练的风格和形式。这就是你大致可以理解这个实体的方式。

好的，如果我要总结我们到目前为止所讨论的内容，我可能会以我认为你应该理解的方式来做 ChatGPT 的自我介绍。这个自我介绍会是："你好，我是 ChatGPT。我是一个 1TB 的 zip 文件。我的知识来自互联网——我在大约六个月前完整地阅读了它，并且我只模糊地记得。我的迷人个性是由 OpenAI 的人类标注员通过示例来编程的。"

所以个性是在后训练中编程的，知识来自预训练中对互联网的压缩。这个知识有些过时，而且是概率性的、稍微模糊的。一些在互联网上被频繁提及的事情我会有好得多的记忆，而一些很少被讨论的事情则不然——这和你对人类预期的非常类似。

那么现在让我们来谈谈这个实体的影响，以及我们如何与之对话，可以期待它能做些什么。

## 基础 LLM 交互实例

现在我想用真实的例子来讲解。例如，今天早上我问 ChatGPT："一杯美式咖啡有多少咖啡因？"我好奇是因为我在和抹茶做比较。ChatGPT 告诉我大约是 63 毫克咖啡因。

我认为问 ChatGPT 这个问题是合适的，原因是：第一，我没有询问任何非常近期的知识——我确实期望模型已经"读过"一杯咖啡有多少咖啡因，我不认为这个信息变化太大。第二，我认为这个信息在互联网上极为常见——这类问题和这类信息在互联网上到处都有。因为有很多相关提及，我期望模型在其知识中对它有很好的记忆。所以这里没有工具使用，模型——这个 zip 文件——回答大约 63 毫克。

我不能保证这是正确答案——这只是它对互联网的模糊记忆。但我可以去查主要来源，也许我可以查一下"咖啡因 美式咖啡"，我可以核实一下，对，大约 63 看起来基本是正确的。你可以查看主要来源来判断这是不是真的。所以严格来说，我不能保证这是真的，但我认为这可能就是 ChatGPT 会知道的那种事情。

这里还有一个我两天前对话的例子——另一个基于知识的对话，以及我放心问 ChatGPT 的事情（有一些注意事项）。我有点不舒服，流鼻涕，想要一些帮助缓解的药物。它告诉了我一堆东西。我想要鼻子不流鼻涕，所以我根据它说的进行了澄清，然后它给出了一些可能有帮助的东西。然后我看了看我家里有的药，我说"DayQuil 或 NyQuil 有用吗？"

它就去查了 DayQuil 和 NyQuil 的成分，以及它们是否有助于缓解流鼻涕。现在，当这些成分出现时，再次记住——我们在与一个对互联网有记忆的 zip 文件对话。我不能保证这些成分是正确的。实际上，我确实把盒子拿出来查看了成分，我确认了 NyQuil 的成分就是这些成分。我这样做是因为我并不完全信任这里输出的内容——这只是对互联网的概率性、统计性的记忆。

但话虽如此，关于 DayQuil 和 NyQuil 的对话——这些是非常常见的药物，互联网上可能有大量的相关信息。这正是模型会有相当好的记忆的那种事情。实际上这些信息都是正确的。然后我说"好的，我有 NyQuil，它大概多久会起效？"它大概告诉我，然后基本上说了"是"。

所以这是一个很好的例子，说明 ChatGPT 对我有用。这是一个基于知识的查询，这些知识不属于近期知识，都来自模型的知识储备。我认为这是常见的信息，这不是一个高风险的情况。我稍微验证了一下 ChatGPT，但这不是一个高风险的情况，所以没什么大不了的。我吃了一粒 NyQuil，确实有帮助。这就是我对这里发生的事情的大致思考过程。

好的，在这一点上我想做两个说明。第一个说明是：自然地，当你与这些模型交互时，你会看到对话变得越来越长。任何时候你切换话题，我都鼓励你始终开始一个新聊天。当你开始一个新聊天时，正如我们讨论过的，你在清空 token 的上下文窗口，将其重置为零。如果那些 token 对你的下一个查询不再有用，我鼓励你这样做，因为这个窗口中的 token 是昂贵的。

它们的昂贵体现在两个方面。第一，如果你在这里有很多 token，模型可能会觉得有些分散注意力。如果有很多 token，模型可能会被过去的所有 token 分散注意力——当它在后面尝试采样 token 时。所以它可能会分散注意力，这可能会降低模型的准确性和性能。第二，窗口中的 token 越多，采样序列中下一个 token 的成本就越高——不是高很多，但会高一点。所以你的模型实际上会稍微变慢，计算下一个 token 变得更昂贵、token 越多越贵。

所以把上下文窗口中的 token 视为一种珍贵的资源，把它当作模型的工作记忆，不要用过量的无关信息使其超载，尽可能保持它简短。你可以期待它工作得更快、表现更好。当然，如果这些信息确实与你的任务相关，你可能想保留它。但我鼓励你尽可能经常地在切换话题时开始一个新聊天。

## 注意你正在使用的模型和定价层级

第二件事是，我总是鼓励你留意你实际上正在使用哪个模型。在左上角的这里，我们可以下拉，看到我们当前正在使用 GPT-4o。现在有很多不同风格的不同模型——实际上太多了——但我们会逐步了解其中的一些。

所以我们正在使用 GPT-4o，我向你展示的一切都是 GPT-4o 的结果。现在，当我打开一个新的无痕窗口——所以如果我去 chatgpt.com 并且我没有登录——我正在对话的模型可能不是 GPT-4o，它可能是一个更小的版本。不幸的是，打开无痕窗口时它不会告诉我我在使用什么模型，这有点遗憾。但很可能你正在使用一个更小的、更"笨"的模型。

如果我们去看 ChatGPT 的定价页面，我们看到他们对个人用户有三个基本层级：免费版、Plus 版和 Pro 版。在免费版中，你可以访问所谓的 GPT-4o mini。这是 GPT-4o 的一个更小版本——参数量更少，不会那么有创造力，写作可能没那么好，知识没那么好，可能会产生更多幻觉等等。但这是免费提供的。他们确实说你对 4o 和 4o mini 有有限的访问权限，但我不是 100% 确定——就像它没有告诉我们正在使用哪个模型一样，所以我们根本上就是不知道。

当你每月支付 20 美元时——尽管页面上没有这样说——我认为他们对他们如何描述这一点处理得不好。但如果你去看小字"限制适用"，我们可以看到 Plus 用户每 3 小时可以获得 80 条 GPT-4o 的消息。这是截至今天可用的旗舰最大模型——这就是我们想要使用的。如果你每月支付 20 美元，你就有这个，有一些限制。然后如果你每月支付 200 美元，你获得 Pro 版，有一堆额外的福利以及无限的 GPT-4o 使用。我们会深入其中一些，因为我确实支付了 Pro 订阅。

我想让你从中学到的整体要点是：留意你正在使用的模型。通常对于这些公司来说，更大的模型计算成本更高，因此公司对更大的模型收费也更高。根据你对 LLM 的使用情况来做这些权衡决定。看看你是否可以用更便宜的产品应付过去。如果智能程度对你来说不够好，而且你在专业上使用它，你可能真的想考虑为这些公司提供的顶级模型付费。

就我的情况而言，在我的专业工作中，我进行大量的编程和类似的事情，这对我来说仍然非常便宜，所以我非常乐意支付这个费用，因为我可以访问一些非常强大的模型，我稍后会向你展示。

所以，是的，跟踪你正在使用的模型，并为自己做出这些决定。

我还想向你展示，所有其他的 LLM 提供商都会有不同的定价层级，不同层级有不同的模型可供你付费使用。例如，如果我们去看 Anthropic 的 Claude，你会看到我正在支付专业计划，这让我可以访问 Claude 3.5 Sonnet。如果你没有支付 Pro 计划，那么你可能只能访问 Haiku 或者类似的东西。所以，使用对你来说最有效的、最强大的模型。

这里有一个我之前使用 Claude 的例子：我只是在问旅行建议。我在问一个很酷的城市去旅行，Claude 告诉我瑞士的采尔马特非常棒，所以我最终去那里过了新年假期，听从了 Claude 的建议。这只是另一个例子，说明我发现这些模型对旅行建议和创意构思也相当有用——给你一些可以进一步研究的指引。

这里我们还有一个 gemini.com 的例子——这是 Google 的。我向 Gemini 询问了对这个问题的看法，我问它推荐一个很酷的城市去旅行，它也推荐了采尔马特。这很好。所以我喜欢在不同的模型之间切换，问它们相似的问题，看看它们各自怎么想。对于 Gemini，同样在左上角也有一个模型选择器，你可以付费使用更高级的层级来使用那些模型。

Grok 也是这样——刚发布。我们不想问 Grok 2 问题，因为我们知道 Grok 3 是最先进的模型。所以我想确保我付了足够的钱来获得 Grok 3 的访问权限。所以对于所有这些不同的提供商，找到最适合你的那个，针对你正在处理的问题尝试不同的提供商和不同的定价层级。

而且我经常最终自己为很多个都付了费，然后把同样的问题问给所有模型。我把所有这些模型称为我的"LLM 委员会"——所以它们就像是一个语言模型委员会。如果我在想办法决定去哪里度假，我会问它们所有模型。如果你觉得对你有用的话，你也可以这样做。

## 思考模型以及何时使用它们

好的，下一个我想转向的话题是所谓的"思考模型"。我们在上一期视频中看到，训练有多个阶段：预训练，然后是有监督微调，然后是强化学习。强化学习是模型在大量类似教科书练习题的问题上进行练习的阶段。它可以在大量数学和编程问题上进行练习。

在强化学习的过程中，模型发现了导致良好结果的思考策略。这些思考策略，当你观察它们时，它们非常类似于你在解决问题时的内心独白。所以模型会尝试不同的想法，会回溯，会重新审视假设，会做类似的事情。

现在，很多这些策略对人类标注员来说非常难以硬编码，因为不清楚思考过程应该是什么。只有在强化学习中，模型才能尝试大量的东西，并找到适合它的知识储备和能力的思考过程。

所以这是训练这些模型的第三个阶段。这个阶段相对较新，只有一两年左右。所有的 LLM 实验室在过去一年里都在试验这些模型。这被视为最近的一个重大突破。我们在此看了 DeepSeek 的论文，他们是第一个公开讨论这个问题的，他们有一篇很好的论文叫《通过强化学习激励 LLM 中的推理能力》——这就是我们在上一期视频中看的那篇论文。

所以我们现在需要稍微调整我们的示意图。因为现在我们的表情符号有了这个可选的"思考气泡"。当你使用一个会进行额外思考的思考模型时，你正在使用一个额外经过强化学习调优的模型。

从质的角度来看这是什么样子呢？从质的角度来看，模型会做更多的思考。你可以期待的是，你会得到更高的准确率，特别是在诸如数学、编程和需要大量思考的问题上。非常简单的任务可能不会从中受益，但那些真正深入和困难的问题可能会受益很多。

但你为此付出的代价是，模型会进行思考，这有时可能需要好几分钟——因为模型会在很多分钟的时间里发出大量的 token，你必须等待，因为模型在思考，就像人类会思考一样。但在你有非常困难的问题的情况下，这可能转化为更高的准确率。

让我们看一些例子。这里有一个具体的例子：我最近在一个编程问题上卡住了。有个东西叫"梯度检查失败"，我不确定为什么。我把我的代码复制粘贴给了模型。

代码的细节不重要，但这基本上是一个多层感知机的优化。细节不重要——这是我写的一堆代码，里面有个 bug，因为我的梯度检查没有通过。我只是在寻求建议。GPT-4o——这是 OpenAI 的旗舰最强大模型，但没有思考能力——它给了一堆它认为可能是问题或我应该仔细检查的事情，但实际上并没有真正解决问题。它给我的所有东西都不是问题的核心，所以模型并没有真正解决问题。它告诉我如何调试等等。

但是，然后我所做的是在下拉菜单中，我切换到一个思考模型。对于 OpenAI，所有以"o"开头的模型都是思考模型：o1、o3-mini、o3-mini-high 和 o1 Pro——这些都是思考模型。他们不太擅长命名模型，但这就是事实。

这里它们会说"使用高级推理"或"擅长编程和逻辑"之类的东西，但这些基本上都是用强化学习调优过的。因为我每月支付 200 美元，我可以访问 o1 Pro 模式，这是推理能力最好的模式。但根据你的定价层级，你可能会想尝试其他的。

当我把完全相同的提示词给 o1 Pro——这是推理能力最好的模型，你需要为此每月支付 200 美元——完全相同的提示词，它思考了 1 分钟，经过了一系列的思考，OpenAI 没有完整展示确切的思考过程，他们只是给出思考的小摘要。但它思考了这段代码一会儿，然后实际上返回了正确的解决方案。它注意到参数不匹配，以及我是如何打包和解包它们的等等。所以这实际上解决了我的问题。

我尝试将完全相同的提示词给其他一堆 LLM。例如，Claude——我给了 Claude 同样的问题，它实际上注意到了正确的问题并解决了它。它甚至用 Sonnet 就做到了，而 Sonnet 不是思考模型——据我所知，Claude 3.5 Sonnet 不是思考模型，而且据我所知，Anthropic 截至今天还没有部署思考模型，但这可能在你看到这个视频的时候已经改变了。但即使没有思考，这个模型也解决了问题。

当我去 Gemini 时，我问了它，它也解决了问题——尽管我也可以尝试思考模型，但不需要。我也给了 Grok——这次是 Grok 3——Grok 3 在一堆内容之后也解决了问题。所以它也解决了问题。

最后我去了 perplexity.ai。我喜欢 perplexity 的原因之一是，当你去模型下拉菜单时，他们托管的模型之一是 DeepSeek R1——所以这有 DeepSeek R1 模型的推理能力，这就是我们之前看到的那篇论文中的模型。Perplexity 只是托管了它，让它非常容易使用。所以我把它复制粘贴到那里，运行了它。我认为他们渲染得很糟糕，但在这里你可以看到模型的原始思维过程。即使你必须展开它们。你会看到"好的，用户在梯度检查方面遇到困难"，然后它尝试了一堆东西，然后说"但是，等等，当他们累积梯度时，他们做的方式不对。让我们检查一下——参数的打包顺序是这样的"，然后它注意到了问题，然后它说"那是一个关键错误"。所以它基本上思考了一遍，你需要等待几分钟，然后它也得出了正确的答案。

所以基本上，长话短说，我想向你展示的是：存在一类我们称之为思考模型的模型。所有不同的提供商可能有也可能没有思考模型。这些模型对数学、编程等方面的困难问题最有效。在这些情况下，它们可以提高你的表现准确率。

在很多情况下——如果你在问旅行建议或类似的事情——你不会从思考模型中受益。没有必要等一分钟让它思考一些你可能想去的目的地。所以对我自己来说，我通常先尝试非思考模型，因为它们的响应非常快。但当我觉得回复可能不够好，想给模型一个机会更长时间地思考时，我会切换到思考模型——取决于你有哪个可用的。

当你去 Grok 时，例如，当我与 Grok 开始一个新对话时，当你把问题放在这里时，你会看到这里有一个"Think"——让模型花时间思考。所以打开"Think"，然后点击发送。当你点击"Think"时，Grok 在底层会切换到思考模型。所有不同的 LLM 提供商都会有某种选择器，让你选择是否希望模型思考，或者是否可以直接使用之前那代模型来回答。

## 工具使用：互联网搜索

好的，下一节我想继续讲的是工具使用。到目前为止，我们只通过文本与语言模型对话。这个语言模型还是那个文件夹里的 zip 文件——它是惰性的、封闭的，没有任何工具，只是一个可以发出 token 的神经网络。

但现在我们想做的是超越这个，我们想给模型使用一堆工具的能力。最有用的工具之一就是互联网搜索。那么让我们看看如何让模型使用互联网搜索。

举个例子，再次使用我生活中的具体实例。几天前我在看《白莲花度假村》第三季——我看了第一集，顺便说一下我非常喜欢这个电视剧。我很好奇第二集什么时候出。

在旧世界里，你会想象你去 Google 之类的，输入"白莲花度假村第三季新剧集"，然后你开始点击这些链接，也许打开其中几个，搜索一番，试图弄明白——有时候你会找到一份排期表。但很多时候你可能会遇到非常疯狂的广告，一堆随机的东西，这只是一个不太愉快的体验，对吧？

所以如果有一个模型能替你进行这种搜索，访问所有这些网页，然后取所有那些网页的内容，塞进上下文窗口，然后基本上给你答案，那不是很好吗？这就是我们现在要做的。

基本上我们引入了一种机制，让模型发出一个特殊的 token，某种"搜索互联网"的 token。当模型发出这个"搜索互联网"token 时，ChatGPT 应用或你正在使用的任何 LLM 应用会停止从模型采样，它会取模型给出的查询，去执行搜索，访问网页，获取所有文本，把它们全部放入上下文窗口。

所以现在你有了这个互联网搜索工具，它本身也可以向我们的上下文窗口贡献 token。在这种情况下，可能是很多个互联网网页——也许有 10 个——也许它只是把它们全部放在一起。这可能是来自这些网页的数千个 token，就像我们自己去看它们一样。

然后，在它将所有这些网页插入到上下文窗口之后，它会回溯到你最初的问题——"嘿，这一季什么时候发布？"——它就能引用文本并给你正确答案。

注意，这是一个很好的例子，说明为什么我们需要互联网搜索。没有互联网搜索，这个模型根本没有机会给我们正确答案。因为像我提到的，这个模型是几个月前训练的，当时可能还不知道排期。所以《白莲花度假村》第三季什么时候出这个信息不在模型的真实知识中，很可能不在 zip 文件中。因为这是大概在过去几周内决定的事情。所以模型必须去执行互联网搜索来获取这个知识——它就像你我一样从网页中学习这些知识。然后一旦这些信息在上下文窗口中，它就能回答问题。

记住，上下文窗口是这个工作记忆。所以一旦我们加载了这些文章——把它们想象成它们的文本被复制粘贴到了上下文窗口中——现在它们在工作记忆中，模型就可以回答这些问题了，因为它们在上下文窗口中。

所以长话短说：不要手动做这个，而是使用像 Perplexity 这样的工具。比如，perplexity.ai 有一个非常好的 LLM 在进行互联网搜索，我认为它是第一个真正令人信服地做到这一点的应用。最近 ChatGPT 也引入了一个搜索按钮，写着"搜索网页"——我们马上会看到。

现在，"白莲花度假村第三季新剧集什么时候出？"你可以直接问，而不必手动操作。我们只需按回车，模型就会访问这些网页，创建所有查询，然后给你答案。所以它基本上为你做了大量的工作。通常会有引用来源，所以你可以自己去访问这些网页，你可以确保这些不是模型的幻觉，你可以实际上再确认这是否正确——因为原则上这是不能保证的。

如果我们把这个带到例如 ChatGPT，说同样的话。但是现在当我不选择搜索而提出这个问题时，我不是 100% 确定模型会做什么。在某些情况下，模型实际上会知道这是近期知识，它可能不知道，它会创建一个搜索。在某些情况下，我们必须声明我们想要搜索。在我自己的使用中，我会知道模型不知道，所以我就会选择搜索。但让我们先看看会发生什么。

好的——搜索网页，然后它输出内容，然后给出引用。所以模型自己检测到它需要搜索网页，因为它理解这是某种近期信息。所以这是正确的。另外，如果我创建一个新对话，我也可以选择搜索，因为我知道我需要搜索，按回车，然后它做同样的事情——搜索网页，这就是结果。

所以基本上，当你在使用这些 LLM 时，寻找这个功能。例如 Grok——我来试试 Grok。不选择搜索。好的，模型做了一些搜索——它就是知道它需要搜索——然后给你答案。所以基本上，来看看 Claude 做了什么。你看，Claude 确实有搜索工具可用。它会说"根据我截至 2024 年 4 月的最近更新"——这最近更新是模型进行预训练的时间。所以 Claude 只是说，根据它的最近更新，知识截止到 2024 年 4 月，这被宣布了但它不知道。所以 Claude 没有集成的互联网搜索选项，不会给你答案。我预计这是 Anthropic 可能正在做的事情。

让我们试试 Gemini 看看它说什么。"不幸的是，白莲花度假村第三季还没有官方发布日期。"所以 Gemini 2.0 Pro Experimental 没有访问互联网搜索的能力，不知道。我们可以试试其他的，比如 2.0 Flash——让我试试。好的，所以这个模型似乎知道，但它没有给出引用。哦等等，好的，有了——"来源和相关内容"。所以我们看到 2.0 Flash 实际上有互联网搜索工具。但我猜 2.0 Pro——他们最强大的模型——这个实际上没有访问权限，它在这里告诉我们"2.0 Pro Experimental 缺乏对实时信息和某些 Gemini 功能的访问"。所以这个模型没有完全接上互联网搜索。

所以长话短说：我们可以让模型为我们执行 Google 搜索，访问网页，把信息拉入上下文窗口，然后回答问题。这是一个非常非常酷的功能。但不同的模型——可能是不同的应用——对这种能力的集成程度不同。所以你必须留意这一点。有时模型会自动检测到它们需要搜索，有时你最好告诉模型你想要它搜索。所以当我在用 GPT-4o 且我知道这需要搜索时，你可能会勾选那个框。

好的，这就是搜索工具。我想再展示几个我如何在工作中使用搜索工具的例子。我使用哪些类型的查询？这对我来说相当容易做到，因为对于这类情况，我习惯性会去 Perplexity——即使今天的 ChatGPT 也能做这类事情，其他很多服务可能也可以，但我碰巧对这些搜索类查询使用 Perplexity。

所以任何时候我期望答案可以通过基本上 Google 搜索和访问几个顶部链接来获得，而且答案在那些顶部链接的某处——每当是这种情况时，我就期望使用搜索工具，我就会去 Perplexity。这里有一些例子。

今天股市开盘吗？这是一个前所未闻的日子，我不是 100% 确定。所以 Perplexity 理解了今天是哪一天，做了搜索，搞清楚了这是总统日——休市。

《白莲花度假村》第三季在哪里拍摄？这又是一件我不确定模型会在其知识中知道的事情——这有点小众，也许在互联网上没有那么多提及。而且这更近期，所以我默认不期望模型知道。所以这很适合搜索工具。

Vercel 提供 Postgres 数据库吗？这是一个很好的例子，因为这类东西会随时间变化。Vercel——一家公司——的提供内容可能会随时间变化，我想要最新的。任何时候当某件事是最新的或会变化的，我更倾向于使用搜索工具，所以我去 Perplexity。

苹果明天发布什么？有哪些传言？再次，这是近期的事情。

《单身即地狱》第四季演员阵容在哪里？必须知道——这又是一个很好的例子，因为这是非常新鲜的信息。

为什么 Palantir 股票在涨？是什么推动了热情？

《文明 7》什么时候出？完全正确。

还有一个例子："Brian Johnson 有谈到他用的牙膏吗？"我很好奇，我基本上喜欢 Brian 做的事情。这又具有两个特征：第一，这有点深奥，所以我不是 100% 确定这在互联网上是否有足够规模，会成为模型知识的一部分。第二，这可能随时间变化。所以我想知道他最近用什么牙膏。所以这又很适合搜索工具。

去越南旅行安全吗？这可能会随时间变化。

然后我在 Twitter 上看到一堆关于 USAID 的东西，我想知道到底是怎么回事。所以我搜索了它，然后你可以以多种方式深入进去。这个用例差不多是这样的：我看到一些热门的东西，我好奇发生了什么——大概的要点是什么。所以我经常很快地调出一个搜索来看看发生了什么事，然后让模型给我一个大致发生了什么的大概。因为很多单独的推文或帖子可能本身没有完整的背景。

这些就是我使用搜索工具的例子。

## 工具使用：深度研究

好的，接下来我想告诉你一个叫"深度研究"的功能。这是相当近期的，大概只有一两个月前。但我认为它非常酷，非常有趣，而且不知为何很多人没有注意到——即使我觉得不应该被忽视。

当我们看 ChatGPT 定价页面时，我们注意到深度研究被列在 Pro 版下面。所以目前它需要每月 200 美元——这是最高层级。但是，我认为它非常酷，所以让我用例子向你展示哪些场景下你可能会想使用它。

大致来说，深度研究是互联网搜索和思考的结合，并且运行很长时间。模型会花几十分钟做深度研究。第一个宣布这个的公司是 ChatGPT，作为其 Pro 服务的一部分，大概一个月前非常近期。

所以这里有一个例子。最近我在网上买补剂——我知道这有点疯狂。但 Brian Johnson 有这个"启动套装"，我很好奇。里面有个东西叫"长寿混合物"，有一堆健康活性成分，我想知道这些东西是什么。当然，像"Ca-AKG"——这到底是什么？"提升能量生产，持续活力"——这是什么意思？

当然，你可以做的一件事是打开 Google 搜索，看维基百科页面或类似的东西，做你习惯的一切。但深度研究让你可以采取另一种路径，它为你处理大量信息，并更好地解释它。

作为一个例子，我们可以这样做——这是一个示例提示词："Ca-AKG 是 Brian Johnson 蓝图中的一种健康活性成分，每份 2.5 克。你能对 Ca-AKG 做研究吗？告诉我为什么它可能出现在长寿混合物中，它在人类或动物模型中的可能功效，它的潜在作用机制，任何潜在的担忧或毒性或类似的东西。"

现在，这里有一个按钮可供我使用——你不会有的，除非你现在每月支付 200 美元——但我可以开启深度研究。所以让我复制粘贴这个并点击发送。

现在模型会说"好的，我要研究这个"，有时它会在开始之前问一些澄清问题。所以"关注人类临床研究，动物模型，还是两者都要？"——我们说两者都要。"特定来源？"——所有来源。"与其他长寿化合物的比较？"——不需要比较，只要 Ca-AKG。"我们可以相当简洁"——模型理解。我们点击发送。

## 文件上传：向上下文添加文档

所以这里真正有趣的是，我们向 LLM 提供了额外的、具体的文档，这些文档可以在其上下文窗口内引用。所以模型不仅仅依赖于通过其参数和大脑中的知识所拥有的模糊的世界知识。我们实际上给了它具体的文档——就像你我在回答某个问题时参考互联网上的特定文档一样。

我们可以通过互联网搜索或类似工具来做到这一点，但我们也可以自己通过文件上传向这些 LLM 提供具体的文档。我发现这个功能在很多方面都相当有帮助。

## 图像输入：OCR

好的，接下来我想转向的是图像。所以就像音频一样，事实证明你可以用 token 重新表示图像。我们可以将图像表示为 token 流，并让语言模型以与我们之前建模文本和音频相同的方式来建模它们。

最简单的可能方式是，例如，你可以取一张图像，基本上创建一个矩形网格，将其切分成小块。然后图像就是一系列小块。你将每个小块量化——所以你基本上创建一个例如 100,000 个可能小块的词汇表。你使用词汇表中最接近的小块来表示每个小块。

这就是让你能够取图像并将其表示为 token 流的方法。然后你可以将它们放入上下文窗口，并用它们训练模型。

这里令人难以置信的是，语言模型——Transformer 神经网络本身——甚至不知道有些 token 碰巧是文本，有些 token 碰巧是音频，有些碰巧是图像。它只是对 token 流的统计模式进行建模。只有编码器和解码器在秘密地知道：好的，图像是以这种方式编码的，然后流以这种方式解码回图像或音频。

所以就像我们处理音频一样，我们可以将图像切分成 token，并应用所有相同的建模技术——什么都没变。只是 token 流变了，token 的词汇表变了。
