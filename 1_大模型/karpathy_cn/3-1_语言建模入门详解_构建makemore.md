## 简介

大家好，希望你们一切顺利。接下来我想做的事情是构建 makemore。就像 micrograd 一样，makemore 是我 GitHub 网页上的一个仓库，你可以去看看。但和 micrograd 一样，我将一步一步地构建它，把每个细节都讲清楚。我们会慢慢地、一起地构建它。

那么 makemore 是什么？顾名思义，makemore 会根据你给它的东西生成更多类似的东西。这里有一个例子：`names.txt` 是 makemore 的一个示例数据集。当你查看 `names.txt` 时，你会发现它是一个非常大的名字数据集。这里有很多不同类型的名字——事实上，我相信有 32,000 个名字，是我从政府网站上随机找到的。如果你用这个数据集训练 makemore，它将学会生成更多类似的东西。具体来说，在这个例子里，这意味着生成更多听起来像名字但实际上是独特的名字。也许你有了宝宝，正在尝试给它起名字；也许你正在寻找一个酷炫、新颖、独特的名字——makemore 可能会帮到你。

这里有一些神经网络在我们数据集上训练后生成的例子：dontel、irot、zhendi 等等。所有这些听起来都像名字，但它们当然不是真正的名字。

在底层，makemore 是一个**字符级语言模型**。这意味着它将每一行视为一个样本，在每个样本内部，它将它们视为单个字符的序列。例如，"reese" 就是这个样本，它是一个字符序列——这就是我们构建 makemore 的层级。字符级语言模型的意思是，它对这些字符序列进行建模，并知道如何预测序列中的下一个字符。

我们实际上将实现大量不同种类的字符级语言模型——从非常简单的二元语法（bigram）和词袋模型，到多层感知机、循环神经网络，一直到现代 Transformer。事实上，我们将构建的 Transformer 基本上等同于 GPT-2 的 Transformer——如果你听说过 GPT 的话。这是一件大事，它是一个现代网络。到这个系列结束时，你将真正理解它在字符层面上是如何工作的。

为了给你一个扩展方向的感觉：在字符之后，我们可能会花一些时间在词级别上，这样我们就可以生成由单词组成的文档，而不仅仅是字符片段，我们可以生成整个更大的文档。然后我们可能会进入图像和图像-文本网络，如 DALL-E、Stable Diffusion 等等。但现在我们必须从这里开始——字符级语言建模。让我们开始吧。

## 读取和探索数据集

和之前一样，我们从一个完全空白的 Jupyter Notebook 页面开始。第一件事是加载数据集 `names.txt`。我们以读取模式打开 `names.txt`，把所有内容读入一个巨大的字符串。然后，因为它是一个巨大的字符串，我们只想要单独的单词并把它们放入一个列表中。所以我们对那个字符串调用 `splitlines()`，将所有的单词作为一个 Python 字符串列表获取。

我们可以查看例如前 10 个单词："emma", "olivia", "eva" 等等——如果我们看页面顶部，确实是我们看到的内容。这个列表实际上让我感觉它可能是按频率排序的，但好吧。

现在我们想了解更多关于这个数据集的信息。让我们看看单词总数——我们预期大约是 32,000。然后看最短的单词：`min(len(w) for w in words)`，最短的单词长度是 2。`max(len(w) for w in words)`，最长的单词是 15 个字符。

现在让我们思考我们的第一个语言模型。正如我提到的，字符级语言模型是在给定前面已有字符序列的情况下，预测序列中的下一个字符。

这里我们要意识到的是，每一个单词——比如 "isabella"——实际上在那个单词中包含了相当多的样本。因为像 "isabella" 这样的单词在数据集中的存在告诉我们：字符 'i' 很可能是名字序列的第一个字符；字符 's' 很可能跟在 'i' 之后；'a' 很可能跟在 "is" 之后；'b' 很可能跟在 "isa" 之后；以此类推，一直到 'a' 跟在 "isabell" 之后。然后这里实际上还包含了一个额外的样本：在 "isabella" 之后，这个单词很可能结束。

所以这是我们在这里拥有的一个更明确的信息片段，我们必须小心处理。因此，一个单词中蕴含了大量的统计结构——关于这些字符序列中什么可能跟在后面。当然，我们不仅只有一个单词，我们实际上有 32,000 个，所以这里有很多结构需要建模。

在开始时，我想从构建一个**二元语法（bigram）语言模型**开始。在二元语法语言模型中，我们一次只处理两个字符。所以我们只关注给定的一个字符，并试图预测序列中的下一个字符。什么字符可能跟在 'a' 之后？等等。我们只是在建模那种局部结构，并且我们忽略了可能拥有更多信息的事实——我们总是只看前一个字符来预测下一个字符。所以这是一个非常简单且弱的语言模型，但我认为它是一个很好的起点。

## 探索数据集中的二元语法

现在让我们开始查看数据集中的这些二元语法，看看它们是什么样子的。这些二元语法就是连续的两个字符。

对于 `w in words`，每个 `w` 是一个单独的单词（字符串）。我们想用连续字符来迭代这个单词——一次两个字符，在单词中滑动。

一个有趣、巧妙的方法是在 Python 中这样做：`for ch1, ch2 in zip(w, w[1:])`。让我们不用所有单词，只做前三个单词。我稍后会展示这是如何工作的。作为例子，让我们只做第一个单词 "emma"：你会看到我们得到 "e m", "m m", "m a"。这是因为 `w` 是字符串 "emma"，`w[1:]` 是字符串 "mma"。`zip` 接受两个迭代器并将它们配对，创建一个遍历它们连续条目的元组的迭代器。如果其中一个列表比另一个短，它就会停止并返回。所以这就是为什么我们返回 "e m", "m m", "m a"——但随后因为第二个迭代器耗尽了元素，`zip` 就结束了，这就是为什么我们只得到这些元组。很巧妙。

所以这些是第一个单词中的连续元素。现在我们必须小心，因为我们实际上拥有比这三个样本更多的信息。正如我提到的，我们知道 'e' 很可能出现在开头，我们知道 'a' 在这个例子中出现在结尾。

所以一种做法是：我们创建一个特殊的字符数组。我们将虚构一个特殊的起始 token——我称它为特殊的 `start`。所以这是一个包含一个元素 `[start]` 的列表，加上 `list(w)`，再加上一个特殊的 `end` 字符。我用 `list(w)` 包裹 `w` 的原因是因为 `w` 是字符串 "emma"，`list(w)` 会把单个字符放到列表中。

然后再次这样做——但不是迭代 `w`，而是迭代字符——会给我们类似这样的结果：`(start, e)` 是一个二元语法，`(a, end)` 是另一个二元语法。现在我们可以看看 "olivia" 或 "ava" 是什么样子。事实上，我们可以对整个数据集这样做，但我们不会打印——那太多了。但这些就是单个字符的二元语法。

## 用 Python 字典计数二元语法

现在，为了学习关于哪些字符可能跟在其他字符后面的统计信息，在二元语法语言模型中最简单的方法就是通过计数。所以我们基本上只是要统计这些组合在训练集中、在这些单词中出现的频率。

我们需要某种字典来维护每个二元语法的计数。让我们使用一个字典 `b`，它将二元语法映射到计数。二元语法是一个 `(ch1, ch2)` 的元组，然后 `b[bigram] = b.get(bigram, 0) + 1`——这基本上与 `b[bigram]` 相同，但如果 bigram 不在字典 `b` 中，默认返回 0。所以这将累加所有二元语法并统计它们出现的频率。

我们查看 `b` 的内容，看到很多二元语法只出现了一次。这个（某个组合）出现了三次。所以 'a' 作为结尾字符出现了三次——这对所有这些单词 "emma", "olivia", "eva" 来说都是正确的，因为它们都以 'a' 结尾。这就是为什么它出现了三次。

现在让我们对所有单词做这个操作。现在 `b` 将拥有整个数据集的统计信息——这些是所有单词中各个二元语法的计数。我们可以查看最常见和最不常见的组合。`b.items()` 返回键值对的元组——键是字符二元语法，值是计数。我们想按值（元组的第二个元素）排序。使用 `key=lambda kv: kv[1]` 按计数排序，`reverse=True` 获取最可能的组合。

所以我们看到 'n' 经常作为结尾字符出现，非常多次；而且 'n' 几乎总是跟在 'a' 后面——这也是一个非常可能的组合。所以这些是我们在整个数据集上获得的单个计数。

## 用 2D PyTorch 张量计数二元语法（"训练模型"）

将信息保存在一个二维数组中而不是 Python 字典中，对我们来说会更方便得多。所以我们将把这些信息存储在一个 2D 数组中。行将表示二元语法的第一个字符，列将表示第二个字符。这个二维数组中的每个条目将告诉我们数据集中第一个字符后跟第二个字符的频率。

我们将使用的数组表示库是 PyTorch。PyTorch 是一个深度学习神经网络框架，但它的其中一部分是 `torch.tensor`，它允许我们创建多维数组并非常高效地操作它们。

让我们 `import torch`。然后我们可以创建数组。例如创建一个 3×5 的零数组。你会注意到 `a.dtype`（数据类型）默认是 `float32`——单精度浮点数。因为我们要表示计数，让我们使用 `dtype=torch.int32`——32 位整数。张量允许我们真正操作所有单个条目并且非常高效。例如，如果我们想改变某个位置的值：`a[1, 3] = 1`。

现在，我们感兴趣的数组要大得多。对于我们的目的，我们有 26 个字母，然后有两个特殊字符 S（起始）和 E（结束）。所以我们需要 26+2=28 的 28×28 数组。让我们称它为 `N`（大写），因为它将表示计数。

现在的问题是，我们有这些字符（字符串），但我们必须用整数来索引数组。所以我们需要一个从字符到整数的查找表。我们取所有单词（一个字符串列表），全部连接成一个巨大的字符串——这基本上就是整个数据集作为一个单一字符串。我们将这个传给 `set` 构造函数——集合不允许重复，所以这会给我们所有小写字符的集合，应该有 26 个。现在我们不想要集合，我们想要一个列表——但不是一个以某种奇怪的任意方式排序的列表，我们希望它从 a 到 z 排序。所以 `sorted(list(...))`——这些就是我们的字符。

现在创建查找表：`stoi`（string to integer）。`for i, s in enumerate(chars)`——enumerate 给出整数索引和列表实际元素的迭代器。然后我们将字符映射到整数。所以 `stoi` 是从 'a'→0, 'b'→1, ..., 'z'→25 的映射。但我们还需要特别设置 `stoi['.'] = 0`（如果我们把特殊字符放在位置 0）。

现在我们可以把字符 1 和字符 2 都映射到它们的整数：`ix1 = stoi[ch1]`, `ix2 = stoi[ch2]`。然后我们可以用数组进行索引：`N[ix1, ix2] += 1`。这应该可以工作，并给我们一个包含所有这些计数的大 28×28 数组。

## 可视化二元语法张量

现在让我们尝试更好地可视化它。我们将使用 matplotlib 库。`plt.imshow(N)` 显示 28×28 数组。但即使这样还是有点丑。让我们创建更好的可视化。

首先我们需要反转 stoi 字典：`itos = {i: s for s, i in stoi.items()}`。itos 从 0→'.', 1→'a', 2→'b'，等等反向映射。

然后我们创建一个图形，绘制 `N`，然后遍历所有单个单元格。我们创建一个字符串 `itos[i] + itos[j]`——这些是字符表示的二元语法。然后我们绘制二元语法文本，再绘制该二元语法出现的次数。

数组的结构：我们有所有这些计数，我们看到其中一些出现频率很高，一些则不常出现。

## 删除多余的 S 和 E token，改为单一的 "." token

如果你仔细检查，你会注意到我们实际上并不够聪明。因为当你看到这里时，你会注意到例如我们有一整行完全为零——那是因为结束字符永远不可能成为二元语法的第一个字符，因为我们总是把这些结束 token 放在二元语法的末尾。类似地，我们有整列为零——因为起始字符永远不可能成为二元语法的第二个元素，因为我们总是以 S 开始、以 E 结束，中间只有单词。

所以在这个小的 2×2 矩阵中，唯一可能发生的非零情况是 S 直接跟在 E 之后——如果我们有一个没有字母的单词（空单词），我们只有 S 后跟 E。但其他的根本不可能。

所以我们基本上在浪费空间。不仅如此，S 和 E 在这里变得非常拥挤。在自然语言处理中通常使用尖括号来表示特殊 token，但我们将使用其他方式。

让我们修复所有这些。我们实际上不会有两个特殊 token——我们只会有一个特殊 token。所以我们将有一个 27×27 的数组。我们将这一个特殊 token 称为 "."。我还想把这个特殊字符放在位置 0，并把所有其他字母偏移一位——我觉得这样更好看。

所以 `stoi` 现在变为：'.' 在 0，'a' 从 1 开始。itos 反向映射也会正常工作——1 是 'a'，2 是 'b'，0 是 '.'。

现在这个行就是所有首字母的计数：'j' 开头多少次，'h' 开头多少次，'i' 开头多少次，等等。这些是所有的结尾字符。中间是哪些字符跟在哪些字符后面的结构。所以这是我们整个数据集的计数数组。这个数组实际上包含了我们从这个二元语法字符级语言模型中采样所需的所有信息。

## 从模型中采样

大致来说，我们要做的就是按照这些概率和计数，开始从模型中采样。一开始，我们当然以起始 token '.' 开始。为了采样名字的第一个字符，我们查看这一行。我们看到我们有计数，这些计数最终告诉我们任何一个字符作为单词开头有多频繁。

如果我们取 `N[0, :]`——这索引到第 0 行并抓取所有列——这会给我们第一行的一维数组：`[0, 4, 4, 10, 1, 3, 0, 6, 1, 5, 4, 2, ...]`。这就是第一行。

现在这些是计数。现在我们想做的是从中采样。因为这些是原始计数，我们实际上需要将其转换为概率。所以我们创建一个概率向量：取 `N[0]` 转换为 float。创建浮点数的原因是我们即将归一化这些计数。我们做 `p = p / p.sum()`，现在我们得到一个更小数字的向量——这些都是概率。因为除以了总和，`p.sum()` 现在是 1。这是一个良好的正确概率分布——它总和为 1，给出了任何单个字符作为单词第一个字符的概率。

现在我们可以从这个分布中采样。为了采样，我们使用 `torch.multinomial`。`torch.multinomial` 从多项概率分布中返回样本——这是一种复杂的说法："你给我概率，我给你根据概率分布采样的整数。"

为了使一切可复现，我们在 PyTorch 中使用一个生成器对象。这使一切具有确定性——当你在你的电脑上运行这个时，你会得到和我完全相同的结果。

我们采样一个样本，得到例如 13。这是索引。我们用 `itos[ix]` 来找出我们采样了哪个字符——采样到了 'm'。所以第一个字符是 'm'。查看这一行，'m' 实际上开始了大量单词——'m' 开始了大约 2,500 个单词（总共 32,000 个），所以几乎不到 10% 的单词以 'm' 开头。所以这是一个相当可能被抽到的字符。

所以那将是我们的第一个字符。现在我们可以继续采样更多字符——因为现在我们知道 'm' 开始了，'m' 已经被采样了。为了抽取下一个字符，我们回到这里，查找以 'm' 开始的那一行。我们看到 'm.' 是 516，'ma' 是这么多，'mb' 是这么多，等等——这些是下一行的计数。那就是我们接下来要生成的下一个字符。

所以我们可以写循环：我们总是从索引 0 开始（那是起始 token）。然后 `while True`：抓取对应当前索引的行 `p = N[ix].float()`，归一化 `p = p / p.sum()`，用生成器抽取一个样本 `ix = torch.multinomial(p, num_samples=1, replacement=True, generator=g).item()`。如果采样的索引是 0，那就是结束 token，所以我们 break。否则，我们将 `itos[ix]` 添加到输出中。

如果我们这样做 10 次或 20 次，我们得到像这样的名字。老实说，这看起来不太对。这些样本之所以如此糟糕，是因为二元语法语言模型确实非常糟糕。你可以看到它们有点像名字——像 "yanu", "oreilly" 等等——但它们完全混乱。

它如此糟糕的原因是：例如它生成了 "h" 作为一个名字。但你必须从模型的角度来思考——它不知道这个 'h' 是第一个 'h'。它只知道 'h' 是前一个字符，然后 'h' 作为最后一个字符的可能性是多少？某种程度上是可能的。所以它就直接让它成为最后一个字符。它不知道在它之前有其他东西，或者没有其他东西。这就是为什么它生成了所有这些无意义的名字。

另一种说服自己这确实在做一些合理事情的方式（尽管它如此糟糕）是：如果 `p` 不是有任何结构，而是 `p = torch.ones(27) / 27`——即均匀分布，使一切都同等可能。我们从中采样：这就是从一个完全未训练的模型得到的结果。它显然是垃圾。然后如果我们有一个仅在二元语法上训练过的模型，这就是我们得到的。所以你可以看到它更像名字——它确实在工作，只是二元语法太糟糕了，我们必须做得更好。

## 效率提升：向量化归一化与张量广播

我们这里有一个低效问题。我们在这里做的是——我们总是从计数矩阵 `N` 中取一行 `p`，然后总是做同样的事情：转换为 float 并除以总和。我们在循环的每次迭代中重复归一化这些行，一遍又一遍，这极其低效且浪费。

所以我想做的是准备一个矩阵 `P`（大写），它直接包含概率。换句话说，它将与计数的 `N` 矩阵相同，但每一行都会有归一化到 1 的概率，指示给定前一个字符（由所在行定义）时下一个字符的概率分布。

所以我们想预先做这件事，然后直接使用 `p = P[ix]`。

这样做的另一个原因不仅是为了效率——我也希望我们练习这些 n 维张量及其操作，特别是称为**广播（broadcasting）**的东西。我们将不得不非常擅长这些张量操作，因为如果我们一直构建到 Transformer，我们将为效率做一些相当复杂的数组操作，我们需要真正理解并擅长它。

直观上，我们想做的是：首先取 `N` 的浮点副本，然后我们想除以所有行使它们总和为 1。所以我们想做类似 `P = N.float() / N.float().sum(...)` 的事情。

但我们必须小心——`N.sum()` 会产生整个矩阵所有计数的总和，给出一个单一数字。那不是我们想要的方式。我们想要同时并行地将所有行除以它们各自的总和。

所以我们查看 `torch.sum` 的文档。我们不仅提供想要求和的输入数组，还提供**沿哪个维度求和**。特别地，我们想沿行求和。

另一个重要参数是 `keepdim`。如果 `keepdim=True`，输出张量与输入大小相同，除了被求和的维度变为 1。如果 `keepdim=False`（默认），那个维度被挤压掉。

`P.shape` 是 27×27。当我们沿 axis=1 求和并保持维度时：`P.sum(1, keepdim=True)` 的形状是 27×1——一个列向量。这是因为我们水平求和，27×27 矩阵变成了 27×1 数组。

现在我们要做的是除以这个。可以取一个 27×27 的数组除以一个 27×1 的数组吗？这由**广播规则**决定。

广播语义规则：
1. 每个张量至少有一个维度
2. 从尾随维度开始迭代维度大小：维度大小必须相等，或其中一个为 1，或其中一个不存在

对齐两个数组的形状 (27, 27) 和 (27, 1)：从右向左——最右维度：27 vs 1 → 一个为 1，所以没问题。下一个维度：27 vs 27 → 相等，没问题。所以这个操作是可广播的。

这意味着这个操作是被允许的。它会把维度为 1 的那个拉伸——复制它——以匹配 27。所以它取这个 27×1 的列向量，复制它 27 次，使两者在内部都变成 27×27，然后做逐元素除法。这正是我们想要的——用这些计数除以每一列。

我们可以通过取第一行的和来检查：我们期望它为 1——这是正确的。

**广播的陷阱**：如果我省略 `keepdim=True`，那么 `P.sum(1)` 的形状就是 (27,)——一个一维向量。根据广播规则，从右向左对齐：(27, 27) vs (27,)。内部广播会在这个 27 向量前面加一个 1，变成 (1, 27)——一个**行向量**。然后这个行向量被**垂直**复制 27 次。所以实际上我们在归一化**列**而不是行！这会导致一个非常微妙的 bug：第一行的和不等于 1，但第一列的和等于 1。所以保持 `keepdim=True` 是必要的。

这相当微妙。希望这能让你对广播保持敬畏——要小心，检查你的工作，理解它在底层是如何工作的，确保它在按照你想要的方向进行广播。否则你会引入非常难以发现的微妙 bug。

## 损失函数（模型下数据的负对数似然）

好的，我们现在处于一个相当好的位置。我们训练了一个二元语法语言模型——实际上只是通过计数任何配对出现的频率，然后归一化以获得良好的概率分布。所以这个数组 `P` 的元素实际上就是我们的二元语法语言模型的参数，总结了我们二元语法的统计信息。我们训练了模型，知道如何从模型采样——我们迭代地采样下一个字符并每次反馈它以获得下一个字符。

现在我想做的是评估这个模型的质量。我们想把模型的质量总结为一个单一数字——它在预测训练集方面有多好。这个训练损失用一个单一数字告诉我们模型的质量。

基本上，我们要做的是复制粘贴之前用于计数的代码。对于每个二元语法，我们查看模型分配给它的概率——即 `P[ix1, ix2]` 中的概率。我们打印这些概率。

如果一切是等可能的，我们有 27 个可能的字符/token，那么你期望所有这些概率大约是 4%。所以任何高于 4% 的意味着我们从二元语法统计中学到了一些有用的东西。你看到大致上其中一些是 4%，但有些高达 40%、35% 等等。所以模型实际上对训练集中的内容分配了相当高的概率——这是一件好事。如果你有一个非常好的模型，你期望这些概率接近 1，因为那意味着你的模型正确地预测了接下来会出现什么。

现在的问题是，我们如何将这些概率总结为一个衡量模型质量的单一数字？在最大似然估计和统计建模的文献中，通常使用的是**似然（likelihood）**。似然是所有概率的乘积。所有概率的乘积就是似然——它告诉我们模型分配给整个数据集的概率，这是质量的度量。所以当你在训练模型且有一个好模型时，这些概率的乘积应该非常高。

因为这些概率的乘积是一个难以处理的数字——所有概率都在 0 和 1 之间，所以乘积会是一个非常小的数字。为了方便起见，人们通常使用的不是似然，而是**对数似然（log likelihood）**。`log(a × b × c) = log(a) + log(b) + log(c)`——对数似然就是各个概率的对数之和。

`torch.log(p)` 从 0（当 p=1）到负无穷（当 p=0）。所以更高的概率给出更接近 0 的对数概率，更低的概率给出更负的数字。对数似然从 0 开始，然后累加。对数似然最高可以达到 0——当所有概率都是 1 时，对数似然为 0。当所有概率更低时，它会变得越来越负。

但我们实际上不喜欢这样——我们想要的是损失函数，其中低值意味着好（因为我们试图最小化损失）。所以我们用**负对数似然（negative log likelihood）**：就是对数似然的负值。负对数似然是一个非常不错的损失函数：最低可以达到 0，越高表示预测越差。

人们有时会做的一个额外修改是归一化——使其成为平均值而不是总和。所以 `loss = -log_likelihood / N`。训练集上由模型分配的损失函数约为 2.4——这就是模型的质量。越低越好，越高越差。训练的任务是找到最小化负对数似然损失的参数。

总结：
- 我们的目标是**最大化似然**——模型分配的所有概率的乘积
- 最大化似然 **≡ 最大化对数似然**（因为 log 是单调函数）
- 最大化对数似然 **≡ 最小化负对数似然**
- 在实践中，人们最小化**平均**负对数似然——得到像 2.4 这样的数字

现在让我们在整个训练集上计算损失——得到约 2.45。

我们可以评估任何单词的概率。例如，"andre" 平均需要约 3 的对数概率来表示它——大致因为 'ej' 组合非常不常见。

## 模型平滑：使用伪计数

如果你把 "andre" 和 "q" 拼在一起变成 "andreq"，测试它在这个模型下的概率——我们实际上得到无穷大。这是因为 'jq' 根据我们的模型有 0% 的概率。log(0) = 负无穷，我们得到无限损失。

这有点不好——因为我们输入了一个可能还算合理的字符串（作为一个名字），但模型说它完全不可能，概率为 0%。原因是 'j' 后面跟 'q' 出现了 0 次。

人们通常会用一种非常简单的修复方法，叫做**模型平滑（model smoothing）**。大致上发生的事情是：我们添加一些**伪计数（fake counts）**。想象给所有东西加 1——`N + 1`——然后重新计算概率。这就是模型平滑。你可以加任意多的伪计数——加得越多，模型越均匀；加得越少，模型越尖峰。加 1 是一个相当不错的数字。这会确保概率矩阵 `P` 中没有零，所以不会有任何东西的似然是无穷大。`jq` 现在有一个非常小的概率——模型仍然觉得它非常令人惊讶，但我们不会得到负无穷了。

## 第二部分：神经网络方法

好的，我们训练了一个像样的二元语法字符级语言模型。我们通过查看所有二元语法的计数并归一化行以获得概率分布来训练模型。我们也可以用这些模型参数来执行新单词的采样。我们还可以用负对数似然这个单一数字来评估模型质量。

我们通过做一些感觉很合理的事情——只是执行计数然后归一化——来得出了这个模型。但现在我想采取另一种方法。我们会得到非常相似的结果，但方法看起来会截然不同。我想把二元语法字符级语言建模的问题放入**神经网络框架**中。

在神经网络框架中，我们的方法会稍有不同，但最终会达到非常相似的位置。我们的神经网络仍然是一个二元语法字符级语言模型。它接收**单个字符**作为输入，然后通过一个带有权重（参数 `W`）的神经网络，输出**下一个字符的概率分布**——它会对输入的这个字符后面可能跟什么做出猜测。

此外，我们将能够使用负对数似然损失函数来评估神经网络的任何参数设置。我们将查看它的概率分布，并使用标签——二元语法中第二个字符的身份。知道第二个字符实际是什么，让我们可以查看模型对该字符分配了多高的概率。我们希望概率非常高——这等价于损失很低。

然后我们将使用**基于梯度的优化**来调整这个网络的参数。因为我们有损失函数，我们将最小化它——调整权重使神经网络正确预测下一个字符的概率。

## 为神经网络创建二元语法数据集

首先编译这个神经网络的训练集——所有二元语法的训练集。我们复制粘贴之前迭代所有二元语法的代码。但现在我们不做计数——我们只是创建训练集。训练集将由两个列表组成：`xs`（输入）和 `ys`（目标/标签）。这些二元语法将表示 (x, y) 对——给定二元语法的第一个字符，试图预测下一个字符。两者都是整数。所以 `xs.append(ix1)`, `ys.append(ix2)`。

我们不想要整数列表——我们从中创建张量：`xs = torch.tensor(xs)`, `ys = torch.tensor(ys)`。我们先只用第一个单词 "emma"，这样就很清楚 xs 和 ys 是什么。

"emma" 的二元语法是：(., e), (e, m), (m, m), (m, a), (a, .)。这个单词为我们的神经网络提供了 5 个独立的样本。这些样本总结如下：
- 输入 0（即 '.'）→ 期望标签 5（即 'e'）
- 输入 5（即 'e'）→ 期望标签 13（即 'm'）
- 输入 13（即 'm'）→ 期望标签 13（即 'm'）
- 输入 13（即 'm'）→ 期望标签 1（即 'a'）
- 输入 1（即 'a'）→ 期望标签 0（即 '.'）

所以在这个数据集中有 5 个独立的输入样本给神经网络。

**注意事项**：使用 `torch.tensor`（小写 t）而不是 `torch.Tensor`（大写 T）。小写版本会推断数据类型（这里会推断为整数），而大写版本默认返回 float32。对于索引来说我们需要整数。建议坚持使用小写版本。

## 将整数输入神经网络：独热编码

现在思考如何将这些样本输入神经网络。这并不像直接插入那么简单——因为这些样本目前是整数（如 0, 5, 13），它们给出字符的索引。你不能直接把整数索引插入神经网络。神经网络由神经元组成，神经元有权重，权重以乘法方式作用于输入（wx + b 等）。让输入神经元取整数值然后与权重相乘没有意义。

所以一种常见的编码整数的方法是**独热编码（one-hot encoding）**。在独热编码中，我们取一个整数（如 13），创建一个全为零的向量，除了第 13 维我们将其设为 1。然后那个向量可以输入神经网络。

PyTorch 在 `torch.nn.functional` 中有 `one_hot` 函数。我们传入想要编码的整数张量，以及 `num_classes=27`。所以 `xenc = F.one_hot(xs, num_classes=27)`。`xenc.shape` 是 (5, 27)——5 个样本，每个编码为 27 维向量。每一行在适当的位置是 1，其他地方是 0。

我们需要注意数据类型——`xenc.dtype` 可能是 int64（因为 `xs` 是 int64）。对于输入神经网络，我们想要浮点数。`one_hot` 不支持 `dtype` 参数，所以我们需要转换：`xenc = xenc.float()`。

## "神经网络"：通过矩阵乘法实现的一层线性神经元

这个神经元将查看这些输入向量。正如你从 micrograd 中记得的，这些神经元基本上执行一个非常简单的函数：wx + b，其中 wx 是点积。

首先定义这个神经元的权重。在初始化时，我们用 `torch.randn` 来初始化——它用从正态分布中抽取的随机数填充张量。大多数数字在 0 附近，一些高达接近 3，很少有数字的绝对值超过 3。

我们需要一个大小输入——这里设为 (27, 1)。所以 `W` 是一个 27×1 的列向量，包含 27 个数字。然后我们可以取 `xenc @ W`——这是 PyTorch 中的矩阵乘法运算符。

`xenc` 是 5×27，`W` 是 27×1，输出是 5×1。这是 5 个输入上这个单个神经元的 5 个激活值。我们同时将所有 5 个输入输入到同一个神经元，并行地评估了所有输入。

现在，我想要的不是单个神经元，而是 27 个神经元。所以 `W` 设为 (27, 27)。`xenc @ W` 是 5×27 乘以 27×27，输出是 5×27。现在每个元素告诉我们：对于 27 个神经元中的每一个，在 5 个样本中每一个上的"发放率"是多少。例如，元素 [3, 13] 给出第 13 个神经元查看第 3 个输入时的发放率。这是通过第 3 个输入和 W 矩阵第 13 列之间的点积实现的。

所以使用矩阵乘法，我们可以非常高效地并行评估批量中的大量输入样本和大量神经元之间的点积——其中所有那些神经元的权重在 W 的列中。

## 将神经网络输出转换为概率：Softmax

好的，我们把 27 维输入送入了一个有 27 个神经元的第一层神经网络。这些神经元执行 W×X——没有偏置，没有像 tanh 这样的非线性——我们让它们保持为线性层。除此之外，我们不会有任何其他层——这就是最蠢、最小、最简单的神经网络：仅仅一个单一的线性层。

现在我想解释我希望那 27 个输出是什么。直观上，我们试图为每个输入样本产生下一个字符的某种概率分布——有 27 个可能。

现在这些数字有正有负——因为它们来自一个用正态分布初始化的神经网络层。但我们想要的是类似之前的东西：每一行告诉我们计数，然后我们归一化计数以获得概率。但我们现在只有一些正数和负数。

我们希望这些数字以某种方式表示下一个字符的概率。但概率有特殊的结构：它们是正数且总和为 1。这不会直接从神经网络中出来。计数也不是一个好的输出——因为计数是正整数。

所以神经网络要输出的——以及我们将如何解释这 27 个数字——是：这些 27 个数字给我们的是**对数计数（log counts）**。不是直接给出像表中那样的计数，而是给出对数计数。为了得到计数，我们取对数计数然后对它们取**指数（exponentiate）**。

指数化是这样的：它取整个实数线上的数字——负数得到 e^x 始终小于 1（趋向于 0）；正数得到大于 1 的数字（趋向无穷）。所以如果我们将这些数字解释为对数计数，然后逐元素指数化，所有负数变成小于 1 的数字（如 0.338），所有正数变成更大的正数（大于 1）。这给了我们一些我们可以使用的东西——解释为等价于原始计数的东西。这些"计数"是正数——永远不会低于零——这很合理。

所以让我们分解一下：我们把这些（WX 的输出）解释为**logits**（对数计数）。然后 `counts = logits.exp()`——这就是指数化后的"计数"。这等价于我们之前使用的 N 数组——计数数组的每一行是下一个字符的"计数"。

然后概率就是计数归一化：`probs = counts / counts.sum(1, keepdim=True)`。所以 `probs.shape` 是 (5, 27)——对于 5 个样本中的每一个，我们现在有一行来自神经网络的概率。

总结这个变换：
- `WX` → logits（对数计数）
- `logits.exp()` → 伪计数（正数，像计数一样）
- `counts / counts.sum()` → 概率分布（正数，每行总和为 1）

这些全都是**可微操作**——我们可以通过它们反向传播。

最后两行（exp + 除以总和）合在一起被称为 **softmax**。Softmax 是神经网络中非常常用的层——它接收 logits，指数化它们，然后除以总和进行归一化。它是一种将神经网络层的输出（可以是正或负）转换为总是总和为 1 且为正数的概率分布的方法。你可以把它看作一种归一化函数，放在神经网络中任何其他线性层之上。它使神经网络输出概率。

## 前向传播总结

我把所有内容整理到一个总结中：

我们从输入数据集开始——有神经网络的输入（xs）和正确下一个字符的标签（ys）——这些都是整数。

我们生成 27 个神经元，每个接收 27 个输入（`W` 是 27×27）。

**前向传播**：
1. 将所有整数输入编码为独热表示 → `xenc` 为 (5, 27)
2. 乘以第一层权重 → `logits = xenc @ W`（5×27）
3. 指数化 logits → `counts = logits.exp()`（伪计数）
4. 归一化这些计数 → `probs = counts / counts.sum(1, keepdim=True)`（概率，每行总和为 1）

第 3 和第 4 步合起来就是 **softmax**。

所以对于 "emma" 中的 5 个二元语法：
- 二元语法 0：输入 '.'（索引 0），标签 'e'（索引 5）
- 二元语法 1：输入 'e'（索引 5），标签 'm'（索引 13）
- 二元语法 2：输入 'm'（索引 13），标签 'm'（索引 13）
- 二元语法 3：输入 'm'（索引 13），标签 'a'（索引 1）
- 二元语法 4：输入 'a'（索引 1），标签 '.'（索引 0）

对于每个样本，我们查看神经网络分配给正确标签索引的概率。目前网络认为这些概率很低（1%-7%），所以损失很高（约 3.76）。这只是因为我们还没有找到好的 `W` 设置。

如果我们重新采样 `W`（用不同的随机种子），我们会得到不同的损失——有些更好（3.37），有些更差。但随机猜测和检查是"业余水平"——不是我们优化神经网络的方式。

## 向量化损失

优化神经网络的方式是：从一个随机猜测开始（即使它不是很好），但因为我们有一个完全由可微操作组成的损失函数，我们可以通过调整 `W` 来最小化损失——通过计算损失对 `W` 矩阵的梯度。然后我们可以使用基于梯度的优化来调整 `W`，找到好的设置。

首先，我们需要向量化地计算损失。`probs` 形状是 (5, 27)。我们想要在正确索引处取出概率。对于第一个样本（第 0 行），我们想要索引 5（即 'e'）处的概率。对于第二个样本（第 1 行），我们想要索引 13 处的概率。等等。

向量化地做这件事：`probs[torch.arange(5), ys]`——这会精确地取出神经网络分配给正确下一个字符的概率。

然后我们取这些概率的对数：`.log()`。然后取平均值：`.mean()`。然后取负数：这就是**负平均对数似然损失**。损失约为 3.76——与之前完全相同。

## PyTorch 中的反向传播和参数更新

现在我们一路到达了损失。我们已经定义了前向传播——通过网络前向传播并计算损失。现在我们准备做**反向传播**。

首先，确保所有梯度重置为零：`W.grad = None`（在 PyTorch 中设为 `None` 更高效）。在调用 `loss.backward()` 之前，我们需要一件事：当我们创建 `W` 时，必须传递 `requires_grad=True`，告诉 PyTorch 我们对计算这个叶张量的梯度感兴趣（默认是 `False`）。

现在 `loss.backward()` 执行。PyTorch 就像 micrograd 一样——当我们在前向传播中做操作时，它在底层跟踪所有操作，构建完整的计算图。它知道所有的依赖关系和所有东西的数学操作。当我们调用 `loss.backward()` 时，它填充所有中间变量的梯度，一路回到 `W`——我们神经网络的参数。

所以 `W.grad.shape` 是 (27, 27)——与 `W.shape` 相同。每个元素告诉我们该权重对损失函数的影响。正梯度意味着稍微增加该权重会略微增加损失。负梯度意味着相反。我们可以用这些梯度信息来更新神经网络的权重。

**更新**：`W.data += -0.1 * W.grad`。学习率 0.1 控制步长。

更新后我们重新计算前向传播——损失应该降低：从 3.76 降到 3.74，然后 3.72……这就是**梯度下降**。当我们达到低损失时，意味着网络对正确字符分配了高概率。

## 汇总所有内容

我把所有内容重新整理并汇总在一起。我们构建二元语法数据集（使用所有单词时有 228,000 个二元语法而不是 5 个）。代码完全不需要修改——它不关心有 5 个还是 228,000 个二元语法。

我们用梯度下降迭代——前向传播、反向传播、更新。在大约 100 次迭代后，损失达到约 2.47——接近我们从显式计数方法获得的 2.45。

这完全合理，因为从根本上说，我们没有使用任何额外的信息——我们仍然只是取前一个字符并试图预测下一个。但不同的是，我们不是通过显式地计数和归一化来做这件事，而是通过基于梯度的学习来做。

显式方法恰好非常适合优化二元语法语言模型的损失函数——因为设置太简单了，我们可以直接估计概率并维护在一个表中。但基于梯度的方法**显著更灵活**。

我们获得的真正收益是：我们现在可以扩展这种方法并使神经网络复杂化。目前我们只取单个字符输入一个极其简单的神经网络。但我们即将大幅迭代——我们将取**多个前一个字符**，将它们输入越来越复杂的神经网络。但根本上，神经网络的输出将始终只是 logits。这些 logits 将经过完全相同的变换——通过 softmax，计算负对数似然损失，进行基于梯度的优化。所以实际上，当我们将神经网络复杂化一直发展到 Transformer 时，**这些都不会根本改变**。唯一会改变的是我们做前向传播的方式——我们如何接收一些前序字符并为序列中的下一个字符计算 logits。

为什么基于梯度的方法更好：显式的表格方法无法扩展。如果我们只看一个前序字符，我们可以把所有东西保存在一个计数表中。但如果我们有最后 10 个字符作为输入，我们不能再把所有东西保存在表中了——有太多可能的组合。所以表格方法从根本上不可扩展，而神经网络方法显著更可扩展，是我们可以随着时间不断改进的方法。

## 备注 1：独热编码实际上只是选择了下一线性层权重矩阵的一行

注意：`xenc` 由独热向量组成，然后这些独热向量乘以 `W` 矩阵。我们把这看作是多个神经元以全连接方式前向传播。但实际上发生的是：如果你有一个独热向量在第 5 维是 1，那么因为矩阵乘法的工作方式，将该独热向量乘以 `W` 实际上最终会**取出 W 的第 5 行**。Logits 就变成了 W 的第 5 行。

这实际上和之前发生的事情一模一样！因为之前的二元语法模型——我们取第一个字符，那个第一个字符索引到计数数组中的一行，那一行给出了下一个字符的概率分布。第一个字符被用作查找表来获取概率分布。

这正是这里发生的事情——因为我们取索引，将其编码为独热，然后乘以 `W`，所以 logits 实际上就变成了 `W` 的相应行。然后和之前一样被指数化以创建"计数"，然后归一化成为概率。所以这里的 `W` 实际上等同于之前的数组——但 `W` 记住是对数计数，而不是计数。更准确地说，`W.exp()` 等于计数数组。

那个计数数组是通过计数和填充二元语法频率来填充的。而在基于梯度的框架中，我们随机初始化它，然后让损失引导我们达到完全相同的数组。这个数组实际上就是优化结束时的 `W` 数组——只是我们通过跟随损失一步步到达了它。这就是为什么我们最终也获得了相同的损失函数。

## 备注 2：模型平滑作为正则化损失

还记得平滑吗？我们给计数添加伪计数以使概率分布更平滑和均匀，这防止了给任何二元语法分配零概率。如果我增加计数，概率会变得越来越均匀——因为计数最多到大约 900，所以如果我给每个数字加一百万，每行在归一化后会变得越来越接近完全均匀分布。

基于梯度的框架有一个等价于平滑的方法。思考这些我们随机初始化的 `W`：我们也可以考虑将 `W` 初始化为零。如果 `W` 的所有条目都是零，那么 logits 全为零，指数化后全为一，然后概率变成完全均匀。所以基本上当 `W` 都彼此相等（特别地为零）时，概率变得完全均匀。

所以**试图激励 W 接近零**基本上等价于标签平滑。你在损失函数中激励得越多，你得到的分布就越平滑。

这引出了**正则化（regularization）**的概念：我们可以增强损失函数，使其包含一个我们称为正则化损失的小组件。特别地，我们可以取 `W`，平方其所有条目（消除正负号），然后取平均值。如果 `W` 正好为零，正则化损失为零，但如果 `W` 有非零数字，就会累积损失。

我们可以将其加入到主损失中：`loss + 0.01 * (W**2).mean()`。现在这个优化有两个组件：它不仅试图使所有概率正确，同时还有一个额外的组件试图使所有 `W` 为零。如果 `W` 非零你就感受到损失，所以最小化的唯一方法就是让 `W` 趋近于零。

你可以把这想象为添加了一个弹簧力或重力，将 `W` 推向零。所以 `W` 想要为零，概率想要均匀，但同时它们也想要匹配数据所指示的概率。正则化的强度正好控制了伪计数的数量——更大强度对应更大的平滑效果。如果足够强，我们就永远无法克服这个损失的力量，一切都会是均匀预测。

## 从神经网络采样

最后，我想展示如何从这个神经网络模型采样。我从之前复制了采样代码。我们从索引 0（起始 token）开始，获取 `P` 的当前行作为概率分布，从中采样下一个索引，累积并遇到 0 时停止。

现在不同的是：概率行不是来自 `P` 矩阵的一行，而是来自神经网络。我们取 `ix`，将其编码为独热 `xenc`，`xenc @ W`（这实际上只是取出 `W` 的第 `ix` 行），得到 logits。然后对这些 logits 进行指数化以获得"计数"，然后归一化以获得分布。然后我们可以从分布中采样。

运行这个——我们得到完全相同的结果。这有点反高潮，或者高潮（取决于你怎么看）。但这是因为这是完全相同的模型。不仅达到相同的损失，而且正如我提到的，这些是相同的模型。`W` 是我们之前估计的计数的对数，但我们通过非常不同的方式得出了答案，有着非常不同的解释。但根本上，这基本上是同一个模型并提供相同的样本。

## 结论

我们介绍了二元语法字符级语言模型。我们看到了如何**训练**模型、如何从模型**采样**，以及如何使用**负对数似然损失**来**评估**模型的质量。然后我们实际上以**两种完全不同的方式**训练了模型——它们得到**相同的结果和相同的模型**。

在**第一种方式**中，我们只是统计所有二元语法的频率然后归一化。

在**第二种方式**中，我们使用负对数似然损失作为指导，在基于梯度的框架中优化计数矩阵（或计数数组）以使损失最小化。

第二种方式——基于梯度的框架——**灵活性大得多**。目前我们的神经网络超级简单：我们取**单个**前序字符，通过一个单一的线性层来计算 logits。这即将复杂化。

在后续的视频中，我们将取**越来越多的前序字符**，将它们输入神经网络。但这个神经网络仍然会输出完全相同的东西——logits。这些 logits 仍然会以完全相同的方式归一化。所有的损失、梯度、基于梯度的框架——一切保持相同。只是这个神经网络将会复杂化，一直发展到 **Transformer**。所以这将相当厉害——我很期待。先到这里，再见。
