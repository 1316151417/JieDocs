# **基于代码库的 LLM Wiki / 企业知识系统设计思路整理**

---

# **一、这个系统到底要解决什么问题？**

一开始很容易把这个方向理解成：

```text
ChatGPT + 企业文档
```

但深入讨论后会发现：

真正的问题根本不是“问答”。

而是：

# **企业长期知识无法沉淀。**

企业内部真实现状通常是：

- 文档质量差
- 文档长期过期
- 系统演进没人记录
- 新人理解系统极其困难
- 业务知识散落在：
    - 代码
    - PR
    - 飞书
    - Confluence
    - SQL
    - 日志
    - 事故复盘
    - 人脑

最终：

```text
代码是真相
文档是解释
人脑是补丁
```

而传统知识库的问题在于：

# **它把“文档”当成了知识源。**

但现实中：

# **文档并不可靠。**

因此：

整个系统的核心思想最终演变为：

# **“以代码为核心，以外部知识为辅助”的长期知识系统。**

---

# **二、系统目标重新定义**

这个系统第一目标不是：

```text
AI 问答
```

而是：

# **形成长期演化的组织知识。**

也不是：

```text
自动生成 README
```

而是：

# **构建企业系统认知地图（System Cognitive Map）。**

即：

让系统知识：

- 可沉淀
- 可演化
- 可增量更新
- 可长期维护
- 可被 AI 理解
- 可被人类理解

---

# **三、为什么“代码”必须成为核心？**

这是整个方向最重要的基础认知。

因为：

# **代码具备天然真实性。**

例如：

```text
代码改了 = 系统行为变了
```

但：

```text
文档改不改，不影响系统运行
```

因此：

代码天然具备：

- 强一致性
- 可验证性
- 可解析性
- 可增量更新
- 可结构化

而文档：

通常：

- 主观
- 易过期
- 风格不统一
- 质量不稳定
- 缺少维护

所以：

# **代码是“系统现实”**

# **文档是“人类解释”**

两者不能平权。

---

# **四、最核心的认知变化**

最初很容易认为：

```text
代码 → 生成 Wiki
```

但后来逐渐发现：

真正的结构应该是：

```text
代码
 ↓
语义结构层
 ↓
Wiki / 图谱 / 搜索 / AI
```

即：

# **Wiki 只是“知识视图”。**

真正核心的是：

# **Semantic Layer（语义层）**

---

# **五、这个系统真正的本质**

本质上：

不是：

```text
文档系统
```

而是：

# **Knowledge Compiler（知识编译器）**

类似：

```text
源码
 ↓
编译
 ↓
IR（中间表示）
 ↓
最终产物
```

这里：

- 源码 = 企业代码 / 文档 / 运行信息
- IR = AST / Semantic Graph / Knowledge Node
- 最终产物 = Wiki / Graph / Agent

因此：

AST、CodeGraph 等技术：

本质不是展示层。

而是：

# **“知识编译过程中的中间层”**

---

# **六、为什么第一版不应该优先做问答？**

这是一个非常重要的结论。

很多团队会：

```text
向量库 + ChatBot
```

然后发现：

AI：

- 理解不了系统
- 无法分析调用链
- 无法理解状态流
- 无法建立长期记忆

因为：

它只有：

```text
文本相似性
```

而没有：

# **系统结构认知。**

因此：

正确顺序应该是：

---

## **Step 1**

形成知识

---

## **Step 2**

形成结构

---

## **Step 3**

形成长期记忆

---

## **Step 4**

最后才是 AI 问答

---

# **七、AST 的真正角色是什么？**

一开始容易误解：

```text
AST 是给人看的
```

其实完全不是。

AST 的作用是：

# **让代码从“文本”变成“结构”。**

例如：

```java
refundService.refund(orderId)
```

普通文本层：

只是字符串。

AST 会告诉系统：

```text
- 方法调用
- 属于 RefundService
- 调用了 refund()
- 参数为 orderId
```

于是：

系统获得：

# **结构化语义。**

---

# **八、AST 真正解决的问题**

AST 解决的是：

# **“代码理解效率”**

不是：

# **“代码展示”**

没有 AST：

Agent 只能：

```text
grep + 猜
```

像新人一样逐文件看代码。

有 AST 后：

系统可以直接告诉 Agent：

```text
RefundController
  ↓
RefundService.refund()
  ↓
RefundDAO.save()
```

于是：

Agent 的探索效率大幅提升。

因此：

AST 本质上是：

# **Agent 的代码导航层。**

---

# **九、CodeGraph 的真正作用**

CodeGraph 很容易被误解成：

```text
画图工具
```

但真正本质是：

# **“长期关系记忆”**

例如：

系统已经分析出：

```text
RefundService
 → refund_db
 → refund_topic
 → payment_rpc
```

后续：

不需要重复分析。

因此：

CodeGraph 本质上是：

# **长期代码语义缓存。**

它解决的问题是：

- 重复探索
- 上下文爆炸
- 大规模系统理解
- 增量更新依赖分析

---

# **十、Graph 与 GraphRAG 的区别**

这是一个非常关键的区分。

当前阶段：

Graph 的作用是：

# **“代码关系结构”**

例如：

```text
Service → DB
Service → MQ
Service → RPC
```

这是：

# **Semantic Graph（语义图）**

而：

GraphRAG：

解决的是：

# **“全局知识推理”**

例如：

```text
退款失败影响哪些系统？
```

这种：

- 多跳推理
- 全局关联
- 社区发现

才属于 GraphRAG。

因此：

第一阶段：

完全可以：

# **有 AST / CodeGraph**

# **没有 GraphRAG**

这是合理的。

---

# **十一、为什么企业知识系统不能“文档平权”？**

这是整个系统架构最关键的地方之一。

一开始很容易想：

```text
代码 + 文档 → 自动融合
```

但这是危险的。

因为：

文档：

- 可能错误
- 可能过期
- 可能主观
- 可能质量很差

如果：

文档直接覆盖代码 Wiki。

最终：

# **会污染核心知识。**

因此：

正确模型不是：

# **知识融合**

而是：

# **知识分层（Knowledge Layer）**

---

# **十二、最终形成的知识分层**

---

## **第一层：Code Truth Layer（最高可信）**

来源：

- 代码
- SQL
- 配置
- API
- MQ

特点：

- 强一致
- 自动更新
- 高可信

这是：

# **系统现实（System Reality）**

---

## **第二层：Runtime Truth Layer**

来源：

- Trace
- 日志
- Metrics
- Incident

这是：

# **系统运行现实**

---

## **第三层：Human Knowledge Layer**

来源：

- 技术方案
- RFC
- PRD
- 事故复盘
- 经验总结

这是：

# **人类意图（Human Intent）**

---

# **十三、最重要的知识设计原则**

不是：

```text
文档修改代码 Wiki
```

而是：

# **文档附着在代码知识上。**

例如：

```text
RefundService

├── Code Truth
├── Runtime Truth
└── Human Knowledge
```

文档不是覆盖代码。

而是：

# **作为解释层挂载。**

---

# **十四、Wiki 的真正形态**

最开始容易认为：

```text
Wiki = 一篇文档
```

但最终发现：

真正合理的是：

# **Knowledge Node（知识节点）**

例如：

```text
RefundService
```

是一个节点。

其下面挂：

- 调用链
- DB
- MQ
- 文档
- 事故
- PR
- 历史演进

因此：

Wiki 不再是：

# **静态文章**

而是：

# **动态知识视图**

---

# **十五、企业 Wiki 与开源项目 Wiki 的本质区别**

这是讨论中一个非常重要的洞察。

开源项目通常关注：

- Installation
- Quick Start
- Usage

因为：

目标是：

# **“让用户快速使用”**

但企业系统真正关心的是：

- 系统职责
- 业务边界
- 核心链路
- 状态流
- 数据模型
- 风险点
- 历史演进

因为：

目标是：

# **“建立系统认知”**

因此：

企业 Wiki 本质上是：

# **系统认知地图**

而不是 README。

---

# **十六、知识组织最核心的问题**

整个系统最终最重要的一步：

其实不是 AST。

而是：

# **Domain Partition（领域划分）**

因为：

知识不应该按：

```text
package
module
repo
```

组织。

这是代码视角。

而应该按：

# **Business Domain（业务域）**

组织。

例如：

```text
订单域
支付域
退款域
分账域
```

因为：

人是按业务理解系统的。

---

# **十七、Pipeline 的最终设计思路**

最终形成的整体流水线：

```text
Git Repo
   ↓
Code Parse
   ↓
Semantic Extraction
   ↓
Domain Partition
   ↓
Agent Exploration
   ↓
Knowledge Node Generation
   ↓
Wiki Rendering
   ↓
Incremental Update
```

---

# **十八、各层职责定义**

---

## **1. Code Parse Layer**

负责：

```text
源码 → AST / Symbol
```

包括：

- Import
- 调用关系
- SQL
- Annotation
- Config

作用：

# **结构化代码。**

---

## **2. Semantic Extraction Layer**

负责：

# **从代码中提取系统语义。**

包括：

- Service
- API
- MQ
- DB
- 状态机
- 链路
- 外部依赖

这里开始：

# **从“代码”变成“系统”**

---

## **3. Domain Partition Layer**

负责：

# **按业务域组织知识。**

这是：

整个系统认知结构的核心。

---

## **4. Agent Exploration Layer**

Agent 的角色不是：

```text
代码总结器
```

而是：

# **系统分析师。**

其目标：

不是逐文件总结。

而是：

# **建立系统级认知。**

---

## **5. Knowledge Node Layer**

形成：

- 服务节点
- 领域节点
- 状态节点
- 数据节点

这是：

# **长期知识结构。**

---

## **6. Wiki Rendering Layer**

最后：

才生成：

- Markdown
- 导航
- 索引
- 可视化页面

Wiki：

只是：

# **人类阅读视图。**

---

# **十九、Agent Prompt 的关键设计思想**

Agent 不应该：

```text
请分析代码
```

而应该：

# **“围绕业务建立系统认知”**

正确 Prompt 核心：

```text
你是一位资深系统架构师。

你的目标不是总结代码，
而是理解：

1. 系统职责
2. 业务边界
3. 核心链路
4. 数据流
5. 状态变化
6. 上下游依赖
7. 风险点
8. 历史演进
```

重点：

# **不逐文件总结**

# **优先系统认知**

# **二十一、增量更新的核心思想**

不要：

# **全量重生成**

而应该：

# **Node-based Update**

基于：

```text
Git Diff
```

流程：

```text
文件变化
 ↓
AST Diff
 ↓
影响哪些 Semantic Node
 ↓
更新相关 Wiki
```

这会带来：

- 更稳定
- 更低成本
- 更长期可维护

---

# **二十二、最终系统真正的长期形态**

最终：

系统会逐渐形成：

# **企业长期记忆系统（Long-term Organizational Memory）**

其核心不再是：

```text
文本集合
```

而是：

# **多层可信知识网络。**

其中：

- Code Truth 是核心骨架
- Human Knowledge 是解释层
- Runtime 是现实反馈层
- AI 是认知与推理层

最终形成：

```text
代码
 ↓
语义结构层
 ↓
知识节点
 ↓
长期知识网络
 ↓
Wiki / 搜索 / Agent / AI
```

而：

Wiki：

只是：

# **这个知识网络的人类可视化界面。**
