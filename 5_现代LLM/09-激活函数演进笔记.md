# 激活函数演进：ReLU → GELU → SwiGLU

> 核心结论：
>
> **现代 LLM 并不是用 Swish 替代 GELU，而是用 SwiGLU 替代了整个 FFN（Feed Forward Network）。**
>
> 真正的创新来自 **GLU 门控结构**，Swish 只是其中表现最好的 Gate 激活函数。

---

# 一、ReLU 为什么已经很好，还需要 GELU？

## ReLU

公式：

$begin:math:display$
\\text\{ReLU\}\(x\)\=\\max\(0\,x\)
$end:math:display$

特点：

- 正数全部保留
- 负数全部归零
- 计算速度快
- 不容易梯度消失
- CNN 时代最成功的激活函数

例如：

```
输入：
-3 -2 -1 -0.5 0 1 2 3

输出：
 0  0  0   0  0 1 2 3
```

---

## ReLU 的问题

### 1）信息丢失

所有负数都会变成 0。

例如：

```
-0.0001

↓

0
```

```
-100

↓

0
```

模型无法区分：

- 稍微负一点
- 非常负

信息直接丢失。

---

### 2）梯度不连续

```
x<0

梯度=0

x>0

梯度=1
```

在 0 点发生跳变。

虽然实践影响不算很大，但优化理论上不够平滑。

---

# 二、为什么出现 GELU？

GELU：

$begin:math:display$
\\text\{GELU\}\(x\)\=x\\Phi\(x\)
$end:math:display$

其中：

$begin:math:display$
\\Phi\(x\)
$end:math:display$

是标准正态分布的 CDF。

它不是：

> 小于 0 就删除。

而是：

> 根据大小决定保留多少。

例如：

```
x=-2

保留约2%

------------

x=-1

保留约16%

------------

x=0

保留50%

------------

x=1

保留84%

------------

x=2

保留98%
```

它是一种：

> **软筛选（Soft Selection）**

而不是：

> **硬删除（Hard Threshold）**

---

## 为什么 Transformer 更喜欢 GELU？

Transformer 中每个隐藏维度都承载着语义信息。

例如：

```
第378维

可能同时编码：

一点语法

一点位置

一点时间

一点语义
```

如果：

```
负一点

↓

ReLU

↓

直接变0
```

容易损失细粒度信息。

因此：

Transformer 更希望：

> 保留弱信息，而不是直接删除。

---

# 三、Swish 又是什么？

Swish：

$begin:math:display$
\\text\{Swish\}\(x\)\=x\\sigma\(x\)
$end:math:display$

相比 ReLU：

负数不会直接变成 0。

例如：

```
x=-1

↓

约-0.27
```

```
x=-3

↓

约-0.14
```

特点：

- 平滑
- 连续可导
- 保留部分负值信息

---

## Swish 与 GELU 的关系

实验结果：

```
ReLU

↓

GELU ≈ Swish
```

两者性能通常非常接近。

很多任务：

提升仅：

```
0.1%

~

0.5%
```

因此：

**如果只是替换激活函数，Swish 并不会比 GELU 强很多。**

---

# 四、真正的创新：GLU

GPT 的 FFN：

```
Linear

↓

GELU

↓

Linear
```

只有一条信息流。

---

GLU：

变成：

```
          Gate

        /

Input

        \

          Value
```

最后：

```
Gate

×

Value

↓

Linear
```

即：

```
两条分支

↓

一条负责控制

↓

一条负责真正的信息
```

表达能力明显增强。

---

# 五、GLU 家族的发展

最初：

GLU：

$begin:math:display$
\\sigma\(W\_gx\)\\odot\(W\_vx\)
$end:math:display$

后来发现：

Gate 不一定要用 Sigmoid。

于是：

| 名称 | Gate |
|------|------|
| GLU | Sigmoid |
| ReGLU | ReLU |
| GEGLU | GELU |
| **SwiGLU** | **Swish** |

因此：

> **GLU 是一种网络结构。**

Gate 使用什么激活函数可以自由替换。

---

# 六、SwiGLU 为什么不是简单替换激活函数？

很多人误认为：

```
GELU

↓

Swish
```

实际上：

真正变化的是：

```
普通 FFN

↓

GLU FFN
```

也就是说：

不是：

```
换激活函数
```

而是：

```
整个 FFN 结构升级
```

Swish 只是：

GLU 中表现最好的 Gate。

---

# 七、为什么最终选择 SwiGLU？

GEGLU 与 SwiGLU：

实验差距其实非常小。

通常：

```
GEGLU

99.9

SwiGLU

100.0
```

只有约：

```
0.1%
```

左右。

因此：

真正提升来自：

```
普通 FFN

↓

GLU
```

而：

```
GEGLU

↓

SwiGLU
```

只是进一步优化。

---

# 八、Gate 为什么不用限制在 0~1？

最容易误解的问题。

很多人认为：

Gate：

```
应该

0~1
```

其实：

这是第一代 GLU 的设计。

---

## 原始 GLU

Gate：

```
Sigmoid

↓

0~1
```

意味着：

```
Value × Gate
```

只能：

- 保持
- 削弱

永远不能增强。

例如：

```
Value=10

Gate=0.8

↓

8
```

最大只能：

```
10
```

不能：

```
15

20
```

---

## SwiGLU

Gate：

```
Swish(x)

=x·sigmoid(x)
```

例如：

```
x=-2

≈-0.24

------------

x=1

≈0.73

------------

x=2

≈1.76

------------

x=5

≈4.97
```

因此：

Gate 可以：

```
0

0.3

0.8

1

2

3

……
```

既能：

- 抑制
- 保持
- 放大

表达能力更强。

---

## 为什么不会爆炸？

原因：

### 1）Swish 增长是线性的

对于：

```
x→∞
```

有：

```
Swish≈x
```

不会指数爆炸。

---

### 2）Linear 权重可学习

Gate：

```
W_gx
```

训练过程中：

模型会自动学习：

合适的缩放。

---

### 3）Transformer 本身还有：

- RMSNorm
- 残差连接
- 权重初始化

共同稳定训练。

---

# 九、现代 Gate 的理解

第一代 GLU：

Gate 更像：

```
开关
```

现代 SwiGLU：

Gate 更像：

```
动态缩放器（Dynamic Scaling）
```

即：

```
Value

×

Scale
```

Scale 可以：

```
0

关闭

------------

0.3

减弱

------------

1

保持

------------

2

放大

------------

5

大幅放大
```

因此：

现代 Gate：

> **不是概率。**

而是：

> **可学习的动态增益（Gain）。**

# 十、整体演进路线

```
ReLU

├── 删除负值

        ↓

```

# 我的思考（讨论记录）

## Q1：GELU 不也是一种门控吗？

最开始认为：

> GELU 根据输入大小决定保留多少信息，也算一种 Gate。

后来发现：

**GELU 与 GLU 的本质不同。**

GELU：

```
一条路径

↓

自己决定保留多少
```

GLU：

```
两条路径

↓

另一条路径学习如何控制当前路径
```

因此：

GLU 的控制能力更强。

---

## Q2：Gate 能看到更全局的信息吗？

最开始认为：

Gate：

```
多了一套 W

↓

能够看到更多信息
```

后来修正：

其实：

GELU 的输入：

```
W x
```

同样来自上一层的全局线性变换。

因此：

**两者都能看到全局信息。**

真正区别不是：

> 谁看到更多。

而是：

```
GELU

↓

固定激活函数

----------------

GLU

↓

额外学习

"如何控制"
```

也就是：

> **增加了一条可学习的门控路径。**

---

# 最终总结

> **现代 LLM 的演进重点已经不是更换激活函数，而是升级 FFN 的结构。**

可以概括为：

- ReLU：硬阈值，删除负值。
- GELU：软筛选，保留弱信息，更适合 Transformer。
- Swish：作为普通激活函数，与 GELU 性能接近。
- GLU：引入双分支门控，显著增强表达能力。
- SwiGLU：在 GLU 中采用 Swish 作为 Gate，是目前 LLaMA、Qwen、DeepSeek 等现代大语言模型的主流 FFN 结构。
